Standard vinyl: current song's similar songs (official Windows 3.1.42)
=====================================================================

Recovery sources
----------------

The official playback page M/182:4372–4405, 4450–4452 and 4510–4545
(M/46:37–39 for navigation labels) separates 歌词 / 百科 / 相似推荐 when
PH-PC-playPage-recommendMore-new is t1. The official startup manifest
(M/147:342–355) defaults the experiment to t1. Cumulus uses that manifest
through the existing verified signed PC experiment resolver, whose fallback
requires a valid response and credential context. It does not enable this
lane without verified context or in an explicitly assigned control group.

SimilarSongCard (M/253:37–74,86–126), M/109:84–91 and M/15:3783–3799,
1012–1014 show the request on card load:

  POST /api/v1/discovery/simiSong
  { "songid": "<current ordinary catalog song ID>" }

The request uses the native PC EAPI context and no response cache. The
successful response supplies top-level songs. UID is an input to the
formatter, never an additional wire argument. This is not the search
recommendation service or the queue's “更多推荐” service. No request is made
from an arbitrary renderer ID. There is no background polling.

Official playback actions
-------------------------

* Card title play: M/253:89–102 and TitlePlayButton M/537:489–544 pass all
  returned rows with default Action.play, text 相似歌曲 and Scene.vinyl.
  M/3085:215–251,309–312,462–481,564–585, M/308:3150–3152 and
  M/1384:5268–5298 select the first displayed row and insert the eligible
  list after the current queue entry, retaining unrelated queued songs.
  An unavailable first row does not silently start a different song.
  When the first row is already current, M/1384:5345–5369 still applies
  the new queue and requests Playing with flag cur. M/308:1625–1632,
  1671–1685 (and stop's native gate at 1030–1056) preserves the active
  decoder/clock or resumes the same paused playback without seeking.
  The native actor preserves the exact selected entry while inserting the
  remaining rows; it never exchanges its current authorized source.
* Song artwork: M/113:505–518 passes only that resource and its label,
  with no parent list. It inserts and starts that one row, retaining
  unrelated songs. The current row can show a pause glyph (M/113:91–109),
  but its click always dispatches Action.play and M/19:72–97 preserves
  click versus dbClick. The same song keeps playing or resumes via
  M/3085:544–585 and M/308:3868–3877,1671–1685; only the double-click
  branch at M/3085:532–541 toggles in this ordinary scene. Artwork does
  not use the double-click preference.
* Song row double-click: M/405:225–255, M/225:590–602 and M/3085:180–182,
  245–251,309–312,431,532–541 pass the displayed parent list. The enabled
  device preference replaces the queue with the eligible displayed list
  and starts the clicked row; disabled preference retains the queue and
  inserts/starts only that row. A double-click on the already active
  resource toggles its own playback, including its pending pause state.
  Generic row playback uses the unknown scene plus the 相似歌曲 label; the
  independent song-song-recommend analytics path (M/352:1575–1594) is
  not part of playback. Cumulus does not send that analytics event.

Native trust boundary
---------------------

The native client requires signed-in current generation, the same
credential revision and API, the native current play ID and catalog
song, and the verified t1 group. It returns a bounded typed projection
and a short-lived opaque page receipt. Playback only accepts that
receipt and a captured row index; callers cannot substitute a song ID,
authorization URL or raw resource. A newer read supersedes the receipt.
There is no usable receipt for an empty reply. Malformed responses fail
closed. Cloud, local, download, podcast, FM, intelligent and together
queues are not accepted as targets for these ordinary playback actions.

Queue mutation uses the existing player actor/control and queue
revision fence, account and credential checks, audio ownership, room
gate, and normal source authorization. The selected row cannot be
explicitly denied by its known privilege. Only sanitized catalog
metadata enters the queue. A title action and artwork action do not
clear unrelated entries; replacement explicitly does.

Scope and verification
----------------------

The isolated Rust player fixture covers exact seed/path
and explicit control suppression, authorized and denied rows, receipt
projection, title/artwork order, both device preferences, native
same-play double-click pause/resume, and stale response rejection after a
newer track, credential revision or account. Current-first title and current
artwork tests also check that neither path reloads or seeks.

The old control layout combines these cards with 百科. M/69:84–115,
151–155 restores a false default, and M/253:55–74,115–127 resets the
similar-song flag to false on the first mounted/new track. The conditional
shows three only for non-t1 plus a truthy flag; its literal 展开更多 writes
true again. The reachable default therefore shows all songs with no
expand button. A preexisting truthy flag would show three and the button
would not change the count or reread; the header still receives the
complete list. This treatment implementation does not expose that old
group or reproduce a stale persisted hidden tab.

Independent “相关歌单” card
-------------------------

The verified t1 相似推荐 tab displays related playlists above similar songs
(M/182:4216–4217,4232–4245,4520–4547; recovered TrackDisplay.tsx:255).
Each card mounts and reads independently. Neither card requires any
rows from the other one. Control 百科 groups wiki, similar songs and
related playlists in that order; the native entry covered here is t1.

IncludeSongCard (M/182:4232–4265,4310–4366; recovered
IncludeSongCard.tsx:119–161,176–240) calls the current-song helper
M/109:93–97. M/15:3800–3809,1012–1014 registers the uncached call:

  POST /api/discovery/simiPlaylist
  { "songid": "<current ordinary catalog song ID>" }

The response has top-level playlists; M/21:41–42,884–926 projects them
in service order. Each card uses a decimal ID, name then title fallback,
coverImgUrl then picUrl then coverUrl, and playCount defaulting to zero.
The native desktop projection exposes only id, name, coverUrl and
playCount, with HTTPS public artwork and incoming query/fragment
stripped by the standard Cumulus artwork rule. No creator ID, private
URL or raw response leaves the adapter. An empty response returns an
empty list; malformed or failed responses fail only this call.

The official card starts at six cards in a three-column grid and offers
one-way “展开更多” when more rows exist, revealing already returned
results. Expansion resets when the seed song changes; remounting with
the same seed retains the setting. The entire card links to ordinary
/playlist/{id}; it has no play button, novel route or mutation. The
native read returns all accepted rows (safety ceiling 100) for that
expansion. It is bound to the current catalog play, account generation,
signed PC experiment/credential scope and fixed endpoint. It creates no
playback receipt and cannot invalidate the sibling's receipt.

The isolated native tests cover the two exact independent endpoints,
playlist order and field fallback, safe URL/ID projection, an empty or
failed playlist response preserving a playable song receipt, and delayed
playlist results being retired on track, account or credential changes.

Desktop integration and proof
-----------------------------

Main-window commands: player_vinyl_similar_available(epoch) resolves the
native group. player_vinyl_similar_songs(epoch,playId) and
player_vinyl_related_playlists(epoch,playId) load the two cards.
player_vinyl_similar_play(epoch,playId,receipt,action,quality) selects the
header or exact displayed row, with no renderer-selected song ID or queue.
The frontend renders the confirmed t1 tab next to lyrics in classic vinyl.
It persists the selected tab as a local presentation preference and keeps
the same song's playlist expansion when returning to it; a new song resets
the expansion. Lyrics, scroll-to-comments and the cover remain separate.
Each card loads and retries independently. A hidden or superseded play
cannot accept late results. A failed play never uses a general playback
retry to repeat its old receipt. Selected tracks from the recommendation
queue show the fixed source label 相似歌曲 (TrackTitle.tsx:555–578, M/253
and M/113's action source text); no synthetic navigation link is created.

Linux X11 validation uses actual Vue, native IPC, the production player
actor and libmpv null output with sealed generated media. Treatment
covers no read before opening, failed song read and isolated retry,
whole-list title insert, cover insert, both row double-click preferences,
late result after a new play, six-to-eight expansion without a reread,
and ordinary playlist 108 navigation preserving the existing paused
track. Control displays lyrics and sends neither recommendation read.
The WebView fixture saves 12 treatment states and 1 control state; no
real account or music service is used. Current-first decode/seek/paused
behavior is also tested independently in the Rust player fixture.

Reproduce with scripts/ci/vinyl_similar_smoke.py --related --binary
PATH_TO_UX_UI_PROBE --root NEW_DIR. Linux CI can capture screenshots;
Windows uses its separate packaged runtime. This is not physical sound
output, live service or old-control wiki/fold verification.

Verified control placement in Rust
----------------------------------

The compiled app/subApp M/182:4383–4405,4520–4545 and recovered
TrackDisplay.tsx:100–103,237–255 use two tabs, 歌词 / 百科, in non-t1
groups. The opened classic 百科 scroll pane mounts 音乐百科, 相似歌曲,
then 相关歌单. Treatment uses an independent 相似推荐 pane with related
playlists before songs; its 百科 contains only the wiki card. The same
two recommendation card components drive the same endpoints in both.

Compiled M/253:55–74,115–127 and SimilarSongsCard.tsx:98–132,164–184
agree that only non-t1 with a truthy similarSongExpand slices to three.
The card starts empty, writes false when first mounted for a different
song, and then accepts the async result. M/69:84–115,151–155 restores
the false default and persists exactly the dispatched value. The
normal control view therefore initially shows all returned songs and
has no song expand button. A latent truthy value would show three and
the literal 展开更多 button would write true again, with no count change
or reread. The title receives the whole response even in that latent
state. Cumulus does not seed the flag or add a guessed three-to-all
control. The related playlist card independently expands six to all
on click (M/182:4251–4259,4351–4362).

Native player_vinyl_recommendation_placement(epoch) projects only
unresolved, standalone or wiki. The existing signed resolver may use
the recovered t1 manifest default after a valid response; a verified
nonempty non-t1 group resolves wiki, and unavailable, blank or malformed
groups do not authorize either lane. Read results identify their
placement. The song receipt is bound to that placement, epoch, play,
API and credential revision. The actor and both read commits reject
superseded observed placement, including a refresh with the same
credential revision. The previous bool remains standalone-only for
the current desktop IPC. This change does not yet mount the control
wiki or alter the recorded treatment/control WebView run above.
