当前实现与职责
- PlaylistEditorPage.vue 是 main 内容区内的编辑页，顶栏/侧栏/播放条保持可用；封面在右，
  文字在左，操作区位于正文滚动区之外、窄窗保持可达。原来的 PlaylistDialog 只负责新建、链接、记录、
  歌曲操作，已删除旧编辑分支。编辑表单、标签、确认窗口与草稿协调分开维护。
- usePlaylistEditor.ts 将输入草稿与 core 最新观察到的歌单版本分开。首次读取填充表单，
  保存拒绝/部分成功/结果未知或封面刷新不覆盖输入；重试使用最新观察版本。保存仍通过
  PlaylistManager/类型化IPC→Rust core；没有在前端增加业务请求、Cookie或签名信息。
- 名称/简介错误有字数和aria-invalid反馈；未修改、无效或未确认写入不能重复保存。
  加载失败可重新读取；保存中阻止离开并给出状态提示，完成后才关闭。
  已确认拒绝与部分成功保留草稿可修正/重试；未知结果显示“核对结果”，核对不重发写入。
- 如果发送后的回读也失败，IPC可能返回错误而非结果DTO；编辑页从同歌单的已有待核对
  日志恢复结果展示和禁用状态。部分成功按实际读回展示各字段已保存/未保存/待核对，
  原始接口状态码保留在业务日志，不直接放在表单文案里。
- 顶栏返回、取消、侧栏/搜索/设置等应用导航共用离开检查。未保存时默认聚焦“继续编辑”；
  放弃后才执行原导航；取消/Escape保留草稿，返回原触发控件。延迟导航回调一次性使用，
  原页面或账号代次变化后失效；账号切换/过期清除旧账号编辑页，不保存旧账号草稿到新账号。
- 封面窗口关闭回到封面入口；编辑页退出在页面动画结束后恢复入口焦点。歌单记录进入
  封面恢复时，退出的记录弹窗不会覆盖新编辑页的焦点，也不会重置它的异步读取。
- 原有清空/公开/删除操作移入“其他歌单操作”菜单，保留原确认与核心用例。没有在视觉
  检查中执行真实清空/公开/删除。保留这些入口属于社区业务兼容，不声称官方编辑页有此菜单。
  共用菜单按钮显式使用type=button，打开菜单不会隐式提交所在表单。
- 页面使用既有transform/opacity过渡；封面悬停尊重系统与应用减少动态效果设置。
  标签入口或选择区的Escape关闭选择区，最多3个时禁用未选项，移除后恢复选择。
  编辑页退出动画结束前，保留的原页面保持隐藏，避免文字交叠。正文控件采用内侧焦点
  描边，避免第一行和滚动边缘裁掉描边；保存中离开提示使用中性状态配色。

适配与已知差异
- 正常窗口保持上述字段/封面几何；<=1050px采用120px封面、20px列距、52px标签列；
  <=650px高窗口采用22px标题、128px简介和紧凑间距。正文可独立滚动、底部操作保持可达。
  这些是760×540最低窗口的社区适配，不宣称官方在同尺寸有相同响应式策略。
- 增加未保存离开提示是社区改进；官方恢复的onCancel直接返回。未实现跨进程文字草稿
  持久化，关闭进程或账号切换不保留未保存文字；封面恢复仍走既有持久化任务。
- 保留Cumulus品牌、语义配色/图标、字符提示和管理菜单；标签当前为正文内展开分类列表，
  官方使用Select浮层。文件选择/裁剪窗口沿用已有实现，内部全套像素对齐仍待单独核对。
- 当前验证使用合成账号、内容与占位封面。真实封面上传新回归、Windows视觉、DPI和物理
  桌面刷新率需独立证据；历史上传结果不能计作本次新页面上传成功。

验收机制
playlist_editor_ui_probe.js 通过生产DOM及正式IPC操作页面；playlist_editor_fixture.rs
只编入example，在隔离内存模拟官方批量元数据响应、读回、失败和丢失确认，Rust核心仍
执行真实校验/持久化日志/回读核对。读取与写入等待观察到加载帧后由探针放行，20秒封顶。
45个状态覆盖两尺寸/两主题的编辑、标签、封面聚焦与弹窗、未保存确认、草稿恢复、字段聚焦、管理菜单不提交表单；
无效输入、加载/失败/重试、明确拒绝/部分成功/未知结果及恢复、保存中导航、放弃后导航。
服务端拒绝使用已有核心明确拒绝码403；500会被正确保留为未知结果，不能拿来假装拒绝。
核对未知结果不发送第二次batch；总共6次写入仅指隔离内存服务，不是真实账号操作。

python3 scripts/ci/playlist_editor_smoke.py --binary /absolute/ux_ui_probe --root /absolute/new-root
