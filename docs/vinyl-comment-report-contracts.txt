标准播放详情：内嵌评论举报

来源为网易云音乐 PC 3.1.42.205594。M182:5236–5246,5276–5286 及
vinyl-page/views/TrackPage/modes/CommentTab/CommentArea.tsx:387–434
证明精彩和最新评论共用 M439 的 CommentCard。恢复的 CommentCard.jsx:
130–135,181–185,289–322,391–404,465–518 显示鼠标移入卡片时出现
「举报」；自己的评论不显示举报。左键从按钮直接进入原因，右键从评论
菜单进入「举报」子菜单。M622:1903–1970 给出五种预设和「其他原因」。
Cumulus 同样支持左右键路径，并在键盘焦点进入行或没有悬停能力的设备
上显露入口。被移除、作者不可用或无可核对作者的评论不提供入口；
自己的评论不提供举报，原版的内嵌删除不在这一批。

M55:81–111,117–157,214–245,412–435 与 M15:2684：选择预设本身
就是发送动作；其他原因打开「举报原因」，取消不发送，空白不能确认，
发送原文。原接口为 uncached /api/report/reportcomment，业务体仅
{threadId,commentId,reason}；原版以 toast 提示 200 举报成功、
-1 重复举报，其余失败。Cumulus 保留预设单次选择触发、其他原因显式
确认、文字原样发送，并沿用已有 4 KiB UTF-8 本地输入上限和可聚焦回执
弹窗。回执不明时只允许查看本机记录；服务没有可恢复的独立核对接口。

player_vinyl_comment_report 仅主窗口可用，接收 epoch、playId、
规范数字评论 ID 和 inspect/prepare/cancel/submit，不接收歌曲/线程、
账号或授权数据。实际 Catalog 播放、当前账号、原 API、签名 t1 分组、
凭据版本都沿用内嵌写入规则。草稿仅存在内存并绑定同一个原生 playId、
线程、评论和凭据版本；不能在独立评论页提交，也不能带到下一次播放。
发送前在同一个绑定下重新读取指定评论（limit=1），要求作者不是当前
账号、评论未被移除、无明确冲突的 threadId。写入与读取皆使用
VinylCommentWrite/Read 的 PC EAPI 绑定，实验路径与实际请求须见到相同
唯一 MUSIC_U 和设备 ID；写请求实际交给后端前再次核对当前账号与播放。

持久回执和独立评论页共享 comment-report-receipt-v1。发送前仅写原
账号的保守状态，不保存原因或评论文字。确定未调用后端时清除此状态；
可能已发送但结果不明时不清除、不重放。确定的 200/-1 分别留下接受/
重复回执。切歌或换账号后迟到回执不进入新页面，原账号仍可从独立评论
页查看记录。打开原因、取消、普通查阅均没有上游举报写入。
未参考其他客户端，测试不触及真实账号或真实举报。

合成原生用例验证取消、自己的/已移除/缺失/其他线程评论、原文、
成功与重复回执、不确定结果不重发，以及临发送切歌、改凭据、换账号
均不发送并清除原账号未发标记。独立评论和用户主页举报单独回归。
Linux X11 WebView 集成使用同一原生 IPC、合成账号及 libmpv null 输出：
通过左键取消自定义原因、右键选择预设并显示成功、自定义原文发送后
丢失回包、从另一评论分组重开并核对回执四态。精确捕获两次提交、
两次单条目标校验；取消、核对和重开没有补发，播放实例、暂停位置及
评论滚动保持不变。保留四张截图；未向真实服务发送举报。Windows WebView
用例已接入 CI，Linux 证据不代表 Windows 运行结果。
