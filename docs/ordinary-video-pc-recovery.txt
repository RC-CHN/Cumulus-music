普通视频与 MV：官方 Windows PC 3.1.42.205594 的已恢复边界
2026-11-04。结论：恢复了普通视频的识别、卡片和路由；本版已解包桌面路径没有
提供一条可证明的普通视频播放授权链。现有普通视频卡片保留展示边界，未接新播放功能。

资源与路由
- recovered-js/modules/hybrid_app.chunk.1482700000000.js/15.js:3700–3717：
  /api/mlog/artist/video 用 artistId、tab、order 和 page JSON 读歌手视频卡片；
  响应 data.records 经 M21 V 转换，页游标来自 data.page。
- M21:242–244,625–679：resource.mlogBaseData.type=2 是普通 video，3 是 mv；
  输入显式 isMv 真值走 MV 优先分支。记录 ID 来自 String(c.id || "")，
  不按数字外观推断资源种类。标题/封面/时长/计数/关联歌曲是卡片资料；
  shareUrl 是分享地址，普通视频没有在这个转换中取得可播放授权地址。
- hybrid_38/3088.js:2953–2959,2980–3018 将歌手“视频”数据交给 M2093；
  hybrid_38/2093.js:141–170 以及 hybrid_41/2093.js:141–170 将普通视频标记
  为 ResourceType.video，MV 标记为 ResourceType.mv，但两者的卡片跳转路径都为
  /videoDetail/{id}，没有类型后缀。hybrid_73/3085.js:1037–1040 的缺省 Action.link
  也如此。路由状态的 resourceType 不能代替路径 type。
- M205:230–234 注册 /videoDetail/:id/:type?，挂 M3098 和 page:videoDetail M3158。
  hybrid_49/3098.js:2533–2561、2605–2614：路径省略 type 时默认 "mv"；只有
  type === "mv" 才 dispatch getDetail({id,type:"2"}) 并渲染 De（MV 播放器）。
  路径显式写 /video 或 /2 不会读取详情，也不挂播放器。普通卡片默认跳转只会
  进入 MV 分支；这本身不是普通视频授权成功。M308:5831–5859 的顶栏联动甚至
  用十进制 /videoDetail/{id} 正则；不能据此改写普通视频的不透明 ID。

详情、权限和边界
