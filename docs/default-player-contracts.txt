当前迁移：原生冷启动与 Linux／Windows 暖转交
- 新启动的 Cumulus 接受 --play=ABSOLUTE_PATH 或 --play ABSOLUTE_PATH …
  （最多 8 个）。路径保留为 OS 原生参数/PathBuf，不经过 shell、HTTP、
  file URI 或 WebView IPC；落入现有 Rust 队列存储前要求可无损表达的 UTF-8。
  Windows 拒绝 UNC/设备路径；相对路径和其他参数不作为打开授权。无法
  无损解码的 --play= 仍是失败的显式打开，不退化成普通启动。
- Linux 和 Windows 的可识别本地资料目录在正式窗口与业务初始化前取得独占
  进程锁。同目录普通重复启动退出 2；显式打开才尝试转交，不创建第二个播放器。
  自动启动 --autostart 独立；旧版、不可识别的 Windows 目录或安全令牌、
  Linux 不同网络命名空间或可共享目录、以及 CUMULUS_SESSION_DIR 指向历史
  会话的启动不承诺暖转交。
- 冷启动的第一条主 WebView player stream 到达有效账号代次后一次性取走原生参数；
  它不会在后续注册或失败重试中重新消费。显式打开会抑制旧队列本次自动播放，
  即使所有候选无效也保留旧队列和时钟。错误消息为固定本地文本，无原始路径。
- MP3/FLAC 的后缀、签名、ffprobe 音频编码和指纹必须一致。受支持的
  PCM WAV 由原生 RIFF/PCM 检查确定格式、采样率、有效范围和时长，不调用
  ffprobe。按官方模式跳过无效文件、保留有效顺序。元数据准备最多等待
  12 秒；新代次/显式播放动作可使已准备请求失效，不用旧结果覆盖新队列。
- 经过现有播放许可和账号代次/焦点栅栏，播放器在真正加载时检查打开句柄
  的文件身份，使用 libmpv 的受限 pinned stream 与固定解码格式，防止把
  伪装清单当作可联网媒体。只保存显式队列条目，不扫描或添加父目录、不创建
  本地库记录，不转成在线 ID。渲染层只得普通本地音轨投影和状态。
  NCM/CUE/CD 及其他普通后缀仍遵守各自现有入口，未暴露在冷启动关联流程。

Linux 暖转交
- 官方暖回调接同一 onPlayLocalMusic 模型；这里使用 Linux 原生 IPC 代替
  Windows 官方原生转交。规范目录 SHA-256 与有效 UID 区分地址，抽象 Unix
  域套接字不创建系统套接字文件；双方都验证内核 SO_PEERCRED 的有效 UID。
  套接字名称不是凭据，其他同 UID 进程与直接调用 CLI 同属用户授权边界。
  显式暖转交在发送方图形检测前完成；发送方无需启动另一个渲染器。
- 只有现有主窗口已经订阅当前账号代次时才开始处理。协议含 ready/busy、
  一次有长度上界的半关闭帧（32 KiB，最多 8 个绝对 UTF-8 路径，无控制
  字符）和独立回执。连接非阻塞，发送前握手和帧接收各限 2 秒；发送后最多
  等 20 秒，遇到断线或未知回执不自动重发。无有效项不会动旧队列。
- 暖请求沿用播放队列、账号代次、最新播放操作和媒体焦点的准备/提交栅栏；
  用户后来操作导致的变化使过时请求失效，主窗口销毁取消尚未提交的工作。
  接受后在主线程显示/恢复原窗口。
  返回 0 表示原进程接受了播放选择，解码/设备后续结果仍显示在原播放器；
  2 为原实例/账号播放器未就绪等不可用，3 为不支持的请求/文件，4 表示
  未确认（先看现有播放器），5 表示已有文件打开处理中。只接收 CLI 路径，
  不转发环境、账号、媒体 URL 或 WebView 命令。

Windows 暖转交候选（尚不进入主线／安装包）
- 原版证据确认暖回调与冷启动复用本地路径播放模型，未确认其内核协议。
  这里使用与独立 Win32 实验共用的单实例重叠 I/O 管道。地址由持有的资料目录
  的卷 GUID、卷和文件 ID、登录 SID、完整性及提升状态派生；窗口初始化时
  重新走不跟随重解析的路径核对同一身份。地址不是凭据。保护 DACL 仅允许
  当前登录 SID，拒绝远端；
  两端按内核管道 PID 查询活跃进程主令牌，要求用户、登录、完整性及提升
  一致。服务端先读取单字节握手（没有路径），再通过仅可识别的连接令牌
  核对实际连接线程；主令牌与连接令牌的可访问组、特权、账户/LUID、完整性
  策略和虚拟化状态须匹配。拒绝 AppContainer、显式受限 SID 和动态用户/
  设备声明；未知令牌信息也拒绝。读完路径后重复核对；恢复原线程上下文
  失败即永久退出该 relay worker，不执行任何应用操作。
- 显式第二次启动在自身图形检测前完成。仅已绑定账号的主播放器订阅才给
  ready，且一直保留发出 ready 时的同一份订阅许可。主窗口重载、销毁、
  退出、订阅被替换或结束均撤销旧许可，即使新订阅仍属同一账号代次。
  一次帧只含最多 8 条本地磁盘 UTF-8 路径（每条 4096 字节、整体 32 KiB）。
  写回执后等待消费字节或关闭，最多 2 秒；停止时先确认内核 I/O 结束再回收
  缓冲。请求送入核心后的错误或失去回执均表示未确认，先查看原播放器；
  不因可能已持久提交的结果错误而重发。
- 收帧后的业务调用同一原生播放器；它不接 WebView 文件路径。候选已通过
  GNU Windows 目标严格 Clippy；两项真实管道测试须在 Windows 运行，尚不能
  代替正式 app 转交、本地解码或系统关联验收。另有同登录但受限线程能打开
  受保护管道、却不能得到 ready 的 Windows 负向用例；也尚未在 Windows 实跑。
  未新增 NSIS 关联或写 Explorer 默认值。
- 暖资料目录解析：RoamingAppData 用 KF_FLAG_DONT_VERIFY 查询原配置，不预先探测
  重定向文件夹。盘符只用 QueryDosDeviceW 查询对象映射，拒绝 UNC、网络盘、
  SUBST、相对/替代流及其它不受支持命名；仅打开已冻结的 NT 本地卷目标。
  卷设备属性、文件系统及卷 GUID 从同一持有句柄取得，要求非远程、非可移除
  NTFS。逐层以父目录句柄和 OBJ_DONT_REPARSE 打开或创建；过程锁是最后一个
  目录内相对打开的普通单链接文件，不截断，不走同名回退。锁持有期间保存各
  级目录句柄并禁共享删除。无法验证的资料目录只保留既有冷启动（其显式配置
  路径仍可由旧流程访问）；已验证目录内可疑锁文件直接拒绝。获准的资料
  目录给 Rust 和 SQLite 的路径取自最后一个持有句柄，使用同一卷的 GUID；
  后续资料文件打开不再解析可变盘符；这不改变 SQLite 对单个文件的常规
  Win32 打开方式。SQLite 同库与日志可见性仍待原生验证。
  资料目录纯解析向量在 Linux 执行；同文件竞争、目录换位及锁链接用例与
  FFI 已通过独立 Windows GNU 链接/严格 Clippy，未在 Windows 运行。实际 Windows
  固定 NTFS 可执行 cargo test -p cumulus-desktop --locked --lib
  native_open::windows::profile::tests；重解析用例需相应建符号链接权限。
- Windows 持有媒体候选只接受固定本地 NTFS 的普通 MP3/FLAC 和受支持的 PCM WAV 文件。先通过
  QueryDosDeviceW 读取当前盘符的直接本机磁盘设备名，再用 NtCreateFile
  打开那个 NT 卷根，而不重新解析盘符。卷根和相对路径打开不跟随重解析；
  远程/可移除卷、SUBST 子目录、UNC、流名、链接与需回迁数据的文件不进入。
  元数据使用同一个持有文件：受支持 PCM WAV 由 Rust 解析，纯 FLAC 与
  MP3 通过受信 ffprobe 的 fd: 标准输入适配器，子进程从不接收媒体文件名。
  MP3 先验证有界 ID3 与连续 Layer III 起始帧，再要求子进程实际解码有界
  起始音频，并由 libmpv 验证最终加载的编码。任一检查失败不会回退到按
  路径读取；这不代表整文件已预先解码。候选未接伴随歌词和本地 EQ 专用
  解码链。
- Windows 桌面冷暖入口调用独立的持有媒体方法，不更改系统文件关联。
  冷启动先建立订阅，再由确切的保留许可一次性消费进程参数；同代次的
  重绑不重放参数或自动播放被恢复的旧队列。每批最多八个文件，只有在
  队列写事务最后通过账号、订阅和选中代际检查后，才会装入本进程播放器。
  事务内的桌面许可只读原子状态，不重进会话或订阅锁。队列记录只有不透明键，不保存
  可重开的路径或文件句柄；进程重启、账号切换和离开现有队列后不能用
  旧键再开。MPV stock 解码读取原文件句柄，用独立逻辑游标处理 seek，
  从不重新解析媒体路径。把同名文件换成不同内容不会改变现有持有对象。
  确认退出时，先停止受理原生文件打开，再等待一起听退房及窗口销毁。
  退出失败恢复受理时，只有新发出的许可有效；旧的冷启动参数和已作废的
  暖转交不会重放。仅隐藏到托盘时继续受理。
- 原生 Windows 固定 NTFS/reparse 验收以及打包 ffprobe 9.0.2 与实际
  libmpv 的完整媒体验收须在 Windows 运行；GNU 交叉检查不算这些通过。
  真实 NTFS、连接令牌、文件解码、原生窗口与持久队列交接均须原生 Windows
  验证。当前候选不作为已发布的 Windows 暖转交。
  平台依据：https://learn.microsoft.com/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient
  与 https://learn.microsoft.com/windows/win32/secauthz/restricted-tokens 。
  卷 GUID 路径：https://learn.microsoft.com/windows/win32/fileio/naming-a-volume
  及 https://learn.microsoft.com/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew 。

Debian 打开方式候选与系统默认归属
- Cumulus 不写系统默认、Explorer UserChoice/Hash 或 Linux mimeapps.list，
  不展示默认播放器复选框，也不启动系统默认选择流程。Debian 包仅声明自己
  可被选为打开方式；便携包和 Windows 不增加关联元数据。
- Windows：固定 Tauri CLI 2.12.4 的 NSIS installer.nsi 调 APP_ASSOCIATE，
  FileAssociation.nsh 的 66–76 行会改写 Software\Classes\.ext 的
  默认值，卸载还会恢复备份，可能覆盖用户后来选择，因此保持关闭。
  后续应只装应用自有 ProgID/Capabilities/RegisteredApplications 候选和
  OpenWithProgids，再由用户从系统 Default Apps 选择。Windows 11 的
  ms-settings:defaultapps?registeredAppUser=… 只在候选已注册时才有意义；
  不复刻原版私有 UserChoice 行为。实际 Windows shell 与现代用户选择未测。
- Debian：保留 Tauri 2.12.4 的既有 Cumulus.desktop 名称、图标、分类和
