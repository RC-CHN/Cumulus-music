当前迁移：仅可信冷启动输入
- 新启动的 Cumulus 接受 --play=ABSOLUTE_PATH 或 --play ABSOLUTE_PATH …
  （最多 8 个）。路径保留为 OS 原生参数/PathBuf，不经过 shell、HTTP、
  file URI 或 WebView IPC；落入现有 Rust 队列存储前要求可无损表达的 UTF-8。
  Windows 拒绝 UNC/设备路径；相对路径和其他参数不作为打开授权。无法
  无损解码的 --play= 仍是失败的显式打开，不退化成普通启动。
- 同数据目录进程锁：普通打开持共享锁，冷文件打开需独占；已有实例时以 2
  退出并提示关闭当前实例后再试，不把参数转发或打开第二套活跃播放会话。
  旧版本不持本锁，跨版本暖启动不承诺。自动启动 --autostart 分支独立。
- 第一条主 WebView player stream 到达有效账号代次后一次性取走原生参数；
  它不会在后续注册或失败重试中重新消费。显式打开会抑制旧队列本次自动播放，
  即使所有候选无效也保留旧队列和时钟。错误消息为固定本地文本，无原始路径。
- 当前只接受普通 MP3/FLAC：原生后缀、签名、ffprobe 音频编码和指纹都必须
  一致，按官方模式跳过无效文件、保留有效顺序。固定总等待 12 秒；
  新代次/显式播放动作可使已准备请求失效，不用旧结果覆盖新队列。
- 经过现有播放许可和账号代次/焦点栅栏，播放器在真正加载时检查打开句柄
  的文件身份，使用 libmpv 的受限 pinned stream 与固定解码格式，防止把
  伪装清单当作可联网媒体。只保存显式队列条目，不扫描或添加父目录、不创建
  本地库记录，不转成在线 ID。渲染层只得普通本地音轨投影和状态。
  NCM/CUE/CD 及其他普通后缀仍遵守各自现有入口，未暴露在冷启动关联流程。

默认归属仍不启用
- Cumulus 不写系统默认、Explorer UserChoice/Hash、Linux mimeapps.list，
  不注册类型，也不展示一个不可验证的默认播放器复选框。没有自动请求关联、
  引导弹窗或安装时修改。暖启动仍缺少保留账号和操作代次的单实例原生转发。
- Windows：固定 Tauri CLI 2.12.4 的 NSIS installer.nsi 调 APP_ASSOCIATE，
  FileAssociation.nsh 的 66–76 行会改写 Software\Classes\.ext 的
  默认值，卸载还会恢复备份，可能覆盖用户后来选择，因此保持关闭。
  后续应只装应用自有 ProgID/Capabilities/RegisteredApplications 候选和
  OpenWithProgids，再由用户从系统 Default Apps 选择。Windows 11 的
  ms-settings:defaultapps?registeredAppUser=… 只在候选已注册时才有意义；
  不复刻原版私有 UserChoice 行为。实际 Windows shell 与现代用户选择未测。
- Linux：标准方式是在安装包应用自有 .desktop 声明已验证 MIME，并接收
  Exec 传入的本地文件参数，不写入用户 Default Applications。与真实文件管理器
  和暖启动选择验证完成后再启用。当前 .deb/.zip/NSIS 元数据不变。
