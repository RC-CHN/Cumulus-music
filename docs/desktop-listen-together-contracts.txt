一起听桌面接入：首批单账号主流程验证
2026-10-26。完整目标仍在进行。本批有独立的真实 WebView/IPC/libmpv 证据，
不把先前 REST 验证当作 UI 验收，也不把本批通过扩大为完整一起听或全部桌面目标完成。

入口与职责
frontend/src/components/TogetherPage.vue：侧栏“一起听”进入房间页，显示成员、共享队列、
同步错误与未决操作；创建、继续本机控制、重新同步、选择/移除歌曲、核对和确认退出。
frontend/src/composables/useTogether.ts：账号代次、迟到响应丢弃、单次提交、磁盘恢复与轮询。
desktop/src/together.rs：together_view / together_command 两个类型化 IPC 和窗口关闭协调。
core/src/client/together/{mod,runtime,selection,view,dto}.rs：原生播放器绑定、队列投影、
生命周期、持久偏好和受限 DTO；业务不依赖 Tauri、Vue 或 Python。

调用链
界面创建 -> TogetherService.create_for -> 确认新房间 -> 保存本机原速度/模式 -> 绑定播放器。
runtime 订阅实际 PlaybackController；有意义的播放/队列变化才上报，普通位置跳动不逐帧请求。
播放器暂停、定位、上一首/下一首、选曲、队列移除通过原生控制器执行，再按官方指令归约同步。
完整歌曲位置毫秒直接来自播放器时间线，不能重复叠加试听偏移。
共享列表只含线上歌曲或有有效文件版本映射的本地曲目，排除播客/未匹配本地文件；
窗口裁剪、去重和随机顺序沿用核心逻辑。队列变化目前以完整 REPLACE 上报。
普通顺序播放在房间内映射为列表循环，速度固定 1.0。退出后恢复入房前相应偏好；
保留期间用户主动选择的其他循环模式，不回滚整个本机队列。
HTTP 字段与核对规则见 core-listen-together-contracts.txt。

故障与生命周期
未知写入保留原账号持久责任，阻止房间同步继续发送；本机播放条仍可操作。
用户核对只读服务端，再显式重新同步当前播放，不自动重发不确定的写入。
如果暂停同步期间本机已切换歌曲，重新同步必须发GOTO而非跨曲PROGRESS；
新增丢回包后本机切歌的本地失败前证据 .build/together-resume-selection-before.log，修正后走同一持久操作路径。
该补充恢复分支有本地原生控制器验证；当前线上e只验证同曲重新定位恢复，不混称跨曲恢复已线上通过。
重开后显示持久房间，但必须显式“继续本机控制”；账号切换不得显示旧成员、队列或错误。
listen-together-player-v1/current 按账号保存房间绑定和原速度/模式；
listen-together-cards-v1/current 保存原生队列卡片，页面 DTO 不含 Cookie、SDK令牌、授权音频 URL。
窗口关闭只处理本客户端显式绑定的房间；先核对未决、刷新同一房间、退出、恢复偏好再销毁窗口。
失败保留窗口，通过仅包含账号代次和受限说明的事件跳转房间页，提示用户核对。
事件错误在页面自动刷新后仍显示；旧账号监听器及迟到注册均清理。
当前扫码切号入口要求先退出绑定房间；这是显式的社区生命周期选择，不声称与官方完全相同。

显式定位到零的修正
直接执行官方 M/3161 cmdFilter，确认“前一次 PLAY，随后同曲 GOTO/0”出站会被过滤。
官方 assembleRequestParam 又把同曲 PROGRESS/0 转为 GOTO，因而显式拖回开头也可能被抑制。
core/tests/client_together.rs 新增真实原生控制器用例先复现失败：.build/together-zero-seek-before.log。
保留原 outgoing/filter 的官方规则；新增 outgoing_seek/seek_for，仅对明确的定位意图按
PROGRESS 语义检查，实际 wire 仍为 GOTO/0。队列许可、近期重复和入站回声检查保持，
未决责任、账号隔离、clientSeq持久化及只发一次仍走同一服务流程。
这是社区修复，不能声称官方原实现就支持此分支；新的直接执行样本共22组过滤对照。
真实 e 的UI定位上报 GOTO/progress=0/clientSeq=5，回读成功，且整个证明无重复clientSeq。
