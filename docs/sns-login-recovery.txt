Cumulus SNS 登录恢复契约与后续实现边界
====================================

记录日期：2026-11-03。对象：官方 PC 3.1.42.205594 的 JSK 0.0.39。
性质：源码审计、有限无会话入口读取与下一批实现设计；本文件不代表 SNS 功能完成。
本批没有修改业务代码、运行测试或构建，没有执行第三方登录、授权确认、绑定或注册。
没有使用 YesPlayMusic。历史 recovered-client 的动作卡仅辅助定位，结论回到官方模块。

当前范围：微信与 QQ 单独评估；下文的微博为历史取证。无需先做网易客服、通用 H5
或小程序宿主。两条候选都已找到第三方入口、HTTPS 回调地址及后续登录请求；实际成功
文档和窗口归属仍未验证，因此当前不显示登录按钮，也不接收复制来的 OAuth code。
下一步取证只需成功回调的实际 HTTPS origin/path、文档层级、消息来源和字段类型；
不要将原始 code、state、Cookie、刷新令牌或账号信息写入日志或公开夹具。没有这些证据
时先继续可离线验证的其他业务。成功授权也只建立候选会话；切换、注册和绑定仍沿用
已有确认和身份核对边界。

1. 已恢复的端到端链路与尚未取得的部分

  已恢复：PC 登录入口 → JSK loginWithThirdParty → nm.sns.snsBindDetailInfo
  → 独立 sns 窗口 → 官方 Hosted 授权入口 → 父窗口收到桌面授权结果
  → M290 返回 token/desktopLoginSnsParam → POST /api/login/sns
  → 通用登录响应、注册/绑定分支、凭据保存与后续验证。

  已用无 Cookie 请求确认 Hosted 入口的三个第三方重定向、公开应用 ID、
  精确 redirect_uri，以及无授权上下文时回调落到 /back/sns 的错误行为。

  未取得：成功授权后的远端回调 HTML/JS、desktopLoginSnsParam 完整字段模式、
  回调与初始 state/临时 Cookie 的完整绑定规则、成功回调的真实 frame 层级。
  不能把 provider 回跳 URL 的 OAuth code 直接当成 M290 返回的桌面 code。
  不能把任意 postMessage、URL 中自报 origin，或前端提交的 JSON 当成原生凭据。

4. PC Hosted URL 与 M290 的真实契约

  入口是 GET https://music.163.com/api/sns/authorize/，参数：
    snsType     数字字符串：微信 10、QQ 5、微博 2。
    clientType  APP_CONF.os；制品默认 pc，M18 会读取 native os 更新。
    schema      字面量 "*"；它不是可由普通前端改写的自定义回调地址。
    checkToken  从 sns 路由取得，默认空字符串。
    musicTu     从 sns 路由取得，默认空字符串；不等于自行添加 musicTuP 头。
    callbackType 路由有值才添加；M290 固定 "login"。

  M290 构造 sns/{encodeURIComponent(JSON.stringify({snsType,callbackType:"login",from}))}，
  from 默认 login；2FA 调用传 doubleVerifyAuth。from 用于本地父页分派，
  getUrl 没有把 from 加入 Hosted 查询。不能任意补入 redirect_uri/appkey/state。
  Other.jsx 的 JSK 入口另设置官方域 Cookie fromPage=jsk，退出时 M290 删除它；
  它是固定分流标记，未来只能写入本次隔离授权窗口，不能改当前账户 Cookie jar。

  窗口 850×530/isSpecialWindow。M290 订阅共享 action，并 skip(1)：
    host/snsAuthResult 或 host/handleDesktopLoginSnsParam → 首次结果完成；
    app/modalClose 且尚未完成 → sns_window_closed；
    120000 ms 尚未完成 → sns_auth_timeout。
  finally 清计时器、退订、删除 fromPage。失败统一回 {error:{code:-1,message:"sns_auth_cancelled"}}。
  成功返回 {desktopLoginSnsParam:对象, token:对象.code}。token 必须非空（M1368:4117–4121）。
  回调对象其它必需字段/类型/最大长度没有在这些消费者中定义。

  父页是本地 React 页面，远端 Hosted 页在 iframe。它直接读取 event.data，
  没有检查 event.origin、event.source 或一个固定的 data.type（207–210/399–400）。
  JSK 回调满足 data.desktopLoginSnsParam && callbackType==="login" 时，
  发 host/handleDesktopLoginSnsParam，payload 包一层 desktopLoginSnsParam；
  M198 再转 host/snsAuthResult；M290 同时接受这两个 action。
  这两者是本地应用 action 名，不是已恢复的远端 postMessage.type。
  legacy 回调是 code=200/account/profile/bindings/token 等账户响应，走 page:sns/login；
  code702 走验证；10004 走风险提示。不能拿 legacy 响应结构替代 JSK 桌面 code。

6. SDK 消费与注册/绑定后继

  普通 SNS：POST /api/login/sns
    {type:10|5|2,tokenJsonStr:nativeResult.token,
     desktopLoginSnsParam?:nativeResult.desktopLoginSnsParam}。
  此处 tokenJsonStr 是 M290 从桌面对象.code 得到的值，不能前端代填、不能凭名字
  擅自 JSON.stringify OAuth 原始 token。响应回通用 handleLoginResponse。
  M1368:2887–2900 从 Set-Cookie 读 MUSIC_U/MUSIC_A，从 x-refresh-token 读 RT，
  body 取 account/profile/bindings；本机必须继续使用真实凭据回包与 candidate 身份核对。

  body.code=200 且第三方无 profile：NEED_REGISTER；保存私有 registration 上下文，
  包含 externalUser/loginType/ursToken/hasAccount/canSkipSetNickname/canSkipBindPhone 等。
  不能因为 code200、收到 token、绑定成功或昵称提交完成就采用未注册 candidate。
  显式昵称/注册操作：GET /api/activate/initProfile，字段
    nickname, avatarUrl, signature, gender, anoniToken,
    isSkipBindPhone, isSkipSetNickname, allowDefaultNickname。
  externalUser 可提供头像/签名/性别回落；跳过能力必须由当前 native 注册上下文限定。
  官方先私存登录信息；Cumulus 仍须延续注册 guard，完整 profile/身份通过才切当前账号。

  第三方绑定专用后继（不可混用普通 2FA 或处罚 RN 路由）：
    GET /api/cellphone/existence/check {ursToken}
    GET /api/user/bindingcellphone/v1 {ursToken}
    GET /api/user/sns/bind-and-login {ursToken,phone,regionCode}
    GET /api/user/replacecellphone/v4 {ursToken,phone}（强制换绑，需要单独明确用户选择）
  bindPhone：exist=-1 走直接绑定；已有号码且 !hasAccount && !hasSnsBinded 才 bind-and-login；
  已有本方账号报 BIND_CONFLICT_CAN_GRAB；否则 BIND_CONFLICT_CANT_BIND，不能自动抢绑。
  PHONE_BIND_SUCCESS 仅表示该动作结果，之后仍可能要 initProfile/身份核对。

  真正生产条件缺口：bindPhoneByType(sms) 要求 sn 返回非空 result.token。
  但 M290.verifySms 只有 {result:{success:true,ursToken:""}}；sn 不接受空值，
  并且与普通手机号登录接受 token||ursToken||null 的宽松分支不同。
  M290.getOnePassToken/getGovVerify/createAndSaveCellphoneAccount 也仅回 code200 占位。
  因此 SDK 方法/REST 路径已恢复不等于 PC 已有可用 URS/一键登录/国家认证生产链。
  必须恢复有效 native URS provider，或另以官方 PC 实际可执行链路取证；禁止伪造 token。

  第三方 2FA 复用 provider，但 from=doubleVerifyAuth：
    登录 scene=0：POST /api/login/2fa/sns/check
    非登录 scene：POST /api/user/auth/sns/check
    字段 {scene,type:"10"|"5"|"2",tokenJsonStr,desktopLoginSnsParam?}。
  Apple 改用 /api/login/2fa/urs/sns/check 或 /api/user/auth/urs/sns/check，{scene,ursToken}。
  只允许服务器本次已提供的方法；不能把本地列举能力当成此账户获准使用。
  scene=1 的 QQ/WEIBO 后续可能要求实名（M1368:5189–5233）；不适用于所有登录 scene。
  未恢复 RN 实名内部动作时必须显示外部处理/取消/重新登录边界。

  Apple /api/user/urs/sns/login 要 token+ursToken；legacy UI 调 App.loginFromApple。
  CITD /api/login/citd 要 certPwdData 或 idCardAuthData。只见接口/原生 schema 或
  code200 占位不能声称 Linux/Windows 已有这些生产者。下一批候选只评估微信与 QQ。

7. PC HTTP 桥选项的明确边界

  M1368 PcPlatform.fetch 总加 fromPage=JSK，method/data/query、expandSetCookies，
  并声明 needsGuardianToken=true/tokenKey=checkToken；挑战时可带 attempt-local x-music-tu。
  M1890 保留选项，但 M290 HTTP normalizer/request builder 仅消费
  path/method/query/data/header，丢弃 Guardian flags。M402 的 MConfig 路径匹配
  另行取得 checkToken/X-antiCheatToken，不能当成消费上述选项的等价证据。
  后续 SNS 接线不能因为 M1368 标记就补造官方 PC 强制 Guardian 调用，
  不能从持久 Cookie 恢复 MUSIC_TU，也不能把 musicTu 与处罚 musicTuP 混同。

8. 下一批原生 host 与状态机设计（设计要求，未实现/未验证）

  core：新增 attempt-local ThirdPartyAttempt 与 native-only provider trait。
    私有持有 provider、候选会话、原 account generation、一次性交换状态、临时 code/对象；
    敏感对象不 Debug/Serialize。前端只见 opaque operation/verification id、provider、
    有界 phase/message/allowed actions；既不接收完整授权 URL，也不能传票据/Cookie/RT。
  desktop：实现受限 native 授权窗口；普通 renderer 只发“开始 provider/取消”，
    生产者只能在可信 native setup 安装；任何测试 provider 也不能从 IPC 装载。
    每 attempt 新隔离数据目录/临时 Cookie jar；不导入当前或保存账户会话，
    只保留这次 Hosted 302 所设的临时状态到该授权窗口，结束即销毁。
    850×530 为官方起点，仍需 Linux/Windows 小窗/缩放/关闭/焦点的真实 WebView 验证。

  remote 窗口无业务 IPC：保持 desktop/src/lib.rs:157–161 的 main-label 拒绝门，
  不给 provider 页面音乐库/文件/播放器/账户命令能力，不把远端页面塞进 main WebView。
  不照抄父页 preLogout，不提前清理旧账户或发送 /api/logout。
  仅 native 构造固定 Hosted URL；不接受来自前端的地址、redirect_uri 或任意 schema。
  禁止弹出任意新窗口/外部 scheme、下载或调用系统浏览器来携带授权票据；
  允许的第三方导航域必须来自冻结的官方重定向与后续实际资源证据，不能匹配宽泛子串。

  回调接收必须证明：本次拥有的 native 窗口 + 活跃 attempt + 原 generation，
  正确 provider + HTTPS 官方精确 callback 文档 + 当前导航/frame + 一次性完成。
  OAuth state 绑定须由冻结协议确定；不能给 Hosted URL 私加自定义 state 并假设服务支持。
  优先让 callback 成为主文档并使用有原生 frame/source 归属的结果捕获适配器；
  该拓扑是否兼容最终 parent.postMessage，须成功回调原文证明后决定。

  窗口，并证明 remote frame 无法绕过该父检查直接调用 native 结果桥。

  状态：Ready → Opening → AwaitingAuthorization（原生 120 秒有界）

  account/get、核对完整 profile/uid 与 generation，再原子采用并广播 safe AccountView。
  POST 已发后断网/超时/取消，可能远端已消费 code：标为结果未决，保留旧账号，
  仅允许候选身份回读/取消/显式全新授权；不自动重放 code、密码、注册、绑定或抢绑。

  迟到消息/响应不能采用身份，不能阻止下一次 begin_login。
