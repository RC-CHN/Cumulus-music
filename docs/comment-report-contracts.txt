实现边界
- core/src/client/comments/report.rs 按类型化 CommentResource 生成讨论串，拒绝
  非规范的数字别名；验证确有当前账号，提交时在同一讨论串按 ID 重新读取对应评论，
  要求目标可读、非本人、作者可识别且未注销。不存在、屏蔽或已删除的评论不提交。
  与现有评论编辑/删除/回复使用同一讨论串的写锁。IPC 不接收任意接口或授权信息。
- core/src/client/report_receipt.rs 和用户主页举报共用一次发送的守卫。准备生成
  120 秒的内存确认凭据，绑定当前账号代次、讨论串、评论 ID 及原因；取消不访问
  服务。提交在请求前把 uncertain 写入账号独立本机记录；只保存状态，不保存
  原因、评论内容、原始响应、认证材料。200 或明确 -1 标记终态；HTTP 错误体的
  200 不当成成功。超时、未知码或崩溃都保留待确认，重开和「核对本机回执」
  不再发送。只有明确 RequestNotSent 可以释放已写记录并由用户重新确认。
- 相比原客户端，Cumulus 的预设同样要求明确确认，额外限制原文 4096 UTF-8 字节，
  并在弹窗显示本机回执结果；未认证时不显示入口，由现有登录入口处理，不续发
  登录前的举报。自填取消、Escape 和关闭恢复发起按钮焦点；右键菜单支持方向键。
  共享的用户主页举报保持独立端点、账号/用户记录和专有 -2 处理。
- 没有访问真实服务或报告实际用户内容。闭合合成传输证明 Linux WebView、EAPI
  加密后精确域名/路由和解包后的字段、故障处理；Windows WebView、真实服务状态
  和官方全局 XEAPI 切换未实测。
