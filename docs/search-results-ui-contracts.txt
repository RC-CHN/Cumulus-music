当前界面与交互
- 顶栏搜索进入综合页；十分类按官方默认次序。分类保留关键词、返回历史和账号代次。
  同一关键词内切换只更新结果区；保留页签焦点，方向键/Home/End 可选择，使用
  transform/opacity 动画并遵守减少动态效果。初版整页重建导致焦点丢失的问题已修正。
- 综合页按服务区块顺序展示已知资源；最佳匹配横排，分类卡片按资源区分。歌曲预览
  与综合页一同滚动，单曲分类沿用有界虚拟列表。歌手/用户13项，其余分类30项分页。
  当前是社区分页控件，未复刻官方 WaterfallGrid 的连续加载与所有滚动恢复细节。
- 单曲操作为播放全部/收藏全部；收藏窗口明确显示当前页数量，选择已有自建歌单后
  才执行。准备阶段重读歌单 revision，账号切换取消写入；未决结果沿用现有核对流程。
- 歌单/歌手/专辑/播客/MV跳转现有页面。声音的所属播客入口进入详情；用户卡片展示已返回
  昵称和简介的详情窗口。缺少播客/MV目标的卡片显示“暂不可打开”并禁用，避免无反馈。
  声音封面播放和整行双击现已接通，详见search-card-ui-contracts.txt；缺radioId时仍
  不能播放，用户完整主页也仍待补齐。用户信息窗口采用应用
  共用的16px圆角、遮罩、关闭/返回焦点与进入退出动画，属于社区临时详情设计。
- 读取失败提供重试；空结果提供换词/分类提示；服务有总数但没有条目时显示独立说明，
  防止无限翻页。迟到响应不会覆盖新分类；账号失效退出结果页。纠正查询使用纯文本。
- TrackTable和搜索长标题使用应用内提示框，切页、滚动、失焦和Escape清理；替代这些
  位置的原生 title，解决已观察到的“合成专辑”GTK提示框跨页面/弹窗残留。
  其他页面仍有原生 title，不把本修复写成全应用提示框验收。

仅为支撑上述 UI 的调用映射
SearchResultsClient → desktop/search.rs search_results → MusicClient::search_results
  → catalog/search/results → 白名单展示 DTO；前端无 Cookie、签名或资源 action URL。
综合 /api/search/pc/complex/page：keyword、scene=normal、needCorrect、channel=suggest、
  初始cursor、bizQueryInfo空；读取data.blocks。尚未实现综合cursor续页/v3 AB方案。
单曲 /api/search/song/list/page：keyword、scene、needCorrect、channel、limit、offset；
  data.resources[].baseInfo.simpleSongData → TrackView。
歌单 /api/v1/search/playlist/get：s、queryCorrect、limit、offset；result.playlists。
歌手 /api/v1/search/artist/get：同上；result.artists。
专辑 /api/v1/search/album/get：同上；result.albums。
用户 /api/v1/search/user/get：同上；result.userprofiles。
声音 /api/search/voice/get：keyword、scene、limit、offset；baseInfo → EpisodeView。
播客 /api/search/voicelist/get：同上；baseInfo → PodcastCard。
歌词 /api/search/resource/lyric：同上；resource.song和matchedLyric，片段按纯文本显示。
MV /api/search/mlog/get：keyword、scene、limit、offset、channel=suggest、os=pc、tag=MV；
  type=mv 的 baseInfo → CatalogVideoCard。实际读取出现总数46但resources为空。
/api/search/pc/result/tab 已提供低层读取与只读验证；本次界面固定官方默认次序，
  不声称算法排序、缓存回退和新分类动态注册已实现。
