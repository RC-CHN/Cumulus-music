实际发现与修复
1. 离开后返回本地页，原查询仍筛选列表，搜索框却重新变成空值。搜索草稿现在从
   同一 LocalQuery 初始化，离开页面前同步提交尚未到 10ms 的完整输入。旧页面
   的计时器只属于原 visit；隐藏、重新进入或销毁后不能覆盖新页面输入。
2. 发出新查询后，旧行仍可播放，导致新查询配旧行/revision。本地快照现在绑定
   keyword/sort/descending/group/groupKey/includeMissing/offset/limit；revision
   仅作为索引前置条件，不作为显示条件。新条件没有成功结果时不显示旧行。
   loading、读取错误或写操作进行中，播放处理函数和按钮都拒绝旧行播放。
3. 读取失败曾与命令失败共用错误；正常后台轮询会清掉扫描失败提示。现在
   readError 与 command error 分开，读成功只清读取错误。扫描失败带具体动作，
   必须由用户再次执行该动作，不以“重读列表”冒充重试扫描。
4. 登录后本地/CUE 曲目进入队列，native_like_selection 曾直接按线上歌曲映射
   解析，导致 mini_snapshot 报非正整数 ID。现在复用主播放器资源投影，未关联
   的本地/CUE 无线上喜欢目标；已下载歌曲保留真正的线上 song/voice ID。
   迷你窗口、系统媒体与快捷键继续共享原播放器、账号及队列控制边界。
5. 原生重新扫描执行期间按钮会禁用，WebKit 因此把焦点移到 body，结束后不会
   自动恢复。现在选择目录、重新扫描、暂停/恢复扫描完成后，若仍属于同一次
   本地页访问且焦点没有移到其他控件，返回原可用按钮；离开页面后不抢回焦点。

搜索与错误交互
- 普通输入 10ms 后发起实际 typed local_page；保留用户输入中的空格。Rust 查询
  仍按原契约处理 trim/casefold，不能用结果文本反向改写输入框。
- 中文输入法组合中不发送中间拼音，compositionend 提交完整文字。这是为避免
  不完整输入干扰结果而添加的社区交互约束；原 FlexSearchInput 的组合分支并非
  完全相同，不能称为逐行复刻。切换分组同时取消待发输入/组合并清空关键词。
- 清空按钮保留搜索框焦点；歌曲/歌手/专辑/文件夹共用权威查询。分类键变化会
  重建输入控件；不从旧类别的延迟回执恢复文字。
- 首次或新条件读失败显示“本地音乐暂时无法读取”及“重试读取”，不显示空库
  引导。确实无匹配显示“没有匹配的本地音乐”，与失败、尚未扫描明确区分。
- 同一查询后台读失败保留已有行并禁用依赖它们的动作；1500ms 可见页轮询仍为
  只读。显式重试成功后，如果原重试按钮移除且焦点落到 body，返回搜索框。
  新焦点已由用户移动时不抢回；失败仍保留可见的读取重试入口。
- 扫描失败不销毁索引，不自动重放命令；后续正常轮询不隐藏命令失败。显式
  重新扫描成功清除该提示。已有 native snapshot_changed 回第一页规则保留。

跨页产品约束
云盘删除仍使用冻结的确认计划及单独的本地文件选项；本批不增加 HTTP 接口。
选择删除本地下载文件：真实文件、完成下载记录、离线登记、本地索引以及队列
中的该文件条目一致移除。返回下载页仍保留原搜索值，不能显示旧完成行；返回
本地库重新读取；原队列中其他条目、CUE 身份及暂停状态继续有效。
不勾选本地删除：云盘记录删除后，已完成文件和下载任务保留，下载页可继续
从已验证的离线资源播放，不因云盘删除重新申请在线音源。
CUE 对应整文件保护沿用组合删除预检，不允许误删共用音源。
