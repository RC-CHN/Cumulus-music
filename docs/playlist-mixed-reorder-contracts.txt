普通自建歌单的混合重排：Rust 与原生提交契约

官方 Windows 3.1.42.205594 依据

M/3160（hybrid_105）1606–1640 读取页面原有 trackIds，识别数值 v=-1 的本地行，
从用户提交的完整排列中去除这些本地 ID 及假值，发送
/api/v1/playlist/manipulate/tracks {pid, trackIds:JSON.stringify(线上 ID 顺序), op:"update"}。
没有 imme 字段。条件检测的是数组对象，空数组也为真；纯本地移动且线上顺序相同
或线上子序列为空，仍调用接口。M/15:2099 绑定接口；M/2997（hybrid_155）823–861
只有 success action 才以原提交完整顺序更新页面和 M/239 playlistTrackIds 本机记录。

M/12:171–191 的共享响应封装把数值 200、字符串 "200" 或假值 code 视为成功。
未恢复端点专属证据证明 code 缺失、0 或 false 表示写入已接受。Rust 复用现有
PC 歌单路由与严格数值/字符串 200 判定；这些弱回执不会授权保存本机顺序。
没有从恢复代码推出服务器必定接受 []，合成测试只确认原生发出的参数和接受回执后
的行为，不声明真实服务对空数组的结果。

输入与互斥

核心入口 reorder_playlist_mixed 接收账号 epoch、歌单 ID、页面组合修订和完整排列。
行是 {kind:"online",id:十进制 ID} 或 {kind:"local",id:本地摘要,revision:修订摘要}。
首先重读当前账号完整 V6 详情并确认普通自建歌单；原线上行和同版本本机行必须各自恰好
出现一次。已经缺失的本机文件可以移动其已保存的成员，但不能因此取得新路径或播放权限。
若远端响应本身有未绑定的 v=-1 占位，拒绝整个混合重排：它没有设备引用，不能在滤除
后安全重建或猜测位置。不能把页面分页、筛选结果或视图列排序当完整成员排列。

桌面手势使用 move_playlist_mixed，传 M/195:388–409 给出的原始表格落点和选中行。
多选时保留 selectedData 原顺序，否则只移动起拖行。M/3085:2470–2505 在完整
trackIds 中留空选中位置、按该原始落点插入，再滤除空位。Rust 在已持锁并核对组合
修订的完整投影上复现该顺序，不要求页面拉取剩余歌曲，也不会跳过投影相同的提交。
列表筛选下仍使用显示列表给出的原始落点，不把目标行映射为完整列表中的位置。

复用账号级歌单写入互斥。启动前检查同歌单普通写入的未决状态；设备本地增删与旧版
曲目写入、删除歌单也拒绝覆盖正在发送或不明的混合重排。普通歌单元信息不被长期锁定。

发送一次和核对

1. 在发送前，SQLite 按账号和歌单原子保存最新操作 ID、已检查组合修订、本机代数、发送前
   完整线上顺序、目标线上顺序和目标本机位置。只保存 ID、修订和位置，不保存网络响应正文、
   文件路径或凭据。此时 phase=Sending，读页面仍用原本机位置。
2. 只发送一次完整线上顺序，包括重复线上投影或空数组；不发送本机 ID，不重试、不自动转
   云盘。明确 200 在一个事务中重新核对账号、本机代数及同一成员集合，写入完整本机位置、
   下一代数及 Confirmed/Acknowledged 回执。远端曲目仍以最新读回为准。
3. 明确拒绝或业务请求尚未发送保存 Rejected，不改本机位置。超时、缺回执及无充分证据
   保留 Uncertain；崩溃或账户变化可能保留 Sending。重开后可按账号、歌单、操作 ID 读取，
   不发送写请求或重放原命令。
4. 显式核对只在发送前线上顺序和目标不同、当前同账号完整线上读回恰好等于目标时，
   以 Confirmed/ChangedReadback 原子保存本机顺序。相同投影（包括 []）无法由读回
   区分接受、拒绝或未送达，永远不自动确认；未知期间保持原本机顺序和写入限制。

桌面主窗口的 reorder_playlist_mixed／move_playlist_mixed、playlist_mixed_reorder_receipt
和 reconcile_playlist_mixed_reorder 分别提交一次、读取本机最新回执和显式核对。
返回均携带账号 epoch，回执只含歌单／操作 ID、阶段、证据和业务状态码；
不向 WebView 暴露原始意图、路径、在线响应或凭据。读取最新回执不会访问网络。
本阶段提供 Rust 核心、桌面 IPC 及类型契约；拖动界面及真实账号未在此验证。
混合增删、未知同投影的显式放弃、未知服务响应格式和未绑定占位重排仍有独立边界。

桌面拖放与恢复
----------------

M/195:361–419、M/57:158–185 的有效拖放在同一曲目表内用最近的行边界，
边缘可滚动。M/3085:2467–2506 按 Set 的选中顺序（仅一项时为发起行）将
曲目移至原始落点。有效的原地落点也走同一操作；单击、Escape、失焦、取消、
离开目标和账号/歌单/列表版本切换均不提交。拖入播放队列仍是既有独立操作。
列表只渲染可见窗口，鼠标拖动显示落点线。不从筛选结果推断在线完整排列；
原始可见表落点交给核心按恢复表达式使用完整服务端详情和本机成员计算。
只开放普通自建混合歌单。完整服务端详情出现无法绑定的本地占位时关闭排序，
已登记但文件暂不可读的本机成员仍有原身份。未实现跨歌单拖入时的先收藏再排序。

桌面通过 move_playlist_mixed 发送一次意图；按账号和访问实例隔离，IPC 回执
丢失后只读本机日志，绝不自动重放。进页只读历史未决状态；「核对结果」按原操作
只读核对。显示「本机曲目位置未更新」，线上成员可能已由服务端接受。确认后以
最新的双修订重新读取原有已加载范围，再更新界面，保留滚动和可恢复的行焦点。
核对中或无法读取状态时不接受新的排序。未决同投影没有自动放弃入口。
