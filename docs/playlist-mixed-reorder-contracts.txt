官方 Windows 3.1.42.205594 依据

从用户提交的完整排列中去除这些本地 ID 及假值，发送
/api/v1/playlist/manipulate/tracks {pid, trackIds:JSON.stringify(线上 ID 顺序), op:"update"}。

或线上子序列为空，仍调用接口。M/15:2099 绑定接口；M/2997（hybrid_155）823–861
只有 success action 才以原提交完整顺序更新页面和 M/239 playlistTrackIds 本机记录。

输入与互斥

核心入口 reorder_playlist_mixed 接收账号 epoch、歌单 ID、页面组合修订和完整排列。
行是 {kind:"online",id:十进制 ID} 或 {kind:"local",id:本地摘要,revision:修订摘要}。
首先重读当前账号完整 V6 详情并确认普通自建歌单；原线上行和同版本本机行必须各自恰好
出现一次。已经缺失的本机文件可以移动其已保存的成员，但不能因此取得新路径或播放权限。
若远端响应本身有未绑定的 v=-1 占位，拒绝整个混合重排：它没有设备引用，不能在滤除
后安全重建或猜测位置。不能把页面分页、筛选结果或视图列排序当完整成员排列。

复用账号级歌单写入互斥。启动前检查同歌单普通写入的未决状态；设备本地增删与旧版
曲目写入、删除歌单也拒绝覆盖正在发送或不明的混合重排。普通歌单元信息不被长期锁定。

发送一次和核对

1. 在发送前，SQLite 按账号和歌单原子保存最新操作 ID、已检查组合修订、本机代数、发送前
   完整线上顺序、目标线上顺序和目标本机位置。只保存 ID、修订和位置，不保存网络响应正文、
   文件路径或凭据。此时 phase=Sending，读页面仍用原本机位置。
2. 只发送一次完整线上顺序，包括重复线上投影或空数组；不发送本机 ID，不重试、不自动转
   云盘。明确 200 在一个事务中重新核对账号、本机代数及同一成员集合，写入完整本机位置、
   下一代数及 Confirmed/Acknowledged 回执。远端曲目仍以最新读回为准。
3. 明确拒绝或业务请求尚未发送保存 Rejected，不改本机位置。超时、缺回执及无充分证据
   保留 Uncertain；崩溃或账户变化可能保留 Sending。重开后可按账号、歌单、操作 ID 读取，
   不发送写请求或重放原命令。
4. 显式核对只在发送前线上顺序和目标不同、当前同账号完整线上读回恰好等于目标时，
   以 Confirmed/ChangedReadback 原子保存本机顺序。相同投影（包括 []）无法由读回
   区分接受、拒绝或未送达，永远不自动确认；未知期间保持原本机顺序和写入限制。

本专项只提供 Rust 核心命令和合成回归；未接入桌面拖动或 IPC，未访问真实账号。
混合增删、未知同投影的显式放弃、未知服务响应格式和未绑定占位重排仍有独立边界。
