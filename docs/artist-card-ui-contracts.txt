歌手卡片、关注菜单与播放状态一致性
2026-11-02；全应用UI/UX目标继续进行，不将本专项当成完整应用完成。

官方依据与场景
- components/ArtistCard/index.jsx：普通网格卡片20px内距/底部23px、10px圆角，圆形
  头像上独立44px播放按钮，默认名称16px/26px行高、描述12px/17px，显示musicSize。
  描述也有AlbumSize变体，本次公共相似歌手入口沿用默认单曲数。hover遮罩与播放按钮
  不应使整张卡片都变成播放操作，名称/头像仍打开歌手详情。
- hybrid_app M622的S.content/check：默认场景为查看歌手、收藏、复制链接；myFollow
  隐藏收藏，保留查看和复制。没有恢复证据支持在普通歌手菜单里照搬专辑的下一首/
  下载/分享项。artist详情和newSongArtist通知场景另有检查，不混进公共卡片。
- user-detail/components/ArtistCard.tsx：关注列表用横向64px头像/名字/关联用户签名，
  独立于普通网格卡片；上下文带myFollow。官方该组件另有用户/私信分支，当前仍为
  明确边界，没有用假入口或自动发送替代。ArtistOperation.tsx的详情页关注/取消
  继续使用现有Rust业务，写后由账号回调使对应列表访问失效。
- 两组菜单向量实际执行恢复S.content/check，用合成枚举/资源/scene冻结到
  frontend/tests/fixtures/official-artist-card-menu.json。研究脚本在忽略的
  references/recovered-client/scripts/netease_artist_card_menu_oracle.cjs；没有运行官方
  原生菜单渲染器，不声称像素一致；未使用YesPlayMusic。来源散列见配套mapping。

实现与产品行为
- ArtistCard独立拆分详情、中央播放和菜单按钮，恢复名称/单曲数/圆形遮罩；坏图
  实际解码失败后退占位。三类控件不嵌套，键盘焦点和当前来源可显示播放键，有限
  opacity过渡并尊重减少动态。虚拟行高按实际卡片宽度计算，保留有界渲染。
- FollowArtistCard保留横向署名/签名/注销状态，新增可发现的More按钮，同时支持
  右键及Shift+F10。More是社区可访问性补充，不冒称原组件有这个可见按钮。
  仅有用户资料的记录没有伪造歌手入口。虚拟项按资源身份key，历史记录仍指向实际
  opener/menu控件，长名称和签名各自省略。
- App统一专辑/歌手的来源播放判断。当前来源且已加载走PauseFor；停止后重新读取
  并建立播放，切另一歌手也重新选曲。prepareSelection失败保留既有原生队列、暂停
  和位置，沿用底栏错误恢复入口。不存在只改变播放图标却不调用核心的分支。
- 关注确认和专辑收藏共用CatalogMembershipDialog，独立服务函数校验账号epoch、
  请求query和返回类型/资源身份。先读取动态状态及持久化意图，再由用户确认Set。
  403可明确重试，结果未知时只允许Reconcile；关闭/重开不会自动重发。加载期间
  保留取消，写入期间锁关闭，完成/取消/读取恢复均保留焦点处理和账号完成通知。
- 复制只通过typed IPC写入公开artist?id=数字链接，不含授权URL。页面/账号变更
  关闭旧反馈/窗口，迟到复制结果不能更新新页面。无真实账号写入或发信。

调用链
播放：ArtistCard -> App.playResourceCard -> catalogResourceSelection -> catalog_page
({kind:artist,id},true)，读取/api/artist/v3/detail及/api/song/enhance/privilege；返回
query/revision交给Rust play_selection Catalog，重读核对后请求song/detail和会员允许
音源，走现有实际播放器、账号fence和队列持久化。复用核心已恢复的热门50曲分支，
不声称恢复了所有AB实验组的曲目选择策略。
关注：artistCardMenu.collect -> ArtistActions -> CatalogMembershipDialog ->
catalog_page({kind:artist_dynamic,id},true)调用/api/artist/detail/dynamic，平行Inspect
持久化意图；确认后catalog_membership Set复用/api/artist/sublist、/api/artist/sub
或/unsub及读回验证。丢响应的Reconcile只读回。详情取消关注仍走CatalogSession。
列表：collection_page followed_artists -> /api/user/follow/users/mixed/get/v2，有界分页
与合成测试的混合记录格式一致；写入开始/完成的epoch通知使followed_artists快照
失效，保留当前筛选词，不影响已购专辑，复用上一专项的访问/切号防护。

菜单定位修复
实际截图发现窄窗键盘菜单可能以卡片不可见的底边为anchor落到屏幕下方。
ActionMenu保留上下方首选方向，最终同时约束上/下边界，避免高卡片或越界point让
菜单超出viewport。新探针必须检查整个菜单在8px窗口内，以及每个可用菜单项均
可见且命中；不能仅用可见子集通过。此为截图发现的产品问题，不是测试取样调整。
