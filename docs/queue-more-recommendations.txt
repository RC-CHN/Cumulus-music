范围：官方恢复证据、Rust 两段只读协议与原生普通队列接线、桌面队列面板。
以下官方分支与已验收的本端分支分别说明，未对实服进行写入或播放验证。

开关、来源及默认值

  PH-PC-recommendMore=t1；该 key 默认 t1，但成功拉取实验后若 PH-PC-tagT
  不是 c/t1 会清掉它。使用现有 Rust PcExperimentGroups 的投影即可。

  写本地 playingListSheet.wantMore[uid]，没有远端偏好写接口。
  M/1384:5294–5302、6451–6530：只在 clear=true 的替换播放来源上重新判定；
  下一首、追加、手动切歌不把队列改成新来源。每日/历史每日/风格推荐直接
  eligible=true，同时允许“空时预取”。其它仅 originalResourceType=playlist：
    songList=t4         允许任何 playlist 来源（在检查 ID 之前）
    无 sourceData.id    其它组均不允许
    我喜欢的歌单       t3 允许；其余按自建歌单分支
    自建歌单            排除（上述 t3 的红心例外，t4 已提前放行）
    收藏歌单            t2/t3 允许
    其它歌单            允许，包括实验缺省组
  专辑、歌手、搜索、普通单曲、本地/下载、播客、FM 等不是该入口的 eligible
  来源；但混合队列里的种子筛选是另外一层，不能按入口粗暴过滤歌曲身份。
  M/3113:1271–1316 和 M/1384:5186–5230 不含直接房间可见性否决；
  一起听走独立队列和同步协议。首次 Rust 产品接入应只作用于普通本地队列，
  不从上述“没有直接判断”推导已支持房间同步。

触发、结束及恢复
  M/3113:707–731、775–792、1048–1051；RcmdMoreSwitch.tsx:52–64,101–123：
  面板实例在 visible gate、wantMore、updateOnRcmdEmpty 都为真且没有活跃
  推荐行（scene=moreRcmd && isMoreRcmd!==false）时，最多自动预取一次。
  用户显式开立即请求；关先清推荐并设 updateOnRcmdEmpty=false，不发请求。
  如果默认关闭且同次面板的首次预取仍可用，打开同时满足两条派发；Rust
  协调器应合并同一快照并发请求，不能重复追加。没有固定轮询或自动重试。
  M/31:793–805、M/397:698–770、M/3:8366–8393：队列侧栏保留包装节点
  keepNode=true，内部 keepDOM=false。完成关闭动效会卸载列表子树；重新打开
  的首次预取仍受空列表/开关条件约束；快速反转动画而未卸载并不重置 ref。
  M/308:1769–1825，M/1384:5108–5126、6260–6293：setPlaying 的 Playing 分支
  与从队列移除后触发检查。先标当前 trackId 对应条目 isPlayedOnce；顺序、
  列表循环、单曲循环仅当前 displayOrder 等于最大 displayOrder 时请求；
  随机/心动需全部当前条目 isPlayedOnce；FM 模式不进这些分支。
  没有固定“剩余 N 首”阈值，最少仅需一个合规种子。M/308:3738–3802 的
  EOF 只遵循既有切歌/结束决策：顺序模式到当时的尾项就 End；新条目已
  写入时自然走下一首；单曲循环重播仍可能再进入 Playing 检查。不要新增
  EOF 上的独立等待、自动唤醒已结束队列或改变普通结束行为。
  M/1384:4855–4904、5131–5159、5497–5552、5996–6010：队列写入 playingList
  文件并同步原生播放器；初启读该文件及 playingListSheet.isRestoredPlayListFromRcmd。
  清空隐藏开关并复位分隔、空时预取。普通队列仍要走账号归属/版权恢复
  （6532–6631）；不可跨 UID 恢复推荐标记、开关或未完成请求。

  2. data.songList 经 M/21.x 规范化，使用 data.algMap[id]，保留前 3。
     POST /api/song/enhance/privilege {ids:JSON.stringify(前三首规范化字符串 ID)}，
     此处没有 trialMode；成功空推荐仍发 ids="[]"。推荐禁用缓存，官方

     给该歌曲填权益；不能按 map 任意补配或把空权益变成可播。正式播放仍
     走现有授权和 URL 解析。UI 不接原始回包、算法、Cookie 或服务端 URL。
  3. 第二段读完再查 wantMore；使用原 addItemToCurPlayingList，scene 和
     原场景均 moreRcmd，文本“更多推荐”，不主动播放、不中断当前曲、不
     清队列、不显示添加提示；offset=种子数−1，不一定是混合队列的尾项。
     M/1384:5270–5298、5366–5377 继续执行同资源去重、现有容量限制和随机

行分隔、标记和提示
  M/1384:4867–4904、5743–5749、6408–6429；M/3113:192–194、480–483、
  561–566、1048–1051、1413–1437：队列显示顺序按 displayOrder，新增开关
  条在标题下，文案“在列表下方推荐你喜欢的相似歌曲”，占用高度从 54 到
  100。分隔线锚定实际条目，删除锚点后向后找仍存在的旧条目；index=0
  不画。moreRcmd 且未取消标记才显示「荐」。拖到分隔线前会取消本次
  被移动推荐项的活跃标记。关闭时保留正在播放的推荐项并转为普通项，
  移除其它仍活跃推荐项；保留已手动转为普通的条目，清除分隔标记。
  关闭或拖动后原 scene 仍可保留；来源操作仅在有 href 时出现，
  官方会提示“来源于当前列表的更多推荐”，不跳转动态目标。
  M/1384:6432–6449、6759–6774，M/83:1359–1374、M/395:1714–1729：
  两版桌面底栏还有一次性提醒，独立于补歌请求。仅有 UID、未记为已提示、
  正在播放活跃推荐项，监听播放进度；前台且 current>0、<=30 秒时弹出，
  5 秒后收起并记入按 UID 的 rcmdMoreTipShowed。不是“剩余 30 秒”。

分隔锚点迁移及恢复
  M/1384:4855–4904 的 moreRcmdSepIndex 和每行 hasSepForMoreRcmd 与 active
  独立。常规列表更新保留仍存在的旧锚点；删除时按旧列表向后找首个在新列表
  任意位置仍存在的行，普通行也能接过锚点。
  M/1384:5743–5749 的显式拖动先清所选行旧锚点位；同一手势仍以旧数字索引
  比较 offset，只有移动的推荐场景项会失去 active。若手势选中了锚点，恢复只
  看旧索引之后的旧行，取其中首个也出现在新列表旧索引之后的行。没有匹配时
  这次结果是无锚点；下一次列表更新才从首个活跃项重建。第零行是有效旧索引，
  仅绘制和 74px 高度不适用（CurPlayingListTrackViewer.tsx:61–64、
  PlayingTrackTitleCell.tsx:434–436）。例如旧 [A,R1,R2,B] 下移 R1+R2 后变成
  [A,B,R1,R2]，两首仍活跃且分隔在 R2；按旧后缀无匹配时可保留活跃项而无分隔。
  M/1384:5131–5159 先执行 reducer 再写整行 JSON（M/78:318–343）；启动读取
  该文件及 isRestoredPlayListFromRcmd 后回灌空模型（M/1384:4819–4827、
  5996–6011），因此数字索引从首个活跃项重算。提取执行官方 reducer 的合成序列
  发现，旧 JSON 的第二个行装饰位可残留；关闭时先替换后设 wantMore=false，
  数字索引也会复位，而阶段性恢复的普通行装饰位可能残留
  （M/1384:6117–6139、6408–6429）。Cumulus 使用一个原生权威锚点统一高度和
  显示，不保留这些与数字索引冲突的装饰位；未用真实官方账号验证可见的残留表现。
  SQLite 把锚点身份或明确无锚点同队列顺序和 active 原子写入。运行中 CAS 重读
  保留提交状态，旧文件缺字段才从首个活跃项迁移；冷启动按官方数字索引规则重建。
  队列身份继续用原生 entryId 区分重复资源，而不是将两个相同歌 ID 当成同一行。
  合成 SQLite 用例覆盖迁移、实时重读、冷重启、移动锚点、普通后继、零索引和关闭。
  Linux 真实 WebView 复跑推荐队列的 16 个状态；另用合成 PointerEvent 在实际
  WebView 验证三段手势：普通行下移不误取消标记，三首推荐组下移使分隔从 51
  迁到 52，再将 51 落在后移的分隔线上，同序只取消 51 的标记。原生播放 ID、
  暂停和位置保持，零真实请求或账号写入。

本端实现和验证
  core/src/catalog/queue_more.rs + core/tests/queue_more.rs：
    QueueMoreRead 只接受认证 SessionToken 与有界数字字符串种子。两次读取分别
    检查当前账号代次；旧账号结果不能进入后续请求或返回。正式签名传输复用
    现有 Api；这层不控制队列，也不获得播放授权。
    安全投影只保留曲目、歌手、专辑、公开封面及所需权益字段；算法仅 native，
    不信任首包夹带的权益。不同位置的权益不补配，缺少算法不影响有效歌曲。
  core/src/playback/controller/queue_more.rs + playback/queue/more.rs：
    每日、会员历史日推、风格推荐、已核验的普通歌单整队列替换记住来源，
    普通追加不改变来源。歌单资格的分组及缓存边界见 queue-more-playlist-policy.txt。
    赋值在首次符合来源时由原生复用 M147 签名读取；失败回到官方启动默认，
    当前账号进程内不会因时钟或重开面板再次拉取。普通顺序/循环用显示尾项，
    随机用同队列已播放条目，第一条新增推荐排到随机下一首。切换账号取消旧
    任务；旧队列、旧播放、房间、
    已关闭开关或新来源的回包不能提交。队列和开关在同一 SQLite 事务写入，
    已有一起听绑定时该事务拒绝。补歌不接管媒体所有权，不在 EOF 等待。
    10,000 项达到容量时不挤掉原有项；与原队列重复的歌曲保留原条目，混合
    队列按合规种子数定位插入。
    当前曲是本地/下载/云盘/节目时没有已验证的公共 currentPlaySongId，
    不发此请求。未接心动、FM 和房间的推荐补歌。
  core/src/client/player + frontend/src/components/QueuePanel.vue：
    queueMoreAvailable 只提示原生可见性变化，queueMoreOpened 和
    queueMoreToggle 通过当前账号及队列版本核对；返回值和视图均不暴露
    原始接口/算法。面板首开仅发一次，开关有键盘焦点和有界等待；虚拟
    列表只有分隔所在的一行从 64px 变 74px，点击、居中和拖放共用坐标。
    拖放请求含实际选中条目和旧插入位置，原生重建完整顺序。拖到分隔线及以上
    只取消选中推荐项的标记；位置不变时也允许取消标记，未移动的推荐不受影响。
    官方组合移动时分隔可跟随历史锚点，按上文的原生分隔迁移规则处理；
    对历史遗留的重复画线采用一个权威锚点。
  desktop/examples/queue_more_ui_probe.js + scripts/ci/queue_more_smoke.py：
    隔离 Linux 真实 GTK/WebKit 与 libmpv 的合成账号和 PCM：控制组无按钮、
    无推荐请求；实验组验证打开、等待、收取三首、重开、双击、真实 EOF、
    关闭保留当前解码、关闭时仍在途的读回后不添加。队列面板关闭时，播到
    尾曲也在 EOF 前触发一次，及时回包可以续播；顺序模式播完后回包只追加
    并保留结束状态和原播放时钟。完整参数和实际解码次数从原生侧独立检查。
    Linux 的 LC_MESSAGES/LC_CTYPE 保持非 C，仅 LC_NUMERIC 为 C。
    合并产品 bcacc227 在 .build/ui-proof/queue-more-final-bcacc227/ 留存
    16 阶段、16 图。独立 --marker-reorder 实窗另有三阶段：拖普通歌曲穿过
    分隔时保留三个「荐」，在分隔本身放开 51 时只取消 51 的标记，
