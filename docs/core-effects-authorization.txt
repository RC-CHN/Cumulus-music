接口和含义
POST /api/vipauth/app/interests/auth/set
  {interestsType:116或127,interestsId:"字符串ID",type:0}
POST /api/vipauth/app/interests/auth/stop
  {interestsType:116或127,interestsId:"字符串ID",type:1}
200/201/202对应116，其余对应127。现有Api处理协议/上下文/登录态，cache=false，
写入确认必须同时有code200和data=true；没有自动换协议、重试或购买动作。
200但data为false/缺失/畸形保留未知结果，不制造登记或停止回执。

GET语义读取仍用业务POST：
auth/query {queryInfo:{interestsMap:{"类型":[数字ID]}}} -> canUse和会员/试用信息。
recyclequery {queryInfo:{"类型":["字符串ID"]}} -> data[类型]中的interestsId/canRecycle。
recyclable()严格区分缺少记录None、false、true；重复身份、非对象/数组及非bool为错误。
query.canUse是权益；recyclequery.canRecycle是是否应回收。两者都不是“此前某个
auth/set或auth/stop已经成功”的回执，不能用于抹去丢包后的未知结果。

代码与调用顺序
core/src/effects/authorization/：record定义持久状态，mutate负责单次登记/停止，
observe负责新读取/恢复；mod负责账号命名空间、持久化和跨进程操作锁。
EffectsApi的写入口是显式方法，目录/材料获取不会顺便登记、开始试用或支付。

EffectAuthorizations.begin_for(token,effect,TrialConsent)：
1. 固定当前账号并获取账号级互斥锁；另一效果仍有待释放登记时拒绝切换。
2. 同效果已Registered时只重查权益，不重复auth/set；未知结果不自动重放。
3. 新登记先查询服务端canUse，未授权则无写请求；50/51试用必须ExplicitStart。
4. 先保存Registering和operation UUID，再发送一次auth/set。
5. 收到200且data=true后保存Registered及start_acknowledged；随后新查auth/query与recyclequery。
6. 返回LeaseObservation.can_use只表示已确认登记且当前读取允许；不表示DSP已启用。
材料应在调用本方法前准备好。逐歌AI/设备/情绪的材料与播放器接入不在这个方法内。

release_for(token,effect,ReleaseRetry)：
只处理本账号已有记录，不能停止未被本实例记录的其他效果。先保存Releasing，
发送一次auth/stop，收到200且data=true后为Released。Released重复调用无请求。
StartRejected是服务器明确拒绝登记，直接保持该终态，不伪造stop成功回执。
StartUncertain可由明确停止操作补偿；StopUncertain不得默认重发，必须调用者显式选择
ExplicitAfterUnknownResult，将再次停止作为新动作，而不是宣称原请求失败。
本批没有后台自动写入定时器。

observe_for(token,effect)：
获取互斥锁后，遗留Registering/Releasing转为StartUncertain/StopUncertain。
先清除旧观察再做两个新读取；错误保留登记回执和错误，不能把旧值伪装成新查询成功。
Registered + canUse=true + canRecycle不为true，返回can_use=true。
canUse=false/缺失或canRecycle=true会返回can_use=false；如登记仍待释放，
should_release=true。宿主应先停本地效果，再显式release；查询本身不隐藏发送stop。
未知写阶段即使查到canUse=true且canRecycle=false也仍然未知，can_use=false。
观察Released记录仍可查到canUse=true（会员权益仍有效），这不表示重新启用了效果。

状态和恢复
Registering -> Registered / StartRejected / StartUncertain。
Registered或StartUncertain -> Releasing -> Released / StopRejected / StopUncertain。
服务明确301/400/403/405记录Rejected；其余错误保守保留Uncertain，不假定500没有执行。
停止被明确拒绝时，已有登记仍可能存在；StopRejected保持待释放义务。
每次操作记录effect、operation UUID、revision、开始/停止回执、最后权益/回收观察和
不含响应正文的错误。只有收到相应确认才允许Registered/Released，反序列化后校验。
operation UUID仅用于本地关联，不发送给服务端，不把它当成远端幂等键。

任务取消不伪造完成：发送前日志已提交，future被取消后锁释放，恢复读取识别未决。
账号切换后收到成功确认，仍在原账号保存确认，然后向旧调用者返回StaleResponse；新账号
不会收到或复用它。网络await不持有账号/数据库互斥锁，账号级文件锁串行化写入。
持久状态仅在当前账号命名空间中读取；重开后必须重新观察，不能直接把历史记录当作
新的当前权限或自动重新登记。一次新的明确登记有新的operation UUID。

已确认登记与已校验的 PEQ 材料绑定
EffectAuthorizations::bind_parametric_for 只接受同一原生会话的 Ready 材料，且
EFB760 只分派一个启用的 PEQ。其它已分派片段即使标记关闭，也不能被悄悄跳过。
登记必须有 auth/set 确认、没有 auth/stop 确认；登记前记录的 canUseType 必须是
已证实非试用的 10/11/12。历史缺此字段的登记仍可读取、恢复和停止，不能靠后来
权益读取推断初始登记不是试用。绑定在账号授权锁内再查 auth/query/recyclequery，
要求 canUse=true、同样的非试用范围、明确 canRecycle=false；不发任何写请求。
BoundParametric 只保留不可序列化的候选和精确登记 operation/revision。
validate_bound_parametric_for 在本地检查这些记录和 Ready 材料回执；同账号
新读取（即使仍允许）、失败或未决状态、停止、材料移除和账号切换都使旧凭证失效。
此检查只证明检查当刻的状态，未开放播放、IPC 或远端注册；后续播放器仍需运行中撤权。

受监督的原生 PEQ 播放
可信原生宿主可用 MusicClient::bind_native_effect_parametric 读取并封存已登记权益，
再用 apply_native_bound_parametric 消耗该绑定。播放器在实际挂载和解除暂停的命令
期间保留账号授权与材料锁；解码期间只排队，首次恢复播放前再检查。正在播放、暂停
或空闲持有节点时，控制器在正常命令与约 200ms 的监督轮次重查本地登记和材料。
已知本地撤权、观察更新或无法验证时清除节点；清除成功保留普通音频，失败则停止并
阻止不安全的恢复。监督不在音频回调内、不对远端轮询或写入；远端变化要由独立权益
观察反映到本地。轮次不是实时撤权保证，已提交至输出的样本不能撤回。
未开放 UI/IPC、试用、自动登记、续期或自动停止远端登记。

已激活原生绑定的显式服务端观察
MusicClient::observe_native_bound_parametric 只捕获当前节点，无任意效果 ID，
一次最多执行 auth/query 与 recyclequery 两次读取，共享 5 秒本地预算；相同绑定
并发调用拒绝，不占用播放器或音频锁。正面结果重新校验原登记与材料且保留节点；
明确拒绝、缺字段、读取失败或超时使原绑定失效，只在登记 operation/revision 仍匹配
时更新本地观察记录。切换/卸载后的旧观察不能授权新绑定。未启用定时轮询、自动
重新启用、auth/set、auth/stop 或 UI；5 秒是读请求预算，不是官方权益期限。

原生解除绑定
------------
BoundParametric.target() 返回仅原生可持有的不透明绑定标识。clear_native_bound_parametric
按账号代次及这个标识匹配已应用或待应用的 PEQ；旧标识不能移除同一音效的新绑定。
等待解码的同一待应用项可以撤销；若正在解码而已应用组件尚未安全拆除，返回忙，
不把等待状态记作已拆除。成功只表示本地解除，不发送 auth/stop，也不清除服务端回执。
后续桌面关闭流程仍需用持久登记回执显式核对并停止。
