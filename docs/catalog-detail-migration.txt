ArtistApi 请求
detail       /api/artist/v3/detail        id,top=50,e_r=false；nginxCache=true
dynamic      /api/artist/detail/dynamic   id；收藏状态与演出数量独立读取
albums       /api/artist/albums/{id}      limit,offset
songs        /api/v2/artist/songs         id,limit,offset
introduction /api/artist/introduction     id
similar      /api/discovery/simiArtist    artistid,limit,offset,total=true
videos       /api/mlog/artist/video       artistId,tab=1,order=0,page
concerts     /api/concert/list/byartist   artistId,limit,offset

除 detail 外不强行启用 nginxCache；官方客户端自己的缓存策略不等同于请求头缓存选项。
歌曲接口传给官方格式化器的 uid 是本地归一化上下文，不发送为 HTTP 字段。
相似歌手使用小写 artistid；视频 page 为 JSON 字符串，其 cursor 是十进制数字。
视频游标不经过 JavaScript 数值或 Rust u64/f64 缩窄，保留十进制内容。
官方默认 limit=20、offset=0；本实现增加 limit 1..100、offset <=1,000,000、
游标最长128位的客户端输入边界。这些上限是本实现的约束，不冒称官方服务端上限。
所有请求只接受成功状态 200；服务错误继续走现有 Api 错误处理，不伪装空页。

第二阶段：原生页面快照与权益合并
core/src/catalog/details/{query,request,service}.rs 提供 CatalogQuery、CatalogDetails 和
SavedCatalogPage。查询覆盖歌手热门、独立动态状态、分页歌曲/专辑/相似歌手/视频/演出、
简介与专辑详情。SavedCatalogPage.response 是原生元数据，不能直接作为 IPC DTO。

page_for 的顺序：
  校验 ID/分页 -> 绑定账号代次 -> 按账号和完整查询互斥 -> 官方读取 ->
  校验响应身份与必要字段/合并权益 -> 再次核验账号 -> 持久化 -> 返回。
缓存键含查询种类、资源 ID、页码/游标及大小；StateStore owner 使用当前账号。
cached_for 校验缓存的查询身份、响应结构和 revision；没有记录返回 None，不冒充空页。
读取失败、返回另一歌手、动态状态缺少 followed、账号切换后的迟到响应均不覆盖已有快照。
歌曲 revision 包含查询及有序 ID，权益刷新不改变队列顺序 revision。
视频声明 more=true 却返回同一数字游标（包括前导零等价形式）时拒绝该页，保留旧快照。

官方 M/15 的 g={enable:false}（1012 行）。本地快照是额外的恢复能力，page_for 每次均联网；
没有引入“缓存三小时内直接成功”的逻辑。前端接线时仍须显式刷新，快照不能授予播放权益。
M/612 的热门歌曲先读详情，再调用 M/15 Dg：/api/song/enhance/privilege，
ids 是 JSON 字符串，默认省略 trialMode；M/15 对照中的 MV 路径显式传 -1。
新 CatalogApi.privileges 保留输入/输出顺序与重复项，按500项分批、最多50000项；
分批和数量上限是本实现约束，不宣称它们来自官方 Dg。

合并按 M/21 B（21.js 683 行附近）恢复：
- 同 ID 权益取最后一次值；未返回权益的原歌曲去除旧 privilege，保持未知。
- 仅在权益条目数大于原歌曲数时，对原列表中没有的 ID 按权益回复顺序补入资料缺失条目。
- 补入条目保留 id/privilege/空 artists；不捏造名称或把它视为已完整读取歌曲资料。
- 原始 ID 集合不会随补入更新，因此重复的额外权益 ID 保持重复，未自行排序或去重。
M/21 R 的 id || albumId 也用于专辑列表、详情校验及歌曲专辑引用，保留大整数字符串。

这一阶段没有复用 MV 域已有的严格权益字典：官方歌手合并需要保留原始顺序及补入分支。
M/21 V 同时处理 base.type=2 的视频与 type=3/isMv 的 MV；前端尚未接线，不能把每个
返回条目或所有数字 ID 当作 MV。相关分流、播放及真实接口验收仍是后续工作。

1. /api/album/v3/detail {id}，nginxCache=true；请求失败再调用一次
   /api/album/v4/detail {id}，nginxCache=false。成功响应身份不符会报错，不伪装成
   版本兼容失败再读。没有其他协议降级或无限重试。

   最后以动态 commentCount/likedCount/shareCount/subCount/isSub/subTime 覆盖。
   动态字段缺失时去掉旧字段，不能从静态 isSub 猜测当前收藏状态。
3. /api/album/privilege {id}，使用与歌手相同的 M/21 B 权益合并。请求或数组校验失败时

4. /api/resource-exposure/config {resourcePosition:"album",resourceId:id,rexposureRecords:[]}

   失败时官方页面回落为不显示，本实现额外用 None 记录“未读到”，避免假装已确认 false。

CatalogView.revision 是目录页的查询/顺序 revision，不是现有 PlaySelection.Album 的

  歌手页有热门 TOP 50、全部歌曲分页、专辑、视频、介绍、相似歌手和演出分栏。
  专辑页有完整曲目、简介、收藏、评论、当前列表下载入口。歌曲更多操作复用既有歌单弹窗。
- 头部、动态收藏和分页分别读取。分页追加保存原顺序和每页 revision；刷新成功才丢弃
  旧续页，失败保留旧内容。账号/资源改变会丢弃迟到回复。连续页之间禁止混入不同资源。
- TrackTable 沿用有界歌曲行；卡片按宽度计算列数，以固定行高260px和两侧2行缓冲虚拟化。
  原歌曲表保留8行缓冲；没有为了卡片改变既有列表默认行为。专辑图、视频图懒加载。
  页面与分栏动画仅用 transform/opacity，尊重减少动态效果。配色均取主题语义变量。
- 实际窗口检查发现8行卡片缓冲会一次保留过多节点，改为2行；还发现外层 overflow:hidden
  会裁掉详情页底部，给详情页加入自身滚动边界。后续检查增加容器边界断言，不能只测按钮
  的 DOM click 成功。点击探针会先滚动目标到可达区域。

收藏与失败恢复
catalog_membership(epoch, resource, action) 仅支持 artist/album，action 为 inspect/set/reconcile。
inspect 只读当前账号的持久化操作记录；set 复用 AccountResources：完整读取收藏列表、
保存 Sending 意图、提交一次、读取对账；结果已有相同状态则 Unchanged，不重复写。
收藏接口为 /api/artist/sub、/api/artist/unsub、/api/album/sub、/api/album/unsub；
前后状态经 /api/artist/sublist、/api/album/sublist 分页读完后核验。
UI 只有动态状态明确、操作记录可读且无未决写入时才允许点击；丢失响应后只 inspect，
显示待确认并阻止再次提交。用户的“核对结果”仅做 reconcile。历史 Confirmed 记录不覆盖
后来动态读取的收藏状态。当前线上验收不执行收藏变更；提交/撤销/丢失响应用隔离合成数据。

播放语义与官方证据
- AllSongsList.tsx 的 onPlayClick 明确是 trackList + from.listData=records，不能把按钮
  误读成“自动下载/读取歌手全部未加载歌曲”。本页明确标注“播放已加载歌曲”。
- PlaySelection::Catalog 接收原生页面查询/revision，不信任前端拼出的远端歌曲元数据。
  热门和分页歌曲读取当前账号快照并验证顺序；页码必须从0连续、同歌手同类型。
  专辑只有一页；缓存中的目标顺序与重新读取的歌曲顺序不同时返回 QueueChanged。
  随后仍逐批读取完整歌曲详情并走现有实际音源授权/播放器，不拿缓存权益当播放许可。
- 播放来源保留 artist/album、资源ID、scene及 M/91 的默认 trial_mode=-1，没有借用会员、
  搜索或日推场景。队列歌曲继续保留歌手/专辑ID，避免入队时丢失导航引用。
- 进一步核对 M/404 album resolver -> M/15 da（导出 v，4094行附近）发现播放链与页面链
  不同：播放读 /api/album/v3/detail，再必需读取 /api/album/privilege；不读 dynamic 或
  exposure，不在播放时做页面 v3→v4 回退。CatalogApi.album_playback_tracks 已单独恢复。
  此处按原 Array.find 的首个同类型ID匹配权益，不追加缺歌曲资料条目；与页面的 M/21 B
  最后值覆盖/补入逻辑分开。合成对照覆盖重复权益、数字与字符串ID不等、缺失权益及读取失败。
- 下载按钮当前按明确标注的已显示歌曲列表调用已有 DownloadDialog/下载用例；没有自动
  替用户确认下载。歌曲列表的专用下载来源/完整官方下载分派仍需与所有入口统一审计。

已确认的边界
普通 type=2 视频播放、未知视频类型和演出外部链接尚未接入；界面明确显示视频支持边界，
演出只显示卡片，没有伪造可购票按钮。新增目录导航目前未遍布 FM/播客等所有 TrackTable
调用处。歌手/专辑收藏总览、详情内排序/筛选、官方完整菜单/分享与缺URL图片ID生成仍待补齐。
