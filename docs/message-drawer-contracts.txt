只读请求和游标
动作                       参数 / 回执
未读                       /api/pl/count {} -> msg, comment, forward, notice
私信列表                   /api/msg/private/users {limit:15, offset:0, time}
                           -> msgs, more；续页游标是最后一条 lastMsgTime
评论                       /api/v1/user/comments/<当前认证UID> {limit:10, beforeTime}
                           -> comments, total, more；续页游标是最后一条 time
提及                       /api/forwards/get {total:true, limit:10, offset:0, time}
                           -> forwards, lasttime, more；续页使用 lasttime
通知                       /api/msg/notices {total:true, limit:10, offset:0, time}
                           -> notices, lastTime, more；续页使用 lastTime
会话                       /api/msg/private/history {userId, limit:10, offset:0, time}
                           -> msgs, hint, more；续页游标是最后一条 time

所有首读的 time/beforeTime 为 -1。只接受账号会话自身的 UID 进入评论 URL；
WebView 不能指定评论账号或请求路径。会话 userId 是当前界面选中私信的对方 ID；
Rust 检查非零数字、游标正整数且不超过 JS 安全整数，拒绝非会话夹带 userId、
不前进的分页及坏包。每次发送前、回包后验证账号代际；仅返回有界文字/计数、
显示所需 ID 和时间。客户端不持久化私信、附件、通知及聊天正文，不暴露附件地址，
不执行服务端提供的 HTML、链接或脚本。未知消息明确显示当前客户端无法展示。

用户流程
账号按钮旁的信封打开独立右侧抽屉；未认证沿用登录入口。只在打开或主动刷新时
读取未读数，无后台请求。初始读取私信，其余三类按激活读取，重复点击当前标签
回顶部；已打开的标签保留当前抽屉内的页和滚动位置。列表触底请求续页，另有
键盘可操作的加载更多。会话时间顺序从旧到新，最新一条在底部；上翻更早页保持视口，
返回恢复滚动及原会话按钮焦点。失败留住已有列表，重试相同游标；再次刷新读首屏。
关闭或切账号作废待返回结果；每类每次抽屉至多保留 300 条，避免无限 DOM/内存增长。
抽屉以应用顶栏、播放器区域为边界，宽度沿用 386 px；打开动画遵守系统减弱
动态效果设置，关闭立即移除私密内容，不保留动画中的旧账号消息。

明确差异
官方对私信及标签未读有本机清零；官方可快速轮询 /api/pl/count，并对正在看的
会话接入云信推送刷新。此只读实现保留服务端回报的计数，打开/切换/返回不清零，
关闭不留私密缓存，也不实现轮询、系统通知或云信推送。官方按未读数可预取评论、
提及及通知首屏；这里统一以恢复出的常规 10 条分页按需读取，显式刷新替换首屏。
原版关闭时 `clearNotice` 只重置本地 notice 列表（M/2171:536–550）。
“一键全读”先弹确认，然后调用 /api/msg/count/clear；发送、回复、删除、举报仍不接入，也不自动调用这些写接口。图片仅显示类型；
外链和任意原生跳转留作惰性文本；下面的附件扩展只开放已识别的客户端动作。
未进行真实账户请求；
静态证据可证明客户端不调用显式清零写接口，不能排除服务端对读取接口的隐式计数策略。

验证
`core::client::messages::tests` 固定官方参数、会话/评论投影及游标拒绝。
`scripts/ci/message_drawer_smoke.py` 走实际生产 IPC 与真实 WebView，后端为封闭夹具。
覆盖无后台读取、代际拒绝、四类读取、私信历史排序、返回恢复、续页失败重试、
通知与提及各自的服务器游标、未读保留及迟到结果隔离。脚本独立检查请求列表，
没有真账号、真实网络消息服务、标记已读、发送或删除。Linux 隔离实测的 7 个界面
与合成截图位于 `.build/ui-proof/message-drawer-5d0f41b/`，Windows 已接入 CI 待实跑。


已确认的消息附件动作
================================================================
- 私信列表的预览依旧只进入对应会话。会话 M/3090:805–1058、1349–1406，
  `TalkItem.jsx:123–160` 与 Appendix：单曲 type=1 和声音 type=5 是
  Action.play/Scene.message，不打开通用链接。原生按目录单曲 ID 或节目 ID
  查详情与音源权限，普通队列保留原条目并使用下一个位置选中；打开播放不关闭抽屉。
  私有云歌曲 type=14 没有可证明的云盘绑定，绝不把其 ID 当普通单曲。
  type=2/3/4 分别用专辑、艺人、歌单详情；type=7 用 MV ID 打开原生视频页；
  type=15 使用下面的评论定位，未识别 ID、图片、外链、推广和综合通知保持惰性。
- M/2119、`CommentItem.jsx:246–278`、Appendix/Comment.jsx:60–85：
  评论提醒从 combindId 取 commentId/threadId，分享评论从专有字段取同一对 ID；
  解析 resourceJson/resourceInfo 的 ID、资源类型与 canonical threadId 必须一致。
  歌单/专辑直接进入其评论标签；单曲/声音/MV 的共享评论用独立评论页。
  第一次读取即请求 /api/v1/resource/comments/<canonical thread> 的
  commentId 和 offset:0，等待核对目标回包，不先读默认列表；失效评论交给
  现有评论状态说明。社区/播客等缺失独立定位能力的路径不接。
- 通知按 `NoticeItem.jsx:255–350`：收藏/分享歌单打开详情；声音的分享、
  收藏、点赞播放该节目；赞评论按已知的歌单、专辑、歌曲、声音 thread 定位。
  此处与独立评论分享的规则不同：官方通知里的 MV/视频评论提示去移动端，本实现
  不生成可点击目标。社区事件入口必须同时使用动态 ID、作者 ID 和有效社区路由；
  当前不具备该动态详情，保持文字。
- 提及按 `ForwardItem.jsx:273–304,405–443,588–612` 与 M/2058 的区分；
  直接动态仅投影明确的非外链附件，评论提及按 resourceType 选对应资源卡；
  type=2 走社区事件定位、被转发的嵌套动态、未知类型均不添加动作。
  编译的 MessageSheet/397 保持 DOM，普通点击没有证据表明会清除本地会话；
  Cumulus 导航时将当前抽屉暂时隐藏，直接 Back 才恢复同账号、同页面、同一
  按钮的焦点和滚动。改走另一页面或切账号时丢弃该内存状态，不重新读消息。
  动作由 Rust 投影已验证类型和数字 ID，WebView 不接收目标 URL 或 HTML；
  不清除远端未读、不发送、不自动运行任何附件动作。
- Rust 投影回归验证类型、资源与评论 ID 匹配，以及外链、云歌曲及社区的拒绝。
  `message_drawer_smoke.py --attachments` 在真实桌面 WebView 验证打开/返回、
  原有队列保留与真实合成音频播放、三种评论首读精确定位，且没有任何消息写入。
  初次链接在确认目标评论后滚到可见区域并聚焦该条评论；普通评论浏览保持原来
  的焦点策略。隔离 Linux 九态及截图：`.build/ui-proof/message-attachments-3ae6604/`。
  Windows 用例已加入 CI，尚未在本轮运行。音频实测仅为本地合成解码/null 输出；
  本次 GUI 专项未单独重测 MV、艺人或声音资源页，其目标形状由恢复证据及 Rust 校验支持。
