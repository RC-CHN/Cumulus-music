core/src/catalog/intelligence.rs：IntelligenceRequest / IntelligenceApi::recommend。
字段 | 线上的值/含义
playlistId | 喜欢歌单ID；本核心沿用正十进制字符串，保留大ID与前导零
songId | 选中的种子歌曲ID
startMusicId | 官方aiPlay中可播放喜欢列表第一首ID
count | 原喜欢列表数量，不替换成固定分页条数
type | fromPlayAll 或 fromPlayOne
starPlaylist、uid不发送；喜欢元数据只在本地解析回退。ApiOrigin/签名/登录上下文继续
由现有MusicHttpClient提供，接口模块不另选协议、设备身份或Cookie范围。
count/喜欢缓存/响应数量沿用完整歌单100000条的本地资源上限，拒绝而非静默截断；
这项是本核心边界，不声称已实测服务端最大容量。

响应与算法细节
- songInfo存在时保留原始目录数据，覆盖alg；algorithm遵循M/21的JS真假值回退。
  liked回退只改algorithm：null、0与缺失要区分，不把未知recommended状态强制转bool。
- 无songInfo且本地喜欢缓存也没有对应歌曲时，返回source=unresolved及song=None。
  保留位置、ID和推荐信息，不额外查询详情、编造可播放对象或忽略掉该行。
- 轨道行顺序及重复行保留；推荐信息字典重复ID以最后一行覆盖，符合原对象赋值。
- 原liked回退重复引用同一对象，所有同ID回退行最终都会看到最后一次回退算法。
  冻结原函数先使朴素逐行clone实现失败；Rust改为私有喜欢副本两阶段投影，保持结果，
  同时不修改调用者的全局喜欢缓存。songInfo行仍保留各自行算法，不套用liked别名规则。
- 空data数组是成功的空批次；缺少data/非法行/非法songInfo或拒绝码返回错误。读失败
  不自动改成随机列表，不自动重发，不在API层决定是否切换播放模式。
- 返回的是native元数据；未来IPC仍须经既有白名单TrackView映射，不能把原JSON直接
  暴露给前端。完整M/21歌曲/Database规范化不在本模块复刻。
