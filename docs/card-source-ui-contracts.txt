修正的实际问题
1. 我的歌单在停止后保留 origin，但原实现只比较歌单ID，继续发送 Pause(false)，
   无法重新播放。现在同时检查已加载状态；已停止时走既有 playlist 选择，保留保存的
   音质偏好，由 Rust 重新核对资源与播放权限。没有通过直接使用搜索元数据绕过权限。
2. 我的歌单原来只将 playing 显示为暂停，buffering 却显示播放。现在与搜索/排行榜
   一致：playing/buffering 显示暂停，paused 显示播放，图标和动作使用同一状态。
3. 搜索与我的歌单的当前来源原来发送不绑定目标的通用 Pause。现共用 toggleSource，
   记录当时 playId/queueRevision，通过 PauseFor 拒绝过期控制；不暂停后来选择的音频。
4. 原生加载暂时禁用按钮时，WebKit 会将焦点移到 body。共享 usePlaybackTriggerFocus
   在同一资源/访问、按钮恢复可用、仍在可视区域且用户没有另选控件时接回焦点。
   菜单关闭保留原触发器；若触发器已移除，可使用本卡片播放键。离开/卸载使回调失效，
   不滚回用户已经离开的卡片。排行榜改为复用这个实现。
5. 播放条“重试”成功后按钮消失会丢焦点。重试时先保留在传输控制组，成功后移到
   当前可用的播放键，仍有可重试错误则返回重试键；账号代次变化或用户另选后不抢回。
6. 我的歌单列表最左播放键的外侧轮廓被滚动容器裁切；改为内侧主题轮廓和4px圆角。
   保留可见键盘焦点，不以移除轮廓解决裁切。

状态/来源规则
- 相同来源且已加载：只暂停/继续，保留当前曲目、位置、播放身份和整个队列。
- 来源类型或ID不同：走对应的既有资源选择；声音额外比较 voiceId。
- idle/stopped/未加载：重新选择资源；空歌单和不可用声音保持不可播放。
- busy 抑制重复卡片命令；独立队列读取等待不阻止控制当前来源。队列回执仍按单调
  revision接受，不能用迟到读取把暂停回滚成播放；提交时核心继续核对实际队列版本。
- 原生继续失败：保留原暂停会话和可见反馈。显式重试仍携带原目标；成功不重载音频。
  若目标已被另一来源替换，旧重试应被核心拒绝，不能改为操纵后来音频。
- 完全卸载、持久化失败等其他错误组合仍按已有播放器恢复路径；本专项没有全部覆盖，
  不将这里的单次 unpause 失败恢复扩大成全部输出异常均已通过。

类型化调用和接口
页面/卡片 -> App -> usePlayer -> CoreClient -> desktop IPC -> MusicClient/actor。
- 当前来源：player_action(epoch,{kind:pause_for,play_id,expected_queue_revision,paused})；
  Rust 先验证账号/目标/已加载状态，再走既有媒体焦点、一起听及持久化控制路径。
  不增加业务网络接口，不将 Cookie、授权音源或签名密钥传给前端。
- 我的歌单/搜索歌单重新选择：play_selection 的 playlist 输入，仍由核心读取
  /api/v6/playlist/detail、/api/v3/song/detail 及 /api/song/enhance/player/url/v1。
- 搜索专辑/歌手：catalog_page 取得账号绑定快照和 revision，play_selection 的 catalog
  输入核对顺序。现有读取包括 /api/album/v3/detail、/api/artist/v3/detail；专辑播放
  继续沿用已有重读/版本验证，不能把搜索卡片内容直接当作权威歌曲列表。
- 分类搜索播单的旧路径：podcast_page 的 radio scope/ascending=true/offset=0/limit=100；
  随后 play_selection 的 podcast 输入携带 scope/revision/start_id。现有读取包括
  /api/djradio/v3/get、/api/v6/dj/program/byradio、/api/dj/program/detail 和既有音源解析。
  分类播单选择首个可用项；综合页最佳匹配和普通播单已改为原生收据与 M404 播单准备
  （见 search-card-ui-contracts.txt）。搜索单集优先用精确 voiceId。
- 查询/账号迟到回执保护、会员/版权判断和选曲取消沿用原用例；没有新增前端业务HTTP。
