我的播客：最近更新单集（官方 PC 3.1.42.205594）
=======================================================

入口和状态
- hybrid_55/M2090:16–64 定义 /myAudio/recentUpdate，但两套菜单常量都未放入该项；
  同模块的 hybrid_120、hybrid_165 副本相同。M3108:897–944,1000–1075
  只在首次读取 pc_mine_pod=t1 时注册该子路由；对照组切回 /myAudio。
  即使该项注册，M3108 不显示最近更新数。M3108:793–842 确认已存在的子页面，
  M3150 的原文包含「最近更新单集」。Cumulus 已采用拆分收藏页，明确把这个已恢复
  的子页面作为「最近更新单集」标签展示，不模拟实验分配，不绘制数字徽标。
- M3150:11–45,114–174 向 M15.vg 发送首次 {}，后续只发送 {updateTime}。
  uid 传入 M21 数据格式化上下文，不进入请求体；列表的 size=100 是表格设置，
  不等于 HTTP limit。固定 PC 路由 POST /api/social/my/recent/update/voice/list/v1，
  读取 data.data、data.hasMore、data.updateTime 和首屏 data.newVoiceCount。
  续页排除旧 ID，保留既有顺序和首屏计数；首屏失败显示重试，续页失败不清除记录。
  M3150:175–207 在 POP 恢复页面快照或重新获取。M155:302–309 配置原客户端的
  一小时状态缓存；Cumulus 对同一进程的回退保留列表、滚动和节目来源按钮焦点，
  新进程重新读首屏，不跨进程保存最近列表。
- Rust 校验当前已登录账号代次，原生持有时间游标、顺序和随机快照版本。
  Vue 无法传任意时间；保留服务端游标原有的 JSON 数值或字符串类型。过期、重复或
  跨账号续页被拒绝，网络失败保持旧列表。
  去除同页重复项（官方只排除已加载页的重复），拒绝无进展游标；每回包最多 200 项，
  会话最多累积 500 项和 20 页，滚动接近底部或「加载更多」才继续。可手动刷新首屏。
  这是客户端的有界保护，不能推断服务端最大数量。

声音和播放
- M21.W:931–979 投影节目 ID、mainSong/trackId、原始 radio、播放量、
  djPlayRecordVo、时长及付费标志；播放量优先 listenerCount，其次 playCount、
  adjustedPlayCount；进度记录的 listenLocation 为毫秒（M308）。
  M3108:643–682,793–842 使用序号、标题、播放量、时长列、来源播客与播放进度。
- M195:399–411 提供当前整个已加载表格作为动作上下文；M405:249–255 双击进入
  action/play；M3085:180–209,243–296,309–312,399–411,532–585 按设置决定是否
  替换队列，直接点击节目只播放该声音，已有当前声音则切换暂停/播放。Cumulus
  根据原生版本和 voice ID 读取该表格中的记录，先解析选中节目，缺 mainSong 时
  在组装队列阶段只对所选节目补 /api/dj/program/detail {id}；原生播放器随后按既有
  流程再读当前节目的详情核验媒体 ID。双击默认以本次加载顺序替换，
  保留队列设置沿用原生插入/跳转；不能把 voiceId 当作歌曲 ID。当前声音同一
  play ID 下切换暂停，不重新申请媒体。排除已标不可播放项及没有媒体 ID 的其他行；
  权益检查 /api/dj/play/url/check {voiceId} 通过后才用媒体 ID 申请
  /api/song/enhance/player/url/v1。既有音频引擎和账号资源规则照常生效。
- 当前只接入源播客跳转和播放；原生共享声音详情页处理评论、下载、点赞等既有动作。
  最近更新不显示泛化的「播放全部」按钮。

收藏播客新节目徽标：显式卡片详情入口
- M21:809–832 取 newVoiceCount || newProgramCount || 0；M2120:145–150,270–286
  仅在有计数时在封面绘制 Badge，overflowCount=99。M3108:304–314 采用该单元的
  收藏列表；「最近更新单集」标签仍没有数字。这里只开启目前拆分视图的「我的收藏 /
  播客」卡片，且只接受正的有界整型或十进制字符串；异常字段、无权限条目不投影徽标。
- 恢复的 audio-detail/views/index.jsx:128–139 和 M3117:457–466 在进入具体播客
  详情后调用 page:audioDetail/clearCount，与详情读取并列；M3018:269–284、M2156:24–26、
  M15.Qb 固定 POST /api/djradio/newcount/clear/byradio {radioId}。官方详情效果本身
  没有“必须来自收藏正计数”的限制。Cumulus 仅在用户显式打开当前这份收藏页中已确认
  正计数的具体卡片时提交；不从直接链接、编号输入、通用详情读取、刷新、启动、播放
  或最近页跳转推断写入许可。没有确认弹窗或附加按钮。
- Rust 保留该列表一次真实 PC 读取的证据，分页/筛选只从相同原生快照投影；不采用
  已跨账号或旧进程的缓存作为写权限。当前页回执仅涵盖实际返回的正计数卡片；
  IPC 只在主窗口，使用 epoch、opaque receipt、ID，在原生回查当前快照修订、同账号
  API 实例、PC EAPI 目标/唯一会话 Cookie 及凭据版本，获取每账号每播客的写入锁并
  在 HTTP 发送前重验。无需前端读取签名、Cookie、授权 URL 或原始列表记录。
- 写入不阻挡详情导航。已收到成功回包时，该行同一观察值在回到收藏时不再显示；
  新观察到的更新标记或正计数改变后可以重新显示。丢应答不伪称成功，也不自动重发；
  同一进程同一观察值不会再次派发，正常读取和刷新也不会提交。没有在启动、跨进程
  或切号后重放未确认动作。不处理已购/有声书或 M3108 的播放时缓存清除和全局
  host.newProgramCount 红点；相同接口的未支持触发保持关闭。
- 合成验证入口：cargo test -p cumulus-core --locked --test client_podcast subscribed_badge_clear
  用真实 Rust EAPI 封包＋封闭假 HTTP，核固定请求、分页过期、账号及凭据切换、确认和
  丢应答；前端 tests/podcast-state.test.ts 核实真实模型只从显式正计数卡片提交，
  详情可继续。这里未声称新的真实服务/桌面运行已验证。
