  {enable:true,preventSystemSleep:<布尔>,preventDisplaySleep:<布尔>}。

- 解包的 x64 redist_packages/cloudmusic.dll SHA-256
  557d7706dedc8556a8bd279d4dfe2bc05b80ad729a8749caccd9e29916935493。
  RVA f6bf91–f6bfa6 的注册将 setPowerRequests 指到 f6d190。
  f6d556–f6d75b 默认 display=false、system=false、enable=true，并读取同名字段。
  f6d760–f6d7ac 从 ES_CONTINUOUS (0x80000000) 开始；enable 为 true 才合并

Cumulus 设置、权限与状态

- Windows 主窗在设置「播放」的启动自动播放下方显示同名开关。仅当原生宿主
  可用、当前 PC 实验分组精确为 t1 才显示；前端不依据 UA、登录状态或自造分组。
  主窗命令 playback_power {epoch} 和 set_playback_power {epoch,enabled} 返回
  {available,enabled}；非主窗、旧账号代次无权使用。设置成功后保留焦点并提示
  「设置已更新」，SQLite 写失败时保留旧值，允许重新读取，不自行重发写操作。
- 读取复用官方完整实验表 EAPI POST /api/rtrs/abt/front/expinfo/list；PC origin、
  原生 UA、clientSign、已绑定的 PC Watchman/设备上下文仍是前提。此分支不额外
  强制登录，也不放宽其他实验接口的登录要求。分组以会话代次和原生 API 实例
  为缓存键；正常回包有效 30 分钟，传输/超时失败只隐藏设置并允许 15 秒后
  重新查询，单次等候最多 8 秒。切号或原生 API 被替换后丢弃旧回包。开关写入
  只在当前有效 t1 缓存内进行，无网络设置写入。尚无真实 Windows 访客 t1 回包
  的证据；Linux 产品没有该原生宿主，隐藏设置且不为此发实验请求。
- 设备设置存在 SQLite 的 local-device / playback-power-v1 / enabled；首次或
  记录损坏按关闭。先提交数据库再通知现有播放器，不为了读或写开关启动解码器。
  退出账号、切号或分组变为非 t1 不会丢弃已保存的开关；分组控制设置曝光，
  不参与播放时的持有条件。设置生效和临时播放状态不能写进同账号接续。
- M/308:1812–1825 将接受的播放写为 Playing，早于 :1847–1853 原生加载。
  Cumulus 以 Rust 播放 actor 收到授权后的原生 Loading 消息为最早安全点：
  首次等待音源和权限时不提前持有，已授权、等待解码或缓冲时保持。暂停、明确停止、
  会话失效/更换、加载失败和最后一曲结束清除；顺序队列自然衔接可保留原持有，
  其他明确写入 End 的切换先释放。停机和失败安全释放是原生宿主边界；原版
  部分失败/原生 stop 回调先保留模型 Playing，等待后续模型事件。
- desktop/src/playback_keep_awake/delivery.rs 只在 Windows 产品启动时创建宿主。
  在一条专用线程执行并清理两个 Win32 掩码；播放 actor 只向容量 16 的队列
  非阻塞投递。正常按顺序送达不同状态，只折叠紧邻、成功且无失败插入的同值
  请求。队列满、停止或释放宿主时丢弃迟到的 Keep，原线程清理后退出；同次
  失败不循环重试。退出事件停止并回收工作线程，窗口隐藏至托盘时保留播放。
  线程启动不改系统电源计划，也不自动发送请求。

验证与边界

- 恢复的 M/473 效果和 M/4 原生桥用十条合成观察对照。Rust 固定相同掩码、
  精确 Playing 状态、同值合并、失败和同线程释放，并用真实原生播放 actor
  验证授权前后、缓冲、暂停、恢复、停止和解码失败。测试使用合成音频和 sink。
- Linux WebKitGTK 用生产 Vue、正式 Tauri 命令、真实 SQLite、libmpv null 和
  密封合成 Windows 电源 sink，四次启动验证 18 个状态和 18 张截图：开关
  写入时的实际播放、暂停和停止；SQLite 拒绝写入后的回读与焦点；重开后的设备
  设置；对照组隐藏但不丢弃已启用设置；无宿主时无实验读取或电源请求。
  消息和字符 locale 为 en_US.UTF-8，只有数值 locale 调整为 C。复现入口是
  scripts/ci/playback_power_smoke.py 和 playback_power_ui_probe。
- 上述检查不调用实际 Win32 电源 API、不访问真实账号或服务。Windows 原生
  调用与实体机睡眠/熄屏仍是独立实测；Linux 不提供此 Windows 功能。
- Linux 已在无外网的独立 X11 会话成功启动正式 Cumulus 程序；工作区
  Rust fmt、严格 Clippy 和锁定测试（2166 通过、17 项标记忽略）以及固定 Node
  格式、814 项前端测试和生产构建通过。Windows GNU 工作区全目标严格 Clippy
  与新增原生夹具的交叉检查通过，不能代替 Windows MSVC 打包、WebView2 实测
  或 Win32 电源请求。Windows CI 的合成 WebView2 夹具不持有真实休眠请求。
- Windows CI 41930821747 的初次 WebView2 夹具在「播放中关闭」捕捉到下一次
  开启后的 SQLite/电源记录，界面同帧为已关闭。原因是无 PNG 模式的 JS 没等异步
  Rust 快照完成。夹具现对每个阶段等待 JSON 落盘及可选 PNG 回执，断言未放宽；
  这不是实际系统电源调用失败。修正后还需由精确提交的 Windows CI 验收。
