社区实现和验证

core/src/playback/keep_awake.rs 的纯模型只接恢复的枚举及设置，不推测现有 Rust
状态对应关系。desktop/src/playback_keep_awake.rs 提供可显式创建的 Windows
专用线程宿主。创建线程不触发电源请求；线程内构造不能跨线程传送或共享的
适配器，同一线程执行、清除和析构。没有将宿主注册到 Tauri、账号、播放器、
设置、IPC 或生产启动路径。

- 提交按次等待结果，只允许一个在途操作，不把不同状态折叠或延后补发。
  仅合并紧邻、上次成功且没有失败插入的相同请求。原逻辑仍可能发出两个
  Clear RPC；专用线程合并这种等效平台状态，不将请求次数称为与官方一致。
- 失败返回调用方并使合并状态失效；没有运行中的自动重试。显式关闭、Drop
  或线程展开时，若曾成功或尝试持有防休眠要求且没有成功 Clear，就在原线程
  尝试一次清除，随后退出线程。显式关闭等待线程退出并报告错误；Drop
  尽力清理，不会再试一次失败的收尾操作。这是宿主的生命周期保护。
- 提交和退出都同步等候，因此将来应由 UI 线程外的播放观察者持有；这个宿主
  本身不映射 Buffering、账户切换、托盘/关闭或应用退出，不更改系统电源设置。

本地 Node VM 曾执行 M/473 原始效果体及 M/4 桥接函数，核对十条合成观察、
重复依赖抑制和 macOS 不调用。Rust 用例固定同样的依赖/请求及掩码，并使用
非 Send 合成适配器实测线程身份、同值合并、顺序、失败后再次显式请求、退出、
收尾失败及展开清除。测试不调用 Win32 电源 API；没有在物理机验证休眠，
未接 Windows 设置、引导、实验刷新或 Linux 休眠抑制。正式接线前仍需验证
原始播放模型信号映射、设置读写及真实休眠回归。没有账号读写或服务请求。
