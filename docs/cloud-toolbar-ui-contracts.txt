交互契约
- 正常已上传页面提供播放、上传、更多，搜索与刷新靠右；删除/下载所选仅在有
  选择时出现，属于社区附加项，不将其宣称为官方普通表格的完整多选形态。
- 更多始终按官方三项顺序；当前搜索无结果时添加/下载禁用，仍可进入完整库批量。
  完整库为空时更多禁用。加载/已有写入/相关弹窗打开时禁用不适用操作。
- “添加全部”使用当前搜索/排序的全部结果；即使正在第2页，也从完整结果开头
  插入当前歌曲之后。保留原来的其他队列项、当前entry/playId、暂停位置，不把
  “添加全部”误当作替换队列或追加至队尾。空队列使用现有核心的启动行为。
- “下载全部”先读取完整结果，再打开显示实际数量的云盘原文件下载表单；取消
  不请求下载授权。只在用户提交下载表单后配置目录并启动真正的DownloadService。
- “批量操作”保持现有完整自然序全库页面；与普通页搜索/分页独立，返回后保持
  query/page/scroll和更多触发按钮焦点。空库在批量页内刷新可以显示空内容；普通
  空库没有可用更多入口。菜单退出、页面/弹窗过渡和减少动态效果沿用共享组件。
- 完整读取进度、失败、上限、快照变化在本页反馈，不显示成音频加载错误。失败
  只能显式重新执行；快照变化先刷新列表，不自动重复队列或下载动作。
- 操作期间将焦点暂放到稳定的工具栏容器；完成、错误关闭或刷新后返回更多按钮。
  用户已经移到搜索、播放器等有效控件时不抢焦点；换账号不返回旧账号入口。
- 待读取期间上传入口禁用；若其他模态弹窗已打开，迟到结果不再打开下载弹窗。
  查询、分页、账号、快照变化或组件卸载取消尚未提交的读取，迟到结果丢弃。
- 添加操作在读列表前捕获播放意图、队列版本、账号/连接、playId/entryId/状态/FM。
  读期间的前端切歌/暂停等意图、新队列、来源或账号变化会拒绝这次添加，供用户
  明确重新执行。不是先读完才拿一个新的队列版本，把旧请求附加到新播放状态。
  已提交原生队列命令继续由核心意图/版本/账号围栏判断；不能把界面关闭理解为
  撤销已经完成的本地队列修改。
- 实测播放/暂停按钮在等待回执时会失去焦点。PlayerBar的四个传输按钮现在先将
  焦点留在播放控制组，结束后回原按钮；用户移开、账号变化或按钮失效时不抢回。

分层与接口
- CloudToolbarMenu负责菜单和焦点；useCloudToolbar负责读取/状态/失效；
  cloudCollection.readCloudCollection按捕获query从offset=0逐批200读完整列表。
  原readCloudBatch改为调用同一完整性读取器，显式传空搜索/自然序，维持其语义。
- 每批核对epoch、初始显示revision、offset、整数total、重复ID、空中间页、
  超出total和跨页revision/total变化；任一失败都不发布部分结果供“全部”操作。
  添加单次上限10000、下载单次5000，超限明确提示缩小搜索，不悄悄只取前N项。
  原生队列整体容量10000及保留当前项规则仍适用，见既有队列契约。
- 只调用类型化CoreClient.cloudPage、PlayerModel.prepareCloudQueue/queueCloud及
  现有download事件。前端不直接发官方HTTP，不持有Cookie/签名或授权音源URL。
- cloud_page(epoch,query,refresh) -> CloudLibrary：首批refresh读取官方
  POST /api/v1/cloud/get，随后从同一revision缓存投射分页，UI不会重复远程翻页。
- player_action(epoch,{kind:queue_cloud_batch,ids,revision,query,quality,
  expected_queue_revision}) -> 重新核对云盘完整快照/归属/排序 -> 本地持久化队列。
  普通歌曲和云盘ID使用独立域，不用普通song/detail替换私有云盘资源。
- 下载表单 Configure -> StartCloud{song_ids,revision,lyrics} -> 每首
  POST /api/cloud/dowonload {songId} -> 既有下载授权、调度、完整性、发布与记录。
  保留接口官方拼写；拒绝/过期/文件失败恢复沿用core-cloud-download-contracts.txt。
