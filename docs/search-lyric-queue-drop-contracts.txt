歌词搜索：拖入当前播放队列
==========================

来源：网易云音乐桌面端 3.1.42.205594。M3095 把歌词搜索交给 M352；
M352:1089、1136–1174 在 page_pc_search_lyric_song 场景使用 M225
普通曲目表和歌词补充区。M225:350–353、363–383 为整个普通曲目行接入
拖动，:563–601 将按住的行与 M106 的有序 selectedData 分开。重复歌词
命中仍是一首歌曲；选区中的该歌曲取第一条命中，实际按住的命中仍用于验证
拖动来源。没有多选时使用实际按住的行。M57:151–157、186–207、292–305
登记本次拖动并将场景归并到搜索。

CurPlayingListTrackViewer.tsx:58–83 和 PlaylistContent.tsx:133–145、
231–251 仅在已有队列的可用面板接受普通曲目，目标是标记指向的行间空隙。
M3085:2508–2533 调用 splice，来源是搜索，clear=false、play=false，
offset=可见空隙序号-1。M308:3150–3152 把 -1 落点解释为当前条目之后；
没有当前条目时使用队首。M308:3167–3248 调用 M59.j，
M59:131–171 保留顺序并跳过确知不可播的歌曲；按住的是不可播歌曲时，

普通歌曲没有额外的曲目详情或授权读取。splice 不携带歌词菜单的
trialMode=42，真正轮播到新条目时才走通常的原生音源授权。

实现：core/src/client/search/lyric_group/queue_drop.rs 在已经核实的
同一歌词搜索访问内为每条普通歌曲命中签发独立 lyricQueueDrop 回执。
该回执不能用作播放、评论、收藏、下载，也不接收曲目显示数据。
前端复用现有队列空隙标记，将当前账号、选区、按住的命中及队列代次固定到
本次手势；离开搜索、切换分类、队列或账号改变、拖动取消时不发送写入。
现有 PlayerAction 的 drop_search_lyrics_into_queue 接收 anchor、rows、
quality、expected_queue_revision、expected_play_id、before_entry_id，
仅主窗口可调用。core/src/client/player/queue_drop.rs 验证同一查询访问、
凭据、按住的行与选区、播放实例、顺序和落点；原生 actor 安装前再校验
授权。队列只插入有效歌曲，不清空、不起播、不改暂停位置；原队列已有同曲
ID 时保持正在播放的条目身份。全部不可用、回执过期或权利未知时无修改。

边界：此路径使用确认属于普通在线歌曲的结果；不推测专有同录音替代、
离线目录与云盘权限、仅试听的来源，亦不将一起听或其他设备的队列作为落点。
本地 UI 和 Rust 实验使用合成账号与音频；实体声卡和正式账号的特殊权限
需各自验证。

验收：Linux WebKitGTK、Xvfb XTest 的真实可信指针和 libmpv 空输出。
