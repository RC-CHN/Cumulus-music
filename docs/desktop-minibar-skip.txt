底栏手动上一首／下一首的版权预判
================================

官方 PC 3.1.42.205594：M83:152–177 与 M395:208–234 将主底栏方向交给
miniBar/call；M308:3841–4056 先核对原相邻歌曲的播放权限，再在
PH-PC-skipSongs2=t1 时进入 M59.j。M1384:5556–5634 和 M176:21–39
决定原队列的方向与错误步进。原始运行对照见 playback-search-priority.txt。

主窗底栏在普通已加载歌曲上提交 step_mini_bar：方向、播放 ID、队列版本。
原生用例先检查当前条目，再核对 focus/transport intent。Vue 不传联网、
分组、版权、目标歌曲或替代 URL。独立迷你窗口、系统媒体键、自然 EOF、
加载中的方向操作、FM 和一起听仍走各自原有路径。

可用的预判依据来自同一原生宿主的当前会话：
- 只使用全量签名 PC 生命周期已有的 fresh 分组，严格 t1 且黑名单实验未启用。
  过期或缺少原生分配不在按键时新发 AB 请求，也不使用持久展示分组。
- 复用 M119/M236 当前浏览器文档的联网 reducer，且要求当前账号已有一次
  成功的固定 POST /api/pl/count 回读、最近一轮未失败。只读 navigator
  初值、非认证账号、已卸载的文档或仅有计数轮询均不激活预判。浏览器当前
  样本和有效联网值都必须在线；这比完整官方信号链更保守。
- 初次相邻曲目必须满足已证实的普通负版权状态，无已发布下载。队列中启用
  M21.D 的替代 MV（type 3、mvInfo、expInfo.mvPlay=true）不进入音频预判。
  原有 M59 的纯本地／同录音／混合队列边界继续保留。若 M59 需要读取同录音
  候选，调用既有 POST /api/v3/song/detail，使用 c 与 trialMode:-1。

等待期间核对原生联网观察与文档代次、签名凭据版本、fresh 分组、会话、
房间、队列和当前控制意图；过时队列不向新队列重复执行。唯一确证的在线
候选仍走普通播放器申请 /api/song/enhance/player/url/v1 并加载；没有候选
时原生暂停；其他不能确定的条件保留普通方向操作。403、网络错误、媒体
URL 或解码失败不会被解释成跳歌依据。原生 SDK 错误编号和正式 EOF 跳过
本批没有启用。完整的 Windows 原生连接通知及真实账号 t1 不由本入口证明。

Rust 合成入口测试使用真实签名 EAPI 适配器和封闭传输，比较 t1+在线、
未挂浏览器、离线和控制组，核对精确授权目标及旧播放回执拒绝。
底栏类型化操作与已加载／加载中分支由前端状态测试覆盖。
