底栏手动上一首／下一首的版权预判
================================

官方 PC 3.1.42.205594：M83:152–177 与 M395:208–234 将主底栏方向交给
miniBar/call；M308:3841–4056 先核对原相邻歌曲的播放权限，再在
PH-PC-skipSongs2=t1 时进入 M59.j。M1384:5556–5634 和 M176:21–39
决定原队列的方向与错误步进。原始运行对照见 playback-search-priority.txt。

主窗底栏在普通已加载歌曲上提交 step_mini_bar：方向、播放 ID、队列版本。
原生用例先检查当前条目，再核对 focus/transport intent。Vue 不传联网、
分组、版权、目标歌曲或替代 URL。独立迷你窗口、系统媒体键、自然 EOF、
加载中的方向操作、FM 和一起听仍走各自原有路径。

可用的预判依据来自同一原生宿主的当前会话：
- 只使用全量签名 PC 生命周期已有的 fresh 分组，且黑名单实验未启用。
  已确认相邻歌曲无权时，t1 扫描；其他分组保留原曲，不调用播放器选择。
  过期或缺少原生分配不在按键时新发 AB 请求，也不使用持久展示分组。
- 复用 M119/M236 当前浏览器文档的联网 reducer，且要求当前账号已有一次
  成功的固定 POST /api/pl/count 回读、最近一轮未失败。只读 navigator
  初值、非认证账号、已卸载的文档或仅有计数轮询均不激活预判。浏览器当前
  样本和有效联网值都必须在线；这比完整官方信号链更保守。
- 初次相邻曲目必须满足已证实的普通负版权状态，无已发布下载。队列中启用
  M21.D 的替代 MV（type 3、mvInfo、expInfo.mvPlay=true）不进入音频预判。
  原有 M59 的纯本地／同录音／混合队列边界继续保留。若 M59 需要读取同录音
  候选，调用既有 POST /api/v3/song/detail，使用 c 与 trialMode:-1。

等待期间核对原生联网观察与文档代次、签名凭据版本、fresh 分组、会话、
房间、队列和当前控制意图；过时队列不向新队列重复执行。唯一确证的在线
候选仍走普通播放器申请 /api/song/enhance/player/url/v1 并加载；没有候选
时原生暂停；未进入分支或没有可用决定时保留普通方向操作。已经开始的
预判若遇 403 或网络错误则返回错误，保留当前播放，不补发另一条方向操作。
媒体 URL 或解码失败不会被解释成跳歌依据。原生 SDK 错误编号和正式 EOF 跳过
本批没有启用。完整的 Windows 原生连接通知及真实账号 t1 不由本入口证明。

Rust 合成入口测试使用真实签名 EAPI 适配器和封闭传输，比较 t1+在线、
未挂浏览器、离线和控制组，核对精确授权目标及旧播放回执拒绝。
底栏类型化操作与已加载／加载中分支由前端状态测试覆盖。

模式对照组的版权拒绝返回后清除旧 playId；同一模型的底栏 miniBar/call

并在主窗口提交 step_ended_mini_bar。请求携带回执、已显示的当前队列条目、
队列版本及方向；不传分组、原生条目号、目标歌曲或 URL。当前状态必须仍是
Ended、playId 为空、同一原生条目仍由控制器保留且为原普通完整在线歌曲；

未换原条目的队列编辑或模式切换可重新显示回执与新的队列版本，旧组合仍无效。
手动方向按新模式的顺序，不套用单曲循环的自然重播。普通 Idle、已有 playId 的
Ended、播放中和加载中没有改用此入口。

现行签名分组、联网和账号权限重新判定。对照组保留同一结束条目/空 playId，

观测时本回执不执行。尚未确认相邻歌曲纯版权拒绝时，仅可用原有带护栏的方向
操作（实际音源另行授权）；已经确认拒绝但不能确认替代候选时仍停在原完成曲目。
原版空候选 dispatch Pause；本边界已有真实 EOF，无仍在播放的 native decoder
可暂停，保留 Ended 及完成进度。未接替代源、特殊音源或原生错误推断。

自然结束后续接已完成的同曲下载
================================

官方 M308 的 onPlayEnd（playing.txt:3929–3977）把真正的自然结束与手动
步进、播放器错误分开。M59.j（59.js:125–154）依队列原序枚举，先按同曲
trackMap 查离线登记，再判本机下载能否播放；M308 的 checkPlayPrivilege
（playing.txt:4764–4778）对 trackMap 的完成状态、路径和 offlineId 再检查。
官方在已读到的离线资源不能播放时仍可能判断在线权利。

Cumulus 的本段只处理经现有签名实验验证的 t1、可信浏览器在线、顺序模式、
成功原生 EOF、相邻线上歌曲已独立预取并明确纯版权拒绝的普通目录歌曲队列。
沿原队列顺序只越过已证实的拒绝；第一个可接续的候选若为同账号唯一完成、
有已发布登记和已验证字节的未加密 FLAC，则选择它原有的队列条目。
不凭路径、同名、另一账号的记录或只有任务没有已发布登记来认定可播。
不改原曲元数据、条目 ID、队列顺序和播放模式，也不为这首本机候选调用
/api/song/enhance/player/url/v1 或读替代同录音。

preflight/download.rs 保存本轮确证的任务／登记身份；source/catalog_download.rs
复验文件和摘要并握住实际文件，controller/eof.rs 核对原生解码器能力及
账号、结束条目、控制意图和队列凭据；queue/persistence.rs 在同一事务内再核对
该任务及登记仍唯一、被跳过的条目没有新完成下载后更新 current。
controller/load.rs 只用受检的固定文件句柄交给 libmpv 的只读流接口。
下载替换、移动中、增加第二个同曲任务、旧回执、损坏、能力缺失等在选择前
被拒绝时保留上一首的 Ended 和结束进度，不发跳歌提示或补发在线授权。
选择后出现真正的文件或解码器错误则沿用本机错误呈现，不转在线请求。

原始证据支持的范围大于本段。当前仍不把这条严格本机接续套到随机、列表循环、
单曲循环、普通无拒绝的推进、混合资源、NCM、CUE 或其它下载格式；不改既有
线上、手动步进、同录音和播放错误规则。本机接续选择只作用于本次播放，未把
固定文件句柄或本轮权限决定写入持久目录条目。验证文件使用真实原生解码器和
合成授权，具体截图、实际音频输出方式及平台结果另记。

Linux 实窗使用同一 Tauri/WebKitGTK 构建，通过原有六组及新增两组、共 20 张截图。
合成在线首曲由实际 libmpv 播到 00:08 并产生成功 EOF；被拒绝相邻曲已有独立的
403 预取。有效分支只从原同账号完成任务拿固定句柄，libmpv 报 FLAC／null，时钟

原 playId、08 秒和原生解码器，无跳歌提示。两组均不请求候选 3 的在线音源，
核对下载任务与离线登记、全队列条目内容及顺序。报告与截图：

Windows 的同用例随 CI 验证，当前仅有 Linux 实窗证据。
