业务调用及状态
- 播放继续使用完整筛选 downloads PlaySelection，从对应任务开始，不能只播放
  当前渲染节点。下一首走 playerAction(queue_downloads, task_ids=[任务ID],
  expected_queue_revision)，保留离线任务身份、当前 entryId/playId 和暂停状态；
  不通过在线 songId 请求流地址。原生空队列行为与边界沿用下载批量队列实现。
- 评论走既有 trackComments：有 voiceId 用 voice，否则 track。收藏打开既有
  PlaylistCollectDialog，分享打开既有公开链接分享窗口；不会直接发布内容。
  复制使用既有 copyText IPC；失败保留重试入口，等待期间保留按钮并阻止重复请求。
- 已完成且有原生目录 ID 的歌曲打开行菜单时，主窗调用
  `download_comment_count(epoch, taskId)`。
  Rust 从本账号原生下载任务得到歌曲 ID，并在响应后重新确认任务仍在、仍是该已下载歌曲；
  WebView 不传歌曲 ID、资源类型、请求地址或凭据。请求不缓存，回包 threadId 必须匹配。
  桌面宿主通过现有系统路由读取判定：只有明确缺少 IPv4/IPv6 默认路由时才略过
  可选计数，Rust 仍核对同账号、完成状态和目录 ID。路由信息未知时继续原请求。
  这项社区适配仅影响打开菜单的预取；系统代理或分流 VPN 下即使没有默认路由，
  用户主动打开评论仍走原逻辑。官方 M556 在线先读计数、错误后显示无数字，本实现
  保留该在线顺序。无路由播放/删除验收无需改变业务请求计数断言。
  评论数网络读取最多等 1.5 秒；零、超时、服务或回包错误在原生身份仍有效时显示无数字的入口。
  任务被移除、换账号或 IPC 未确认当前身份时不显示旧菜单。待回包时任何新鼠标/键盘动作、
  离开焦点、滚动或改变窗口都会取消这次显示，不从下一条回包补开菜单。
- 普通已下载歌曲使用任务歌曲 ID；云盘原文件只用保存时从服务端 simpleSong 得到的
  `_cloud_public_id`，与同时存在的目录 ID 一致才投影 `commentTrackId`。没有目录证据的
  私有或旧任务不显示评论，也不能请求数量。数量与点击后的歌曲评论共用该原生目标，
  不把云盘文件 ID、名称或音频 ID 当目录 ID。声音的既有评论仍用节目 ID；
  播放、授权、歌词和文件操作继续用各自的原资源身份。
- 已完成声音的节目 ID 只从原生下载类型投影。M27:114–116,130–155 与
  M754:699–718 生成 voice-节目ID 的 offlineId；M622:1223–1265 以去前缀的

  A_DJ_1_{节目ID}；返回同号歌曲或其他线程、零计数、错误或超时时显示无数字入口，
  用户点击仍进入对应节目评论。同账号、完成状态、迟到响应和离线规则与歌曲一致。
- 公开链接与分享（2026-11-08）：M556:401–457、725–761 给两个动作传下载
  `origin`；M35.j 隐藏负版权状态，M556.k 隐藏多选动作。M3085:1578–1603

  行入口，但社区版无法证实其私有 ID 可公开，不沿用这项行为。

  `/api/song/enhance/privilege {ids:JSON.stringify([id])}`，省略 `trialMode`。

  文件，也不请求播放权益。平台 worker 在交给 Windows Explorer 或 Linux

  完成依靠原生日志/后台 worker，不用前端改路径模拟。冲突保留原文件并显示错误。
- 文件窗口从最新可用视图解析同一个任务；缺失、状态改变、路径改变、已在整理、

- 用键盘打开菜单时先聚焦该下载行，让仅在行有焦点时显示的“更多”按钮可用；

- 控制或文件写入等待时确认按钮和关闭按钮禁用，重复点击不会再提交。失败/取消
