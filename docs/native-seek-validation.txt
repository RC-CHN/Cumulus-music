原生暂停 seek 的验证语义

40499502432 的 Linux 打包验证在暂停后 seek(1.5) 时，time-pos 稳定回读约 1.32，5 秒后仍未达到目标。
独立调用 libmpv 复现了此行为，未使用本项目播放器控制器或真实账号：
- Ubuntu 24.04 / mpv 0.37：在 seek 指令后固定等待 200ms，回读 1.310457，seeking=no、pause=yes，已收到 seek 和 playback-restart。
- 本机 mpv API 2.5：同样回读 1.309937。
- 恢复播放 100ms 后分别回读 1.600010 / 1.600172，实际 seek 目标正确。

null 输出模拟音频输出缓冲（默认 0.2 秒）。暂停时 time-pos/audio-pts 可以包含尚未恢复输出的缓冲延迟；刚确认指令的瞬间也可能先返回请求目标。
此前立即轮询目标位置，既可能偶发失败，也可能依靠瞬时值提前通过。单纯等待更久、放宽阈值或重复运行都不能验证实际 seek。

探针现在在暂停 seek 后刻意等待 150ms，确认暂停仍然有效，再恢复播放，将播放位置减去恢复后的实测 elapsed time，与 1.5 秒目标比较。精度仍为 30ms。
报告明确标记 paused_seek_verified_on_resume；不宣称 null 后端暂停期间的裸 time-pos 精确等于请求值。生产播放器逻辑未因测试而改变。
本机和 Ubuntu 24.04 各 8 次实际 Rust 解码/控制验证通过；中文 GTK/WebView 启动后的真实 PipeWire 静音流程也通过。

暂停后向后定位与慢音源

官方 M/308:1474–1525 以当前 playId 与单次 seekId 提交定位，并另外标记等待。
libmpv 0.40 的 seek 命令先排队，seeking 反映播放重启状态；命令返回并不表示
解码已经移到新位置。参见 mpv 0.40 的 player/command.c:1340–1347、5163–5174
及 player/playloop.c:421–445。
https://github.com/mpv-player/mpv/blob/v0.40.0/player/command.c
https://github.com/mpv-player/mpv/blob/v0.40.0/player/playloop.c

原生时钟采样在读取 time-pos 前后核对 seeking。等待或状态不可读时，不把同条目的
旧时钟用于播放进度、暂停/继续回读或恢复位置。已确认的显式暂停定位保留请求值直到
继续播放或替换当前解码；如果 seek 尚在原生队列内、还没观察到 seeking，这也不会把
向后定位盖回原位置。显式继续的即时回执与保存位置也保留该定位值。正常暂停仍接受
既有的原生时钟更新；一起听的新控制以其已校验的位置与暂停意图更新本地锚点。继续后
恢复采纳同一解码条目的时钟；仅当原生仍报告 seeking 时抑制继续后的周期采样。
原生失败仍可见，拒绝的定位不覆盖前一次，切歌不继承旧等待。
不增加音源请求、不自动重试或切歌。

控制器合成回归在暂停 60 秒后定位到 10 秒，并注入同条目仍报告 60 秒：修复前
实际断言失败，暂停/读回返回旧值。还覆盖原生队列尚未开始和已经等待两种状态、
重复暂停、继续、被拒绝的定位、新定位、终止错误及切换到下一首。

独立 Linux 原生试验使用私有网络/挂载命名空间、本地 TLS、120 秒合成 AAC 和
libmpv 空输出。初始读取、向前 70 秒及向后 24 秒分别收到 0、1145240、407409
字节起点的 HTTP 范围请求。服务器暂扣第三条响应数据，原生保持同一条目且
seeking=true；放行后暂停回读约 23.81 秒（空输出缓冲），继续后实际回读超过
24.1 秒。此原生试验中的等待样本是新目标 24 秒，旧 60 秒反例由控制器夹具
单独证明；不把无 GUI 的原生试验当作 WebView、物理设备或实服通过。

原生定位等待的界面提示

官方 PlayProgress.tsx:776–803（SHA256
fc8d2e0dc531c50fbe6d3ffdd407f80ef18eb0119687f2ad52490cddb81a5f0f）订阅
isSeekOrLoadingState$，同一次等待超过三秒后提示。社区版原先只在定位 IPC 未回执或
播放状态是准备、加载、缓冲时计时；定位命令已返回但解码器继续定位时，滑块会停在
目标位置而没有等待提示。

Rust 现在将当前解码条目的既有 seeking 观测作为 nativeSeeking 投影。上一条目或没有
匹配条目的样本不能开启或清除提示；当前条目确认完成才清除，停止、失败、结束和替换
解码也不继承。等待不切换播放或暂停意图，不修改时钟、队列、权限范围和自动重试策略。
主播放条继续使用三秒计时，快速定位不闪烁，减少动态效果时使用既有静态提示。

`playback_controller` 覆盖暂停定位保持暂停及目标时钟、旧条目正反信号、切歌清除。
`player_layout_smoke.py` 在真实 WebView 以生产 IPC 调用实际 libmpv 定位，测试适配器
只延长当前条目的 seeking 标记。回执结束后仍显示延迟提示，解除后同一播放实例
继续推进。这是可控慢定位界面验证，不将夹具标记当作真实 CDN 延迟。
