当前交互
- 歌单/专辑/歌手/播客卡片：详情与播放是独立按钮，悬停、键盘焦点或当前资源显示
  播放键。只有正在播放/缓冲的当前资源显示暂停，暂停后恢复播放图标；普通卡片
  通过右键或Shift+F10打开菜单，不额外放常驻更多按钮。
- 声音卡片：封面播放键和整行双击播放选中声音；所属播客文字单独跳转详情；
  行末更多含播放、所属播客、评论和下载。双击按钮/链接不触发行双击播放。
- 菜单按窗口边界定位；Escape返回发起操作的按钮，支持方向键/Home/End。
  从播放键用Shift+F10打开后，关闭返回播放键；不是一律跳到详情入口。
- 卡片读取准备/失败/重试沿用播放条反馈，不先跳页。菜单中的评论跳转已有评论页，
  声音下载打开已有下载选项窗口；本轮探针只检查下载窗口打开/取消，不执行真实下载。
- 封面解码失败替换占位图，来源变更后允许新图片加载；播放遮罩不叠着显示占位图标。
  长标题使用应用内提示框；标题不遮挡独立播放键。图片错误测试注入本地数据URI，
  验证实际img加载/error回调，不是CDN网络可靠性验证。
- 主题/尺寸沿用搜索网格；transition以opacity/transform为主并遵守减少动态效果。
  当前播放来源以标量身份缓存，播放器计时更新不改变卡片props引用。

仅为支撑界面的调用映射
SearchResultCard → SearchResultsPage → App → usePlayer.prepareSelection：
  歌单使用已有playlist选择；专辑/歌手重读catalogPage取得revision和首个可用曲目；
  综合播客卡片和播客分类表使用不同的原生搜索播单收据；单个声音则由专用声音 ID 入口读取。
  读取失败显示可重试反馈；新操作或账号代次变化后的迟到读取不能启动播放。
Rust PlayerView.origin仅投影已知playlist/album/artist/podcast的公开资源ID；不向前端
  暴露队列来源的其他字段、Cookie或完整授权URL。当前项精确匹配来源或voiceId。
评论和下载沿用现有类型化入口，没有在前端增加业务网络请求。

搜索声音只播放所选单集
官方 M/3095:1201–1218、1230–1257 对声音卡片使用 voice 和 assignedPlayId，
不传播单列表或 needFetchAudio。综合页 PC recommend.jsx:537–556 将 Scene.search
传给 VoiceCard；其 index.jsx:200–218、290–298 默认不请求附近声音。M/3085:399–411
在没有 needFetchAudio 时只处理本单集，显式播放的普通队列不清空。
Cumulus 无论是否有所属播单，只用声音 ID 解析该单集的原生节目详情和授权，
不为播放单集读取播单，不替换成邻近节目；明确点击播客卡片播放仍选择播单。
新单集放在当前项之后；已有单集按节目 ID 复用，不与同音源 ID 的普通歌曲混淆。
搜索双击也沿用社区的普通保留队列策略；编译分类行的双击数据没有明示 Scene.search，
未断言官方在所有双击偏好和特殊播放模式下的行为相同。旧账号和不可用节目仍拒绝。
search_results_smoke.py --voice-direct 可验证无所属播单的单集播放及暂停。
search_results_smoke.py --voice-queue 用有父播客的单集复验：与同音源 ID 的普通
歌曲分别保留，单集插入后保留原队列顺序和条目 ID，暂停不重建播放项或再读单集。
单集分支只读取所选节目，不调用 /api/v6/dj/program/byradio；显式播放播客卡片
仍读取该接口并载入节目列表。搜索高亮和暂停只匹配 voice 类型，已下载版本不
被当成在线单集。该用例使用合成数据及原生音频输出测试路径，纳入两平台 CI。

搜索声音首载期间的暂停和继续（官方 3.1.42.205594）
综合搜索的普通声音块 M/3095:1998–2035 使用 VoiceCard，最佳匹配使用
VoiceMetaCard；`VoiceCard/index.jsx:288–301`、`VoiceMetaCard/index.tsx:248–279`
将所选 voice 和 assignedPlayId 交给 TrianglePlayButton。按钮按当前 resourceType
与 resourceId 匹配；当前非暂停发 Pause，当前暂停发 Resume，其余发 Play
（`XPlayButton/TrianglePlayButton.tsx:86–161,188–205`）。声音分类
M/3095:3305–3359 → M/2061:259–298 → M/2042:25–56，按声音 ID 读取当前项及
播放状态（M/157:35–87），序号按钮在搜索上下文同样分派 Pause/Resume/Play
（M/539:38–118）。M/308:1769–1852 先发布当前声音、首载和 Playing，再检查
voice 权限并分派 nativePlay；M/308:988–1029 的 Pause 更新状态并传原 playId
或该资源的回退 ID 给 AudioPlayer；M/308:870–984 的 Resume 先走当前项的播放权限
守卫，再按已存在的 playId 继续，或在 Stop/End 等条件下回到既有 nativePlay/跳曲分支。

社区只在原生已发布可控制的同一声音（Preparing/Loading、具体 playId 和队列版本）时
显示待处理的播放/暂停意图；尚未发布原生选择时不猜测临时 ID。分类行和综合卡的
按钮发送既有 `pause_for {play_id, expected_queue_revision, paused}`，不二次选歌。
原生首次解码沿用最新意图；若命令到达前切换账号、选择、队列版本或离开面板，拒绝
过期目标，不回退到新建选择。仅在原按钮仍属于该页面且用户未移开焦点时恢复焦点。
普通歌曲、其他声音、下载声音、播客集合及一起听等不会匹配该控制；行双击和菜单
保持原有策略。首次选择仍由 Rust 查询 `/api/dj/program/detail {id}`，以
`/api/dj/play/url/check {voiceId}` 校验主音频，之后才请求
`/api/song/enhance/player/url/v1`；本轮不改变授权失败、重试、试听或恢复策略。

`search_results_smoke.py --voice-direct` 在真实 WebView 拦住一次合成声音 401 的原生

epoch、playId、entryId 和队列版本保持不变。三个动作只有 `pause_for`，一次选择和
一次解码；其后显式继续才推进原生时钟。合成声音和同 ID 的底层歌曲仍分离，未调用
真实音乐服务、未写账号数据；原生使用 null 输出，不代表真机声卡听感。
Linux 隔离复验的 8 态、基线失败（解码挂起时声音行不可暂停）及既有声音队列的
8 态回归保存在 `.build/ui-proof/search-voice-pending-5d2fcda/`。
