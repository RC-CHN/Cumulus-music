接口与内存边界
- AudioEngine::output_devices -> Option<OutputDevices>；None 为引擎不支持，
  也用于明确配置 null 输出的验证引擎。普通 MpvEngine 返回真实枚举结果。
- devices[].id 是原生不透明字符串，description 为显示文本。保留大小写，
  不把 Windows WASAPI ID 换算成 Linux ID，不解析或拼造驱动参数。
- configured 是请求配置；active_driver 是当前后端，未初始化音频时为空。
  二者都不是实际物理设备身份证明。测试已复现设备拔除后 configured 保留旧值。
- set_output_device 在每次变更前重新枚举，只接纳本次列表里的完整 ID；
  拒绝空值、NUL、超过4096字节、列表外或已拔出的设备。不修改 ao、播放状态、
  当前文件或播放位置。成功返回仅表示配置命令得到确认，随后仍可能初始化失败。
- null_output 引擎不枚举硬件并拒绝所有选择，包含 auto；不能借设置接口脱离
  静音测试隔离。音频焦点包装和 MpvVideoEngine 转发相同能力，但不会获得播放权。
- mpv_command_async("expand-text", "${=audio-device-list}") 独立序号匹配，
  5 秒等待上限；迟到回复不满足新请求。读取时保留播放事件供原播放器消费。
  命令及原始属性展开参数固定，没有设备或用户输入插值。结果是属性 JSON，
  不解析人类可读/本地化 OSD 文本。匹配序号的 COMMAND_REPLY 才解释为设备列表；
  不匹配回复按普通命令处理，失败回复不解引用数据，匹配回复消费后清除查询。
  配置命令复用原有异步5秒等待；设备可能在枚举后消失，调用方仍须处理失败。
- 设备数据的不安全内存读取位于 engine/ffi/devices.rs；检查 command result 的
  STRING 标记和非空指针，借用事件字符串并完整解析到 Rust 所有权后才允许
  下一次 wait。事件结果由 mpv 管理，不调用 mpv_free/mpv_free_node_contents。
  JSON 最多32MiB、1024设备、ID最多4096字节、描述最多16KiB；重复ID/重复必填
  字段/缺失/错误类型/UTF-8/NUL均失败。未知JSON字段兼容忽略，递归采用serde_json
  默认上限；替代旧节点解析器的每设备64字段限制。错误不包含设备名或原始JSON。
  这些约束检查可信 native ABI 的数据形状，不能防护恶意原生库提供的任意指针。
- 原生调用只在阻塞工作线程执行。现有同步属性字符串读取没有新增硬取消保证；
  不把异步枚举的5秒上限描述为整个 libmpv/系统驱动不可卡住的保证。

可执行验证
1. cargo test -p cumulus-core --lib playback::engine::ffi::devices --locked
   冻结64位ABI布局、事件生命周期之后仍有效的复制、中文描述、空数组、空指针/
   标签/计数/必填字段/重复名/ID长度，以及迟到/普通/失败回复隔离共6项。
2. 原有 engine_roundtrip 与桌面 native_audio_probe 增加实际原生设备枚举，
   未加载音频的枚举器检查 auto 与无活动后端，并拒绝非法选择；显式 null 引擎
   拒绝选择，之后照常完成PCM解码、播放/暂停/定位、CUE EOF/复位/取消。
   两平台既有CI会执行这些探针；不能用Linux通过替代精确提交Windows结果。
3. Linux两虚拟设备完整路由测试：
   cargo build -p cumulus-desktop --example native_audio_probe --features custom-protocol --locked
   LC_ALL=en_US.UTF-8 GDK_BACKEND=x11 WEBKIT_DISABLE_DMABUF_RENDERER=1 LIBGL_ALWAYS_SOFTWARE=1 \
     dbus-run-session -- xvfb-run -a python3 scripts/ci/output_devices_smoke.py \
     --desktop --binary .build/target/debug/examples/native_audio_probe --root .build/output-proof-NEW
   依赖 PipeWire/pipewire-pulse/pactl/WirePlumber 的 policy-only profile。
   使用临时 runtime socket、隔离的 XDG 目录和仅策略会话管理器，不启用硬件监视器；
   建立两个 null sink。测试探针只允许加载到指定的隔离 Pulse 设备，生成60秒静音PCM。
   由独立 pactl 查询实际 sink-input 路由，不用播放器 configured 字段自证切换。
   检查 a→b→a→b→a、播放中切换、暂停切换及实际cork/静止时钟、旧ID拒绝、
   拔除/重接枚举、活动设备消失后的显式恢复、保持同一播放条目与恢复时钟。
   进程退出时回收自己启动的服务；不会终止用户原有音频服务。
   --desktop 使用正式GUI初始化并核对只将 LC_NUMERIC 改成C；非桌面模式可使用
   core/examples/output_device_roundtrip，不能冒称它覆盖了GTK初始化。
