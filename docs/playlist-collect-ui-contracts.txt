实现与操作
- PlaylistCollectDialog.vue独立承担收藏流程，PlaylistCollectList.vue承担64px虚拟行。
  普通歌曲菜单、综合搜索和分类收藏入口使用同一弹窗；移除旧“下拉选择+确认”步骤。
- 重新读取账号歌单，保留已有列表直到更新；加载/读取失败/重试/空列表可见。
  迟到响应只在当前弹窗和相同账号代次应用；会话失效交给已有账号恢复流程。
- 上下/Home/End定位目标；长列表使用有界渲染；被滚出视口的焦点交给列表容器。
  关闭后回原入口；创建页返回保留草稿，列表位置独立保存。重复点击不会重复写入。
- 创建/列表过渡用opacity/transform，并遵守减少动态效果。短窗口保持标题/关闭可达、
  内容内滚动；主题使用共用语义色。长名称截断，完整名称保留在可访问名称中。
- 创建成功不跳离来源页面，继续收藏；若第二步失败保留新歌单ID，按钮变为“继续收藏”，
  不重新创建。输入/私密选项锁定到已经创建的资源，提交按钮在等待/失败时保留焦点。
- 核心已记录写入但回读失败时，从刷新后的操作记录识别“本次新记录”，显示核对入口。
  不将旧的同名创建记录误认为本次创建；未知写入期间禁止再提交，核对只读。
- 收藏仍使用现有Rust playlistEditor → mutatePlaylist(add) → 确认/对账状态机。
  本轮核心业务模块未改；新增的Rust文件仅是隔离WebView验证的合成服务。

明确未一致/未验证
- 当前仅列出普通自建歌单；核心编辑器禁止favorite歌单直接写入，因此“我喜欢的音乐”
  目标仍需单独对照官方收藏/喜欢的批量交互，不能让一个看似可点击的目标必然失败。
- 下载的付费缓存提示、购买单曲入口和其他资源收藏类型不是本轮已验收范围。
- 完整长名称悬停提示、封面加载失败与真实位图、独立创建歌单窗口的所有官方样式，
  仍需后续专项。只对齐了本弹窗的默认列表/创建衔接，不能称全部歌单UI已一致。
- 本轮合成账号、隔离Linux WebView，不代表真实账号新建/收藏验证、物理桌面刷新率、
  Windows视觉或DPI检查。没有同状态官方运行截图，不声称官方像素一致。

默认排序与常用优先
- 官方 hybrid_104.chunk.1482700000000.js/3132.js:102–145 使用
  /api/user/playlist/v2 {uid, offset, limit, sortType}；M/66 定义 default、recently。
  收藏入口每页 10 项，offset 是从 0 开始的页码。includeTopPlaylist=false 只控制
  客户端是否另查置顶列表，不是请求字段。
- 类型化 playlist_collect_page 从当前账号取 uid，不接受前端提供的账号标识。按
  服务返回顺序投影本人的可编辑歌单，保留服务的续页边界；其他用户及红心歌单
  不进入目标列表。空原始页不应声称还有结果；过滤后为空仍保留合法下一页。
- Vue 为每个排序独立保存行、页码、错误与滚动位置；切换后旧响应只更新自己的排序。
  滚动近底或点“加载更多歌单”续页，失败只重试原页，不提交任何收藏写操作。
  在后续读失败时保留已展示列表；首次默认读使用已有账号歌单作为暂时显示。
  本地偏好只保存排序枚举。键盘切换排序、长列表定位均不等待动画帧。
- Rust 边界测试核对页码、两个 sortType、账号代次、私有字段不出 IPC 及异常续页。
  Linux WebView 验证常用顺序、键盘返回默认、260 项的有界分页、失败与原页重试、
  创建后继续收藏及未确认写入只读核对。队列收藏全部另通过 32 个检查点。
  使用合成账号和接口，不代表真实服务排序或 Windows 实机验收。
