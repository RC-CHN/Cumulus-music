单进程桌面合成验收
  测试入口 desktop/examples/main_flow_ui_probe.rs 使用应用实际打包的
  Vue、Tauri IPC、MusicClient、播放器与 SQLite。只在测试入口注入
  封闭的账号/API/媒体替身，正式产品没有替换源或凭据开关。
  由登录态恢复出发，依次进入每日推荐、搜索，使用实际 libmpv 播放
  并暂停；创建、编辑和删除一张固定合成歌单；下载一首合成 FLAC，
  切断替身 API 和媒体传输后从完成列表播放本地文件。

  这一条链证明正式桌面和原生业务在同一进程内可以串接。替身中
  在线音源交给 libmpv 前替换为合成文件，解码走真实引擎，输出为
  null。离线阶段验证替身禁止网络、没有新增音源请求和传输，且
  从下载文件真实解码。它不证明上游 CDN、真实会员权益或声卡输出。
  验证脚本独立核对原始歌单集合、合成歌单回执、下载任务、实际
  文件和引擎进度。不会加载真实账号或设备身份。
  最终 Linux WebView 10 阶段通过；测试运行产生 9 张截图，本机
  KDE/XWayland 125% 又复核 9 张。截图见
  .build/main-flow-desktop-integrated/contact.jpg，完整计数与 SQLite
  核对结果见 .build/main-flow-integrated-webview/report.json。
  Linux 和 Windows CI 有独立入口；本机未实跑 Windows。
  复跑：构建 cumulus-desktop 的 main_flow_ui_probe example（开启
  custom-protocol），用 scripts/ci/main_flow_smoke.py --binary <程序>
  --root <新目录>；Linux 可在 Openbox/Xvfb 和私有 D-Bus 下加 --screenshots。

主分支生产 Vue 的普通 HTTPS 音源合成回归（Linux，手工运行）

  该模式复用 main_flow_ui_probe 和既有生产 Vue/IPC 主流程。合成服务给
  搜索结果返回唯一固定的 HTTPS 音源，原生测试引擎核对完整地址后，直接
  交给 MpvEngine 的普通 URL 入口；不会替换为文件或调用固定句柄入口。
  界面核对 AAC 已推进时钟、暂停后不再推进、恢复后同一播放项继续前进，
  最后停止。其余合成登录、歌单、下载后断网播放和重开状态断言保留。

  npm --prefix frontend ci
  npm --prefix frontend run build
  cargo build --locked -p cumulus-desktop --example main_flow_ui_probe --features custom-protocol
  python3 scripts/ci/main_flow_https_smoke.py --preflight
  python3 scripts/ci/main_flow_https_smoke.py --binary .build/target/debug/examples/main_flow_ui_probe --root .build/NEW_HTTPS_MAIN_FLOW

  由当前非 root 用户执行，需要 sudo -n、unshare、ip、OpenSSL、Xvfb、
  dbus-run-session 和 Openbox。sudo 仅建立私有挂载和网络空间并回到当前用户。
  仅开启回环接口，隔离 hosts、DNS 和 CA 路径；证书/密钥在临时目录生成并
  清理，不归档。TLS 服务检查精确主机和路径，不接受 Cookie、授权头、路径
  或非零起点范围变体，只允许一次合成音频 GET。固定夹具 playback-12s.m4a
  是 ffmpeg 8.0.1 生成的 12 秒 440Hz 单声道正弦波，脚本核对长度和 SHA-256。
  这段长度让暂停恢复测试不受原一秒夹具的自然结束干扰。若 Openbox 安装在
  系统 PATH 之外，使用 --openbox-directory <包含 openbox 的目录>。
  main-flow 的下载仍经过原有封闭传输替身。
  --preflight 独立验证命名空间和 TLS 限制，不能代替桌面运行。Linux 必需 CI
  跑此模式；Windows 必需 CI 保留合成源路径。两者均未验证真实 CDN、账号操作
  或物理输出。

普通 HTTPS 的失败与手动恢复（Linux，可选）

  在同一 main_flow_https_smoke.py 命令加 --retry-once。回环服务器仅让首次
  授权地址的 GET 收到一次 HTTP 503；只有生产播放器第二次向封闭合成 API
  申请音源，才会拿到不同的固定查询地址。服务器只给后者发送一次合成 AAC。
  页面等待实际打开失败提示稳定，核对没有自动重放或地址外露，再点击底栏
  「重试」。之后继续原有时钟、暂停、恢复同一播放项、停止和下载断网断言。
  报告核对两次音源授权、两次加载尝试（仅一次成功），以及一个失败 GET
  和一个成功 GET。无真实 CDN、账号或物理音频输出请求。既有 CI 正常 HTTPS
  模式不启用此故障注入。

双曲普通 HTTPS 的自然曲终推进（Linux，可选）

  同一 main_flow_https_smoke.py 命令加 --eof-next（不可与 --retry-once
  合用）。搜索结果含两首固定合成歌曲，第一首用原路径，第二首用独立精确路径。
  主窗口点第一首后，先验证原生授权已预取下一首而播放器只打开了第一首；
  保留第一首原生播放项直至实际 libmpv EOF，不发手动切歌。随后验证第二首
  使用新播放项 ID、原生时钟推进，暂停、恢复、停止均走正式控件。
  隔离服务器按顺序各允许一次 GET，第一首播放回执之前拒绝第二首。报告保留
  读取次序、授权和加载次数，未加入现行默认 CI 模式。命名空间预检不替代
  实际桌面验证。
