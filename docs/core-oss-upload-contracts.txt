分配和账号边界
只接受Whale实际返回channel=3；channel=1继续NOS。不能因请求参数channel=3强迫使用OSS。
需要bucket、key/objectKey、resourceId、endpoint、accessKeyId、secretAccessKey、token。
key与objectKey同时存在时必须一致；端点限oss-<region>.aliyuncs.com及同bucket的虚拟主机形式，
规范为HTTPS，不接受userinfo、异常端口、路径/query/fragment或别的bucket前缀。
对象key按UTF8字节做URL编码，保留斜杠；签名资源使用原始key。百分号与加号不可二次解释，
拒绝URL库可能消除的字面量单点/双点路径段。秘密字段限制ASCII及长度，不允许换行。
对象请求不使用账号HTTP客户端、CookieJar、Cookie、Referer，不自动重定向/重试或解压正文。
Authorization和x-oss-security-token标记敏感头。错误仅保留HTTP状态及有限格式的OSS Code；
不把原始XML、服务URL、STS元组、uploadId或签名放进公开视图。
所有服务绑定构造时SessionToken；同UID重新登录也使旧在途ACK不能写入新会话。
私有SQLite命名空间oss_uploads_v1/oss_upload_controls_v1；按账号隔离，跨进程oss-upload锁互斥。

签名与请求契约
Authorization = "OSS " + accessKeyId + ":" + Base64(HMAC-SHA1(secretAccessKey, canonical))。
canonical = METHOD + LF + Content-MD5 + LF + Content-Type + LF + Date + LF
            + canonicalizedOSSHeaders + canonicalizedResource。
Header名转小写并排序，仅x-oss-*头参与；有x-oss-date时该值覆盖Date签名行。
同名但大小写不同的输入头拒绝。资源为/<bucket>/<原始key>，签名子资源按原始键值排序。
本实现操作使用uploads、uploadId、partNumber参与签名；ListParts的max-parts与
part-number-marker是URL分页参数，不加入V1签名子资源。URL参数独立百分号编码，不用+表示空格。
Content-MD5是实际正文MD5的Base64；与NOS整文件十六进制MD5不是同一约定。
默认Content-Type application/octet-stream；Complete XML为application/xml。

小文件（<=持久part_size）：PUT对象原始字节；确认HTTP200、ETag=源文件MD5及可用CRC。
大文件：POST ?uploads 初始化，确认响应Bucket/Key并保存UploadId；
PUT ?partNumber=N&uploadId=... 发送原始分片；每片ETag必须匹配该片MD5；
GET ?uploadId=...&max-parts=1000&part-number-marker=... 读取分片；
POST ?uploadId=... 发送连续编号的CompleteMultipartUpload XML，ETag使用大写十六进制并带引号。
合并响应必须是CompleteMultipartUploadResult并确认Bucket/Key；合并ETag不作为整文件MD5。
HTTP200但XML根为Error仍是失败，不当作完成；XML限制1MiB、16层和50000节点，拒绝DTD、
自定义实体、重复必须字段、非UTF8、错误根/对象/UploadId和不前进或跳过分片的分页标记。

CRC64采用反射ECMA多项式0xc96c5795d7870f42、初始/结束异或全1，previous参数接受前段结束值。
源文件CRC在流式准备阶段计算；PUT/Complete返回的x-oss-hash-crc64ecma非零时必须匹配。
缺失或0表示未验证CRC，不能将crc64_verified置true；格式错误/不匹配阻止完成。
小文件PUT仍有MD5证明，大文件有每片MD5；未知完成的只读核对另有整文件MD5/SHA256证明。

源文件、调度和持久化
Source复用NOS的普通文件、规范路径、长度、MD5/SHA256约束，非空且最多512MiB。
准备时流式CRC前后复核原句柄与当前路径；阻塞文件工作在spawn_blocking运行。
默认1MiB/3并发，适配器允许100KiB..64MiB/1..3并发；最多10000片。
part_size/concurrency写入任务，重开后不能因宿主默认值变化更改现有分片边界。
每批先读取/校验待发分片，保存各片字节/MD5及整批Pending::Parts，再启动最多3个请求。
每个成功响应独立落盘；某片失败仍收集同批所有已启动结果，不把另两片成功一起丢弃。
该批失败后不启动下一批/合并。中止Future保留已写意图；恢复先ListParts。
合并前再次复核源文件；源文件在传输中改变时不得合并或发布。
固定子ID可复用相同源/对象；不同源或bucket/key/endpoint/resourceId不能套用旧任务。

公开API
OssUploads::new(session) 原生HTTP、1MiB、3并发；with_backend用于明确传输/配置注入。
create(Some(id), path, allocation, expected_md5)、get/find/list、run(id,OssRunOptions)；
control(Pause/Cancel)、resume、cancel、reconcile、replace_credentials。
run预算按实际待发片数计算；预算用尽保存Paused。control是持久请求，不能把请求提交等同完成。
Pause在批次边界停止；Cancel不能被Pause覆盖。已完成对象保留，不提供DeleteObject操作。
OssView仅含进度、状态、Pending种类、配置、确认片数、CRC/内容验证事实和稳定错误类别。
CloudView.transfer按transport=nos/oss带各自脱敏状态；云盘附件仍使用NOS，不假装是OSS。

恢复及取消规则
明确4xx拒绝可清除对应写意图，保留同一对象重试；408以及PUT的409、合并的404/409仍未知。
初始化/PUT/合并回包丢失、XML成功响应不完整、提交ACK失败，均不能直接重发。
初始化未获得uploadId：没有可靠身份，停止；不能重启一次初始化，也不能猜测ID进行删除。
已知uploadId：ListParts逐页校验对象/ID/序号/大小/MD5，与发送前日志逐一匹配。
仅认领已记录且内容匹配的片；未知远端片或不匹配的片返回MutationUncertain，不继续合并。
本地记录但远端缺少的片才允许重新发送，已接受但ACK丢失的片不重复传输。

PUT或合并结果未知：仅HEAD→GET。初始化/PUT附加x-oss-meta-cumulus-upload=<固定任务ID>，
PUT/初始化/合并附加x-oss-forbid-overwrite=true；这是恢复适配措施，不冒称官方原始请求字段。
HEAD要求该标记及Content-Length精确匹配；GET再次校验标记/长度，并流式计算MD5和SHA256，
全部匹配才标记Uploaded/content_verified=true。内存不缓存整段媒体正文。
缺对象、缺GET/HEAD权限、标记或内容不符时保持未知；404不能授权重发PUT/合并。
此核对不需要源文件仍存在，但云盘父任务后续元数据提交仍要满足原输入复核条件。

取消已知multipart：保存Pending::Abort后DELETE ?uploadId=...；只有204或明确NoSuchUpload
才能确认Cancelled。响应丢失可对同一uploadId再次中止，未知结果期间父任务保持非终态。
PUT/合并未知时取消先执行上述只读内容核对；若对象已完成则保留对象，停止父任务发布。
完成ACK迟于Cancel到达时保存实际Uploaded，父任务可以Cancelled，二者不互相伪造。
父control现为async，等待必要的OSS中止确认；在途父任务持锁时先记控制，由工作任务处理。
父任务reconcile_transfer只核对音频对象，不提交metadata/publish；reconcile_publication仍独立。

STS续期边界
没有恢复出自动获取“同一对象的新STS元组”的官方接口，不能用NOS refresh或新Whale分配替代。
replace_credentials/CloudUploads::replace_oss_credentials仅供原生宿主持有合法新元组时调用，
严格保持bucket/key/endpoint/resourceId，更新凭证也不会清除未知写事实或改变uploadId。
前端不接收这组凭据。过期且无法提供同对象凭证时明确受阻，不能宣称自动恢复。
