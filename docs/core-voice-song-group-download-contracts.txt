本批实现
- 业务由 Rust API 负责。prepare 接 epoch、playId、
  原生卡片回执、触发行号和 2..100 个有序唯一行号（必须含触发行），输出已选
  批次的可用/省略行号与决定。不会因一个旁边的行已喜欢而跳过目的地；未知和
  尚待核对均不发凭据。准备、取消（丢弃旧计划）、被替换计划均不发送下载或
  收藏请求。只有显式调用普通 start 或已购 confirm_quality 才能持久化任务。
- 沿用同账号、播放器节目/卡片、PC 设备/凭据版本、同目标 Cookie 和普通
  下载授权。仅用原生明确普通曲目权益（fee=0、st>=0、dl>0，无 bd 或
  云盘/节目/混合权益）；第一阶段先去掉已完成、本机有效映射、下架行。
  对同歌重复行按首个可接纳行去重；跳过进行中、暂停、失败任务，不在多选
  路径恢复旧任务/旧码率。权利不完整不会扩权；有效本机匹配必须绑定同账号
  的文件/CUE 版本。
- 已购组复用单曲已购权益（原生数值字段，payed & 6，非下架、dl > 0、无 bd
  或云盘等扩展标记）。至少两条不同、原生确认的初筛幸存歌曲才能进组选音质；
  普通混合和全已购都支持。仅剩一条的旧客户端单曲前置检查还会读触发行，
  此处不替代；未购、云盘、矛盾权益和无可选档位均保留为不支持。并集来自
  初筛幸存的已购行；按现有本机安全边界，已有非完成任务能贡献选项但不会
  重排或恢复。Vivid 仅沿用两项已验证 PC 分组，确认及提交前重查资格。
- 已购 prepare 只返回 purchased_quality_required、purchasedQualities 和
  原生批次回执。confirm_quality 只接该回执和一个明确显示的档位，才查
  原始触发行的喜欢与目录，或返回 playlist_required / membership_unknown /
  directory_required。没有写歌单或支付。确认后每条任务都用同一档位走各自
  下载授权，普通曲目也不夹档；授权拒绝不重试较低档，不改变保存的下载偏好。
  普通 start 无法消费已购回执；同档重复确认只回读已接纳结果，已提交回执不能
  用另一档位再次启动。
- 普通 start 只收当前原生批次回执，不收歌曲 ID、音质、文件路径或授权 URL。
  两种起点都读保存的本机格式/封面等选项，已购组仅覆盖本批音质；要求配置中的
  目录仍可用且未在迁移。构建工作目录和完整
  记录后复核卡片/播放/凭据、本地索引和调用取消；在同一个 SQLite 事务再次
  核对原始触发行喜欢快照（包括挂起操作）和任务冲突，并写入所有有序任务和
  最新回执。不能只接纳冲突之前的部分行。回滚只清理本批确切身份的私有空
  工作目录。进程崩溃不宣称跨文件/数据库完全原子；没有已保存任务的准备目录
  不会被当作任务执行。
- 任务和回执一同提交；同一个有效回执重复读取原接纳 ID，不重新创建或重新
  唤醒。新的卡片/计划或重启不能把已过期回执恢复为写入权限。提交后现有
  下载调度器照常并发、逐曲发同档授权；只承诺持久任务的相对顺序和调度
  候选顺序，不承诺并发授权/完成的实际先后。下载失败仍由任务管理显示；
  播放器队列不动，不借播放 URL、节目或试听权限。

主窗口 IPC 与桌面交互
- player_voice_songs_download_prepare：平铺 JSON
  {epoch,playId,cardReceipt,anchorIndex,indices}。cancel/start 为
  {epoch,playId,cardReceipt,selectionReceipt}；仅 confirm_quality 在相同
  回执范围中增加 quality。全部由主窗口调用，整体解码严格拒绝未知字段；
  不接收 voiceId、歌曲 ID、目录、options、歌单或替代目标回执，后续提交
  不能覆盖触发行/选择。Tauri adapter 只投影该命令声明字段。
  open_voice_song_group_purchased_quality_guide 同 cancel 的回执范围，
  只对当前未提交的已购准备有效。原生在同一已验证分组中复用单曲的固定公共
  帮助地址，交给系统浏览器，不在解析时访问网络，也不向 WebView 返回地址、
  Cookie 或授权数据。
- 已购准备只投影有批次回执、非空且降序的 purchasedQualities。与单曲已购
  共用八档 allowlist：vivid、sky、jymaster、jyeffect、hires、lossless、
  exhigh、standard。IPC 只做类型/范围检查；原生仍逐回执验证确实可选的档位。
  普通和阻塞计划不出现 purchasedQualities。
- 界面使用 VoiceSongsCard / voiceSongSelectionSnapshot 已冻结的
  indices，使用右键 VoiceSongRowTarget.index 作为 anchorIndex，而非
  indices[0] 或后来的焦点；该行即使在 omittedIndices 仍是触发行。
  UI 在本地保持原卡片、节目、账号代次与页面归属；异步返回后检查相同
  epoch/playId/anchorIndex 和当前卡片，再按 eligibleIndices、omittedIndices
  显示实际接纳范围。不把 onlineEligible 或当前行红心自行当作下载权限。
  多选菜单只在本账号观察到触发行已喜欢、该行不在喜欢操作中且整组至少有一个
  原生 ordinary 或 purchased 提示时显示「下载」；unknown 或 unsupported
  隐藏。只提示当前卡片已解析的权益，不能替代本地索引、任务、Cookie 或喜欢
  日志核验。保守隐藏包含已知不支持行的选择，即使该行随后可能被本地筛掉。
  原客户端会在选音质后为未喜欢触发行打开歌单选择；该目的地未接入，桌面
  只显示已确认喜欢的直达入口，确认时状态已变化则给出当前原生阻塞结果。
- decision=ready 和 purchased_quality_required 有原生批次回执。关闭未
  开始的确认时可显式 cancel；普通提交 start，已购只在明确确认后提交
  confirm_quality。后者结果为 kind=started（带入队结果）、playlist_required、
  membership_unknown 或 directory_required。directory_required 只指向
  既有下载目录设置，返回后
  显式重新 prepare。playlist_required、unsupported_selection 不跳过现有
  安全门，也不循环单曲接口；membership_unknown、unavailable 保持未启动。
  start 的 accepted 是入队任务而非已下载文件。只有返回 epoch 仍属当前账号、
  operationId 等于当前批次回执且卡片仍有效时才显示结果；结果不明不自动重放。
  普通 ready 在菜单点击后直接排队；已购与单曲共用「选择下载音质」弹窗，
  最高档只预选。改选和打开帮助不提交；「确定」才用冻结的批次回执提交一次。
  关闭或切换页面会撤销尚未确认的回执；已提交结果不明时不重放。
  留在当前播放详情，在标题旁报告接纳、跳过数量或失败原因；未确认结果只能
  手动查看下载。缺目录时明确点击「下载设置」才进入既有「音质与下载」，
  不自动打开系统目录选择器，也不从设置保存自动回放批次。既有单曲下载及
  多选收藏保持各自入口和原流程。
