正式调用链
nim_talk 普通/批量回调 -> RoomMessage 精确附件解码 -> 账号代次/音乐roomId过滤 ->
Together runtime -> PlayCommand::from_official -> TogetherService::receive_play_for ->
PlaybackSync::incoming -> 持久 Pending -> Receiver -> PlaybackCommand::ApplyRemote ->
原生播放器/授权源/时间线 -> finish_incoming_for。
会话身份与操作锁沿用 TogetherService；Waiting 不应用播放消息；有 userId 时必须属于当前房间。
成员未知、错误房间、非共享队列歌曲、过期/重复/回声以及非选曲命令指向其他歌曲，均不能触发音频。
收到的 roomId 不可用控制器当前房间补写；缺 roomId 兼容问题仍保留。
队列中同一在线ID有多个实例时，优先使用当前选中的实例，避免进度更新导致重载。

原生播放器行为
ApplyRemote 一次携带 entry_id、全曲时间秒数、暂停状态与 PlaybackFence。
围栏由 control_revision、queue_revision、play_id 构成；读取、进度轮询和音量变化不使其失效。
本机选曲、定位、暂停、停止等意图会使旧围栏失效；账号令牌另行检查。
新曲目使用正常 SourceResolver 授权与 Timeline 验证，再以目标定位/暂停状态首次呈现。
暂停切歌不先执行可播放的 Select；加载期间接受的本机暂停决定首次呈现状态。
同曲目先验证授权时间，再在同一引擎操作内暂停（需要时）、定位和应用最终暂停状态。
试听采用全曲时间转媒体时间；越权区间失败，不扩大源授权。引擎部分失败后停止，保留失败收件状态。
播放位置继续进入既有持久化和 Restore 流程；不把界面进度模拟当作音频操作。
普通加载中的 Seek 仍可能返回未加载错误；本批没有新增“加载中排队定位”能力。

持久状态与恢复
TogetherState.incoming 带 serde 默认值，可读取没有该字段的旧状态；内容为命令、接收时间和phase。
Pending 在音频操作之前落库；成功且未被后续本机操作替代才写 Applied。
本机更新/旧围栏导致 Superseded；音频或资源失败写 Failed；进程退出可留下 Pending。
Applied/Superseded 是终态，同阶段重复完成幂等，不允许旧完成回调覆盖更高序号或改写终态。
Pending/Failed 阻止队列和播放的远端写入；退出房间仍可执行，用于可靠清理。
普通 Seek 与用户点“重新同步”使用不同的内部信号；Seek 不能隐式重试失败的远端播放。
显式重新同步先捕获本机围栏，再只读刷新房间和共享快照；期间新的本机操作优先。
只有当前服务端命令完全匹配持久命令、目标仍在共享列表且房间仍有同伴，才重试音频。
命令已变化、曲目移出共享列表、角色回到Waiting，旧命令标记Superseded，不盲目重播。
重启后保留本机房间绑定且存在未完成收件时，可显式“继续本机控制”重连并执行同样恢复。
恢复不会重发 play/command/report。普通多成员房间附加仍受未完成共同权限/队列接线限制。
只读快照不得回退已接收的 serverSeq，也不重置重复消息过滤计时；本机clientSeq取最大值。
接收成功后更新 Runtime 已观察快照，防止播放器 watch 事件产生远端命令回声。
