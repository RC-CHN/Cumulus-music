Rust 与桌面边界：
- 只在已有 PcMessageConnectivity 主计数 actor 上新增
  message_read_all(epoch, action) -> AccountData<MessageReadAllState>。
  status 不发请求；prepare/cancel 不写远端；confirm 只认一次性的本机 intent；
  check 只接受当前账号持久操作编号。桌面只接受主窗口调用
  `message_read_all(epoch, action)`；命令先取当前计数 actor 的请求句柄，再释放桌面锁，
  等待 actor 返回。状态只包含本机不透明编号、账号代际和结果，不含地址、签名或凭据。
- Prepare 需要原生抽屉已打开、同一认证代际、最近 30 秒完整四类成功样本且至少
  一个正值。新样本、失败、抽屉关闭、账号切换或凭据改变会使旧许可失效；
  到实际 HTTP 交接前也检查截止时间和当前账号。相比官方直接确认，这是
  有限意图保护；同一数字也可能代表新消息，不能让旧确认一直有效。
- 写入用固定 PC EAPI 路径与空业务对象，无缓存、重定向、自动重试或其他协议
  回退。计数、账号资料及清除目标必须观察到相同唯一 MUSIC_U 和当前凭据
  修订；不能用 guest 或任意通用 API 适配器取得权限。响应若改变了用于观测的
  凭据修订，不用该回包向新凭据投影清除。
- 每账号一个持久操作及非阻塞跨进程锁；调用写入前先持久化 uncertain。
  已接收的写入先丢弃 actor 旧的在途计数读取，运行期间不启动其他计数读。
  仅当前作用域的肯定确认在持久结算成功后发布四个零；之后合法新读取可再
  报未读。确定未交给 HTTP 的情况记 not_sent。已交接但失败、超时、缺确证、
  账号退场或进程终止不补发，也不推测计数为零。
- 遗失回执后 status/reopen 只恢复未决状态，check 通过同一 actor 单独读取
  /api/pl/count {}。仅四项均明确为 0 才记录 checked_clear（只证明当时
  没有未读，不能证明上次写入成功）；正值、缺字段、失败仍未决，不能重发。
  没有服务端操作回执查询或幂等键证据。

桌面交互：
- 分类栏右侧展示“一键全读”，未读总数为零时禁用。点击先向原生获取意图，成功才
  打开官方文案确认框；取消或 Escape 只撤销该意图。按钮的默认焦点为“取消”，
  关闭确认框后回到入口；入口已禁用时回到当前分类。
- 仅当本次确认在同一账号、同一次打开抽屉中收到 confirmed，才清除当前缓存的
  私信行角标。分类及顶栏仍由同一个原生计数发布更新。稍后新服务回包可显示新未读。
  状态恢复不当成新确认；只读核对全零表示当前没有未读，只更新原生计数。
- 回执不明保留既有行角标，显示“核对未读数”，重开通过本地记录恢复。
  核对返回正值或失败继续保留待核对状态。用户不能绕过未决记录发第二次清除。
  新快照令确认失效时提示刷新，不会自动替用户重新确认。
