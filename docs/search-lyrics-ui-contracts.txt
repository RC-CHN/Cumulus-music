当前界面
- 统一复用 TrackRow 保留歌曲、歌手/专辑入口、喜欢、时长和更多操作；表头与歌曲页一致。
  不把变量高度歌词放入56px固定行高的虚拟列表。每批10项，单条最多512行/64KiB；
  超出时显示“歌词过长，仅显示部分内容”，复制按钮与成功反馈明确显示部分内容。
- 歌词默认前三行；展开/收起保持当前控件焦点；切分类/详情返回保留展开和滚动位置，
  状态只在账号隔离的搜索内存保存。新搜索和换账号不会复用旧关键词的展开记录。
- 少于四行时展开不可用；没有歌词时明确说明，复制不可用；长行可换行，不产生横滚。
  950px以下操作行移至正文前面右对齐，左距40px；展开后操作不会被推至视口外。
  此为Cumulus窄窗适配；28px按钮高度/6px圆角亦非已证明的官方像素值。
  展开/收起文字用160ms透明度/位移动画，图标旋转；尊重减少动态效果。
- 复制通过类型化 copyText → desktop copy_text → 原生剪贴板；复制成功/失败和重试反馈
  在按钮下方，不用浏览器剪贴板权限提示。请求进行中保留焦点、忽略重复点击。
  Tauri官方剪贴板适配说明：https://v2.tauri.app/plugin/clipboard/
  使用与现有Tauri兼容的clipboard-manager 2.3.2；锁文件不升级现有Tauri/WebView依赖。
  正式前端没有读取/清空剪贴板权限；此能力不进入Rust业务core。
- 旧 matchedLyric 字符串/数组仍作为兼容输入；移除em/b标记，其余内容按文字插值。
  优先官方 lyrics/lyric，不再静默截为五行。不存在HTML注入或额外歌词网络请求。

单曲及歌词表格的主名称高亮
- M352:879、1107 的标题列使用 M113；M113:122–139、184–243 的歌名和带 ID
  歌手链接由 M87.b/M123.d 标记，无 ID 歌手是纯文本。M134:42–85 对有名专辑

- Rust 复用从 M123 冻结的匹配器和繁简映射，只对请求生效词做原有规范化。例：
  `Ａ＋Ｂ 樂隊` 可标记 `A+B` 与 `乐队`，不把标题原有全角字改写为半角，
  也不会把 `+` 当作正则运算符。一次响应只准备一个匹配器。primaryMatches
  存在时，空槽位表示原文无高亮，`[]` 表示原匹配器裁掉的空显示；均不回退到
  前端模糊匹配。文本标签照常按纯文本渲染，不创建元素或链接，不新增 API 请求。

  回包纠错字段，使用实际请求词。M3001:454–477 与 M3095:2489–2502 表明
  单曲连续续页若给出不同纠错词，官方会用新词重新请求第零页；这条转换与
  混合旧行的风险单独处理。本批不把单页高亮当作该转换通过的证据。
- Linux Tauri/WebKitGTK 的 `search_lyrics_smoke.py --primary-marks` 六态验证
  纠错与原词、全角与繁简匹配、字面标点、点击歌手后返回原焦点，以及无 ID
  专辑和歌词中的字面 HTML。原生轨迹核对了八次只读请求；没有真实服务请求或
  账号写入。报告和六张截图在 `.build/ui-proof/phase315-search-primary-marks/linux-primary-r2/`。
  Windows WebView2 使用同一探针，仍待对应提交的 Windows CI 验证。

  已返回列表长度作为 offset；M3001:299–301、405–416、477–485、503–515

  不生成歌词分类纠正。原 formatter、请求包装和 effect 四组合成向量已离线执行，

  展示；不会因 hasMore=false 提前丢失续页，也不会让短批因旧总数继续请求。
  nextOffset 计原始条数，避免畸形条目被过滤后重复请求。列表缺失/格式不合法
  仍是可重试错误；失败时保留本次有效请求词、已加载内容和滚动锚点，只响应显式重试。
  不新增歌词分类响应中的纠正词，已有综合纠正进入歌词时继续生效。

  有界定时器更新。展开、分类往返及宽度变化按行和行内位置恢复，不按固定行高猜测。

- Lyrics 页分别签发 groupDownload 和 lyricGroupCollectionReceipt；

  右击保留原组合，点中行仍是独立菜单锚点。下载使用已有单次 100 项

- 原生调用顺序：
  1. EAPI /api/search/resource/lyric 读取 keyword、scene=normal、limit、
     offset；同账号、同查询、连续批次的匹配行分别签发收藏与下载回执。
     点中行的完成／本地状态只查本机，打开菜单没有服务端写入和入队。
  2. 收藏：lyric_group_collect_prepare 接收 epoch、anchor、rows，只返回
     计划回执和展示用的有效歌曲。选取普通歌单时，/api/user/playlist/v2
     按 uid、offset、limit=10、sortType 读取候选；
     /api/v6/playlist/detail 核对目的地和已有曲目；
     /api/v1/playlist/manipulate/tracks 以 pid、op=add、JSON 字符串
     trackIds 提交一次。未决用同一操作 ID 重读详情。系统喜欢目标另读
     /api/user/playlist 与 /api/song/like/get 核对真实 ID 和成员；
     显式新建私有歌单用 /api/playlist/create（uid、name、privacy=10），
     收到明确的创建回包才有对该新 ID 的添加权限。
  3. 下载：prepare_lyrics_group 接收点击回执、所选行回执和相应歌曲 ID，
     先查本地/完成/版权及费用，再读本地已核实的点击行喜欢状态。尚无可信
     状态时不猜测目的地；需要歌单时在确定目标写入状态后才入队。传输阶段
     /api/song/enhance/download/url/v1 用 id、level、immerseType=c51；
     拒绝试播 URL、其他 ID 的回包和未授权格式。媒体地址留在原生，
     用既有下载日志与最终文件状态确认提交。
