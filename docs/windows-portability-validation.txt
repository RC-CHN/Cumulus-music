1. Windows 路径
Windows canonicalize 会生成扩展路径并展开 8.3 短名。测试夹具此前直接比较临时目录的原始路径字符串，和产品使用的规范路径不一致。
夹具现在显式使用规范路径，不能通过取消文件身份/目录边界检查来解决。
产品层也修复了旧队列 path 字段使用非规范别名时，移动/删除文件未同步队列的问题：仅将解析后等于被操作文件的绝对路径识别为同一来源。
legacy_queue_path_aliases_follow_moves_and_deletes 在真实临时文件上覆盖移动和删除；不是仅比较字符串。
歌曲元数据可含 Windows 文件名禁用字符，编码测试将这些字符放在标题里，并使用平台合法的文件名。

2. 一起听自动退出后的本地恢复
服务端状态首次回读为房间关闭时，结束操作可能仍持有跨进程锁等待第二次确认。
后台曾在此时遇到 MutationBusy 后永久结束工作循环，留下恢复标记。
现在仅对这一临时锁竞争进行最多 5 秒的异步等待；重做的是只读核对和本地恢复，不重放结束写请求。其他错误继续保留恢复责任和明确错误。
waiting_timeout_and_empty_queue_exit_also_restore_local_settings 将确认间隔加长至 2 秒，确保旧行为在后台计时器触发时可被检验；断言恢复速度/模式且结束写请求只有一次。

3. 桌面测试的 Windows loader
STATUS_ENTRYPOINT_NOT_FOUND 出现在实际测试执行之前。Tauri 对话框依赖 Common Controls v6，单独的集成测试不能只依靠主程序的资源清单。
桌面 build.rs 按目标系统为 MSVC 统一嵌入 Common Controls v6 清单，覆盖程序、测试和 WebView probes。
依据：
https://github.com/tauri-apps/tauri/blob/dev/examples/api/src-tauri/build.rs
https://learn.microsoft.com/en-us/cpp/build/reference/manifestdependency-specify-manifest-dependencies

4. 进度上报测试的时间边界
40488689024 的第二次执行中，shared_queue_ui_probe 复用的进度测试假定第二次相同请求仍处于去重窗口，实际多了一次上报。
官方 cmdFilter 仅在 1000ms 内抑制相同 PROGRESS；异步数据库/消息操作和并发测试不能保证下一次请求仍落在此窗口。
集成测试继续验证原生播放时钟、忽略账号/房间过滤、请求内容和队列不被修改；窗口测试使用显式时间验证 0/250/999ms 被抑制、1000ms 允许发送，并检查被抑制的请求不会延长窗口。
不延长产品去重时间、不忽略失败、不依靠重复 rerun 获得通过。

5. HTTP 测试连接的阻塞模式
40499502432 的 Windows 单元测试捕获 WSAEWOULDBLOCK（10035）。测试服务器使用非阻塞 listener 轮询 accept，却没有显式设置接收连接的模式；Winsock 可以继承非阻塞模式。
夹具现在对接收连接设置阻塞读取并保留 2 秒读取超时；响应体按实际 read 返回长度累积，不假定一次读取包含全部 body。
仍检查不跟随重定向、不回放 Cookie/Authorization、Range/If-Range 请求头和禁用透明解压。产品下载实现不变。

上述测试均使用合成账号/本地临时媒体，不代表真实双账号一起听验证完成。
