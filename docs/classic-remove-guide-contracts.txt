旧版明确失效后的登录引导（Windows PC 3.1.42.205594）

恢复证据
- hybrid_app M/198:2628–2673（JSK）与 M/1384:4587–4610（旧版）在数字
  action=2 时完成失效处理，然后等待 1000ms，派发 login{path:"removeGuide"}。
  普通失效不打开此路由。M/198:753–797 中显式 path 优先于快捷登录默认。
- M/1384:3287–3326：已存在登录窗口不重复开；只由 PH-PC-newLoginBenefit
  决定是否使用 752×520 新主窗登录弹层，其他使用旧登录子窗。是否采用 JSK
  则要求双 t1（M/34:73），不是同一个门槛。
- 旧 pages/login/views/RemoveGuide.jsx:91–134,136–163,198–239：进入立即
  获取旧版 type3 二维码（Windows），1000ms 轮询，194px QR、低纠错，
  显示失效标题（空则「扫码登录」）、说明，过期和错误可「点击重试」，
  关闭停止轮询和旧票，未渲染其他登录方式。
- 新 NewLoginLegacyModal/legacy-login/views/RemoveGuide.jsx:57–99 右栏
  的「其他登录方式」进入 /login/phone，左栏 LegacyQrcodeLeftPanel.tsx:151–196
  使用不同的扫码 URL，可能进入微信链。此处不移植新版，不开放微信/QQ。

Cumulus 边界
- 仅原生确认旧登录校验返回数字 action2，当前认证账号的实验明确为旧外壳，
  且本地凭据清除和已有队列清理（如适用）成功后，才发给主 WebView 一个
  短期、一次性的不透明引导许可。许可不持久化；普通 Expired、实验未知或
  新外壳、启动读回旧提示、磁盘或队列清理失败均保留既有手动入口。
- 主界面从原生账号变化延迟 1000ms 打开专用登录区域，发生切号、存在其他
  登录/模态或窗口隐藏时取消自动打开。不创建官方专有子窗、未照搬背景图。
  Rust 再用当前失效 epoch、单次许可和原生计时核验；桌面命令要求主窗口
  可见且未最小化，排队后及二维码取回时重验。许可最长五分钟。
- 自动初次取码及显式错误/过期重试都使用固定 Legacy type3 和独立候选；
  从不替换另一个仍进行的登录。重试只由可见「点击重试」触发；关闭撤销
  许可并取消候选。已经在途的旧候选不能在关闭或换号后回填二维码、继续
  轮询或采用账号。二维码只把矩阵传给前端，既有 803 身份回读与采用照常。
- 不自动执行官方 host/logout 的远端退出，不在界面定时器重复执行队列清理。
  普通登录路径、短信、续期与账号切换保持各自的原生协议和门禁。
