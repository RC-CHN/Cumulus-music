新歌发布：关注歌手的单曲与专辑（Windows PC 3.1.42.205594）

来源及入口
- 官方 app/205.js:200–203 的 /followNewSong 是早期组件 M3130（恢复源码里的 song/album
  仍是文字占位），使用 M3020。实际新版 M3105:378–395 的社区新歌通知点击导航到
  /NewSongPublish 并在 host 清 hasNewSongNotice；其埋点仍写 /followNewSong（400–418）。
- 官方 app/205.js:243–246 注册 /newSongPublish，M3115:166–256、448–679 和 734–969
  是完整卡片、滚动、展开及最新播放，使用 M3026。M3130:88–109 显示跨 latestVisitTime
  时的历史分隔；M3115 按天分组，不显示该分隔。Cumulus 使用完整卡片和按天分组，
  保留已恢复的历史分隔。项目暂无社区通知页，当前从“专辑与关注 → 关注歌手 → 新歌发布”
  进入；不宣称还原了社区通知入口或已清除服务端提示。
- 此批使用官方资料，无 YesPlayMusic。源文件均见
  references/netease-3.1.42.205594-analysis/recovered-js/modules/ 对应 hybrid_* 目录，
  另有 references/recovered-client/docs/product/models/page_followNewSong.txt 动作卡。

请求和状态
- M15:1012–1014、1166–1204 与 M12:278–319：两条均 PC POST、禁用接口缓存。
  首次进入已登录的页面，先发独立的播放列表请求
  /api/sub/artist/new/works/song/playall {}，同时加载
  /api/sub/artist/new/works/song-mv/list/v2
  {startTimestamp: 本机当前毫秒,firstRequest:true,sourceType:1,limit:10}。
  UID 用于本地身份、格式化、存储，未放进两条请求 body。Rust 复用已有原生认证传输。
- M3026:137–192、193–246 和 M3020:98–220：仅数字 sourceType=1 且 info 存在的记录
  参与资源与游标计算，取其中更小的 publishTime（先取游标，后按 UI blockType 过滤）。
  后续请求固定 sourceType:1、limit:10，传同一个最早时间，firstRequest:false。
  只按原序追加，不跨页重排。hasMore=false 停止；续页没有推进时间却仍有下一页时
  Cumulus 显示可重试错误，避免无限滚动请求。明确失败保留已显示的记录。
- 首次成功读取保留响应 latestVisitTime，并原生按账户保存本机最后进入时间；
  后续页不覆盖分隔值。离开或切号释放页面状态，旧账户的回包和本机写入均拒绝。
  页尾滚动加载并保留可键盘操作按钮；每组最多渲染 40 张卡，组间可切换；
  一次最多展开一个资源且每组最多 24 首，避免原生 WebView 随页数增长持续膨胀。
- 单曲默认显示首曲，可展开伴奏；专辑卡打开真实专辑、可按专辑来源播放，展开后
  按回包原序展示曲目。M3115:120–157 的专辑曲目使用通用标题单元 M113:162–175,337，
  M21:549 取 mv/mvid，M35:35–45 和 M358:34–37 决定普通 MV 标记及独立视频身份。
  本客户端保留普通 MV 的十进制 ID，负版权状态不展示普通 MV；配置控制的无版权 MV 兜底
  仍未接入本页。虽然接口路径含 song-mv，当前官方两版渲染只处理 song/album；
  不把其他 sourceType 或 blockType 当作歌曲、专辑或独立 MV 项。
播放最新
- M/3115:904–920 的实际播放动作携带 album scene、显式 listData 和
  /newSongPublish；同一组件 :934–943 的 trackList 和 unknown 只用于埋点。
  M/3085:215–219、309–312、456、532–585 选择列表首 ID、清空替换旧队列，
  不触发行双击的暂停切换；其中同来源短路要求资源本身有 ID，此处资源是数组。
  M/265:17–47、63–68 把实际播放资源转换为 track、原始资源保留 album，
  路由不是某一张专辑。M/308:3132–3250 针对这条路径检查最初指定的首 ID
  仍在可播放集合，否则保持原队列，不直接改播下一首。
- M/1384:2580–2669、5186–5308、5345–5369 更新可见列表，再以首 ID 提交
  playing/setPlaying；M/308:1547–1571、1620–1632、1671–1685 发现普通当前曲
  身份相同时，正在播放就保留，暂停就恢复。因此再次点击不是暂停/播放切换，
  即使显示队列须替换，也不重新打开正在播放的首曲。若当前已到第二曲，
  新点击重新打开首曲。普通同 ID 的现有原生音源/进度和本地队列行 ID 一起
  保留；其他行以本次返回的顺序替换。官方本地数据库的行 ID 不作等价承诺。
- Rust 将 playall 返回绑定到登录代与原生列表版本；WebView 只提交版本，不传
  曲目列表或来源。点击直接用已读取的正规化资源，不增加歌曲详情请求。
  M/15:1181–1197、M/21:326–367、537–610、M/59:113–176、M/23:326–327、
  426–467 对应在线播放权利的明确判断：有 privilege 且 pl<=0、没有试听标志
  时过滤。缺 privilege 时仍由普通权益/音源解析校验。独立 FM 或一起听
  不由此操作切换；列表读取失败只禁用该动作并允许单独重试，普通卡片
  播放保持既有路径。
- M/59:139–148、M/127:115–151 从同一目录曲 ID 的 trackMap 条目读 offlineTrack，
  M/23:579–606 验证下载完成状态、容器及授权。M/308:2094–2106 请求
  M/163.f，M/163:299–337、357–383 为已验证下载优先选择物理文件，然后才考虑
  本地匹配。Cumulus 在首曲明确无在线权时只接受同账号、同歌曲 ID、Song 类型、
  已完成且没有进行中文件操作的最近一次发布下载；普通在线首曲及后续行仍走
  上面的在线流程。读台账验证任务、歌曲、路径、容器标记及文件摘要；加密文件
  同时复用已在有效期内的本地会员/权益凭据，不自动续期。无匹配或校验未通过，
  保留当时的队列、播放状态和进度；不请求在线音源，也不改播下一首。
  当前播的是同一已验证文件时重复点击可保留解码器或恢复暂停，旧在线音源
  不因 ID 相同而被复用。验证是提交前的本地检查，若验证后文件在解码打开前被
  外部删除则由原生加载报错；后续重新加载仍按下载规则校验。
- M/23:373–446 的 localMap 按已匹配的目录 ID 索引；普通在线的 pl 拒绝不会
  用同名本地文件放行。离线才走该段的本地/缓存资格判断；即使符合，M/163:321–337
  仍须对应本地文件存在。M/163:391–455 的缓存是 PH-PC-playCache2 实验控制的原生
  完整音频缓存，匹配 trackId/码率/MD5、要求 100% 并排除试听；Cumulus 的内存
  URL 缓存不具备这些事实。这里不猜测本地/缓存等价分支，也不代选 M/59 的版权替代曲。
  M/308:3898–3918 的 isOfflineDownOnline 是队列中明确处理缺失下载的路径，
  不是新歌列表响应可传入的授权。

取消该歌手新歌通知
- M/622:692–701 在 Scene.newSongArtist 提供“不接收此歌手的通知”；M/3085:3012–3041
  的确认框提示“后续将屏蔽此歌手的新歌通知”，只有确认才派发 page:followNewSong/unfollow。
  M/3026:99–136 与 M/15:1176–1179 提供 /api/sub/artist/publish/switch
  {artistId,switchStatus:0}。保留十进制 ID；不调用取消关注歌手接口。收到 200 后只移除
  当前发布页该歌手的所有卡片，不改关注列表或已在播放的队列。
- Rust 发送前按当前账号和歌手将保守的未决状态存入 SQLite；并发点击、进程重开、账号
  变更或响应丢失均不能重发。明确发送前失败或业务拒绝可由用户重新确认。确认记录和
  未决记录可通过本地只读查询取回，不用当前三个月的发布页猜测是否关闭通知。
  未找到官方独立核对或重开通知接口：不提供伪造状态或自动恢复，未决时提示在官方客户端
  核对。正式页只在收到确认后过滤卡片；取消弹窗、未决和错误时保留所有发布内容。
