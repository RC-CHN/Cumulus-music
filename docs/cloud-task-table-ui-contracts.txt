UI逻辑和范围
- CloudTasksToolbar与CloudTaskTable分离。三项全部按钮各114x48、圆角8、间隔12。
  #列44px；表格最小772px；超出宽度等分到标题/进度，保持差值148px。
  用ResizeObserver测实际容器后设像素列宽，避免WebKit忽略col上的calc导致均分。
  只在自身横向滚动，不撑开窗口。每次展示最多200行，64px；任务无常驻选择框。
- 全部上传/暂停由Rust枚举本账号完整未完成任务，不局限当前页、筛选或选择。
  直接单次指定任务上限5000；全部操作上限50000，超过拒绝而非截断。
  已在取消/移除的任务不可再次启动，全部上传也不重启明确转码失败项。
- 全部清空通过cloud_upload_selection先读取完整范围（最多50000，不能静默截断），
  确认弹窗固定IDs和标题/文件名；确认之后新添任务不会被纳入。单项删除同样捕获
  原任务。对话框只渲染前20项及剩余数，正文滚动，固定头尾。
- 取消不执行；确认按5000一组提交，组间检查账号/组件生命周期。部分失败留在
  原弹窗，逐项保留结果；读回全范围确认hidden且terminal才关闭。收到发送成功
  只是接受请求，不冒充实际取消完成；丢回执先只读核对，不自动再发写请求。
- 返回任务列表可稍后重新打开处理。显式重试仅剩余原任务，removing任务标记
  retry=true；每次只读核对不增加取消、分配或发布。没有自动支付/删除云盘歌曲。
- 各页独立保留查询。已上传的搜索/排序/页码不带到任务/历史，也不会被往返丢失。
  查询切换清旧反馈；迟到命令反馈不能显示到新分类。账号替换清原弹窗和旧结果。

Rust持久化与恢复
- UploadSchedule新增serde(default) removing，旧记录兼容；保留revision/enabled/
  running/hidden/error。entry按单ID读取，避免每个任务反复枚举整张排程表。
- UploadScheduler::remove先确认父任务、取消日志和子传输边界。Complete/Cancelled
  只做本地隐藏；未完成先持久Cancel并停止调度，实际终态后才hidden。
  在途对象未结束时保留removing可见；worker收到真实取消结果才隐藏。
- 已有removing且retry=false只返回当前状态，不重发远端取消。Cancel落盘后隐藏
  事务失败，显式重试对已取消任务只补本地隐藏；原文件保持原样。
- 恢复时停止自动排程；removing且已有Cancel的任务按既有NOS/OSS日志继续处理。
  不可核对的父分配/附件分配/元数据/发布意图、未知对象写入保持可见；不通过清空
  擦去未决证据，也不重放可能已成功的请求。发布中歌曲不能作为取消对象删除。
- retry_encoding仅接受Failed+encoding_failed、已知song_id和metadata、未Cancel的
  原任务；重置Encoding并保留deadline，再启动已有worker。只查询已知song ID，
  成功后走既有publish+完整列表回读。无需再次读取已删除的源文件。ResumeAll和
  普通Resume不能将此状态重置为重新check/上传。仍遵守官方容量满保护。
- 官方 M622:3463–3490 将上传任务的 filename 交给 viewFileLocation，
  M3085:3160–3214 调用 revealInFileExplorer；M4:13798–13806 默认调用 os.shellExplor，
  参数是源文件本身。正式 IPC 只接账号代次和任务 ID，Rust 在 worker 中按任务记录
  校验路径、大小与 SHA-256，并核对文件和父目录身份。交给系统前再次校验任务、文件、
  父目录和账号代次。Windows 请求 Explorer 选中文件；Linux 调用 FileManager1.ShowItems，
  仅在选中接口确定不可用时回退到打开同一父目录。前端 DTO 不接触本机路径或授权 URL；
  此动作只处理上传任务的原音频，不发业务请求或修改文件。
