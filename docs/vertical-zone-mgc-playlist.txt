Cumulus 原生契约
- vertical_zone_playlist_origin(epoch,viewId,cardKey,id) 仅主窗口可用；用
  当前签名实验、菜单、页面和该卡片核对同一歌单，签发无账号信息的 visit receipt。
  普通网格、别的卡片、旧专区页面和任意 ID 不能签发。账号代次、原生 API、
  凭据版本及已登记专区不变时，从该卡片打开的详情可跨子标签使用此凭据；
  普通入口打开同一 ID 不会继承。最近 24 个访问凭据只留在本次进程。
- vertical_zone_playlist_detail(epoch,receipt,id,page) 从该次已验证的专区
  卡片保留原生数字 specialType=100，不经 WebView DTO；或复用已成功读取的
  当前账号 /api/user/playlist 中自建条目。列表依据绑定账号代次、原生 API
  和凭据版本，不额外读账号列表或官方 getTop 补充列表。列表只在访问签发时
  提供依据；晚到的列表可在重新打开时使用。作者名称、同名卡片、旧账号或
  持久化展示数据不能改变当前访问。V4 返回 100 时
  完成 dynamic 后升至 V6；每次初读至多提升一次，明确刷新优先使用该访问最新
  的权威详情。自建身份与详情作者必须一致；详情作者同账号但未验证自建时停止。
- 后续分页必须带当前轨道版本，仅读取该页歌曲。动态数据不能改 trackIds
  或歌单身份；会话失效、取消、凭据变化不作普通回退。详情和行投影复用
  现有 TrackPage、分页边界及本地项占位；首次读取失败由现有整页重试表达。
- play_selection 的 vertical_zone_playlist_detail 分支接受 receipt、同
  歌单 ID 和当前详情版本、可选 start_id 与 double_click。Rust 从已确认访问
  导出 121，或对已核实的红心歌单导出 43，给歌曲详情与播放器资源；
  WebView 不提交数字 trialMode。队列仍遵循
  普通双击偏好。播放前后检查同一访问、登记和数据快照。普通详情、普通播放、
  卡片直接播放的既有请求不改；不自动写账号、下载、分享或扩张订阅权益。
- 从详情「批量操作」打开时，读取 vertical_zone_playlist_batch_page 的第一
  页和续页均须带同一详情 revision 与 receipt，不重新请求 v4/v6，不降级
  普通入口。原生复用已加载的连续歌曲，未补齐的在线行走 trialMode=-1；
  本地、不可用行保留可见状态。缺失整个访问或详情已变更时提示返回重开。
- 「播放所选」和「添加到播放列表」分别使用 vertical_zone_playlist_batch、
  queue_vertical_zone_playlist_batch；原生校验所选 ID 全部属于该访问，
  按原歌单次序和 121/43 读取并构建队列项，放在当前播放项之后。播放会切到
  第一首所选；添加保留当前播放 ID 和时钟，队列为空时才启动。已有同曲条目
  会合并并带上该次来源。实际播放仍需音源授权；FM、心动和房间队列不由
  这两个普通动作改写。下载保持普通按曲授权与明确确认，未把 121/43 传入。
- 详情页「添加全部至播放列表」和单曲行「下一首播放」分别用
  queue_vertical_zone_playlist_all 和 queue_vertical_zone_playlist_next。
  二者校验同一次 receipt、账号、菜单、详情及队列版本；整单从原生
  trackIds 推导在线项目，单曲按歌单成员校验。原生复用该详情已加载的曲目；
  缺的曲目用 -1 补元数据，并给新队列条目保留实际授权场景 121/43。
  不回读普通歌单详情，不重启当前曲目；同一当前曲目的 Next 无需操作。
  现有歌单内关键词搜索仅筛选显示行，整单动作仍是整单。官方另外支持
  红心语义筛选和手工排序（Common.jsx:217–219、289–297、433–449），
  这里不从关键词猜测这两个范围。音源备选、FM、心动及房间仍走各自协调器。
- 卡片直接播放的旧元数据路径及特殊编辑仍分别追踪。
  官方自建歌单还会在首读后合并本机数据库曲序和云曲（M/2997:282–322，
  M/239.b/c）；此处仅显示服务端 trackIds，不迁移该旧库或喜欢歌单的
  AI/筛选。Cumulus 不跨普通访问复用专区实体，继续按当前可见页读取歌曲
  详情，不用 V6 内嵌曲目预填本地缓存，也不自动预取全部歌曲。不会展示官方
  先显示 v4、随后替换为 v6 的中间画面。

隔离验证：vertical_zone_playlist_detail 覆盖同一 ID 的两类入口、动态失败、
分页、旧账号/凭据/菜单、卡片首读 V6、V4 后提升和凭据变化取消、本人自建
与红心试用 43。URL 与歌曲详情调用对照 121、43 和普通选择的 -1；
HTTP 和音频输出为合成夹具，无真实账号、外部写入或实体音频验证。
V6 另以 scripts/ci/vertical_zone_smoke.py --case playlist-v6 实际运行 Linux
WebKitGTK、Tauri 和 libmpv，验证 8 个状态：同号普通入口、卡片直达 V6、
V4 合并动态后提升 V6，以及红心歌单 43 的真实解码时钟。普通路径不带试用，
普通专区路径带 121，红心路径带 43；逐项核对歌单、歌曲和授权请求。Windows
由独立打包检查执行，未以 Linux 截图代验。

真实 Linux WebKitGTK、Tauri 和 libmpv 的 10 个桌面状态验证同一 ID 的普通网格
和 MGC 横排入口。普通详情用 v6 并走默认授权；MGC 详情先读 v4 再合并动态数据，
播放全部、行播放和双击分别观察到试用场景 121。回到普通入口后 121 不残留。
两类返回都恢复原卡片焦点与纵向、横向滚动；修正了播放全部异步准备期间 WebKit
因按钮暂时禁用而丢失焦点的问题。可用 scripts/ci/vertical_zone_smoke.py
--case playlist-detail 复现。HTTP、音频及账号为合成夹具，没有实服、外部写入
或实体音频验证；Windows 由独立打包检查验证。

详情访问与「更多」焦点。未在本夹具提交下载或验证真实版权。
