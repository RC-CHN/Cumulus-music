结构
membership/api.rs：会员信息接口；state.rs：官方到期转换；clock.rs/manager.rs：时钟、缓存与刷新。
quality.rs：官方音质码；offline.rs：映射本地/下载歌曲的离线判定。
center/ 分 banner转换、模块加载和状态/历史协调，不依赖前端组件。
测试中使用合成会员状态；真实运行从该账号的服务响应计算，不从请求音质推断权益。

会员与时间
/api/music-vip-membership/client/vip/info {userId}，要求data.now为有限正数，返回userId若存在须匹配账号。
五组：associator黑胶、redplus超级会员、musicPackage音乐包、albumVip数字专辑、voiceBookVip有声书。
严格expireTime>serverNow才有效；相等即到期。黑胶和超级会员同时保存服务返回的vipLevel。
M/224的isNeverVipUser按JS对象真假值；空对象表示曾有该组，不能按Rust/Python空集合当假。
服务时间+运行中单调时钟推算serverNow；最早有效权益到期后1秒给出refreshAfterMs。
重启使用保存时wall与当前wall的差值恢复；墙上时钟回退超过5秒要求重新在线读取。
不通过回退系统时间延长有效期。跨账号代次响应不入缓存，持久化失败不发布新权益。
refresh_if_due每次最多执行一次在线读取；新的服务状态替换原锚点，宿主自行安排tick/失败退避。
当前纯转换拒绝非有限/非法类型的到期值和非整数会员等级，不模拟畸形数据的所有JS隐式转换。

离线歌曲
Downloaded要求调用者确认下载记录完整，未完成直接DownloadIncomplete；明文已完成音频可读。
Imported明文本地文件可读；加密文件需要映射得到的真实privilege与当前MembershipState。
fee=0优先免费。按官方Number(null)处理显式fee:null=0；缺fee不是免费证据。
flag第13位要求albumVip；dolby/sky/jymaster要求isPlusVip；其余要求黑胶。
下载歌曲的普通会员分支还可使用已购买mask(payed&6)或musicPackage；导入文件不继承此分支。
读取错误类型的privilege会拒绝，不能以无效解析结果放行。权限不足返回明确原因。
M/23 K/Y、M/35购买mask和M/84码表直接运行得到387组离线样本，与Rust一致。
这个判断是已恢复的客户端策略；不是服务端授权、新DRM签名或绕过付费的凭证。
本地库、NCM和下载状态接入之后，才可把完整文件/来源/权益串成实际播放流程。
下载声音/有声书还有独立audio权益规则，当前offline_access只覆盖歌曲，声音链路继续迁移。

官方 M/198:2262–2295 在启动恢复到已登录用户时分发 switchUser；1051–1072、
1247–1259、1346–1361 在已登录/切号后读取用户详情、权益和认证身份。会员一支由
M/100:84–92 调 M/15:1757–1762 的 /api/music-vip-membership/client/vip/info
{userId} 并同步 data.now；这与凭据刷新和购买确认是不同的链路。M/198:167–213
允许启动时预填同 UID 的四组缓存日期，未预填有声书日期，之后仍做在线读取。
M/224:145–183、M/198:1427–1437 只在五组绝对到期日有变化时，选择最早的正差值
再加 1000ms；M/198:158–160 上限 2147483647ms，到计时点仍执行一次会员读取。
若到期读回仍给出相同的五组绝对日期，虽然活动布尔值可变，也不会自动再安排一轮；
若服务调整日期，且仍有有效组，才重新计时。无有效组不轮询。

Rust 原生 MembershipLifecycle 仅由生产 Tauri 初始化启动，使用已验证账号代次，复用
MembershipManager 的服务时间、单调时钟、账号持久化和现有搜索权益通知。未认证、
注销、旧账号没有新请求；换账号取消旧 GET/定时器，不等待迟到响应。凭据版本变化、
不符 UID、过旧服务时间或保存失败不覆盖已提交权益；只有同账号最近的已验证日期可
重新安排定时器。会员中心与启动共用 manager 和读门，重叠成功的读取合并；独立的
播放质量/下载等显式授权读取仍使用各自 manager，已提交的新日期也能通知调度器。
仅日期变更且权益元组不变时，重新安排日期但不触发综合搜索重查。切到其他账号不会
用上一账号的到期日期作基准；同账号冷启动只在已有的安全缓存可验证时预填基准。
生产前台聚焦或定时刷新登录实验不会新增会员请求；关闭原生任务撤销在途读取。

Cumulus 不附带重跑官方用户详情/认证身份聚合，也不自动重试其中的空响应循环；
超时、服务失败或畸形回复保留原状态，不伪造新权益或轮询。恢复可由下一次认证或既有
用户/播放权益读取触发。原版模型多个效果并发的计时器不会一比一复制，原生只保留
当前账号、当前日期的一条计划。没有支付、会员状态写入或真实账号调用。本轮验证
采用冻结时钟和合成接口，覆盖真实认证启动顺序、切号取消、同/异日期、无重复定时
读取以及长计时器上限，不以 Rust 合成测试宣称 Windows 实机验收。
