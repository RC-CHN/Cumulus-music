歌手发现
========

恢复的官方入口是 ChoiceRoot 的 /choice/artist。PageArtistGallery.tsx:52–88、
113–125 将服务列表交给 WaterfallGrid 和已有 ArtistCard，Selector.tsx:84–147
提供地区、类型、首字母三组独立筛选。M/2248:60–89、139–188 对应默认
全部地区、全部类型、热门，每次读取 20 条，服务顺序追加。

前端「歌手」→ desktop artist_gallery {epoch,query} → Rust MusicClient::artist_gallery
→ M/15:1116–1129 的 /api/v1/artist/list：
  area: -1/7/96/8/16/0（全部/华语/欧美/日本/韩国/其他）
  type: -1/1/2/3（全部/男歌手/女歌手/乐队组合）
  initial: -1 为热门，65–90 为 A–Z，0 为 #
  offset: 页号（从零开始）× 20，limit: 20
原生只投影返回的 artists 和 more；保留服务顺序，过滤无有效 ID、不可显示姓名
和重复项。续页以服务页宽推进，不能根据当前可见卡片数推断 offset。封面仍经过
统一的公共图片投影，不向前端传认证数据、原始回包或服务动作。

Cumulus 将官方精选页的「歌手」子入口放在发现侧栏；没有声称实现整套精选子页。
官方由 more 决定终点，没有 200 条总上限。为约束当前视图和缓存，Cumulus 每批
最多显示 200 个服务位置，按服务页宽划批。批内靠近页尾自动追加，保留键盘可用的
「加载更多」；服务仍有结果时，显式「查看下一批」从第 200、400… 个位置继续，
「查看上一批」从上一批起点重新读取。同一账号最多保存 8 组近期筛选的当前批次，
换号丢弃。读取失败保留已经加载的结果，并在同一 offset 显式重试。快速切换筛选和换号
拒绝旧响应；详情返回保留结果，并恢复发起详情的卡片焦点。卡片播放、菜单和详情
复用既有接口，打开或筛选不写账号资源。当前沿用 Cumulus 已登录发现界面，
未验收官方匿名打开、遥测和 A/B 开关；批次入口是内存约束所需的交互差异。

search_results_smoke.py --artist-gallery 使用真实 Tauri WebView 和合成原生 API；
验证默认/地区/类型/首字母、滚动触发续页、一次失败及同 offset 重试、详情与返回、空结果、
回到已有筛选不重新读取、跨第 200 项继续且视图不超过一批、详情返回恢复第二批，
以及按服务状态终止。
无真实账号或资源写入。
