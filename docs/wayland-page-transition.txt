Linux 主页面切换等待动画帧

现象：在本机 KDE Wayland 的默认图形路径上，隔离合成账号恢复已经完成，
播放器订阅也有响应，但旧启动页保持离场，欢迎页未出现。
在同一会话中切换空输出不影响复现；Wayland 软件图形和 Xvfb 对照均可进入欢迎页。
只记录 DOM 布尔状态及合成 IPC 时序，没有采集桌面截图、文本、账号或请求内容。

原因：主页面 Vue out-in 过渡在下一批动画帧中才开始等待 CSS 完成。
本次原生 Wayland 观察到第二个连续动画帧迟迟不来，计时器和 IPC 仍正常。
旧页因此未释放；只绕过离场也可能让新页一直留在透明的进场起始状态。

处理：仅主内容区负责进出场的生命周期，沿用 90ms 离场和最长 220ms 进场 CSS。
普通情况下在本元素 transform 完成时结束；450ms 的独立计时器在帧未到或
过渡事件未送达时移除所有状态类并完成。取消或卸载清理帧、计时器与监听，
降低动态效果设置时直接完成。未更改渲染器选择、账号恢复、IPC 或其他弹层。

验证：相同默认图形配置的原生 Wayland 仍只观察到一个连续动画帧，
新页面已可见且旧转场类消失。Xvfb 在探针故意禁止交付动画帧时也通过，
两次均只使用合成账号请求。658 个前端测试、格式、类型及构建通过。
此证据不代表底层 GPU 帧调度已修复，也不代表 Windows 或物理显示帧率已验证。

搜索分类结果采用同一有时限的完成机制，保留原 140ms 动画及进入后的
滚动位置恢复。68 状态 Linux WebView 回归在键盘切换分类期间故意扣留
动画帧，确认新分类结果可见、两边状态类清理、焦点跟随新标签。

主页面修复后，原生 Wayland 在关闭均衡器时又复现了相同类型的停滞。
共用弹窗沿用原有进出场、遮罩和焦点恢复，帧或过渡事件缺失时最迟
450ms 释放，离场取消时解除 inert。修复后用隔离合成 WAV 在同一原生
Wayland 会话运行两次：打开、关闭、预设、滑杆、归零通过；重启保持
原曲线和暂停位置，恢复播放后继续处理。libmpv 报告 PipeWire 输出，
测试全程音量为零、无外部网络；不代表扬声器听感。
