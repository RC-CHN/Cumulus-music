Desktop default Windows compatibility mapping

Unset CUMULUS_DEVICE_IDENTITY now selects automatic Windows compatibility mode.
This is native launch configuration, selected before account initialization;
there is no identity selector or raw fingerprint accepted through frontend IPC.

Linux x86_64:
- The request user agent is the recovered official Windows desktop literal.
- osver declares Microsoft Windows 10 Professional build 19045, 64-bit.
- clientSign still uses actual local sysfs facts through the existing Linux
  collector and IdentityService. No Windows MAC, disk or board facts are invented.
- The stored installation persistentID is reused. Existing account deviceId and
  saved credential records are not replaced by the compatibility declaration.
- If the Linux collector specifically returns hardware identity unavailable,
  the automatic default retains Windows declarations with no clientSign, so
  sandboxed hosts with no readable hardware can still start. One static native
  warning per process states that no local signature is available; it exposes
  no hardware facts, IDs or credentials. No identity state is opened by this
  collection fallback and no fields or persistentID are invented.
- Other collector errors, invalid persisted identity, corrupt storage and failed
  persistence propagate when local facts are available; they never trigger the
  no-hardware fallback. The fallback occurs only at the collector boundary,
  before storage is accessed, and never catches storage or identity errors.

Windows x86_64:
- Default and explicit windows-local use the same official compatibility UA and
  osver declaration, with no extra clientSign.
- These modes do not invoke the Linux collector or initialize identity state.
- A real Windows hardware collector remains unimplemented. This declaration is
  not evidence that Windows WMI/SCSI collection, native signatures or a Windows
  runtime roundtrip have been verified.

Native launch overrides:
- CUMULUS_DEVICE_IDENTITY=native restores the previous platform-default UA/osver
  behavior and supplies no local hardware clientSign, on both supported systems.
- CUMULUS_DEVICE_IDENTITY=local retains the native platform profile plus real
  Linux local facts. It remains unsupported on Windows.
- CUMULUS_DEVICE_IDENTITY=windows-local selects Linux local facts with Windows
  declarations and still fails if hardware is unavailable. On Windows it uses
  declarations only, like the automatic default.
- Empty, unknown, misspelled and non-Unicode values are rejected.

The existing native Watchman host recognizes the official Windows UA and enables
its bounded read-only WindowsBrowserIdentity mapping, including Win32 and locale
mapping. This change does not replace global navigator properties or move secrets
to the frontend. Compatibility declarations do not authenticate an account,
grant permissions or establish feature entitlement.

Added construction-mode tests cover Linux synthetic sysfs facts, retained IDs,
the default-only missing-hardware fallback, strict explicit local modes,
unrepresentable facts, corrupt databases, invalid stored IDs, transaction
failures, unsupported local collection and the Windows no-collector/no-signature
path.
They avoid process-wide environment mutation and live accounts. These tests
passed in the Linux workspace batch (305 programs, 1621 passed, no failures or
ignored tests), alongside strict all-target Clippy, format and native build.
The final WebView batch and its precise scope are recorded separately; the
construction tests do not prove actual Windows startup or WebView behavior.
The final 23-state Linux WebView probe also constructs native_profile with the
override unset and checks the official Windows declaration; the physical desktop
run uses the same native path. It records only signature presence, not facts or
signature bytes. See login-notices-validation.txt for screenshots and boundaries.
