2. Windows 原生桥、调用次序及失败

- M4:14663–14716 发 app.recognizeMusic(guid)、app.stopRecognizeMusic(guid)、
  app.clearRecognizeMusicCache(guid)，并通过 app/RecognizeMusic 注册
  回调；M1190:58–70 的兼容导出还订阅 app.onRecognizeMusic。
  Native ED1D77/ED1D94/ED1DEB 将三者分别注册到 ED1360/EDEF80/EBDC10。
  ED1690–ED16CA 与 EDF2B0–EDF2EA 提取字符串，再转 2FA690/2FA960；
  这些入口未见浏览器麦克风授权或账号资格判断。
- 2FA690 准备识曲控制对象、带当前 GUID 建任务；2FA7CC 缺工作对象
  写 -2，2FA865 入队失败写 -3，2FA8F5–2FA905 把失败送回统一回调。
  WASAPI 2F8610 → 30A040 默认走系统 eRender/eConsole 输出回采，
  不是当前客户端指定输出或麦克风；默认设备、显式 ID、格式、辅助
  render 分支见 host 契约。启动、worker 和终态失败不等于“歌没命中”。
- 2FA960 停止入口在 2FAA1C–2FAA3D 比当前 UI GUID；匹配走
  2FAC50/2FAFC0 后续清理，另在 2FAAB5–2FAB44 路径投递 stop job。
  EBDC8B → 2F8560 投递另一个 cache 清理 job。两条链不能合并成一个
  必定即时中止的操作；没有实际驱动/网络竞态证明。Native 3078A4
  还检查内部任务代际，不用同一 UI GUID 去匹配所有状态。
- Native 2F89E0–2F9047 构造 guid、sessionId、code、httpmsg、
  recordtime、responsetime、times、duration，调用 app.onRecognizeMusic。
  M377:39–42 将回调取第一个参数，M3157:372–385 再 dispatch onRecognized。
  回调收尾会清活动 GUID/缓存、置前窗口（M3157:248–309），但 JS

3. 原生请求客户端、授权上下文和返回码

- M318/M841/M18 与 EC7843→33D450→315330 的宿主 e_url 配置见
  host 契约。3138A5–313977 用 e_url 拼 /music/audio/match，
  在 313977 构造通用原生 curl 请求对象 2FFE90：默认实际 POST
  https://music.163.com/eapi/music/audio/match；CE42F0 规范路径
  /api/music/audio/match。不是 WebView fetch、旧 /api/music/matcher、
  文件匹配、通用 PC 域代替地址，也不从回包接受新目的地。
- 3146E6–3147E0 显式装外层 User-Agent: Windows_Curl;、os: pc、
  Referer: music.163.com（没有 scheme）和 Cookie。314665–314692
  先把配置 e_url 传 3375D0→3371F0；3372AF 后比较 URL 解析所得
  host 和管理对象配置（337306），可用本地 Cookie 回读 3369D0；
  否则 3377D0 路径尝试初始化，失败返回空串。这里不是新的登录会话、
  账号硬件凭据或 Cookie 跨域许可。应用只能给可信最终 HTTPS origin/path
  绑定本次账号代际内已有授权 Cookie；游客资格、风控和实际服务未验。
- 加密 JSON 的 deviceId 来自 SystemHelper 32B770（现有恢复 asm
  含 localware、neteasecloudmusic、Device ID 日志），不是此路径从扫码
  凭据 DTO 读取；clientSign 来自 32D5C0→32DA30→CEE370 的 mask=15
  设备标识入口，314967–31497B 用 CP_UTF8=65001 转窄串。日志
  “Get AD ID Failed.” 单独不能作为 Windows 广告 ID 的依据。
  314651 取的 OS 版本缓存不进入已见五字段 header；保留 appver、
  os、deviceId、clientSign、每次 GetTickCount 的十进制 requestId。
  设备身份、会话 UUID、URL 签名、账号/风控是不同概念。当前 Rust
  fixture 只接受受限可打印 ASCII；未来使用真实身份需另证编码、
  转义、作用域和资格，不直接复用凭据 deviceId 或伪造默认值。
- 默认 Content-Type 已从下层确认：2FFE90 的 3000B3 初始化 +0x180=1，
  +0x2E8 默认空（30023A–300243）；识曲路径设置普通 POST、无附件，
  314EED 设置原始 params=... 正文。3033DE–30340F 选 CURLOPT_POST，
  3037E4 添加 Content-Type: application/x-www-form-urlencoded，
  30384E–303861 以 CURLOPT_POSTFIELDS 写正文，303B6D 加空 Expect:
  取消默认 100-continue 期望。引用 A/00314510.asm、
  A/00303130.asm 和 DLL 2FFE90 初始化；已恢复的是普通识曲分支，
  不是其他附件或文件匹配通路。
- 303BB4 是 curl_easy_perform；303C1A 的 0x200002 是 CURLINFO_RESPONSE_CODE，
  单独写 +0x138。303BCC/30423F 返回 +0x2A8 的 curl/native 执行码，
  314F52–314F5E 保存此码，314F7C–314F92 从 304310 另取响应正文，
  31508F/3150AB 装任务。不能将 HTTP status、原生执行码、正文 JSON code
  混为一谈；可见正文随后走 JSON 解析，没有证据说服务的所有响应都明文，
  也未见在该读回点先调用通用 Rust decrypt_response。
- 通用 curl 3034F9 配 FOLLOWLOCATION；2FFE90 默认 +0x2E4=0 不启用
  304136 的自动重试，+0x2E0=-1 不走覆盖总超时配置。识曲代际的 16 秒
  门控是另一层。未来生产适配须拒绝跨 origin 重定向、明确短超时及停止，
  不能把通用 curl 的行为等价为可以追随重定向携带 Cookie 或无限挂起。

4. 结果转为可播放曲目

- Native 正文 code==200 且 data.type==1 的提前命中门槛与第五次
  收尾见 request 契约；页面 M3157:51–102 单独映射桥 code：
  0/200 完成；负数 timeout；其他正数 offline；缺码 unknown。
  对 httpmsg JSON.parse 后取 data.result[].song，以当时 host.uid
  走 M21.D/x 的曲目规范化。完成无曲目才为 NOTRACK。
- M21.x（537–558）把 track.id 转为字符串，保留规范化歌名、艺人、
  专辑、版权状态等；M3157:337–368 等 500ms 后以这些 ID 调 M15.Dg
  /api/song/enhance/privilege，正文 ids 是字符串数组的 JSON 文本，
  不传 trialMode；取 data。M21.e（683–706）按 ID 合并当前 uid 的权限，
  同 ID 最后值胜。进入结果页及已购资源、会员状态变化触发补读
  （ResultView.jsx:88–92、152–176），不是在采集开始时或每个分包补读。
- 结果卡首项默认展开，不自动播；点卡片只切当前项。TrackCard.jsx:
  158–202、250–295 显示封面、歌词状态和当前曲目的进度，圆形播放按钮
  使用 ResourceType.track、Scene.listenToSong。通用 RoundPlayButton
  根据是否当前曲目/正在播，在 pause、resume、playAll 之间走既有
  动作；并无识曲专有试听/下载 URL。喜欢、收藏、下载、分享、下一首
  均是单独显式动作（Operation.tsx:64–163）。上传音频反馈另有用户选择；
  识曲成功、超时或播放失败都不能自动触发上传。
- Cumulus 的 Scheduler 只保留安全候选 ID。大于 JavaScript 精确范围的
  JSON 数值不采用；正十进制文本保留前导零和超过 u64 的值，限 64 字节，
  一轮最多 100 条，重复保留，且不存识曲回包正文。内部
  core/src/client/recognition_results.rs 绑定同一个 Scheduler 的原生完成代际
  与 AccountSession 的 UID/epoch，只有认证账号的当前成功结果可以发起读。
  关闭、切换账号（包括同 UID 新 epoch）、新一轮采集和同一结果的新一次读
  都会让旧读失效；500ms 等待和最多 8 秒远端读取有取消检查，返回前再次
  核对账号与读取代际。未来接入层仍须对延迟交付的界面更新核对当前代际。
- 权限走现有 CatalogApi::privileges(ids, None) 及已绑定账号的通用 catalog
  传输，不另设识曲签名或固定 cipher。只读回候选本身的权限，同 ID 最后项胜，
  缺失留未知，忽略额外条目。由于 Scheduler 目前不携带原始歌曲元数据，当前
  并行补读 /api/v3/song/detail；这是本项目额外的目录读，不是官方页的第二条
  请求。详情回包的内联权限不会替代独立权限请求。结果 DTO 保留候选顺序、重复
  和无元数据的条目，只投影名称、艺人、专辑、时长、fee 和非授权性质的权限
  观察，不带 URL、账号 UID 或回包原文；失败也只返回精简的类型和数字状态。
  匹配和权限观察都不授予播放资格，
  仍须正常播放来源授权。用合成传输验证请求与失效分支；未接生产调用、真实
  识曲服务或结果页，不宣称可识曲开播。

5. Linux 启用门槛（产品边界，非官方 Linux 行为）

- 明确入口点击后才建立一轮捕获许可；不因历史页、恢复窗口、网络恢复、
  默认设备切换或一个未知外部启动参数自动打开音频。事前明确提示
  “只识别所选电脑输出正在播放的声音，不使用麦克风”；说明会向
  已授权的识曲服务发送派生指纹，拒绝后不暂停也不打开设备。
  确认目标及服务许可后，只暂停当前自己会话的活动音乐；确认失败
  不开录，不停止其他应用、不切换输出、不自动恢复先前音乐。
- 官方 Windows 选系统默认 render，而 Cumulus 的 mpv audio-device
  是配置名，current-ao 只是驱动（core/src/playback/engine/mpv.rs:
  565–577），不是实际 sink 证明。Linux 必须由音频服务器提供明确
  当前选定的 render sink；确认它的 monitor_of_sink、名称、索引
  和服务器实例绑定，不能把名字包含 .monitor 当成证明，也不查默认
  source。没有权限、选定输出消失/改变、服务切换、格式不可支持时
  停止；不移流、不改默认 sink、不重建播放引擎、不切麦克风。
- 现有私有探针证明本机显式 Pulse monitor + DONT_MOVE 和每次读前
  核对可用。生产的用户级 Unix 音频服务需要独立的可信发现（权限、
  本机连接及服务器生命周期），不能照抄仅在私有目录/PID 启动的
  合成条件，也不能使用 pactl/parec 子进程代替生产适配。纯 ALSA、
  独占设备或未知 monitor 关系当前保留不可用状态。
- 先撤销本地 generation 再取消设备/请求；取消、离页、账号变更、
  输出变更、网络掉线和超时都停止并释放原生流及有界缓存。拒绝
  迟到回包、不自动重试、不存储 PCM/指纹/响应正文。验证要求至少：
  私有双输出（一个默认干扰）正向采样，取消和正在发包时换输出，
  移除/重启音频服务，证明正常播放设备与其他流未改动；然后在独立
  用户授权下验证真实客户端环境。真实服务资格与提交指纹授权必须
  单独成立；当前合成往返通过不构成授权、上线或播放结果证明。
