Signed same-window read proof: transport gate
=============================================

desktop/examples/support/signed_window_read_gate.rs is a research-only Linux
component, with no connection to the production entry point or renderer. The
caller must supply the selected PC Credentials from a private copy, the
production local ClientProfile, a validated saved PcConfig snapshot, and an
independently authorized expected UID, fixed public query and selected public
song ID. The gate has no network constructor. Tests use only injected fakes.

The gate reconstructs the exact current `build_request` wire for every permitted
request. It compares the prepared headers, encrypted business fields, exact PC
origin/path, account-scoped Cookie jar, saved native MConfig header, device and
clientSign. Credential revision/identity is checked against the original scope.
No batch, mutation, login, renewal, SDK token, cache URL or unrelated query is
permitted. No request is retried. The caller must separately fence egress and
disable redirects/retries in the injected transports, before dispatch; rejecting
a returned 3xx alone is not a network isolation mechanism.

Account/get must return the independently selected UID before any other read.
The owner's playlist list allows at most 16 consecutive pages of at most 200
items each, advancing only by the actual row count. The list may include
subscribed items; completion is not proof that every row is owned. Liked IDs
are one bounded read with the same expected UID. A single default keyword read
is optional. The query requires the complete native 190-key experiment vector,
chooses exactly one V1/V3 comprehensive branch, and reads result/tab first for
V3. The fixed query uses the current SearchBox `typing` channel and the first
Songs waterfall page (limit 10, offset 0). No corrected or alternate keyword is
admitted. Exactly one matching song from that page permits one detail and then
one source request, with `standard`/`aac`/`c51` and the current SearchNextPlay
scene 42. A different account, credential rotation, malformed/partial reply,
HTTP redirect, error or interrupted transport closes the gate. Declared EAPI
encryption is decoded for validation; the unchanged original body is returned.
No Set-Cookie or fresh configuration response is applied by the proof.

A valid single nontrial source reply authorizes one exact normalized CDN URL
for a brief period, with expected size and MD5. The verifier issues one offset-0
GET without Range or If-Range through the injected credential-free media backend.
It requires HTTP 200, a complete identity-encoded body, unambiguous declared
length, matching byte length and MD5, and returns only a private anonymous file.
A failed or cancelled fetch cannot retry or substitute another URL. The proof
does not print response bodies, URLs, cookies, UID, signatures or source hashes.

Reproduce the closed Linux checks:

  npm --prefix frontend ci
  npm --prefix frontend run build
  cargo test --locked -p cumulus-desktop --features custom-protocol --test signed_window_read_gate

The suite uses the actual current Rust request context and both search cohorts
against fake API and media transports. It is not evidence of a real account or
GUI playback. The next stage needs an isolated HTTPS broker and a current
production Vue/Tauri window consuming the anonymous file through the real
MpvEngine pinned-descriptor path. Historical real decode 8771a8fc happened in a
second brokerless process; historical same-window ordinary libmpv URL testing
at c8ceda86 used synthetic audio. A pinned file handoff in the current window
would prove same-window native decode, not direct upstream URL playback.

Closed synthetic desktop shell
------------------------------
`signed_window_read_ui_probe --synthetic` uses the production Tauri configure
path and the embedded Vue assets. The executable rejects an ordinary network
namespace and uses a new proof profile with synthetic PC credentials, a fixed
query, one playlist and one liked song. Only the fixed in-memory PC/CDN
responders are wired; ordinary download transport and auxiliary SDK/config
requests are closed. The proof opens My Playlists, checks the liked song in
the Songs search tab, and uses the row's Next Play action on an empty queue.
The gate's one authorized AAC response goes into an anonymous, mode-0600
file and the same window's playback controller decodes it through the real
libmpv pinned-input path. It checks advancement, a stable pause, resume of
the same logical entry, and stop. Physical audio output is disabled.

After the production frontend build, compile and run in a private namespace:

  cargo build --locked -p cumulus-desktop --features custom-protocol --example signed_window_read_ui_probe
  sudo unshare --net --fork --kill-child runuser -u "$(id -un)" -- \
    xvfb-run -a -s '-screen 0 1440x1020x24 -nolisten tcp' \
    env -u AT_SPI_BUS_ADDRESS -u AT_SPI_DISPLAY -u NO_AT_BRIDGE dbus-run-session -- \
    env GDK_BACKEND=x11 LC_ALL=en_US.UTF-8 LIBGL_ALWAYS_SOFTWARE=1 \
      WEBKIT_FORCE_DMABUF_RENDERER=1 WEBKIT_DMABUF_RENDERER_FORCE_SHM=1 \
    /usr/bin/python3 scripts/ci/signed_window_read_smoke.py \
      --binary .build/target/debug/examples/signed_window_read_ui_probe \
      --root .build/ci-signed-window --screenshots

The driver's report binds the actual embedded asset set and probe binary by
SHA-256. Screenshot barriers keep each frame tied to its named native state.
Only result counts, action categories and clock observations enter the report.
This is the same-window synthetic pinned file proof; a supervised HTTPS broker
and independent real-account input remain separate work. It proves neither
real-account playback nor direct upstream URLs through libmpv.
