CI 耗时对照与验证
================

基线：42566059738 attempt 2（adaf75b6）。作业最终失败，以下是已发生
的耗时，不推断旧失败后的尾部或完整成功时间。分阶段用 Actions jobs
API 的 started_at/completed_at；长步骤内部从未截断的原始行时间核对。

- Linux 打包约 22 分钟；之后 Linux WebView job 约 82 分钟。后者的
  广泛回归步骤约 70 分钟，其中实际记录的 Cargo 完成时间合计约 65 秒；
  已识别的一段独立桌面检查用时约 36 分钟。
- Windows 打包 job 约 110 分钟。媒体运行库约 18 分半，正式包步骤约
  33 分钟，其中两段 Rust Release 编译约 30 分钟；包启动等专项约
  11 分钟；广泛桌面回归约 42 分钟时终止在旧下载验收错误。
- Windows Native 的 9.91 GB cache 下载/保存各约 4–5 分钟。Windows
  Package 曾匹配相同前缀但下载最终失败；该缓存由 debug/test 构建写入，
  不能据命中日志推断已预热 Release。Linux 现有约 101 MB cache 只含下载。

试验：仅 Windows Package 的正式包步骤允许 Cargo 三个并行编译任务，
全局、Native、测试和桌面回归仍用 2。源码、锁文件、媒体库、包内容
检查、门禁和发布来源校验不变。未在 Windows runner 测得缩短，不能
用理论并行度外推整条 CI。比较时记录相同镜像/锁文件/缓存条件下的
两段 Release 编译、打包步骤、CI gate 总耗时，以及缓存实际传输、
内存/磁盘和链接失败；另测长桌面回归分组的独立 runner 耗时。

并行候选
- Linux：独立编译一次 ux_ui_probe；一组仍等包以核对滤镜/FLAC，一组
  不等包，独立跑下载、搜索和播放器等 85 个场景。二者只接收同提交、
  同次运行/尝试、完整 SHA 校验的共享探针和前端文件。测试自身依然串行，
  避免焦点、键盘输入、音量或临时 DBus 互相干扰。
- Windows：保留正式打包、包内验收及使用 MSYS2 测试编码器的本地队列。
  其余 277 条 WebView 检查分给 playback、search-account、catalog 三个
  runner；各自核验同一次 CI 的已校验 ZIP、实际运行库及共享探针。
- 对照原工作流的验收命令，未省略任何平台检查。184 项脚本检查中 183
  通过、1 项只适用于 Windows；复原的同一实际 Linux ELF 在独立环境
  跑过搜索密度和 V3 播客播放，保留 16 张合成界面截图。详见
  .build/ui-proof/phase171-ci-parallel-review/。
- CI gate 和 CD 同时要求新分组成功；仍只有原两个包产物能进入发布。
  待完整 hosted 运行后，比较 package 开始至各依赖 lane 完成的关键路径；
  不把本地单场景耗时、旧失败时长或 runner 分组数量当作提速测量。
