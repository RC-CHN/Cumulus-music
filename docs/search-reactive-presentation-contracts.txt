================================

  见 pc-presentation-lifecycle-contracts.txt。M3095:1688–1690 同一 connect

  1991 将独立 footer 开关交给歌曲卡片；M2071:255、480 消费 footer。

Rust 本地候选
- core/src/client/search/presentation.rs 在综合结果已经类型化后、应用 footer
  开关之前保存候选。只保留区块 ID、行位置、曲目 ID、歌词/别名提示和类型化推荐
  理由。候选不含原始服务包、Cookie、媒体 URL、完整权限或播放器命令。
- 每区块最多六首歌曲，页面限 16 条，解析后的候选 JSON 每页最多 2 MiB、
  总计最多 8 MiB；命中提升 LRU 顺序。预算不是进程 RSS 或临时序列化峰值承诺。
  超过单页限制不签发 receipt，普通搜索结果仍可使用。
- receipt 随机且不持久化，绑定 SessionToken、实际 API 对象及私有 credential
  revision。publish/resolve 前后核对凭据；账号/API/凭据变化后旧 receipt 无效，
  即便相同账号新分组又为 t1，也不能复活旧凭据下的候选。
- 综合 V1/V3 在各自真正发送结果请求前记录该私有 revision（V3 的 tab 查询
  已完成）。如果结果本身通过 Set-Cookie 换了凭据，旧结果可保留普通条目，
  但不显示 footer，不签发候选 receipt，也不沿用旧布局；新分组恢复 t1 后只有
  以新凭据获取的页面可签发新候选。旧结果不自动重搜。同凭据下分组更新仍按
  最新全局表现重投影，不把 cohort revision 当作请求凭据版本。
- 官方 M3095:3940–3969 完成 tab 并设 tabsUpdated，:1728–1736 随后派发 complex；
  M3001:543–549、568–576 在 effect 开始重新读取 PH-PC-searchHot 选择 V1/V3。
  Rust 保留这个时点：如 V3 tab 在途期间全局切到 c，结果直接请求 V1、用固定
  tabs，不再查实验、不重发 tab、不持久化被抛弃的动态 tabs；下一次真实 t1
  仍可读动态 tabs，失败时用上一次已接受的动态 tabs。
- search_presentation(epoch, receipt, revision) 只重投影已有候选。全局表现版本
  必须仍然当前，回复只含 receipt/revision/layout 和窄字段补丁。前后检查来源，
  不发送 HTTP、不初始化音频、不重跑搜索，也不覆盖 VIP、限免、原曲/替代 MV、
  收藏或 playAllIds 等其他业务字段。

桌面与前端
- desktop::pc_presentation::start 是 native setup 的显式入口，拥有唯一 core
  runtime lease 和 watch observer。主窗销毁/退出均幂等清理；主窗本地 snapshot
  IPC 可建立被动事件转接，但不会启动远端读取/定时器。没有 renderer 强制分组
  或刷新接口，也没有接收前端授权 URL、Cookie 或分组输入的入口。
- App 先监听后取快照。前端用原生十进制 u64 revision 比较，不用到达顺序；
  旧事件、非法版本或同版本冲突被拒绝，账号边界清空缓存和版本水位。
- 关闭 footer 时立即清除当前页和全部 Back 缓存的提示/理由；开启后凭原生
  receipt 恢复。Back 等待本地重投影期间不先展示旧 footer。receipt 缺失、淘汰
  或失效时保留普通结果并隐藏提示/理由，失败不自动重新搜索。
- 表现补丁合并到最新结果，不能覆盖同时完成的权益刷新。布局使用既有 keyed
  节点，保留滚动、正常键盘焦点及播放；控件被移除时只尝试同卡片/区块的可用
  控件，不抢走用户已经移到搜索框等位置的焦点。

验证入口及限度
- core/tests/pc_experiment_transport/search_presentation.rs 使用真实
  MusicHttpClient/PC 请求上下文/EAPI，后端封闭；校验 t1→c→t1 仅增加完整
  实验读取，不重发搜索，旧版本/账号/凭据失效及 ordinary DTO 保留；另覆盖
  搜索响应真实提交合成 Set-Cookie、同账号新 t1 后旧页无 receipt 而新搜索有。
- search_footer.rs 暂停真实 EAPI tab 响应，让同一 UID/凭据的全局完整分组
  先切 c，再交付不同 tab，核对 V1 精确请求序列及下次 t1/Tab 403 的旧缓存。
- 私有单元覆盖候选预算、LRU 和来源边界；前端测试覆盖乱序、Back、失效 receipt、
  权益更新的两种完成顺序、焦点与滚动策略。
- scripts/ci/pc_presentation_smoke.py 在实际 WebView 通过封闭服务器响应改变
  分组，触发同一 native fullbatch 路径；该测试不通过 renderer 直接改布尔值。
  原生 paused-time 测试验证周期，桌面脚本不等待实际 30 分钟。实际执行记录另见
  rust-core-validation.txt、ui-ux-validation.txt；测试入口存在不等于通过。
- 合成测试使用 null 音频输出，不代表实体声卡或真实匿名注册服务；真实账号只读
  搜索的独立证据见 search-signed-live-read-proof.txt。

本轮 Linux 复验：生产前端和 Tauri 在隔离账号中通过 10 个检查点。6 次真实
签名夹具实验读取、2 次搜索请求（Tab 与综合），4 次本机表现重投影，没有因
分组切换或返回页面重发搜索。深色实拍中，对照组撤掉歌词/别名/原因，恢复
t1 后按原位置恢复；保留搜索滚动、播放暂停和卡片焦点。10 张截图与报告见
.build/ui-proof/phase66-pc-presentation-r1/。Tab 与综合回包各自轮换凭据的
分支由另行签名传输测试验证，不把该图形复验当作真实账号凭据轮换。

搜索脚注的迟到签名复验：渲染层先清空无授权脚注时不把本地遮蔽后的内容视为
已应用目标签名修订；权威事件或查询返回随后可按同一个真实修订重建脚注。两种交错顺序
均有定向前端回归。合成 Linux 真实 WebView 的 t1、c、未知分组、签名失败四组分别
显示 3、0、0、0 项，保留应有播放与返回，未额外发出查询或访问真实服务。14 阶段、
14 张截图与签名传输记录见 .build/ui-proof/phase85-search-signed-r1/。
