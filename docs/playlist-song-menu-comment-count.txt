普通歌单单曲菜单的评论数
========================

官方 PC 3.1.42.205594 的 playlist/views/TrackList.jsx:235–240,313–348
把歌单 ID 和 Scene.playlist 交给曲目表；TrackTitleCell.tsx:729–745 将点中
Track 和父列表的选区交给菜单。M556:144–229 在打开菜单之前读取这个
Track 的评论数；本地、云盘、miniBar 或 songType=1 不显示此项。M21:537–560
从原歌曲 t 得到 songType；会员收费或负版权本身不影响评论入口。
M3085:4565–4615 表明菜单等待异步检查完成后弹出。带私有云盘标记
的资源不被当成公开单曲来读计数。

详情及权限均未返回的歌单条目：M2997:415–450 只将详情格式化返回的行写入
trackEntities（:107–126）。TrackList.jsx:108–128 遇到未解析的原始 ID 会中断
当前展示范围，这个 ID 不会自己成为 TrackTitleCell 或 M556 菜单资源。
Cumulus 为保留位置和本人歌单管理入口显示「暂不可用的歌曲」占位；这不是
已验证的 Track，不显示评论也不读评论数。M21.B:683–705 还存在只收到
单条权限信息时合成最小实体的分支；本合成遗漏样本没有匹配的权限行，不据此
判断该分支的实际显示和菜单。

读取：POST /api/resource/commentInfo/list（M232:824–842）。
字段仅 resourceType=4、resourceIds=JSON.stringify([准确的歌曲 ID])；
不批量读取整张歌单。沿用 CommentApi，要求恰好一行且 threadId 等于
R_SO_4_<歌曲 ID>，计数必须在 JS 安全整数范围内；不使用缓存。
正数附在「查看评论」后；零、超时、错线程或读取失败显示普通文案。
点击仍走已有的歌曲评论页和原线程，不修改评论、歌单或播放状态。

前端只在普通歌单主页面读取时给现有 playlist_page 传 songMenu:true；
批量选择器、混排设置和离线缓存不取得该回执。原页仍通过
现有歌单读取拿歌曲和原始类型，不为了打开菜单重新查歌单。Rust
playlist_song_comment 从有效原始投影签发不透明行回执，绑定账号代次、
API、歌单及其服务端/本地版本和准确的行；后台一般读取不替换这个访问，
新的活跃访问会替换。重读同一段会以当前原始投影为准。在线时长排序只为
仍匹配同一已观测访问的完整投影保留或补发原始行凭据，不增加业务请求，
也不会把视觉排序位置当成歌曲 ID。切回原始顺序仍用相同的行身份。
返回长歌单可以恢复前端保留的后段；只有新首页确认同账号、同 API、同歌单
及顺序与本地版本，并且该原始行位置还未重新读取时，才接受短期内存中
已观察过的后段回执。已重新读取的行以当前数据为准。旧后段记录有界、
不持久化（最多 8 次旧访问、合计 10 万条可用行、30 分钟），不为它重读
整张歌单；失效或驱逐时仍能打开普通文案菜单。

主窗口 playlist_song_row_comment_count 接收 epoch 和 receipt，只对
回执里的歌曲读一次，1.5 秒无结果走普通文案；前后校验本地版本、账号
和访问。前端在真实菜单打开前等待，仍检查原路由、选区、锚点及取消
信号；迟到响应不得弹出旧菜单。当前多选直接省略评论项和查询；
官方部分组选区在隐藏前可能仍读取点中行，未复刻这条冗余读取。
这份契约只覆盖普通歌单的歌曲行；不把搜索、队列、下载、历史的
专门菜单或离线结果声明为已通过。


验收与复现
scripts/ci/playlist_menu_smoke.py --song-comment-count 通过生产 Vue、Tauri
命令和原生 CommentApi，与真实账号隔离。Linux 在仅回环的 Xvfb 环境运行；
Windows 交给相应 CI 使用同轮打包的媒体运行时（--runtime）。复用现有
ux_ui_probe，不另外构建。Linux 的 14 态覆盖三种菜单入口、计数与原评论
线程、零/错线程/传输失败、特殊歌曲、迟到响应、排序往返、以及从另一张
歌单返回后点击保留的第 101 首。请求记录精确核对返回只读取首页、没有
自动查评论数或改动账号。该轮使用合成数据，不能证明实服结果或 Windows
实际界面；截图与回执在 .build/ui-proof/phase307-playlist-song-comment-count/。
