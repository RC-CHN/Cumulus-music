原生表现宿主
- client/pc_experiments/{presentation,store,runtime,anonymous}.rs 与原 shared
  fullbatch gate 共用实际 transport；不使用 Tauri 或 renderer 轮询。宿主只投影
  searchHot、search-result、searchMore2、searchPageEfficiency 四项 t1，其他组
  仍由既有原生消费者各自读取。完整请求保持固定 190 键及顺序，没有新增 short3。
- pc_presentation() 是本地快照；subscribe_pc_presentation() 是 watch；
  start_pc_presentation_runtime(&self) 返回唯一 Native RuntimeLease；Drop 取消，
  shutdown 等待退出。第二 lease 返回 MutationBusy。refresh_pc_presentation()
  仅供原生启动/主机事件及封闭测试，生产 IPC 不接受 renderer 强制 cohort。
- View 是 epoch、单进程单调十进制 revision 和 searchFooter/searchExpanded/
  searchDense。内部 snapshot 另持 search_v3，只有可信 native capability 可供
  endpoint/reprojection 使用；generic Api 的默认本地 false 不覆盖旧三桶选择。
- 同一 token/API/credential revision/owner 内表现稳定则保留 revision；身份/实际
  凭据/API/匿名私有 UID 改变先生成新 revision。watch 最新值和 snapshot 竞态可用
  revision 比较；内部 is_current 供投影前后同步验证。此 revision 不是授权 token。
- 同进程同 token/API/owner 已知发生 credential rotation 时先清空四项表现，直到
  当前上下文新 live 成功；不得重新加载该 owner 旧 t1 来覆盖本次凭据交付 fence。
  初次宿主 bootstrap 或正常 owner 切换仍读 owner 最后持久表现，不新增持久化
  credential hash 权限门槛。新旧凭据之间这种保守清空是明确的分发隔离边界。
- 初次、账号 watch、实际凭据提交触发读取；固定 30 分钟 interval 不随账号变化
  重置，错过 tick 不补发风暴。generation 在取样后前进只重绑到最新 watch，不让
  一个仍持有的 lease 静默永久停掉。正在读取时 Drop/账号变化取消旧结果。
- Credentials 只在实际存储 CAS 提交成功后通知；普通响应逻辑相同（包括
  CookieStore 顺序不同）时不换 revision/不发通知。clear、invalidate_login
  与显式 import_legacy 是撤销/替换屏障，即使结果字段相同仍持久换 revision
  并通知；空会话退出也必须拒绝此前在途的登录回包。一个 AB 响应自发凭据轮换可立即
  重读一次；连续轮换进入 CredentialChurn，等待后续外部变更或下一周期，避免
  自响应无限请求。这是本实现的有界恢复策略，不声称原客户端同样只有一次。
  若 Cookie commit 与 refresh 返回发生在同一次 poll，result 分支同样消费实际
  变更并计入这一次重启，不能在底层 watch 中把它再次当作新外部通知重开预算。
  先订阅并标记 watch，再读取实际凭据版本；成功回执必须匹配返回 fullbatch 的
  bound revision。匿名注册本身 r0→r1 不触发重复读，但回执 r1 之后实际已到 r2
  不能借“注册自身变更”吞掉通知。取样之后的 commit 留作下一条未读 watch。

持久表现不等于新鲜权限
- Registry 根存储按 verified UID 或 anonymous:<privateUID> 分隔四个布尔值；
  local-guest 不从别人的 owner 恢复。文件不包含 Cookie、签名、客户端配置、
  opaque logs 或签名 URL。新 schema 缺失才兼容迁移旧 owner 下
  search-experiment-v1/assignment-v2 的 v3/expanded/dense，永不从旧数据产生
  footer。新记录为 c/损坏/不兼容时均不复活旧 t1。
- 仅成功 live fullbatch 写入 Assigned/fetched，fresh consumer 原本的严格 30 分钟
  TTL 不变。持久 bootstrap 与 latest-successful display catch 都不能供自动跳歌、
  评论写入、素材/权益等 dispatch 授权。服务 403 后可继续显示旧表现，但同次
  fresh-authority read 必须失败。存储失败不伪装成功落盘；运行期有原生状态区分。
- phase66 按 M147:2966–2969 区分实际 full reply 与同进程 fresh cache hit：只有
  实际成功回包更新持久表现，重复读取鲜活 native assignment 不写 SQLite、
  不发新表现版本。账号/API身份切换与同步的 bootstrap/persist/watch 发布共用
  native account fence；同一个宿主内在表现锁内取样凭据，避免旧线程盖回新上下文。
  匿名 UID 读取如发现凭据版本与刚取样不一致，拒绝这次快照；不先掉入 local-guest
  再为同一匿名 UID 重新读回旧桶。凭据和 registry 仍是分开的存储，本实现不承诺
  跨数据库事务；凭据版本在持久表现写前后都核对，旧回执不更新当前 watch。
- 本批只保证已映射四个表现键的 owner/cache/reactive source，不持久完整未知
  官方 localStorage 对象；其他模块的表现迁移继续按具体源逐项接线。

匿名注册前置与安全状态机
- M115:106–110 先复用已存 anonimousToken，否则 native encodeAnonymousId
  (M18.deviceId)；M100:54–60 固定 M15.Af({username})，只严格 numeric200 且
  truthy userId 返回 UID；M15:1312 是 /api/register/anonimous。
- M198:645–679 的已完成分支要求 UID 与 Cookie.getAll，有界实现保留这两者。
  官方会循环到 UID；本实现最多重试三次“完整 numeric200 但无 UID”明确回执。
  网络断开、未知/部分回执、发出后取消/超时均留 durable Sending→Uncertain，
  不自动重播注册。未实际 dispatch 才恢复 Prepared。事务只允许缺失/Prepared
  转 Sending；另一个 caller 已完成 Registered 时不能重新打开该写操作。
- 编码器与真实原 DLL 38 个冻结输出向量见 anonymous-identity-native-contracts.txt；
  Rust &str 不承诺 UTF16 孤立 surrogate。注册本批没有线上发送；38 个编码器
  原生向量不代表真实服务注册成功。原生设备/签名上下文继续复用当前安装来源。
- 默认运行期早于前端 restore。Unknown 未完成恢复不得注册；实际 native
  account/get 明确 301 且本来无登录时，private guest_ready 通知相同 token，
  不改公开 Unknown、不给 Expired、不增 generation，不取消并行 QR。SignedOut
  可进入 guest；已有 MUSIC_U/待恢复登录或 Expired 不借此新建匿名会话。
- 使用安装私有 guest store 和独立 MusicHttpClient，只复制同安装 deviceId 与
  已有 PC profile/context，不复制已选账号 Cookie。Guest adapter 的每个响应
  （包括注册后 AB）均在实际 Cookie commit 前过滤 MUSIC_U，对应 M198:671。
  正常登录候选使用新 with_backend，anonymous_store=false，真实候选的 MUSIC_U
  不被该过滤影响。匿名 UID 仅是本地私有表现 owner，不写 SessionToken.uid，
  不授予账号资源、写入或原生 fresh consumer 的 authenticated eligibility。
- durable token/UID/unknown receipt 保存在私有 guest 库；同设备已确认身份重启
  可复用，不重注册。设备变化清理该 guest 的旧身份/凭据；账号切换取消旧结果。

空撤销屏障回归修复（2026-11-05）
- 本批 full Rust 检查实际抓到已有 credentials::logout_rejects_late_cookie_and_
  token_resurrection_in_same_or_another_instance 的原断言失败：空会话 clear()
  被普通 no-op 优化跳过，旧 revision 仍可接受迟到的登录 Cookie/refresh pair。
  保留既有断言，不通过放宽或删除测试处理。
- 普通 change 继续用 canonical 内容对照；clear、invalidate_login 和
  import_legacy 使用同一个持久 CAS 路径的显式 barrier，强制新 UUID revision。
  只有成功提交后发送 native watch，不给失败提交/普通重复 HTTP 响应制造事件。
- 该边界来自真实调用职责：clear 用于退出、候选取消、移除和独立 Interface
  授权撤销；invalidate_login 由 session/invalidation.rs 持久撤销服务器已拒绝
  的会话；import_legacy 是 host 显式选中的身份/会话替换。这些操作都要让
  先前版本的在途回包失效，是否本来已有 Cookie 不改变该语义。
- seed_switch_device 在 quick/exchange.rs 构造 fresh candidate、任何 wire
  请求前调用；seed_anonymous_device 在独立 jar 同设备重开时复用，不能凭同值
  初始化触发刷新风暴。两者保持普通 change。set_login_ticket 的同票重复写
  也保持 no-op；finish_queue_reset 成功必然从 Some→None，本身已有内容变化，
  重复/错 ID 仍 StaleResponse。没有泛化所有本地 setter 为撤销。
- 新增两个 lib 单元测试：空 clear/连续 clear 的持久版本与 watch、旧实例和旧
  回包拒绝、普通空响应不通知；同字段显式 import 与重复 invalidate 仍有屏障。
  两个新增单元与原有credentials回归均在0318bfac完整Rust测试中通过，未替换原断言。
