听歌识曲：默认声学特征和峰值选择的原生证据

来源：PC 3.1.42.205594 x64 cloudmusic.dll，SHA256
557d7706dedc8556a8bd279d4dfe2bc05b80ad729a8749caccd9e29916935493。
以下均为 RVA。原生执行范围、离线向量、封包及服务边界见
docs/song-recognition-contracts.txt。本次只观察合成样本的原生状态，
没有设备采集、账户、服务请求或生产启用。原生探针只在本机 .build；
仓库只存无私人信息的合成输入及输出向量。

输入和时频矩阵

- D0A9C0 → D10000：有符号 i16 精确乘以 1/32768 得到 f32。测试输入
  为已转换好的 8 kHz 单声道，未恢复设备混音格式至该输入的精确路径。
- D0CA30 保留剩余样本，D10660 用 2048 样本窗（256 ms）及 160 样本步长
  （20 ms）。无结尾补零；对至少一窗的 n 个样本，帧数为
  floor((n - 2048) / 160) + 1。24,000 个样本实测 138 帧。
  D0CBD0 还检查 D14AB0 返回的最少 10 帧，低于门槛返回空峰值向量；
  空峰值向量不等于封包或服务结果为空。
- D16600/D1662F 的默认窗为 f32(0.54 - 0.46*cos(i*2π/(2048-1)))，
  各项按上述顺序用 f64 计算，最后转 f32；D106E0–D10703 单独以 f32
  乘窗。数学式生成的 2,048 个小端 f32 与原生系数 SHA256 一致：
  45c215e0882e4f38e6430c779e331c251eafb396a9b1cd2e7cad3d6a4cd2d0bc。
  另一 Hanning 公式所在 D166F0 不是本次观察的默认分支。
- D169E0 将乘窗后的实信号写入复数工作区，D178F0 → D17500 执行
  长度 2048 的正向混合基 FFT。默认 plan 整数头为长度 2048、inverse=0，
  因子对为 (4,512)、(4,128)、(4,32)、(4,8)、(4,2)、(2,1)。
  D16A40–D16A65 对每个输出 bin 单独 f32 平方再相加，没有除 FFT 长度；
  原始矩阵按帧连续存 1,025 个功率 bin。尚未以 Rust 冻结 twiddle、
  递归排序和 radix-2/4 运算的逐位等价。
- D13DE0 的默认配置实测分辨率 3.90625 Hz、100/4000 Hz 边界，
  使用 [25,1024) 的 999 个功率 bin。D13EA0–D13EEC 将帧优先的数据裁剪
  并转成频率优先，每行是一条频率随时间的值。D13F20–D13FB9 对功率
  开方，夹住最小 f32 位形 0x359637bd（约 1.1192093e-6），再用
  C90B60 计算自然对数。D13FD1–D140C4 按矩阵存储次序累加 f64、
  求均值，转为 f32 后对每项作 f32 减法。使用原始 log 矩阵独立重做
  中心化，完整 f32 矩阵一致。

默认有限输入的筛选（D13DE0 模式 +0x40=1、+0x54=true）

1. D14570 每行从第一列向右查找，使用裁剪至矩阵边界的 ±1 频率行、
   ±1 时间列邻域。存在严格更大的值即拒绝；相等不拒绝。接受后跳过
   下一列，拒绝则继续检查下一列。这里不预先排除零或负值。
2. D142A0–D1432F 仅保留中心值大于零的候选。D14910 用含中心的
   裁剪邻域（频率 ±10、时间 ±5）按行逐项作 f32 加法，再除以 f32
   单元数。如果局部均值严格大于 2.0（D1428E），或 f32(中心 - 均值)
   严格大于 signFactor（默认 1.0），进入下一筛选。
3. D143BC–D1444C / D14750：在中心化原矩阵内用 ±30 频率、±8 时间
   邻域重查，存在严格更大值即删除。比较对象是整个矩阵中对应邻域，
   包括已被第 1/2 步过滤的点。相等保留。
4. D144D1–D14519 将频率坐标加 25，D121E0 比较时间优先、频率次之，
   升序排序。候选序列以 little-endian (i32 bin, i32 frame, f32 value)
   原位形送 D0F4C0；不会在封包里重新对值取整。

实测及复验

使用 song-recognition-official.json 的 24,000 样本整数 xorshift 噪声。
原始功率矩阵 138×1025，SHA256：
7175b574b3787346dfa826d2dc549b7c2a81c7e559e70229789e27a844ad4c11。
自然对数矩阵 999×138，SHA256：
4e7ecf40331f9e506d19aad9511a33e536c964954913da415319bdb111c94242。
中心化矩阵 999×138，SHA256：
d3e75088290d3870f0a903e3d7210441afa7fbafb62836661e9a1ba05459690f。

独立标量实现从原生中心化矩阵复现 4,333 个初始候选以及全部 105 个
最终候选，每个整数和 f32 位形与原生相同。由原始功率重做时，宿主
f64 ln 再转 f32 在 137,862 个 log 元素中有 102 处不同，中心化后有
80 处不同。此噪声样本的最终 105 个候选恰好仍逐字节匹配；不能据此
将任意宿主 ln 当成 C90B60，也没有验证其它 FFT 或浮点库的整体等价。
原生 6/9/12/15 秒同噪声前缀最终产生 218/334/447/562 个候选；本次
没有逐矩阵复验这些长输入的标量数学。

本机私有复验（同版本 DLL；合成数据，不执行官方程序）：
  bash .build/song-recognition-math-dump-run.sh --noise --record \
    > .build/song-recognition-extended/math-noise-matrices.log
  unshare -Urn python3 .build/song-recognition-extended/check_centered.py
Rust 离线峰值选择与回归

core::song_recognition::CenteredPeakMatrix 只接收行优先、频率为行、
时间为列的有限 f32，允许 1–999 行、1–738 帧（15 秒采样的帧数上限）。
它不生成、重心化或验证输入的统计分布。小矩阵用来覆盖筛选算法的边界；
采样上游的完整 999 行和至少 10 帧是另一个阶段的契约。
select_default_peaks 返回封包可直接使用的 (bin, frame, f32 位形)；
没有录音、播放取流、UI、识别请求或账号依赖。

core/tests/fixtures/song-recognition-peaks-official.json 收录 16 个小矩阵。
初始化 D0A2C0 得到默认选择器，只为控制合成矩阵的行数调整裁剪上界
与高度；在 D13DE0 的 D140C6 写入合成中心化矩阵，不更改此后任何指令。
分别在 D140E5 读取 D14570 初筛向量、D142D8 读取 D14910 返回均值，
最后从 D13DE0 输出读最终向量。两轮各自从空虚拟内存开始，记录一致。
覆盖相邻对角线、拒绝后继续、接受后跳列、相等峰、正值门槛、严格均值
和突显度阈值、±5/±10 均值裁剪，以及恰好在抑制半径和刚刚超出的
更大值。其中一个向量的逐项 f32 和为 3、真实数值和为 2，可区分
以 f64 或不同顺序累加；另有较大邻点已被初筛淘汰但仍产生抑制的向量。

song-recognition-noise-centered.f32le.gz 是上述完整 999×138 合成噪声的
原生中心化矩阵，解压后的长度为 551,448 字节。重复执行未改算法的
原生信号链，两份矩阵及输出相同。测试核对矩阵散列、初筛计数
4,333 和首批记录，并用独立冻结的 song-recognition-official.json
比对最终 105 个峰的全部坐标、位形和排序。gzip 只用于存放测试向量。
本地及 Linux/Windows CI 的识曲核心命令：
  cargo test --locked -p cumulus-core --lib --features song-recognition-zlib song_recognition

仍需逐层恢复窗口至功率矩阵的 FFT 运算顺序和 C90B60 的 f32 对数，再
核对设备输入下混、捕获与服务授权边界。完整矩阵回归仅覆盖已中心化
矩阵之后的峰值选择，不能证明这些上游步骤或真实服务结果。
