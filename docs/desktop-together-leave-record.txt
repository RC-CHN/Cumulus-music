一起听结束记录桌面契约
======================

依据：官方 PC 3.1.42.205594 M/75:658–710 的房内结束回调，只有
成功且有 shareInfo 才打开记录；房间另一端结束的提示是另一条分支。
M/31:682–709 与恢复源码 AppModal/index.tsx:830–861 给出 442×404
尺寸、无通用页脚和关闭行为。ListenTogetherLeaveRecordModal/index.tsx
:95–205 与 M/3043:49–149 给出双方头像、两栏数字、累计记录和页脚。
M/3043 使用 M/103.i:35–39：参数单位为秒，显示完整分钟，小于一分钟
显示“1分钟”；超过一小时时保留剩余整分钟（3600 → “1小时0分钟”）。
不以关系历史统计替代本次结束回执。

请求和投影路径：M/15:1030、M/75:926–945 的
/api/listen/together/end/v2 接收 roomId 和序列化 shareInfo；官方
thisListenCount 默认 1，Cumulus 当前仍传 1。核心的
core/src/listen_together/{api,leave_record}.rs 解码直接回复，
service/commands.rs 等待原房间解除，client/together/leave_record.rs
按账号代次和原 End ID 持有显示收据。desktop/src/together.rs 复用
together_command（含 dismiss_leave_record）和 together_view，
frontend/src/composables/useTogether.ts、App.vue 和
components/TogetherLeaveRecordDialog.vue 决定显示、消费和焦点恢复。
拒绝、失效时已无原房间、等待室、无统计或统计格式错误均不生成记录；
丢失回复则通过只读对账确认本机恢复，不重发 End，也不补出记录。

桌面接收当前账号的临时原生 leaveRecord；必须已经确认离开并完成本机
房间解除，没有活跃房间或未决 End，且四项统计为非负安全整数。直接
结束可随命令回复，已确认的队列清空可随当前 view 送达；视图读取、
核对待定写入和失败都不自行计算或生成记录。账号切换、新房间、原生
撤销及过时响应清理旧呈现。关闭按 operationId 发送一次本机消费命令，
消费回复不覆盖当前房间；原生会话保留仅内存，前端不会保存私人记录。
房间失效或外部选歌阻断的待处理提示优先；结束记录不改变导航或播放。

头像沿用核心筛选的双方公开头像，缺失或加载失败使用本地图标。页脚
采用 Cumulus Music 标识，保留官方 M/3043:66–70 的固定公开活动
二维码；静态矩阵为 byte mode、Version 4、ECC M、1 模块边框。
独立解码确认只含该固定公开活动地址。不会使用服务器的 shareUrl、
距离、可跟踪链接或遥测，也不会上传、邀请、发消息或自动打开网页。

验收用例（合成账号及密封房间，无真实同听对端）：
1. 从 Together 页真实点击退出和确认，冻结直接回包。没有四项统计、
   等待室、回包丢失后只读核对均不出现 dialog；点击取消不发 End。
2. 精确直接确认已解除的双人房，捕获 [data-together-leave-record]；
   442×404、两头像、两栏、累计、72px 固定二维码，关闭按钮持有焦点。
   合成 3 首 / 35 秒与 27 首 / 3665 秒分别显示 “3首歌曲”“1分钟”
   和 “累计27首歌曲，1小时1分钟”。读取 SVG 模块并解码固定地址。
3. 记录弹窗的取消事件或关闭按钮本机消费一次，不新增服务请求；
   同一记录迟到不重开。手动退出的原入口已卸载时回到“一起听”页标题，
   队列清空后保留侧栏中的“关闭播放队列”焦点。单机设置和播放恢复
   沿用已有退出路径。
4. 合成播放队列清空的已确认回执走当前 view；临时失效提示仍优先。
   显式更换房间或在回包前切换账号，旧记录不得出现在新视图。
Rust 和前端单测另验证输入、账号代次、在途视图和消费顺序；跨账号和
新房间迟到响应并未在本次实窗中模拟。

合成桌面脚本使用已有 shared_queue_ui_probe（不新增探针二进制），
使用本地 API、IM 和音频夹具，不等同真实对端或物理音频：

    cargo build --locked -p cumulus-desktop --features custom-protocol --example shared_queue_ui_probe
    sh scripts/ci/loopback_only.sh env LC_ALL=en_US.UTF-8 GDK_BACKEND=x11 \
      LIBGL_ALWAYS_SOFTWARE=1 WEBKIT_FORCE_DMABUF_RENDERER=1 WEBKIT_DMABUF_RENDERER_FORCE_SHM=1 \
      xvfb-run -a -s '-screen 0 1280x900x24 -nolisten tcp' dbus-run-session -- \
      /usr/bin/python3 -B scripts/ci/together_leave_record_smoke.py \
      --binary ABS_SHARED_QUEUE_PROBE --root NEW_PROOF_ROOT --screenshots

九个阶段核对取消、等待室、格式错误、丢回包和只读核对都不会显示
记录；另外验证直接退出、实际队列清空的 view 投递、两种关闭方式、
独立二维码解码和累计 End 请求账本。直接退出前先确认当前房间与
原生播放都在播放，再发暂停并等待房间 PAUSE，随后才定位到 12 秒。
探针对照同一歌曲的 PAUSE 与 PROGRESS（后者仍为暂停状态）两条夹具
请求和原生播放、队列身份；若超时，只保存有限状态、定位、合成歌曲
编号与本次房间控制请求摘要。没有重试暂停、定位或 End。宿主不会
把连续手势可合并成的单笔 PROGRESS 当成两个操作都已确认。
