普通自建歌单混合删除：原生提交与恢复

依据 Windows 3.1.42.205594：M/3085:1475–1498 在绑定账号和确认后传当前
资源或 selectedData 及歌单 ID；M/3160:1398–1420 有 tracks 时把带 fileId 的
设备行从请求中滤除，保留其他选中 ID 的顺序。只在在线子集非空时向
/api/v1/playlist/manipulate/tracks 发送 {pid,trackIds:JSON.stringify(在线ID数组),op:"del"}。
M/15:2099 绑定接口。此入口没有普通即时编辑的 imme 参数，不走清空或更新顺序。
成功事件 M/2997:769–815 更新页面；M/3160:1875–1914 写 M/239 的本机曲序，
删除全部选中项后保留其余顺序。纯设备项不发写请求，已有本机增删继续处理。

原生只接受当前已认证账号的普通自建歌单，V6 detail 必须提供相符的所有者、
specialType=0、完整且可区分的 trackIds，并且此设备已有持久本地成员。
输入使用与混排重排相同的 online 十进制 ID 或 local 本地摘要和精确版本，
必须至少选中一条在线行。严格核对组合版本及完整投影，不从文件名、路径、
线上数字 ID 或关联的下载记录推断设备文件。拒绝重复、过期、未知或未绑定的
远端 v=-1 行；它们无法证明是同一个本地文件。不同资源种类的字面 ID 相同
时仍是两个独立成员，删除设备绑定不会把同名在线项发给服务端。

复用账号级歌单写入互斥、原生账号 Cookie 目标范围和实际传输前核对。
发送前持久化独立删除回执：歌单／账号／操作 ID、组合修订、本机代数、原线上
顺序、选中线上 ID 和本机引用、剩余线上顺序和本机位置。不保存路径或凭据。
同歌单未决混排和普通成员写入互斥；普通元信息编辑不被长期锁定。

只发送一次。明确 200 还须完整 V6 读回与冻结的线上目标顺序完全一致，才在
一个事务核对账号、本机代数和原成员，保存剩余本机位置及确认回执。即使
删光设备成员也保存空记录的新代数。明确拒绝、发前凭据变化不改本机位置；
失联、空回执、读回失败或结果不同保留未决及原位置。重开后只读本机回执；
显式核对只读取当前同账号的完整线上顺序，完全匹配时原子确认，不重发。
服务器没有 CAS；完整读回只能证明当前结果，不声称排除并发官方客户端。

核心 MusicClient 与桌面主窗提供 remove_playlist_mixed、playlist_mixed_remove_receipt、
reconcile_playlist_mixed_remove；返回只含阶段、操作 ID、业务状态和账号 epoch。
核心测试覆盖请求顺序、同字面 ID 碰撞、异常拥有者/占位、旧本机引用、发送边界
凭据变化、丢失确认、ACK 未生效、跨账号隔离、重开只读核对与全删空代数。
当前证据是合成服务和实际 SQLite；没有真实账号写入或上游兼容性验证。
