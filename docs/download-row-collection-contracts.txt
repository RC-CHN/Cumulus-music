已下载单曲行菜单：收藏到已有自建歌单

已恢复的官方桌面 3.1.42.205594：
- hybrid app M/556:277–286 的下载行入口从 offlineId 去掉资源前缀，按歌曲
  {id} 进入收藏。普通多选以及组操作的 M/556 k 不能替代此单行入口。
- M/15:1049–1083、M/21:543–560、M/27:114–150、M/754:699–718：云盘文件
  songId 与 simpleSong.id 分开；下载 offlineId 对应展开后的资源 ID。完成任务
  保留 origin；M/127:79–101 的旧记录可以没有完整权限对象。
- M/3085:700–706 先检查登录；768–792 的多选和单选 subPriv 筛法不同。
  单选判断保留 JS falsey（未记录/null/数值 0）；有值且为负权限时阻止。
  没有把未知的历史权限改判为拒绝，也不把字符串 "0" 当成数值 0。
- M/3160:1214–1231、M/232:662–693、M/15:2099：已选普通歌单调用
  POST /api/v1/playlist/manipulate/tracks，发送 {pid,trackIds,op:"add"}，
  trackIds 是由一个字符串 ID 组成的 JSON 数组字符串；普通歌单编辑命令
  的 imme:true 不能替代该调用。M/3160:1044–1061、1208–1226 有独立归因分支：
  当前队列有相同目录歌曲时，官方另外从队列项与入口提取 songRqRefer、
  rqRefer 和可用的 alg。本实现采用不附带归因的普通业务路径，不从当前队列
  伪造这些字段；队列重合时的官方归因未迁移。

实现：
- 下载行只显示由 Rust 投影的 collectionAvailable；UI 不发送歌曲 ID、目录 ID、
  权限、文件路径或请求参数。普通歌曲要求完成任务和一致的原生歌曲元数据。
  云盘只用保存的 _cloud_public_id；如果新记录同时保存 _cloud_catalog_id，
  两者必须一致。有明确旧公有标记而尚无新目录标记的记录保留有效；无标记、
  私有、矛盾记录、程序/MV、仅凭同名或原云盘文件 ID 都不能进入此 lane。
  当有已知任务权限时保留单首 falsey 语义；不接受不明的 truthy 权限表示。
- 主窗打开 picker 才建立本次短期 native receipt，绑定账号代次、API 和有效
  Cookie scope、下载任务、目录歌曲。只有此 receipt 经原生新读的候选歌单
  页实际返回的普通自建歌单才可以提交。写前读完整歌单详情并再次验证当前
  归属和普通歌单资格；下载任务移除或失去目录身份、账号变化、旧弹窗被替换/取消会撤销尚未派发操作。
- 沿用歌单原生互斥、凭据派发栅栏和持久日志。只发一次绑定的 mutation；
  失去回包后保留原记录，“核对结果”只读，切账号不投影旧回包。普通详情/
  歌单导航与下载文件状态不受影响。默认排序/常用优先使用现有真实分页。
- 此版只开放已有普通自建歌单。官方系统“我喜欢的音乐”和“创建新歌单”入口
  仍待在下载来源上单独恢复，不通过已有通用动作绕过本流程。后续需要建立
  不依赖声音卡的系统歌单与点赞读回权限，及显式创建回执到单次独立 add 的
  关联。M/3160:1139–1142、1241–1255 以原生 starPlaylistId 区分系统目标，
  确认后还同步点赞集合；不能用歌单名猜系统目标。FavouriteModal/index.jsx:
  419–441、529–540 将“创建新歌单”分成独立目标 null，M/3085:823–844 只在
  创建回执返回 playlistId 后加歌，取消不加。下载批量收藏的独立原有行为
  不在本次范围。
- 合成 Rust 测试在 client_downloads/download_collection；WebView 证据脚本为
  scripts/ci/download_collection_smoke.py，不使用真实账号或真实写入。
