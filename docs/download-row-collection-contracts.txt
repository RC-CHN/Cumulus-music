实现：
- 下载行只显示由 Rust 投影的 collectionAvailable；UI 不发送歌曲 ID、目录 ID、
  权限、文件路径或请求参数。普通歌曲要求完成任务和一致的原生歌曲元数据。
  云盘只用保存的 _cloud_public_id；如果新记录同时保存 _cloud_catalog_id，
  两者必须一致。有明确旧公有标记而尚无新目录标记的记录保留有效；无标记、
  私有、矛盾记录、程序/MV、仅凭同名或原云盘文件 ID 都不能进入此 lane。
  当有已知任务权限时保留单首 falsey 语义；不接受不明的 truthy 权限表示。
- 主窗打开 picker 才建立本次短期 native receipt，绑定账号代次、API 和有效
  Cookie scope、下载任务、目录歌曲。只有此 receipt 经原生新读的候选歌单
  页实际返回的普通自建歌单才可以提交。写前读完整歌单详情并再次验证当前
  归属和普通歌单资格；下载任务移除或失去目录身份、账号变化、旧弹窗被替换/取消会撤销尚未派发操作。
- 沿用歌单原生互斥、凭据派发栅栏和持久日志。只发一次绑定的 mutation；
  失去回包后保留原记录，“核对结果”只读，切账号不投影旧回包。普通详情/
  歌单导航与下载文件状态不受影响。默认排序/常用优先使用现有真实分页。
- FavouriteModal/index.jsx:419–441、529–540 将“创建新歌单”分成独立目标
  null，替换选择界面；M/3085:823–844 以 noToast:true 打开创建，只有创建回执
  返回 playlistId 才追加歌曲，取消不加。AppModal/index.tsx:541–574 与
  PlaylistModal/create.jsx:51–129 确认“创建歌单”、默认公开、可选隐私及空名
  禁提交。下载行复用该创建表单的状态，打开或取消没有写入。
- 新建入口由同一下载回执的 canCreate 决定。新建命令只接原生 receipt、显式
  名称和隐私，或独立的核对/续加意图；不接歌曲、目的地 ID、日志 ID 或路径。
  原生绑定与现有添加相同的账号、凭据修订和 URL 范围 Cookie，另验证创建与
  自建列表读回范围。冻结两个独立的持久操作 ID。已明确收到 create 200 和
  playlistId、完整列表看到同名同隐私的新普通归属行、详情复核成功后，才允许
  对当前下载歌曲发一次无额外归因的加歌。旧 ID、冲突 creator、系统歌单、账号
  或任务变更、关闭的回执均不授权追加。
- 创建回执不明可显式只读核对；只靠列表差分看见新 ID 不允许加歌。收到明确
  创建回执而暂未看到列表时，核对后仅可明确继续从未发送的加歌。若 add 回执
  不明，只核对原 add；已派发结果不重放。新歌单经确认后同步侧栏并保留下载
  视图，成功关闭并归焦原行；已经创建但没有加歌时明确提示。无已购音质、下载
  任务、播放队列或授权 URL 变更。
- 系统“我喜欢的音乐”见下方独立目标规则；下载批量收藏不在本次范围。
- 合成 Rust 测试在 client_downloads/download_collection；WebView 证据脚本为
  scripts/ci/download_collection_smoke.py。封闭 Linux Xvfb / GTK WebKit 实跑
  7 个阶段、7 张 PNG：取消归焦同一下载行且零写入、普通歌曲 1 确认、
  私有与无目录身份旧行不出现收藏、已匹配云盘文件 5 只写目录 ID 9010、
  丢回执显示核对而不显示正在写、只读核对不重发。原生合成端仅收到两个
  {pid:"2",trackIds,op:"add"}。没有真实账号、真实写入或 Windows 运行证据。
- 新建流程单独由 scripts/ci/download_collection_create_smoke.py 验证。封闭 Linux
  GTK WebKit 实跑 7 个阶段、7 张 PNG：空名默认公开、取消恢复原行焦点、明确
  创建并追加、丢失创建回执只读核对且不追加、已匹配云盘歌曲丢失追加回执后
  只读确认。合成端仅收到 3 次明确创建（公开／隐私／隐私）与 2 次绑定追加
  （普通目录歌曲 1 与已匹配云盘目录歌曲 9010）；SQLite 保留 5 条确认日志。
  每阶段核对同一播放队列，无真实账号、网络写入或 Windows 实机证据。

系统“我喜欢的音乐”
- M/3160:923–967 的 host 歌单读取用当前账号的系统标记取得 starPlaylistId；
  :1139–1142 用此 ID 分支，:1241–1255 才将目标歌曲并入点赞状态。M/3085:
  845–858 从显式选择的歌单进入相同收藏操作。系统目标不是另一次 toggle，
  仍使用上述有界的单首 add；歌单名不能作为系统身份。当前支持不带队列归因的分支。
- 打开下载收藏窗口后，原生完整读取本账号 host 歌单，在唯一归属一致的
  specialType=5 行和新鲜歌单详情上确认系统目标，给 WebView 一次选择回执。
  “我喜欢的音乐”只在此回执有效时显示。手工输入 ID、重名普通歌单、旧或
  失效的窗口、账号／凭据代次或系统目标改变，均不能派发。
- 写前、写后（含“核对结果”）同时核对新鲜系统歌单详情和 /api/song/like/get。
  只有两者确认请求歌曲才更新原生缓存，界面只合入确证的本次歌曲 ID，不把
  歌单一侧的变更当成已点赞。已有双侧一致状态不重复写入；回执不明保留同一
  持久操作，关闭窗口后也可按原记录只读恢复。已下载普通歌单与系统歌单共用
  一个在途操作资格，不能从另一个目标路径重发。
- 该原生权限使用同一账号在目标读取与收藏端点的有效 Cookie，不借用声音卡、
  播放状态或实验权限。未接入下载来源的系统移除或同队列歌曲的官方归因。
  没有真实账号或真实写入验证。
