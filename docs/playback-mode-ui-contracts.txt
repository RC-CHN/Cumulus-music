播放器模式及 FM 操作一致性（2026-10-31）

范围与来源
- 主播放条按官方 PlayBar/PlayMode.tsx 的点击循环及 FM 独立分支恢复，不引入系统
  select。官方文件 SHA256 为
  6aa41644381ae6f88bfdcd106f2915091e6aecf45e613c4f905237d48fd35e0d。
- 实际循环算法来自 recovered-js/modules/hybrid_app.chunk.1482700000000.js/7.js
  导出 t（内部 v），SHA256
  4914ce443197d0538f055ae064b910a1a5f7c3d83c1c1e60978b9d7f2b055e1e。
  在隔离 Node vm 中执行原函数冻结12个无私人信息向量，core/tests/fixtures/
  official-playback-mode.json 同时记录来源、原枚举和社区枚举。
- 官方非心动普通循环：顺序→列表循环→单曲循环→随机→顺序；一起听：列表循环→
  单曲循环→随机→列表循环。非法现态按官方 max(index,0) 再向前一步。
- FM 保留独立无限漫游/单曲循环，不使用普通随机及列表循环。官方单曲入口受
  PH-PC-FM-Single 实验影响，本项目暂直接提供两态，未验证该实验分配。
- 未参考 YesPlayMusic。官方源码不纳入公开仓库。

实际调用及并发
- frontend/usePlaybackMode → usePlayer.configureMode → client.player_action(mode_for)
  → MusicClient::player_mode_for → 普通 PlaybackController 或 FmPlayer。
  输入包含 mode、expected_queue_revision 和 fm；epoch 仍由类型化 IPC 传入。
- UI 先显示最新点击目标及“正在切换为…”，原生实际 mode 独立保留。连续输入只串行
  提交首个和最终目标，每次采用成功回执的新 revision；不使用播放器全局忙碌/错误，
  模式切换不取消正在加载的音源，也不自动暂停或重新载入当前歌曲。
- 原生获取账号代次，串行化房间附着与模式限制，验证队列 revision 和 fm 身份，
  再通过 playback fence 提交。换队列的旧操作返回 QueueChanged，不应用到新队列。
  一起听已附着时原生拒绝顺序播放，保留既有同步信号；本次无双账号验证。
- FM 检查相同条目顺序/当前项，并先保存领域 repeat，再投影到原生队列。只有模式
  未提交成功时可以重试相同目标；其它队列未同步仍要求恢复。只修复模式不会发送
  skip、取下一首、重载音频或改变暂停进度。

错误、恢复及页面动作
- 保存失败显示控件旁独立错误和“重试切换”，回到已确认图标；不会变成通用音频加载
  错误。停止自动写入，显式重试取最后目标和当前队列上下文。账号/场景/卸载/断开
  清除过时任务，独立媒体身份或实际模式变化清除已过时错误。
  SQLite拒绝候选也会推进queue revision，单独的版本变化不能作为恢复依据。
- Escape 隐藏错误并返回模式按钮；从其它控件重新聚焦可再次查看保留错误。重试在
  离场 surface 变 inert 前把焦点交回持久按钮，避免丢至 BODY。
- FmView.modePending 区分“条目一致而模式不一致”和普通 refill_failed 提示。
  仅模式失败时显示“播放模式尚未同步，继续播放时将同步模式”，按钮为“同步并继续
  播放”；恢复保留同一 playId 和位置。普通推荐加载提示期间仍显示/执行“暂停漫游”。
- FM 页的播放/切歌控制同时核对领域 active 与 PlayerView.fm，避免过时页面暂停普通歌曲。
  空推荐仍按领域所有权保留返回原队列入口。
  返回普通队列保留原模式/当前项/暂停位置，消失的返回按钮把焦点交给主题色页标题。

2026-10-31 空FM队列的模式与返回一致性
- 修改前client_fm用例确认：FmView.active为true、仍有返回按钮，但PlayerView.fm
  为false，主播放条会提供普通四态循环。根因是原生只从非空条目的source推断所有者。
- QueueSnapshot新增可选fm_source（原生持久化，不导出给前端）；FmPlayer每次投影
  将来源与队列一起CAS提交。空FM现在仍是FM，主播放条仅循环无限漫游/单曲循环。
  随机/列表循环被FM策略拒绝，旧普通身份的ModeFor操作返回QueueChanged。
- 初始化和竞争落盘失败后的重读可识别旧空队列：须存在本账号已保存的普通队列备份、
  合法FM来源及FM两态模式。只读加载不改库；下一次成功提交保存新字段。普通队列的
  序列化不增加空字段，原官方队列冻结向量继续保持原样。损坏/混合来源明确拒绝。
- 从空FM退出到空普通备份时，队列与旧FM来源/备份在同一事务释放，避免重开又变回FM。
  登录队列清空也识别新身份并取备份中的普通模式。普通新队列的各构造入口显式无FM来源。
- 空态主按钮由“继续播放”改为“重新获取推荐”，仍经原有FmCommand::Resume调用
  FM协调器、权益检查和/api/v1/radio/get；取回空结果仍保留原队列备份及返回操作。
  上/下一首和底栏播放保持禁用，模式按钮与返回按钮可用。保存失败仍独立提示，显式
  重试修复领域repeat和原生队列；未发送skip、未启动不存在的音频。
- 这是社区持久化及空态一致性修正；没有同状态官方运行截图，不声称该空态文案/布局
  是官方逐像素复刻。其余官方普通/FM模式来源与实验边界继续适用。
- 验证入口：playback_fm_identity的旧数据/账号隔离/落盘/损坏测试、扩展client_fm
  空结果/模式拒绝/重开/退出用例；mode_ui_smoke.py --empty-fm的首次13态+重开5态。
  同脚本已接入Linux、Windows独立runner，必须按精确提交CI结果核对Windows。
