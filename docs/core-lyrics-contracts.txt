歌词解析与展示契约（Rust）
2026-10-25

来源与模块
官方 hybrid_app M/370 的 a/b/c/d 四个导出；复核归档 cumulus_core/lyrics.py，
以直接执行官方函数生成的 fixtures/lyrics.json 为准。另迁移 M/21.s/m 响应转换和
hybrid_200 M/3081 的请求/缓存/偏移/选择流程。未参考 YesPlayMusic。
core/src/lyrics/ 分 types、credits、lrc、yrc、presentation、format；不依赖网络或 UI。
CatalogApi::lyric 负责 /api/song/lyric/v1，id、cp=false、tv/lv/rv/kv/yv/ytyv/ytlv/ytrv=-1。
CatalogApi 返回原始响应；先 normalize_song_response 把 offset 毫秒转为秒，按
sgc/sfy/qfy 映射权限、转换贡献者ID，并移除没有文本的 LRC/YRC/翻译/罗马音节。
parse_lyrics 接受该规范化对象或同格式本地对象，不能直接把接口毫秒当秒传入。
LyricsService 封装了这条链路；service/ 下按缓存、请求、输入/快照与协调分工。

请求与恢复
LyricsService 固定账号代次，账号更换后需重新创建。请求/文件读取期间不持有状态锁。
按桌面歌词/详情页/mini/桌宠/force 判断是否需要拉取，同一首已成功展示的歌词不重复请求。
普通歌曲调用 /api/song/lyric/v1，发送 id、lv/tv/rv/yv；版本取缓存真值，0按官方回退-1。
云盘调用 /api/cloud/lyric/get，发送 songId、userId、lv、kv=-1，响应字符串 lrc 转规范格式。
缓存与本次响应浅合并，重新计算 noLyric；网络失败且旧缓存有效可继续展示，并标记 networkFailed。
缓存按账号与 song/cloud/local 来源分开，schema=1 明确已规范化，避免二次除1000。
显式导入旧官方缓存时：只有YRC而无yromalrc/ytlrc的旧缓存拒收；旧offset>500除1000一次。
同资源跨实例文件锁防止拉取/改偏移并发覆盖；改变选择、clear、账号代次变化会拒绝迟到结果。
Future 中止会释放操作锁并结束 loading，可显式重新请求。持久化失败不会发布成功快照。
同实例切歌时先清空旧显示，track-MV/没有需求时取消旧请求；这是避免串歌的工程化处理。
translationEnable/romaEnable 默认true，按账号保存；偏移按 0.5*gain 秒调整原文并保存。
修改前核对持久缓存仍与当前原文一致，避免其他实例修改后静默覆盖。

本地文件
LocalLyrics 是本地来源接口。阻塞工作线程优先读取非空的相邻 .lrc，支持
UTF-8 BOM 及带 BOM 的 UTF-16，4MiB 上限；旁挂文件编码错误仍明确返回失败。
无旁挂文件或文件为空时，从普通本地文件读取 MP3 ID3v2 USLT、FLAC Vorbis
LYRICS 或 M4A ©lyr 文本标签。标签解析不读取封面或计算音频属性，空、超限
或不可解析的标签不作为歌词。沿用 LRC 时间与纯文本规则，界面区分本地/网络来源；
IPC 的 fromEmbedded 与 fromSidecar 分开。不访问网络或修改音频，正文变化重置旧偏移。
远端和缓存均无歌词时可读取显式提供的 downloaded_audio 邻近 .lrc。
官方恢复 async_lyric.txt 的同分支先用远端/缓存正文，再由下载路径派生 .lrc。
桌面只给当前选中的已完成歌曲/云盘下载启用这个回退：账号、任务/歌曲、文件位置、
目录身份和发布摘要必须相符；文件操作期间不读取，拒绝重定向的侧车文件。
附件的偏移按本地路径和正文隔离，不写进线上歌词缓存；同曲目其他来源不会继承侧车展示。
只给有明确任务来源的选择读取附件，不为在线播放按歌号猜选其他下载，也不扩展嵌入歌词。
忘记下载保留的队列项也可回退：必须在有界范围内找到同账号已完成的Forget日志，
确认原任务和发布记录已移除，核对原目录、文件身份、完整摘要及离线权益；不会续期。
仍在发布中的心动内嵌记录不能靠内嵌字段授权此分支。播放选择或文件变化时拒绝旧附件结果。
官方恢复的 3081.js（local 分支）证明将原生路径交给 orpheus://localmusic/lyric
并消费文本；具体标签与优先级未证实。上述文件选择是本客户端适配规则；
不含二进制 SYLT、其他格式内嵌或 NCM 内嵌。下载回退仍只读取受保护的 .lrc。
Rust 的 lyric_service 使用独立生成的三种音频验证优先级、未访问网络和未改写音频；
client_local 从真实本地库选择流程验证详情 DTO 与桌面歌词帧。后者使用合成播放引擎，
另以 desktop_lyrics_smoke.py --embedded 启动真实 Tauri 双窗口与 libmpv：
Linux Xvfb 实测本地索引、播放时钟、暂停后同一 playId、详情行和桌面歌词行，
无旁挂文件和在线歌词请求。两张合成截图保存在本机 .build/embedded-lyric-webview-proof/first/；
CI 在 Linux/Windows 单独运行该用例。音频为 null 输出，物理声卡与实机屏幕未验证。

行为
LRC 存在且为 JS 真值时优先，空对象也占用 LRC 来源；不能擅自用 YRC 覆盖。
未提供 lrc/yrc 时直接返回 none/default。version 缺失与显式 null 保持区别。
多时间标签复制行，只有所有正文行均带时间才排序并标记 scrollable；稳定排序保留重复行。
翻译/罗马音按原始时间戳双指针精确对齐，缺行补空；不做模糊时间匹配。
贡献者头尾插入原文，已有翻译/罗马音插入同时间空行；LRC 尾部保持顺序，YRC 尾部反序。
offset 单位秒，只从原文时间中减去，翻译时间不变。这是官方语义，不是统一修改三列。
YRC 保留去除贡献者后的逐字原文及翻译/罗马音；降级行按开始毫秒转换为秒。
英文首尾字母片段追加空格；纯 YRC 的 scrollable=false，此处为官方解析事实。
后续桌面展示另外解析绝对词时钟，具体动画、偏移边界与证据见desktop-player-contracts.txt。
纯音乐、上传/翻译权限、贡献者、云盘标记按官方条件保留；当前通路不会强造 ask 状态。

导出与本地辅助
render_lrc 接受时间可选的行；0 是有效时间。format_timestamp 按 JS 数字字符串截取
最多3位小数，不四舍五入、不强行补3位；保留官方对负数/科学计数的文本行为。
protect_timestamp_only_lines 对仅含合法 LRC/YRC 时间标签的原始行追加 U+200B，
保留 CRLF/CR/LF 及空白，重复调用幂等。用于避免无字时间行被解析时丢弃。
active_line 是社区辅助函数：接受未排序行、重复时间选后出现的行，第一行前返回 None；
NaN/Infinity 位置或行时间不参与选择，不将0当空值。

明确的输入边界
正常有限时钟与官方结果一致；Rust 不把非有限时间送入播放器。
非法/非有限 LRC 时间标签和溢出的 YRC 时间行被丢弃；非法 JSON 响应、文本类型、
非数值 offset/贡献者时间、贡献者结构返回明确错误，不复刻 JS 的 NaN 或 TypeError 崩溃。
无时间贡献者在有 offset 时仍保持无时间，官方可能算出 NaN；这是明确的异常数据差异。
裸的 [0,0] 若出现在贡献者提取位置会先被识别为 JSON 数组；官方抛错，Rust 返回错误。
输入数字/文本不做 JS 任意隐式强制转换，正常接口类型按字符串/数值处理。
