正式桌面入口

- 主窗 vertical_zone_menu {epoch} 返回 available、前五个 defaultZoneTags 和
  moreZoneTags；未命中 PH-PC-zhuanqu=t1 不读专区菜单。已授权时由
  /api/secondary/tab/list {} 的第一个 music_top_tab_full 投影，保留服务顺序，
  过滤固定入口/旧原创入口；前端没有目标 URL。失败和空刷新保留同账号同凭据
  的上次有效菜单；新账号、新原生传输或签名凭据变化不能复用。
- vertical_zone_page {epoch,pageCode,tabKey?,tabKeyName?} 只接受已经登记的
  pageCode。两个标签参数互斥，tabKeyName 只用于本次搜索入口的本机匹配。
  读前和发布前检查菜单成员及凭据。返回带当前页签、布局、菜单、四类模块和
  非授权的本机 viewId/cardKey。精选栏的更多项可用键盘打开、选择和 Escape
  返回；浅深色和窄窗保留界限。二级标签至少有两个具名项才显示，切换期间保留
  同页标签；经典回退仍展示默认内容。由搜索解决了真实标签后，同一个历史项
  返回使用真实 key，不重复按显示名匹配。每个标签保存滚动、横轨和按钮焦点，
  切换账号清空。失败可显式重试，空态和个性化关闭分别展示。
- M/3089 以 PH-PC-jingxuanPageEfficiency 精确 t1/t2 选择横排每组六/五张，
  普通四张；网格沿用响应式最小宽度。横排、网格用同一真实歌曲/歌单资源动作；
  榜单是否显示播放按原始 canPlay，轮播只接已确认的站内类型。
- 歌单封面、标题打开正式歌单；独立播放按钮用选择 viewId/cardKey/id 校验当次
  原生卡片和当前菜单、账号、签名分组，再读取真实歌单/歌曲详情并授权。两张卡
  即使同一 id 也不共享播放场景。只有 M/91 的横排个性化场景加 trialMode=121；
  普通网格不加。授权、实际播放和时钟都走已有 Rust 播放器，前端不持媒体 URL。
  详情使用同一账号、页面和卡片绑定的本机凭据；后续分页、单曲及播放全部保留
  试听场景。详见 vertical-zone-mgc-playlist.txt。专辑、歌手、
  用户及播客打开已有对应详情；FM 封面和播放按钮分别执行打开当前播放详情
  和按卡片规则播放/暂停，详见 vertical-zone-fm-card.txt；
  页面挂载会被动预取 FM 首曲封面，调用与状态边界见 vertical-zone-fm-preview.txt。
  远程广告/直播、未经确认的视频轮播目的地、其他设计实验未用占位按钮。
- 综合 V3 热点先走原有搜索。只有返回合法的 RN 专区候选才建立验证菜单，
  不给普通搜索额外请求；无同组/同页不给入口。不输出链接和 query。跳专区后
  保留搜索返回位置及原按钮焦点，详情权限读取和标签协议仍由专区服务完成。
