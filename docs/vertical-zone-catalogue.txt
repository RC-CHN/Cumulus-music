- 普通专区 /choice/verticalZone/:pageCode/:tabKey? 按精确
  PH-PC-zhuanquTab=t1 决定链路。缺失、关闭和对照组只 POST
  /api/zone/get {pageCode}，取 data 的首项，不用 URL tabKey 多请求一次。
- t1 才 POST /api/zone/tab/get {pageCode,tabKey}；空 key 用 default。
  普通入口必须匹配回包的 tabKey。仅 searchHotExplain 且无显式 key
  可以用精确 tabKeyName：先查 default，首个同名 tabMeta 如果不是回包当前
  tab 就用其真实 key 重读一次，再核对回包名称。拒绝或不匹配降级经典端点，
  账号失效、取消或凭据变化不降级。默认空内容和读取失败分开。
- 四种模块顺序与回包一致。轮播只投影 M/437 确认的站内资源动作，不开放
  广告、外链、直播或 M/437 无法区别资源种类的视频入口。横排接受歌单、
  专辑与独立专区 FM；按原版在过滤后不足六张时不展示。榜单只接受
  PLAYLIST 和 singleRow/doubleRow，展示前三名，以 tracks 的对位文字优先。
  网格只接受歌单。图片 URL 限制公共音乐 CDN 并去掉上游 query；不输出授权 URL。
- M/3089 的 PersonalityContainer 在个性化关闭后把整组替换为说明和
  「去设置页重新开启」；保留标题，不投影该组数据。未标记横排、网格还会
  在单卡粒度过滤。标记的横排 FM 或歌单需要原生接已有 MGC 试听场景；
  不把标记写成已有播放授权，不扩展到普通网格。
- core/src/catalog/vertical_zone 提供两条真实 Rust 请求及有界投影。
  MusicClient::vertical_zone 只接受已验证账号和当前原生传输；在带签名的
  PC 组可用时读取实验，未知分组走默认。新请求不发布旧页签结果；账号
  代次/传输变化清空旧缓存和中止旧读取。最近使用的八项标签在同一次进程内
  复用；经典模式不复用标签缓存。每次先读账号的个性化状态，未知不展示，
  不允许复用不同隐私状态的内容。该隔离比只比较官方 uid 更严格。
  未接主窗 IPC、精选与搜索入口、卡片动作或 UI；既有专区 FM 不改。
