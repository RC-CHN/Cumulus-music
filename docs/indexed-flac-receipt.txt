Indexed local FLAC: one-shot native file receipt
===============================================

Recovered PC 3.1.42.205594 M/163:267–283 distinguishes downloaded resources
from ordinary local localTrack.filename. M/163:373–381 sends an existing
ordinary file as type 0; offset/duration are added only for CUE. In legacy
cloudmusic.dll, 103B83C–103B840 enters the zero-type file selector. This is
source routing evidence, not authorization for arbitrary paths or proof
that the file format is eligible for DSP.

Cumulus already uses the recovered fixed local equalizer graph (including
slot 50) for selected explicitly opened native stereo files. The ordinary
indexed library resolves a selected local revision to a pathname
(library/index/decoded.rs, playback/source/mod.rs). Before an eligible
Linux source can enter the same graph it must now acquire this native handoff:

1. Check the selected LocalResource against a single durable ordinary file
   row, including stable local ID, available status and exact File
   fingerprint. Derive the only path from that native row. A CUE resource
   never enters it. No NCM resolution, decrypted-cache selection or arbitrary
   path fallback occurs, including paths inside the app state directory.
2. On Linux x86_64 require the index's device/inode, size and modification
   time fingerprint. Check the indexed path is canonical, open read-only
   without following a symlink leaf or blocking on a replacement FIFO, and
   verify the actual descriptor before reading. Confirm only the plain FLAC
   marker, rewind, and check the same descriptor and durable row again.
   Neither indexed nor container metadata establishes decoded PCM layout.
3. The receipt owns one File. Consuming it checks the exact still selected
   row, the actual descriptor and both the original and current
   cancellation predicates. It cannot clone or reopen. If a pathname is
   replaced after preparation while the index row stays unchanged, only the
   previously held object can be returned; a rescan invalidating the row
   makes it stale. The native file fingerprint is not a content hash and
   does not guard against all in-place writes.

Windows currently persists creation time, or no identity, in
library/identity.rs. The pinned file-id 0.2.3 library's public verification
functions take a path and open another handle. The separate
library::identity::windows::WindowsFileIdentity helper uses the already
locked windows-sys 0.60.2 calls GetFileType and GetFileInformationByHandleEx.
For a supplied no-follow disk handle, it rejects FileAttributeTagInfo
directory/device/reparse attributes or tags and reads FileIdInfo's volume
serial and full 128-bit identifier from that same handle. An unsupported
class, zero identity or ineligible handle yields no ID. There is no
timestamp, low-resolution or path fallback; other file-information query
errors propagate.
The caller must open the leaf with FILE_FLAG_OPEN_REPARSE_POINT and validate
the parent path. A handle cannot reveal whether a previous open followed
a link.

The indexed receipt still returns unavailable on Windows without opening
the path. Before enabling it, add a separate optional native identity record
bound to the exact existing indexed ID and FileFingerprint revision. An
explicit Windows rescan must capture the legacy metadata and new ID on the
same checked handle, including rows whose normal scanner metadata cache
would otherwise skip re-probing. Publish the companion record with the
matching row or leave it absent. Compare against the actual held decoder
handle on load. Old queued resources and the serialized legacy fingerprint
stay unchanged; absent/mismatched companion records remain on stock.
Windows native tests must exercise replacement and a real reparse point
before product admission. No index persistence or scan behavior is changed
by the helper.

Linux ordinary indexed player attachment
----------------------------------------

A fresh ordinary indexed selection, with enabled local material, can
prepare the receipt at the controller's existing native-load boundary.
This requires a full independent timeline, the exact indexed FLAC path
(not a resolved NCM cache), no separate loudness data or PEQ conflict, and
a configured native FLAC adapter. The underlying transport remains the
existing source resolver. A multi-link file is not admitted. A boolean
native exclusion checks all owners' exact offline path keys and download
targets, named/configured download roots, and pending file/directory
migrations. It does not look up an authorization URL, parse another
account's credentials or expose any owner/path data to the renderer.
This excludes known managed files, not arbitrary historical copies
that have no current managed provenance. Typed CUE, NCM, cloud, download
and room sources keep their existing routes.

Once the held descriptor is chosen, even missing/wrong trusted-library
digest, unsupported FLAC geometry or a recoverable unpublished preparation
failure can only choose stock with that same descriptor. Trusted libFLAC
STREAMINFO and actual callback checks select the same preexisting graph:
44.1/48 kHz, stereo, signed 16-bit, known bounded length and block size.
The ordinary indexed lane accepts STREAMINFO maximum blocks up to 4608
frames. A valid 48 kHz stereo FFmpeg FLAC in the native application proof
declared 4608 by default and previously took stock at this check.
One bounded callback (at most 36 KiB of interleaved float PCM) is staged;
the decoder emits contiguous packets of at most 1024 frames to the same
2048-frame graph worker. It validates the actual callback against the
selected maximum before copying PCM. The existing compressed read and
seek budgets and graph EOF/tail rules are unchanged.
Seek discards any staged suffix before the native decoder's seek callback
and tags new slices with the new generation. The old Native Open and
protected/cold lanes retain their 1024-frame callback limits.
During ordinary local effect playback the bounded refill covers one
125 ms raw packet in source time plus 250 ms of output and observation time
scaled into source time at the native speed. The reserve is 375 ms of source
at 1×, 625 ms at 2×, and 1125 ms at 4×. The in-process queue allocation does
not grow with the speed. The worker receives credit only for the matching
native entry, and accepting a speed does not advance its clock. The unbound
startup and the protected source retain their previous limits. A newly bound
fast ordinary pass can prefill for its native rate before the first clock;
settled pause and seek still freeze further production. A native seek
reapplies the actual speed to the replacement pass. Master bypass retains
the source and entry, and already queued PCM drains before it is audible.
The old pathname never supplies another file after ownership transfers.
Actor generation and ManagedOutput lease fence preparation. After native
load and before first unpause, the actor checks the current local index,
managed exclusion, queue and exact native entry; existing Focused unpause
still owns presentation. Native seek reclaims the same held file after the
old sink retires, then resets and republishes the graph. Current-entry
output reload stops the held indexed entry with an output error rather
than reopening a retained pathname after audible playback. A separate
user selection can obtain a new checked receipt. Windows and other
unsupported sources stay stock. No UI or IPC protocol changes.

cargo test -p cumulus-core --locked --test indexed_flac_receipt

cargo test -p cumulus-core --locked --lib indexed_4608_flac_matches_1024_flac_and_wav_through_seek_and_tail -- --ignored

The decoder test covers a real 4608-frame callback, a seek with an old
unconsumed suffix, exact signed-16 PCM after that seek, a seven-frame
file tail and single EOF; the narrow decoder still rejects the large
callback. The paced-reader test compares all graph output bytes and EOF
with real 1024-frame FLAC and WAV at 44.1/48 kHz, at frame zero and after
a nonaligned seek. These tests do not validate a physical sink or the
ordinary packaged desktop's output for this wider callback.

Synthetic cases exercise the real indexed CUE row, NCM and renamed NCM,
same-size/same-mtime substitution before a new open, old descriptor

The native_local_equalizer_probe and scripts/ci/native_local_equalizer_smoke.py
--indexed-flac-only exercise an actual isolated GTK/WebView process, native
library scan and typed indexed row selection, verified graph and wrong-digest
held stock, paused seek, resumed source clock, EOF and durable settings.
On Linux both cases passed with system libmpv and libFLAC, using synthetic
audio, null output, a real GTK WebView and no service egress. The trusted
case loaded one indexed descriptor as pcm_f32le, processed both native
entries around a paused seek, and reached a single EOF. The incorrect
digest loaded that route as stock flac, kept one native entry across seek,
and reached EOF with no graph callback. Neither made a pathname-based
ordinary load. The receipts are in `.build/ui-proof/phase83-indexed-flac-r1/`.
Both cases also passed with the packaged FLAC decoder (SHA-256
2187c6cf9cc5d60a4a02b28502dd2f4a9ac6712be45d1f6df295a462d2f0e873) and the
Ubuntu 24.04 libmpv 0.37 runtime; numeric locale was C after GTK startup
while the system message locale stayed intact. See
`.build/ui-proof/phase83-indexed-flac-old-r1/`. This is a local run with

The ordinary installed executable also has an opt-in sink monitor:
`scripts/ci/installed_linux_smoke.py --verify-indexed-flac-equalizer
--verify-local-playback --verify-monitor-pcm`. In the script's isolated Xvfb,
D-Bus and PipeWire environment, supply the usual Debian or portable package
arguments plus `--verify-packaged-flac`. The mode uses the real directory
picker and indexed row with a generated 48 kHz stereo s16 FLAC. It observes a
dry baseline, saves independent tone controls, stops, and explicitly selects
the same indexed resource in a new queue entry. It requires an executable
mapping with the attested decoder's path, device and inode in the ordinary
process, and measures bass and treble gain followed by master bypass on that
same entry. The monitor uses one continuous private recorder across the
switch, preserves 50 ms summaries and the longest exact-zero run, and rejects
an active sample containing at least 1 ms of contiguous zero PCM. Stop
requires the old mpv output to detach before the silence sample. This is
separate from the existing installed LADSPA probe.

The installed proof defaults to a 1024-frame FLAC fixture. Pass
`--indexed-flac-block-size 4608` with the indexed proof flags to exercise
the larger-callback lane. The script checks the exact generated STREAMINFO
before launch and records both block limits in the successful report. It
requires the same exact decoder mapping, boosted PCM, same-entry bypass,
and paused sink silence in either mode.

For a developer build, use `--binary` instead of the package arguments, and
`--indexed-flac-sha256` instead of `--verify-packaged-flac`. The binary must
already have been compiled with that Linux FLAC digest and staged beside the
matching regular decoder file. The script does not supply a runtime trust
override. This mode reports a developer binary and does not attest a package
or physical audio output.

An opt-in `Ffprobe::inspect_held_flac` can compare Windows scan metadata
without giving FFprobe a pathname to reopen. It accepts a previously checked
regular file with a plain FLAC marker and a separate leaf filename used only
for metadata projection. It duplicates the existing file as child stdin,
forces the FLAC demuxer, permits only the `fd` protocol, and restores the
caller's original cursor after child exit. A failed probe has no pathname
fallback. This helper does not validate the original open or enable a new
scanner, queue, or playback route.

The pinned Windows source archive in `scripts/ci/windows_media.lock.json`
is FFmpeg 9.0.2. Its `libavformat/file.c:494–533` selects fd 0 for reads,
checks it with `fstat`, and exposes seek on a regular input. Source recovery
does not establish UCRT inheritance or installed metadata parity. To verify
the exact staged Windows executable with its accompanying DLLs, set
`CUMULUS_HELD_FFPROBE` to its absolute `ffprobe.exe` path, then run:

cargo test -p cumulus-core --locked --test held_flac_probe -- --ignored --exact actual_ffprobe_held_flac_matches_path_metadata_and_never_reopens

The test compares every projected field, including tagged and untagged title,
duration, and bitrate. It substitutes another valid file at the same name,
probes the original held file again, checks both cursor and following bytes,
and requires a corrupt held FLAC to fail even when a valid pathname exists.
These cases ran with the local Linux FFprobe 8.0.1; the bundled Windows
FFprobe 9.0.2 test remains pending on an actual Windows runner.

The native Windows probe can now obtain that file from the opt-in
`WindowsFileIdentity::open_local_fixed_ntfs_nofollow`. It first admits only
an absolute drive-letter path, including its extended drive spelling. The
original spelling is checked before any filesystem lookup. UNC, device
namespace prefixes, alternate streams and ambiguous components are out of
scope. It opens the drive root, checks the root handle resolves to an actual
local fixed volume GUID root on NTFS, then uses the held root as
`OBJECT_ATTRIBUTES.RootDirectory` for a single relative `NtCreateFile`.
This avoids using an earlier pathname check as authority for a later open.

The open is read-only, synchronous and restricted to `FILE_OPEN`.
`OBJ_DONT_REPARSE` rejects reparses during resolution, and the nofollow leaf
option and the existing attribute/full-ID helper reject a reparse object at
the end. `FileStandardInfo` requires one link and no pending deletion on
the same returned descriptor. Sharing permits rename and excludes ordinary
writer opens; the link count and attributes are point-in-time checks, not
a content digest. The helper neither binds a queue selection nor replaces
the current Windows scan. It uses the existing locked windows-sys package.

Microsoft contracts: https://learn.microsoft.com/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile
and https://learn.microsoft.com/windows/win32/api/ntdef/ns-ntdef-_object_attributes.
The focused Windows GNU harness links the exact bindings but does not run
Win32. On an actual Windows x86_64 runner with a fixed local NTFS temp
directory, run the replacement fixture and the exact staged FFprobe fixture
above; opt into the real symlink fixture only where Windows permits creation:

cargo test -p cumulus-core --locked --lib fixed_drive_handle_rejects_writes_and_keeps_old_bytes_after_equal_metadata_replacement -- --ignored
cargo test -p cumulus-core --locked --lib fixed_drive_handle_rejects_real_leaf_and_ancestor_reparse_points -- --ignored

The first exercise rejects a writer, keeps reading the old handle after
a same-size/same-creation-time/same-modification-time replacement, confirms
different full IDs, and rejects hard-linked files. The second requires both
leaf and ancestor reparses to be rejected despite their targets being readable
via ordinary paths. Neither fixture has run on Windows yet.
