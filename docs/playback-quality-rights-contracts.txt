接口及顺序
player_quality_details(epoch, playId) 先检查账号代次、当前普通在线歌曲、已加载状态，
随后并行执行七个读取，每个独立最多 8 秒：
1. /api/song/enhance/privilege，沿用 CatalogApi 当前 song ID 和 trialMode；
2. /api/song/music/detail/get，{songId:十进制字符串,immerseType:"c51"}；
   l/m/h/sq/hr/db/je/jm/sk/vi.size 映射对应档位；零值/缺失不伪造大小；
3. /api/music-vip-membership/client/vip/info，沿用 MembershipManager、服务端时钟、
   身份验证和账号隔离缓存；
4-7. /api/vipauth/app/auth/query，{resourceIdList:0,resourceTypeList:PC 数字类型}。
query 只接受零/一行；提供身份字段时必须匹配，重复、畸形或不匹配视作读取失败。
c51 与现有播放/下载 URL 请求一致，不是对本机声道设备或空间 DSP 的检测结论。

各部分 ready/missing/failed 独立，超时或部分失败保留其它有效结果。301、取消、
账号换代不能作为普通未知项继续显示。发布 DTO 前再校验账号、playId 和偏好 CAS，
迟到旧曲目结果不可成为新曲目的权益。会员读取可能更新本地缓存；七个 RPC 均无
线上写入，不宣称完全没有 SQLite 写入。

DTO 不含原响应、URL、Cookie 或密钥。sizeBytes 使用十进制字符串，避免 JS 精度损失。
revision 包含播放身份、偏好和权益/能力；试用尚未启动时包括所提供的时长，活动试用
倒计时和文件大小变化不使同一稳定权益结果换标识。refreshAfterMs 是读取调度建议，
不是音频授权或试用激活。倒计时最少 1 秒，最大 i32::MAX，与官方计时上限一致。

规则和未知值
普通音质 maxbr/fl 向上取整到 kbps；Hi-Res/Dolby/Master/Effect/Sky/Vivid 分别
使用 flag 位 12/14/16/17/18/21。缺字段不是零，不把失败当作没有音源或没有会员。
payed&6、可免费码率、VIP/SVIP、音乐包和试用场景分别计算；Vivid 在当前部分/完整
试听时间线上不可用。服务端最终返回音源及授权时间线仍由现有播放 resolver 验证。
canUse=true/userSrc=0/trialStatus=1 为可开始，状态2为活动试用；userSrc>0 为已有
使用权；canUse=false 为不可使用。未知状态保留 unknown。
生产投影尚未读取 musicPackageCanUseHiresAndLoseless 与 StandardAudio_VIPLogo_PCV2
实验配置；相关分支明确 unknown，不能以 false 冒充官方配置。

试用写入边界
QualityApi::activate 是 /api/vipauth/app/auth/set 的底层原语，数字 resourceId=0、
resourceType=对应 PC 类型，仅 data===true 算正面回执。读取用例从不调用它。
后续已通过显式确认向界面开放试用激活动作。原生生命周期已迁移并通过注册 IPC 验证，
见 playback-quality-trials-contracts.txt：发送/未决日志、只读对账、偏好绑定与后台到期
恢复已有实现，确认界面和动态菜单专项见 playback-quality-dynamic-ui-contracts.txt。
正面回执也不能当成实际播放通过；
不得因打开菜单、读取失败或超时自动激活/重放。没有使用真实账号额度。

为动态权益菜单。它证明 GUI→IPC→Rust 用例，不证明真实账号网络或试用启用成功。
