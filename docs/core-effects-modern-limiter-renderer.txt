Offline modern limiter material renderer

`ModernLimiterPlan::from_material` accepts only an `aev2` object with
exactly these enabled components: GEQ (`eq`), modern bass/treble (`bt`),
material PEQ (`peq`) and explicit B0 (`limiter`). `se`, `rvb` and `cmp`
must be explicitly disabled. See `core-effects-modern-limiter-oracle.txt`
for the original component slots, setter calls and recovered receipt.
It rejects missing or mistyped switches, any extra sibling (including an
explicitly off one), implicit/defaulted active parameters and unsupported
numeric values. Legacy top-level controls remain ignored when an `aev2`
object is present. PEQ band indices must be unique and typed, with at least
one active band, and coefficients are checked at both supported rates.
This is deliberately a narrower offline contract than the service's full
material parser. It permits validated GEQ ±12 dB, BT/PEQ and limiter gains
±24 dB, explicit infinite-ratio limiter, attack 1–10 ms and release 1 ms–1 s.
BT material frequency/Q fields have no effect, as in EF8CA0.

The typed API consumes a decoded material JSON value and caller-owned PCM:

    let plan = ModernLimiterPlan::from_material(&material)?;
    let format = Format::new(44_100.0, 2, 2048)?;
    let mut renderer = plan.pcm_renderer(format, 8192)?;

`ModernLimiterPlan::pcm_renderer` opens an owned stereo f32 renderer at
44.1 or 48 kHz with a 2048-frame quantum. The existing outer stream owns
bounded input/output FIFOs; each original quantum passes through C GEQ,
modern BT using the shared PEQ kernel, a separate material PEQ, then Rust
B0. The source FIFO inserts the one-frame EOF sentinel before all three
upstream stages; only B0 inserts lookahead tail padding. Initial enabling
creates three dry-to-wet edges, including neutral BT. Reset drops queued
input/output, clock and EOF, clears native histories and settles current
bypass targets while retaining material controls and PEQ gain state.
A format, malformed input or FIFO admission error has no sample/clock
side effects. For backpressure, drain queued output and retry the same
input, including a pending EOF write. A failed DSP call quarantines the
renderer, and no
queued samples can be read from that instance after it fails.

`core/tests/fixtures/effects-modern-limiter-graph-official.json` contains
only two invented profiles and synthetic PCM hashes, no service payload or
SDK code. Both use the original whole SDK under the isolated x64 harness
in the oracle report, using the same tap and host boundaries.
One profile explicitly enables neutral BT and the other uses fractional
nonzero gains; the BT frequency/Q fields in both are intentional negative
controls. Fixture PCM comes from the integer-index formula in the Rust
test. At both rates compare the block geometry and interleaved f32 bytes
for irregular/canonical packetization, EOF then reset, reset with buffered
input/output, a 2043-frame last block requiring a second zero-input drain
quantum, and an empty source with the real sentinel. The test also rejects
unsupported topology/geometry, verifies retry after FIFO backpressure,
and quarantines a deterministic overflowing DSP input.

    cargo test --locked -p cumulus-core --test effects_modern_limiter_original

The Rust code is platform independent and calls existing owned C FFI.
The original SDK source data requires no live requests and the checked-in
regression uses no vendor binary. The assembly does not own a decoder,
media descriptor, auth receipt, player state or a sound output. No preset
availability, route, lease or native playback defaults are changed.

Live control of an owned PCM stream
----------------------------------

`renderer.set_material_active(false)` follows outer 68770 → 6B960:
send default B0 controls (0 dB, 5 ms attack, 100 ms release, 0 dB output,
infinite ratio, ratio 4) and run processor 1C590(true). It targets dry for
GEQ, modern BT and PEQ while retaining their previous wrapper state and
parameters for the next quantum. B0 remains enabled in this topology.
Already buffered output is untouched. Pending input remains in the same
FIFO and participates in the next whole quantum, under its new controls.

`set_material_active(true)` after off follows the same-material apply
sequence: 68000 → 1BBA0 defaults (GEQ flat/off, BT flat/off, PEQ off,
0 dB with nine disabled default bands), clear master bypass, B0 defaults,
then GEQ/BT/PEQ setters and B0 material parameters. Already-off siblings
do not affect PCM. The next quantum consumes the pending native wrapper
mix; applying both commands before the next quantum does not add a fake
dry block. Repeating the requested target is a local no-op. Different
materials are not accepted by this API. After source EOF controls are
rejected until an explicit reset; draining remains available.

The B0 timing setters 65581/655A0 set +C5. On the next process, 64F40
rebuilds the B0 delay/envelope and initializes its new skip and EOF drain
debt, even when only release changed at a fixed attack and identical
lookahead length. The Rust owner replaces only that private node; no
read of its state intervenes before its next graph call. If the entire
B0 setting matches the defaults, it keeps the old envelope and pending
lookahead. An equal-timing change to gain/ratio is outside the supported
live scope and is rejected before modifying the graph or FIFOs. That is
not a restriction on the existing fresh-renderer API. No output silence
or padding is inserted to make up for the discarded old B0 history; the
ordinary EOF sentinel and native B0 drain remain distinct.

The frozen `effects-modern-limiter-switch-official.json` uses original
native graph and outer FIFO calls at 44.1 and 48 kHz, with the two existing
synthetic materials plus exact-default and release-only timing variants.
In each of 24 runs, the first output has 31 frames read and unread PCM
retained; controls arrive with 511 and 257 pending input frames. The
receipt records full little-endian f32 hashes of three output segments,
all graph frame counts, B0 +C4/+C5 observations and setup calls. There
are steady, separated off/reapply and coalesced off/reapply controls.
Neither hot call invokes graph Reset 1B960 or B0 Reset marker 65490.
The Rust test compares the PCM hashes and counts, checks that the
existing source clock still advances by the accepted input frames, and
verifies that rejecting an unsupported gain-only switch retains all PCM.
Fixture SHA-256: `7a1be03d74b6d3e9f6e9e8d320fe0beb9217715ac2d68fa17b18bd810d9f12d0`.

To regenerate the fixture with a local copy of the pinned original and
the optional `capstone`, `pefile` and `unicorn` Python packages, use a
loopback-only namespace:

    unshare -Urn python3 scripts/research/freeze_modern_limiter_switch.py \
      --dll LOCAL_ORIGINAL_NEAUDIOEFFECTS_DLL --out NEW.json

The Rust tests require neither those dependencies nor any DLL. This is
PCM and FIFO verification. It does not verify controller takeover, device
queue latency, current authorization, decoder fallback or audible output
on a physical device. The host clock contract is separate from this
renderer, as is the held-source seek/drain path. The focused Linux x86_64
Cargo batch passed 13 tests: modern renderer (5), material preflight (4),
old fixed master (2) and slot-50 tone (2). No Windows device was tested.
