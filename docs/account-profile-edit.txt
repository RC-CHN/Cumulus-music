Cumulus 个人资料保存与网易云 App 扫码转交

入口：设置 → 账号 → 查看个人资料。编辑个人信息打开账号专属草稿，
绑定账号中的“扫码设置”打开单独对话框。

保存协议和边界：
  官方 PC 3.1.42.205594：M15:3649、M3101:917–941、
  pages/user-detail-edit/views/MainView.jsx:129–187。
  POST /api/user/profile/update，只发实际变化的 nickname、signature、
  gender、birthday、province、city。读取和目标 UID 由原生会话决定。
  昵称按 M32 加权 UTF-16 规则，改变时 POST /api/nickname/duplicated，
  已占用、禁止（407）、无法确定分开；这些属于预检，未提交保存。
  简介最多 300 加权字符，可清空。性别只提交明确选择。
  生日是所选日期本地午夜的毫秒数，按该日期的 UTC 偏移换算，
  不把未知值写成零。地区必须是当前已验证地区表中的省市配对；未改变的旧地区不提交。
  core/assets/account-regions.json 是 Rust 和 Vue 共用的 M591 内置回退地名表。

  ProfileEditor 校验草稿和最近快照，再回读同 UID 的 detail 做比较。
  资料已变化时保留草稿，要求重新读取；无实际改动不发保存。
  按账号串行，在首次发送前持久化 UUID、期望版本和实际字段。
  HTTP 或业务 200 只是确认收到请求；成功界面需要所有提交字段
  在同 UID 详情回读中一致。确认后更新该会话的资料和已保存账号摘要。
  超时、回包丢失、不完整回读或中断留待核对，不自动重发。
  “重新核对”只读详情；若结果不匹配，可以在确认后采用当前服务器
  版本，这不会声称原保存成功。未知结果阻止下一次保存。
  前端只经 account_profile_edit_page / account_profile_edit_command；
  原生账号代次检查覆盖读取、保存和回读，IPC 没有任意 UID/URL 参数。

固定扫码转交：
  官方 M3153:186–190 和 M3047:16–29：固定内容
  orpheus://settings/bindaccount，纠错级别 L，二维码为 180px。
  原生仅返回矩阵，由 WebView 本地绘制。没有动态登录票据、Cookie
  转发、网络读取、轮询、自动确认或远端写入。具体变更在官方 App 完成；
  返回后可手动刷新绑定摘要。头像上传、直接解绑/改密、登录设备移除
  属于其他流程，不能以这张码算作已验证的远端业务。

远端地区表：
  来源：M15:1024 /api/lbs/region/code，M198:76–87、590–609，以及 M12
  的 PC 加密封装。定义标 GET，官方符合加密条件时封装为 POST；当前
  Rust 使用现有 PC EAPI POST，参数 {}。未验证官方非加密 GET 变体。
  200 取 data.version 和 provinces[{id,name,type?,cities:{代码:名称}}]。
  Native 只投影这些公开字段，拒绝空表、重复省份、零代码、畸形及超限字段。
  account_profile_regions(epoch) 独立读取，不把地区请求失败当作资料读取失败。
  成功缓存于当前账号 SQLite，读失败使用同账号上次有效表，未缓存时用 M591；
  账号过期和迟到回执仍由代次保护。前端显示名称；新写入由 Rust 按同一表校验。
  已记录的未确认提交可以继续只读核对，即使地区表后来变更，不自动重发。
  Rust 7 项通过，包括新省市配对、无效配对不发写、坏回包保留上版及名称投影。
  Linux WebView 5 个检查点及截图通过；先读到合成地区表，保存后的资料页显示
  缓存地区名，第二次故意返回空表时仍使用原版本，SQLite 独立确认未被覆盖。
  使用合成接口，没有修改真实账号；尚未复验真实服务返回的地区表。
