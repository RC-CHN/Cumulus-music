行为与界面
- 普通行更多按钮、右键、Shift+F10/ContextMenu进入同一菜单；标题保留64px行高，
  更多按钮在悬停/行内焦点时显示。菜单遵守视口边界、键盘导航、退出和焦点返回。
- 只读cloud_resource先核对账号epoch、云盘revision和成员身份。加载/失败/显式
  重试呈现在同一菜单。普通只读重试保持面板打开；过期快照要求刷新列表重开。
  加载面板获得焦点后，首个可用项出现时将焦点移到该项。用户已移动焦点时不抢夺。
- 点击已选中的行时，操作对象为当前显示顺序的已选歌曲；只有一项选中也隐藏
  分享。点击未选行时使用该行，不把其他已选行混入。目标query/epoch/revision/
  clickedId/选择范围在打开时冻结。单行播放使用完整当前筛选/排序列表并从该行
  开始；多选播放只替换为所选子集。下一首按同样顺序加入当前项后，不重启解码。
- 播放使用selectForPage；页面拥有本次失败，不往播放底栏保存旧revision重试闭包。
  正常行按钮、双击和播放全部也使用页面反馈。查询/账号改变后的迟到反馈被丢弃。
- 收藏复用PlaylistCollectDialog，删除复用CloudDeleteDialog。关闭返回发起行，
  行被移除时回搜索入口；旧账号不能恢复旧焦点。弹窗打开时父页面热键受保护。
  收藏失败保留实际结果与目标供显式重试；删除取消不发请求，拒绝不自动重发。
  既有未知/部分删除只读核对和持久化规则沿用cloud-page/batch契约。
- 换账号、换查询、快照失效或卸载清除菜单上下文，迟到读取不能打开旧菜单。
  分享弹窗随账号清除；转场节点不能继续触发已退休操作。
- 云盘、共享歌单/下载弹窗和批量列设置的复选框统一使用主题变量绘制，16px，
  支持checked/indeterminate/focus-visible/disabled，不受GTK白色控件背景干扰。

Rust / IPC / 请求
- CloudLibrary::metadata保留原cloud songId用于播放/收藏/删除，同时单独保存
  simpleSong.id的公开身份依据；CloudTrackView.publicSongId只投射有效公开编号。
  分享构造https://music.163.com/song?id=<publicSongId>，绝不代入cloud songId。
- CloudResourceView只包含epoch/revision/安全歌曲DTO/localAvailable，不含绝对路径、
  Cookie、签名、授权URL。cloud_resource/open_cloud_directory仅主窗口可调用。
- 原云盘列表请求POST /api/v1/cloud/get。菜单读取使用现有本地快照，不新增远端
  变更。play_selection(cloud/cloud_batch)或player_action(queue_cloud_batch)
  刷新并核对云盘revision，保留cloud_song_id资源域，不换成普通song/detail。
  CloudBatch新增可选query：普通行菜单保留筛选排序；独立批量页不传，仍完整自然序。
  云盘播放授权走既有源选择流程；本专项没有增加任意HTTP/业务请求入口。
- PlayerView.resourceKind投射catalog/cloud/local/downloaded/voice。队列去重和
  普通NextPlay共用身份规则，数字ID相同的云盘与在线歌曲互不顶替。
  云盘普通/批量页仅在resourceKind=cloud时标亮当前行。
- 收藏仍经目标歌单读取、revision、持久化意图、POST
  /api/v1/playlist/manipulate/tracks与读回确认；删除仍POST /api/cloud/del。
  参数、未知写入边界和单次/批次上限见cloud-batch-ui-contracts.txt。
- 目录关联优先已发布/完成上传的已登记源文件，再找完整下载的Cloud来源或已知
  catalog ID关联的Song来源，再查明确扫描库映射；catalog身份与分享权限分离。
  下载候选必须完整、没有进行中文件操作、大小符合且非符号链接。真正打开前
  重新读取并验证各来源完整性、成员、账号和revision。扫描/CUE细节见后续契约。
  路径只在core→desktop内部传递，前端仅请求songId/revision。
- desktop/file_manager为下载/云盘共享本机适配：Linux以直接argv调用xdg-open，
  观察最多500ms即时失败，长期运行的管理器在后台回收，不等待窗口关闭阻塞IPC。
  Windows使用专用STA线程、固定open动词的ShellExecuteW，按其返回约定判断
  接受/失败，不拿Explorer进程的退出码当显示结果。显式处理UTF-16与verbatim/UNC
  路径；无shell拼接、任意URL或提权。COM与Shell约定参考微软原始文档：
  https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew
  UI仅反馈“已请求打开”，接受请求不等于目视验证文件管理器已展示目录。
