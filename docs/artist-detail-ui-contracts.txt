结构及操作规则
1. CatalogPage负责读取和来源快照；ArtistHeader、ArtistTabs、useArtistPages分别负责
   页头、标签语义和独立分页。六种子内容各有一个useCatalogPages实例；返回已访问标签
   保留完整分页前缀、原失败提示与滚动，不把第一份缓存替换已加载的后续页。
2. 默认热门列表仍来自歌手详情。页头“播放全部”在专辑、简介、MV等标签也播放热门
   列表，使用详情query/revision。全部歌曲页的“播放已加载歌曲”使用该页所有已加载
   query/revision，保留实际顺序及artist/id来源；没有假装已读取服务端全部歌曲。
   当前列表下载仍使用既有DownloadDialog，需用户继续选择目录及确认。
3. 全部歌曲隐藏歌手头部及标签，提供独立标题和返回热门歌曲入口；全局返回键也先返回
   当前歌手热门页。返回不发停止/重建队列命令。App统一处理访问历史，
   统一导航前记录旧详情位置；当前路由明确保存歌手标签，逐步返回行为见
   catalog-navigation-ui-contracts.txt。批量页/编辑页的离开保护仍优先。
4. 内层列表和页面外层分别记录滚动；入场开始时恢复，快速切换使旧恢复失效。
   面板dataset核对标签身份，防止把尚在退出的旧面板记录为新标签位置。新指针/滚轮/
   触屏或非标签键盘操作取消尚未完成的恢复，避免覆盖用户的新操作。
5. 刷新失败保留旧数据、分页和错误；子标签返回不自动消除列表错误或重发列表请求。
   整个详情重入重新校验页头，见跨页专项。重试明确
   区分第一页刷新与后续页失败，分别替换前缀或追加同一下一页，禁止把刷新重试当加载
   更多。错误区与详情错误共用页内吸顶容器，避免遮挡彼此或滚动后丢失失败提示。
6. 不同资源/访问使用独立会话；账号代次/状态变化释放所有缓存模型和旧读取，使迟到
   回复不能写入新账号/新歌手。同一账号同一ID的资料对象更新仍保留当前标签。
   关注复用既有持久化日志、
   未知/未决禁用和明确对账，不在切换、刷新或截图中自动重试写入。
7. 标签是tablist/tab/tabpanel，单一键盘停靠点，支持方向键/Home/End和可见焦点。
   MV数为0时隐藏，未知数保留视频入口；演出数为0时隐藏。当前选中的入口不因动态
   计数暂时变化而消失。社区响应式在<=900px用168px头像/24px间距，<=620px纵向140px；
   这是社区断点。长标题/无断点别名换行；颜色沿用两主题语义变量。

接口/字段和调用边界（本轮没有增加远端业务接口）
CoreClient.catalogPage(epoch, query, force)经IPC进入core/client/catalog及catalog/details：
- artist：/api/artist/v3/detail，id/top:50/e_r:false；随后现有歌曲权益合并。
- artist_dynamic：/api/artist/detail/dynamic，id；followed与concert.onlineCount决定状态。
- artist_songs：/api/v2/artist/songs，id/limit/offset；songs/total/more，默认每页20。
- artist_albums：/api/artist/albums/<id>，limit/offset；hotAlbums/artist.albumSize/more。
- artist_introduction：/api/artist/introduction，id；briefDescription/introduction。
- similar_artists：/api/discovery/simiArtist，artistid/limit/offset/total:true。
- artist_videos：/api/mlog/artist/video，artistId/tab:1/order:0/page；page是保留十进制
  cursor精度的JSON字符串，不通过JS浮点转换。MV和普通video继续按恢复的真实类型区分。
- artist_concerts：/api/concert/list/byartist，artistId/limit/offset；simpleConcerts/total。
关注CoreClient.catalogMembership：inspect/set/reconcile，/api/artist/sub的artistId，
/api/artist/unsub的artistIds字符串，以及/api/artist/sublist完整分页对账。
播放沿用playSelection Catalog分支和原生来源快照，进入已有详情/权益/音源授权/实际
音频引擎；前端无Cookie、签名密钥、完整播放授权地址，也不自行访问这些业务API。

全部歌曲批量操作
官方 AllSongsList.tsx:92–107、156–159、216–228 的更多菜单打开批量选择，
M622:714–733 与 BatchOperation.tsx:160–179、192–199 给出该入口和选中歌曲动作。
Cumulus 在已加载歌曲上复用有界批量表，将所选可用歌曲传给现有歌单和下载确认框；
打开或取消不提交请求。BatchOperation.tsx:114–126、160–166 的「播放」从所选
歌曲的第一首开始；Cumulus 使用原生明确播放命令，队列只包含所选歌曲，保留列表
顺序，不采用双击行的队列设置。「添加到歌单」对应官方批量 Favorite 打开
FavouriteModal 选择目标歌单，见 album-detail-ui-contracts.txt；不作为批量心形喜欢。
未加载曲目不在歌手批量弹窗范围；所选歌曲入队见下文。
catalog_smoke.py --artist-batch 核对勾选、确认框范围与取消，并读取原生队列验证播放。

全部歌曲的「添加已加载歌曲至播放列表」
官方 AllSongsList.tsx:92–107 传入页面 records，M622:735–759 绑定歌手菜单的
addToPlayList，M308:3216–3246 传入插入点及是否播放，M1384:2625–2661
去重并在该点插入。Cumulus 仅消费当前已加载的连续歌手歌曲页及其版本，在当前项之后
添加并复用已有歌曲项；保持当前项和暂停位置，空列表从首个新增项播放。不自动加载
剩余页面。代次、页面版本和队列版本由原生核验；FM、心动模式和一起听不走此入口。
catalog_smoke.py --artist-batch 同时验证已加载页的范围、去重、插入顺序及播放保留。


全部歌曲的「添加所选至播放列表」

- 官方 artist/BatchOperation.tsx:30–38,91–113 取当前歌手 records，按展示顺序筛选，
  以第一首作为 Action.addToPlayList 的 resource，整组为 Scene.artist 的 selectedData；
  :160–179 的动作顺序是播放、入队、下载、收藏。:59–89 的独立批量页无 records 时
  会恢复请求；社区从已有全部歌曲页打开弹窗，只允许已加载的前缀，不补全剩余页。
- M7:139–140 固定官方 PC 为 file 队列；M3085:243–296,297–311,553–584 据队列长度
  区分是否为空；只在空列表把 Add 改为 Play，
  非空不清队、不触发同曲切换或播放。M308:3138–3152,3214–3248 使用当前项之后的位置，
  没有当前项就在队首。M1384:2628–2666,5241–5267,5273–5298,5366–5376,5695–5723
  处理资源去重、空队列首曲（随机模式随机选）和随机后继。Rust 复用已迁移的随机顺序规则，
  用相对条目顺序表示后继，未迁移官方播放日志和原随机标量。
- 前端打开弹窗时冻结账号所属歌手及已加载分页，确认入队时捕获队列意图，退场前不重绑到
  新列表。原生核对账号、连续页类型/资源/偏移/版本、所选 ID、队列和播放器代次；原生缓存
  决定实际顺序，不使用渲染器传来的排序。页刷新与小版本标记同事务，原生准备完和安装前
  仍检查；旧合法缓存按需本地升级。只补所选歌曲的普通原生元数据，按 M59.j → M23.z
  的普通在线码率/试听信号排除明确不可播项，实际起播才申请对应音源。此入口不复刻
  M59:145–169 的下载、本地缓存或同音替代支路，不借未选歌曲或放宽会员权限。原生保留已有条目身份、当前解码和暂停时钟，
