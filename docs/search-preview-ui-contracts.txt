原生候选
- 支持签名 PC 实验能力的实际 MusicHttpClient 通过既有验证宿主取得完整分配，
  同一批同时决定 searchHot、searchMore2、searchPageEfficiency 与页脚；不再
  先读旧的短三桶，也不为第四桶追加请求。签名、PC 来源 Cookie/device、UA、
  clientSign 与原生 PcConfig 仍由原传输校验。搜索响应中的任何自报开关无效。
- 没有该原生能力的通用 Api 仍可使用旧三桶的兼容布局选择；它不能授予页脚。
  默认未启用实验宿主、匿名/未验证 profile、未知/缺失/非字符串/非t1分配都不
  产生新的页脚资格。普通搜索不会因可选实验读取失败而整体失败。
- 一次成功的完整分配复用共享宿主的原30分钟期限，不从第一次搜索消费时续期。
  失败按原周期合并后续尝试；只有相同账号代次、同一 Api 实例与同一凭据版本的
  已知内存分配可以按官方 catch 保留。旧磁盘三桶只保留既有布局回退，不能开启
  页脚。其他原生消费者成功更新共享分配后，即使搜索仍在失败退避期，下次读取
  也会使用新分配。没有新增后台定时器，也不在等待期间占有播放器 actor 锁。
- 失败 catch 必须优先使用同一账号代次/Api/凭据版本下最近一次全局成功分配，
