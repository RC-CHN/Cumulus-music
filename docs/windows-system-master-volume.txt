Cumulus
- desktop/audio_diagnostics 在独立阻塞任务中平衡同线程 COM 初始化和释放，
  只读同一默认端点，不发送服务请求。主窗口 IPC system_master_volume 只返回
  unsupported / unavailable / ready(percent)，不传设备标识、原生错误或原始标量。
  读取有两秒 UI 截止时间，一个未返回的 OS 调用占用唯一槽位，避免请求累积。
- 设置的音频输出区首次进入时读取，使用现有「刷新」明确重新取值；不轮询。
  成功静音或实际零音量显示 0%；原版 JS 的真值保护有机会保留旧的非零数字，
  本端不保留它。端点/接口读取失败或越界标量显示不可读取，避免把失败报成静音。
  Linux 不显示此 Windows 专项，不把播放器滑条值冒充系统音量。
- 此处没有系统音量或静音写入、设备迁移、空间音效/系统增强开关、自动恢复音量。
  淡入淡出仍受 DirectSound 限制，见 playback-fade-mute-contracts.txt。

验证
- Rust 冻结 native f32 转百分比的临界舍入、零值、静音优先及非法标量拒绝。
- scripts/ci/system_master_volume_smoke.py 使用 ux_ui_probe 和真实 Vue/Tauri
  WebView。合成 Windows 端点按 37% → 静音 0% → 不可读 → 84% → 重开 84%
  返回；检查焦点、深色窄窗口及每次一次原生读取。另起未注入的 Linux 进程，
  原生返回 unsupported，页面隐藏。真实 libmpv/null 同一暂停曲目的 ID 和
  时间不变；两个进程只调整 LC_NUMERIC=C，系统语言保留非 C。6 个状态和
  6 张截图；没有读取 Windows 实体设备或修改系统音量。

Windows CI 与实际端点边界
- Windows x64 上用相同已嵌入生产前端的 ux_ui_probe.exe，需已安装标准
  WebView2 runtime。包构建阶段准备好 .build/package-stage/windows-x64/native
  后运行（Windows 不带 GTK 截图参数）：
    cargo build -p cumulus-desktop --example ux_ui_probe --features custom-protocol --locked
    python scripts/ci/system_master_volume_smoke.py --binary .build/target/debug/examples/ux_ui_probe.exe --root .build/ci-system-master-volume-windows --runtime .build/package-stage/windows-x64/native
  只跑五个合成端点状态；不在 Windows 执行 Linux unsupported 流程。探针在
  创建 WebView 前强制安装合成 reader，记录每次调用。驱动用绝对运行时路径，
  拒绝探针旁 DLL 覆盖指定包，记录所选 libmpv 文件名和 SHA-256。隔离
  APPDATA、LOCALAPPDATA、TEMP/TMP 和显式 WebView 用户数据目录，不继承
  外部 WEBVIEW2_* 或 MPV_DLL_DIR_CUMULUS 覆盖。没有实际 Windows 音量读写。
- 另做 Windows runner 的真实只读 COM 诊断时，不能用本功能 UI 的 unavailable
  推断「无设备」：仅在 GetDefaultAudioEndpoint(eRender,eMultimedia) 返回
  E_NOTFOUND（HRESULT_FROM_WIN32(ERROR_NOT_FOUND)，0x80070490）时报告该
  默认端点不存在。若已经返回 IMMDevice，后续激活/标量/静音读取失败应报告
  「端点存在但不可读」，保留失败阶段和 HRESULT；若初始化、枚举器创建、音频
  服务或端点查找因其他错误失败，则存在性未证实。纯读取成功只记有效范围已验证，
  不记录实际音量、静音值或设备名称/ID，不安装驱动或改变默认端点。
- 可选 Windows system master volume runtime sample workflow 只接受手动触发。
  在与 workflow SHA 相同的提交上，编译 desktop/probes/windows-system-master-volume，
  直接复用生产 COM 读取源码，不启动 Tauri/WebView、播放器或账号。子进程只
  采样一次，10 秒上限。结果 artifact 保存 commit、固定 eRender/eMultimedia、
  上述分类、失败阶段和 HRESULT。若超时，单独记录 backend_unknown/probe_timeout
  和 probeReturned=false；不得推断端点存在与否。无端点、不可读、状态未知
  都是诊断结果，不是发行门槛。合成 WebView2 检查与此 workflow 独立。

普通播放栏音量诊断提示

- 3.1.42.205594 VolumeVertical.tsx:349–412 / hybrid_app M/83:720–768：
  音量面板打开记录软件音量，关闭后只有相对提高且到达 80% 才检测。
  Windows 原版依次读系统主音量、系统音频增强及空间音效。低主音量判断
  采用有效原始浮点数，大于零且严格小于 30%；系统静音折为零，单独不触发。
  29.99% 可以触发，设置行仍显示舍入后的 30%。增强或空间音效返回
  code === 0 且 enable 时，也可以各自触发原提示。原版桥调用抛异常时中止本轮；
  社区版的只读探针通过类型化结果报告端点不可读取，此时仍可由另一个成功读取
  触发。主音量正常而空间音效开启也可触发；系统音频增强尚未接入。
- M/473:11843–11930 的弹层原文「当前系统设置可能影响播放体验」「去查看」，
  5 秒自动关闭；「去查看」进入 /setting/play，refer=volume_dignose。
  M/1384:4323–4373 手动关闭或跳设置才持久化时间；仅当
  autoCloseFrequencyControl=true 时自动关闭也持久化。
  M/247:447–451 的默认配置为 7 day、autoCloseFrequencyControl=false；
  M/103:127–142 支持 day/hour/minute，判断严格超过冷却时间。
- Vue 主窗口仅在真实改动普通音量面板后，使用已有原生音量命令的成功回执
  计算关闭资格；被拒绝的写入、过时代际及未操作退出不触发。Rust 比对播放器的
  已确认软件音量和会话（读取前、两次读取之间、发出收据前均校验）。依次使用
  既有两秒单槽探针读取主音量和空间音效；平台不支持和端点读取失败分别保留，
  两者都不被视为成功读到关闭。冷却仍存于设备本地 SQLite；原生标量、空间状态及
  设备信息不经此提示的 IPC 输出。
  默认策略或已加载的受信任 PC 配置由 core 读取，不新增网络、账号写或遥测。
  单次短期收据仅允许已有弹层关闭；Linux 不具备端点时不出现提示。
  「去查看」使用已有音频输出设置聚焦和滚动；不调音量、不换设备、不改播放队列。
- 可执行合成验收：对同一实际 WebView / libmpv null 运行
  scripts/ci/system_master_volume_smoke.py --diagnosis（既有 --binary、--root，
  Linux 可选 --frontend-dist / --screenshots；Windows 需 --runtime）。
  Linux 实际 GTK/WebKit 验证 12 个诊断状态：合成端点覆盖系统主音量 84% 而
  空间音效开启、空间读取失败、原阈值和冷却；独立进程验证 Linux 原生不支持。
  设置页的 6 个状态也通过。两个流程均经原生 IPC 和 libmpv null，外部请求、
  真实账号及系统设置写入均为零。未验证实体 Windows 端点的实际状态或听感。

系统空间音效：独立只读设置项

- Play.jsx:95–132、560–589 在 Windows 的播放设置先读主音量，再读空间音效，
  最后读系统音频增强。M/4:15332–15339 是 `audioplayer.getSystemSpatialSound`。
  同一 x64 DLL 的 F23130–F2317B 绑定 F1C140；F1C231 调 1B0220。
  1B023E 初始化 STA，1B0260–1B0299 创建 MMDeviceEnumerator 并取
  eRender/eConsole（不是主音量的 eMultimedia）。1B02BE–1B02C5 激活
  `ISpatialAudioClient`（BBF8E066-AAAA-49BE-9A4D-FD2A858EA27F），
  1B02DD–1B02EB 调 `GetMaxDynamicObjectCount`，成功时大于零才返回启用。
  不激活音频流。微软说明零也可能表示设备不提供动态空间对象：
  https://learn.microsoft.com/en-us/windows/win32/api/spatialaudioclient/nf-spatialaudioclient-ispatialaudioclient-getmaxdynamicobjectcount
- 同一设置区进入或手动刷新时，桌面在主音量之后以独立、有界的阻塞调用读取
  这个默认控制台端点。结果只区分已开启、未启用或设备不支持、暂时不可读取。
  失败不当作关闭，不保存账号偏好，不输出端点 ID、对象数或 HRESULT。
  Linux 原生返回 unsupported，隐藏整项；不提供开关，不改变输出或播放。
- 相邻增强读取 F1BAD0→1AF2E0→1AEDD0 使用默认端点 ID 拼装系统注册表路径，
  在 1AF10F–1AF172 读私有值，读取失败仍可沿用内部默认 true。没有把公用
  `PKEY_AudioEndpoint_Disable_SysFx` 当作相同字段，不复制私有读取、注册表写入、
  修复或官方客服入口。播放栏诊断与本设置复用空间探针，设置仍为独立只读行。
- 同一 `system_master_volume_smoke.py` 真实 WebView/IPC 夹具同时核对两个端点
  读取的顺序和次数、空间音效开/不可用/恢复及 Linux 隐藏；只在测试宿主注入
  空间状态，仍以真实播放时钟和当前暂停实例不变作为约束。其结果不代表有
  实体 Windows 端点或当前播放器使用了默认控制台设备。
