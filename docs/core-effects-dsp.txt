Rust组织

effects/dsp/state.rs：C布局查询、独立分配/释放、暂存干声、处理前检查与失败隔离。
effects/dsp/ffi.rs：私有C声明，不向业务或前端暴露原始指针。
effects/dsp/filter.rs：两套有区别的滤波器枚举、Coefficients、Biquad。
effects/dsp/graphic.rs：GraphicEq、BassTreble与低高音参数。
effects/dsp/parametric.rs：九槽ParametricEq、总增益和LFE处理。
effects/material.rs：PEQ/旋转/空间片段解析，显式片段枚举及安全PEQ应用。

内存与线程契约
所有状态由Rust独占分配，大小/对齐由同一C编译单元返回，Drop使用同一Layout释放。
这四类状态均只含内联数值，无堆指针、回调或线程归属；允许Send转移，禁止Sync共享，
变更和处理都要求&mut。C不持有Rust缓冲区指针，不发生跨线程回调。
Format范围8000..384000Hz、1..8声道、每声道容量1..4096帧。
PlanarBlock始终包含channels*capacity个float；逐声道stride为capacity，
不是valid_frames。干声缓冲在初始化时分配且不与输入重叠；process不再分配堆内存。
容量/采样率/声道不匹配、valid_frames超界、输入含NaN/Infinity时，在调用C前拒绝，
不推进DSP状态。参数更新由C先验证后提交；PEQ整份材料计划另在Rust预验证后才应用。
有限输入运算溢出产生非有限输出时，当前整块清零并锁定该级；后续处理要求重建。
Biquad提供显式reset清历史；其空输入直接返回，不把空切片的悬空指针交给C。
这是社区边界的错误隔离，不能把畸形参数路径宣称为官方逐位等价。

保留的官方行为
1. GraphicKind 0..8与ParametricKind 0..10不是同一枚举。GEQ峰值的三角函数/快速幂
   和参数EQ的成对正弦/powf不同；没有换成通用均衡器公式。
2. Biquad按指针16字节对齐处理标量头部、四采样矩阵和尾部，修改系数保留历史，reset清历史。
3. 十段GEQ按恢复的搁架端点和中间八段构造。全零参数不是强制位流直通。
4. BassTreble默认低搁架120Hz、中间峰值2000Hz、高搁架5000Hz；低高音增益裁到±24dB。
5. PEQ九槽，前三槽默认启用。类型0/1/4/5不使用Q，允许有限的0/负Q；其他类型要求正Q。
   总增益和段增益裁到±24dB。dirty参数在有效音频处理时更新并保留历史。
6. 开关只记录目标状态；从旁路重开清滤波历史。状态边沿按完整capacity做干湿混合，
   valid_frames为0也可能触发整块混合。不能只给有效帧分配内存。
7. 外层处理临时设置SSE FTZ，处理后恢复原FTZ位，再做混合；其他舍入/DAZ位不变。
8. PEQ输出增益的四采样前缀和1..3帧尾部用不同坡度起点，按官方顺序保留。
9. 含LFE且初始化时排除它，滤波声道数保持固定；后续processLFE只改变输出增益路由。

材料解释器与应用边界
on必须为bool；缺失/错误类型视false。关闭时仅发最终关调用。
PEQ开启时先发可用总增益，再读f的前九个位置；非对象项占位置但不发调参。
循环前默认band0/type1/freq80/gain0/q0/on=true；缺失或错类型字段沿用前一项的局部值。
band/type仅接收int32再转u32，负值保留回绕；数值参数转float32，布尔不是数字。
最终才发开关。过大数值转float32非有限时额外拒绝，不交给DSP。
apply_peq先校验整份计划，band>=9按官方外层忽略；其他无效类型/参数拒绝且不留半份更新。
旋转片段默认velocity20；空间片段默认presence0/stereoizer0/sshaper=false/ambience0，
依官方数字/布尔/int32类型规则提取。这里只解释调用，不声称旋转或SE声音已接入。

peq_sections枚举顶层peq和aev2.peq；不做整机引擎选择。官方旧分支没有读取顶层peq，
因此显式选择顶层peq做组件渲染不能当作官方完整预设效果。
spatial_sections遵循静态恢复的EFB760规则：aev2是对象时只取其se/rotate，
即使aev2为空也不回退顶层片段。完整材料效果图及其状态仍待迁移。

channels*capacity个float32。输出保留整块容量；生成音频文件时只取有效帧。

按官方材料分派选择 PEQ
`effect_dsp_render material-render-active-peq INPUT.ncae` 使用 EFB760 整份材料分派
和 EFC380 的 PEQ 调用，然后只渲染该 PEQ 组件。旧式顶层 peq 不派发；空或错型
现代片段不回退到顶层。缺失组件时工具报错，不输出部分 PCM；显式 on=false
仍触发组件原生旁路过渡。底层 apply_routed_peq 在缺失组件时不修改已有 PEQ 状态，
此调用只执行分派，不执行整图 begin/reset；原片段诊断模式保留。命令不渲染混响、
空间音效或整份预设。
合成 NCAE 由已恢复的 CEB6A0/CEB7E0 密钥流和 raw DEFLATE 封装，现代片段参数取
公开冻结 PEQ type-slot 首块；Rust 解码、路由和渲染结果与原生首块 PCM 对照，
另测旧片段拒绝以及已激活组件在缺失/显式关闭时的不同状态。

原生播放器生命周期
可信原生宿主可以通过 MusicClient::set_native_parametric_component(epoch, plan)
设置或清除已核验、调用者已获准使用的 PEQ 组件。它不会获取材料、查询或占用权益，
没有 IPC、账号持久化或自动恢复，也不会在冷离线播放器里沿用。桌面播放器使用同一
可信音效库；宿主不传库路径、材料 JSON 或控制 ID 到 renderer。
控制器依账号代次处理命令；正解析或解码时不等待引擎锁，只记录最近一次待应用命令，
正常加载完成并首次 unpause 前处理。DeferredUntilLoaded 是排队回执，Configured
是配置回执，都不证明实际 PCM 已处理。普通曲目切换可以保留配置；停止、加载失败、
切换账号或关闭控制器会清除。清除失败会停止播放并阻止新加载，直到原生清除成功。
上面 libmpv 探针使用生产 AudioEngine 的应用、清除方法；控制器合成回归另外验证
解码期间的排队、首次 unpause、账号隔离和失败后的停止/重试。不宣称整个效果图、
Windows 音频输出或官方权益激活已验证。

显式关闭 PEQ 时，EFC380 只设置 on=false；已挂载节点保留历史并运行原生湿转干过渡
（netease_peq_bypass / netease_peq_process），无需重建 libmpv 滤镜图。无已挂载
节点时保持干声；None、停止和所有者变更仍立即卸载。旧 v1 插件缺可选 bypass 符号时，
控制器报告失败并清除旧节点。重新启用带参数的材料仍建立新节点，避免继承省略的频段。
每个 LADSPA 声道在自己的下一个处理块读取新配置；本桥不承诺跨声道同一采样点切换。
