本轮变化
- 已确认成功且没有清理/回读警告时，裁剪窗口退出，焦点回到封面入口，编辑页显示
  “封面已保存”。名称、简介、标签草稿不随封面保存而提交或丢失。
- 正在准备、上传、暂停和保存/核对显示各自阶段；进度条旁显示已确认的百分比。
  暂停请求返回并不代表正在发送的数据已停止：“正在暂停…”保持禁用，直到传输结束。
  已完成的原传输结果优先于晚返回的暂停快照，不能把已确认保存的界面退回上传中。
- 上传中断时不再显示“正在上传图片”。保留恢复权限和继续保存的入口，不把失败重试
  当成自动后台动作；结果未知时保存不可重复点击。
- 展开最新歌单信息时，当前窗口正文滚动到恢复操作，短窗口也能看到确认应用入口。
  长词和简介换行，底部动作和关闭按钮保持可达，不滚动背后的编辑页。
- 已成功保存但本地清理失败时保留窗口，用主题中的警告色与失败分开显示。可以重试，
  再次失败保留反馈；清理成功后正常退出。它不意味着封面保存失败或远端图片被删除。
- 统一底部两按钮的边框占位，使两列均为官方175px；避免描边按钮176px、主按钮174px。
- 为文字和百分比保留覆盖式滚动条的空间。减少动态效果和关闭后的焦点沿用共用动画。

实际操作矩阵
1120×760 / 760×540，浅色 / 深色：上传中、请求暂停、暂停完成、继续保存并成功退出。
760×540深色 / 1120×760浅色：
  申请结果未知、上传结果未知、放弃上述任务、保存被拒；
  上传权限失败、重新获取权限、继续保存；
  绑定响应丢失、只读核对成功；
  外部修改冲突、查看长简介、明确确认后保存；
  清理警告、重试仍失败、恢复后清理成功。
最后在深色短窗口和浅色宽窗口检查登录失效后的退出、明确的失效说明与重新登录入口。
通用欢迎页在expired状态改用失效文案；已有服务端登录提示继续优先显示。
总50个界面状态，代表上述矩阵，不代表全应用50个页面完成。

验证实现
- playlist_cover_feedback_ui_probe.js 只操作生产 DOM 和正式 IPC。example 的 API/NOS
  对端在内存中模拟；core 实际进行图片解码、裁剪编码、分块、持久化和对账。
  合成1024×1024噪声BMP让裁剪后JPEG超过256KiB，暂停发生在真实多块发送之间。
- 申请/上传/绑定结果丢失、403和外部修改来自对端行为，不直接给前端注入任务DTO。
  同一任务恢复核对不重复绑定；终态与元数据未写入由对端计数及实际核心状态共同检查。
- 清理失败由example临时改变它自己在隔离目录生成的JPEG制造，随后恢复原字节；
  不触碰用户文件，不假装生产程序自动修复外部文件。所有等待均有超时。
- 合成服务没有提供外部封面URL；本项证明成功反馈和流程，不证明CDN图片刷新或真实
  服务上传。真实账号用的playlist_cover_ui_probe.js已同步成功关闭流程，本轮未执行。
- pause并发的前端测试覆盖重复点击和请求失败；单元测试不替代上述WebView操作。
