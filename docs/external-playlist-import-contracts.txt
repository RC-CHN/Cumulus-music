外部歌单导入：官方桌面入口、公开 H5 与本地预览
研究对象为官方 PC 3.1.42.205594 及其固定公开 H5 入口。没有用真实账号访问导入服务。

官方触发和宿主

  「创建的歌单」旁的加号显示「创建歌单／歌单导入」；未登录会唤起登录。已登录且本地

- 下载的公开静态页面（匿名 GET）引用 s7.music.126.net 的 new/index.8910399d.js。
  SHA256 39ecd509b89e4d9dc3dbe866310536c952184e6e23bb65f5697132394d114095；
  runtime.10183021.js SHA256 3cf64b1995661a849611975b6323fb6be283e2146035e194fae63b9e99877148；
  vendors.f2f78b87.js SHA256 4cc2d5c0b6eab8a8137d011438483826075921ffd9dff575c3a456331da5a635。

官方输入和请求
- H5:6323–6400 默认显示链接、文字、图片三种导入。pCmP:6433–6467 是无依赖的分享
  文字提取器；链接页初始一个输入，最多十个，每个取一个候选，手动输入时不自动去重。
  通常取第一个 URI，某些平台特殊路径优先，并识别 QQ、酷狗、酷我、小米标签。
- H5:3473–3517,4467–4517 的 POST /api/playlist/import/url/check {link:encodeURI(url)}
  仅在非桌面的剪贴板自动填充启用后执行；桌面分支直接跳过。它不构成桌面手动输入的
  曲目预览或可导入回执，Cumulus 也不调用它或读取剪贴板。
- H5:3618–3685,7796–7816：用户主动开始后，链接分支为
  POST /api/playlist/import/name/task/create 构造 playlistName、createBusinessCode、
  extParam、taskIdForLog、importStarPlaylist、rqRefer 和 songs。songs 是 JSON 数组字符串，
  每项 {name,type:"",url:encodeURI(提取结果)}，保持输入次序。默认名称为「导入音乐 」加
  本地时间 `YYYY/M/D HH:mm:ss`，也是每项的 name（H5 Ws0M:464–470）。固定桌面入口的
  query 仅给 appBizName，createBusinessCode 和 extParam 均为 undefined，WEAPI JSON 中省略；
  taskIdForLog 是空字符串。importStarPlaylist 默认 false，属于另一个可选目标。
  桌面 rqRefer 取 window.rqRefer，无值时用空字符串（H5:7211–7228）。
  文字分支复用接口，把整个输入封成 rpc://playlist/import?text=...（4590–4652）；
  图片使用 /api/playlist/import/create，带 playlistId 和 picIds JSON 字符串（5359–5407）。
  H5 的本地音乐隐藏页分支通过 /api/playlist/local/detail 读详情，提交 multiSongs；
  官方桌面固定入口没有 initPage=3 或对应目标，不能把该页当外部链接的预览。

桌面 CEF 到 H5 提交路径（静态恢复）
- 两个安装包的 cloudmusic.dll 均把同一个带 `NeteaseMusicDesktop/3.1.42.205594` 的 UA
  字符串设置到 CEF 初始化结构。它与已记录的 WinHTTP 字符串一致，但这里独立核对了
  CEF 的调用链。以下为 `objdump -d -M intel` 显示的虚拟地址，`objdump -p` 可核对导入表。
  x86 DLL SHA256 b080a1c8c90cce1e2eefe93d992f81dc4db02dee7bc8c3b681e69e55a001cace：
  0x10001170 从字面量 0x10ac3020 初始化全局字符串 0x10bb212c；0x1001996b 调
  0x10023d40，把字符串写到 CEF 设置 +0x70（0x10023fc1–0x10024016，0x1002428f 调
  cef_string_utf8_to_utf16）。0x10019ad6 将同一设置缓冲传给 cef_initialize。
  x64 DLL SHA256 557d7706dedc8556a8bd279d4dfe2bc05b80ad729a8749caccd9e29916935493：
  0x18000318b–0x180003199 将字面量 0x181dbb590 拷贝到全局字符串 0x1822059c8；
  0x1802e1268 调 0x1802e7300，在 0x1802e74da–0x1802e752d 把字符串写到设置 +0xc8
  （0x18006718f 调 cef_string_utf8_to_utf16）。0x1802e12ee 把同一设置缓冲交给
  0x1804f2cf0，后者在 0x1804f2ebe 经导入跳板调用 cef_initialize。
- H5:6400–6431,6645–6664 的 oEee、网络包装器判定固定入口启用加密。固定哈希
  vendors 的 TSUN 将上述 UA 归为桌面；WoLd 的 HostPatcher 将 mp.music.163.com 映射到
  interface.music.163.com，其移动 App 正则要求 `NeteaseMusic/` 或 `NeteaseMusicIpad/`，
  不匹配 `NeteaseMusicDesktop/`。如果相对路径已选中桥接，HostPatcher 会在发送前报
  DOWNGRADE，HpmA 改用直接浏览器请求；本来未选桥接时，直接换到该接口域名。
- vendors/jA/N 的浏览器分支将 /api/ 改成 /weapi/，加密表单参数为 params、encSecKey，
  带 `credentials: include`。从 H5 文档 Cookie 读到非空 __csrf 时，csrf_token 同时进入
  请求 URL 的查询和加密载荷。链接提交因此走
  POST https://interface.music.163.com/weapi/playlist/import/name/task/create 。PC 虽有
  hybrid_app/290.js:196–228,265–334 的通用 net.nativeRequest，不能由此把该固定桌面 H5
  提交改成 interfacepc 的 EAPI。以上是二进制配置和脚本分支证据，没有实机抓包、真实登录
  Cookie 或服务端受理验证；也没有扩大任何账号 Cookie 的作用域。

任务受理、完成与回包丢失
- H5:6635–6664 解开成功回包的 data（没有 data 时用原对象），链接分支需取到 taskId
  才调用 nm.mine.importPlaylistTask({taskId})（H5:3650–3678）。PC 的 hybrid_app/290.js:
  436–442 忽略实参，无条件回 code 200，未登记或回查该任务；这只确认桥调用成功。
  H5 随后调用无 taskId 或 playlistId 的 orpheus://nm/base/startExternalPlaylist。
  M/290:45–53 只派发 step: start-external 并关闭 iframe，M/1384:4279–4306 只显示
  「歌单正在导入」，提示到「创建的歌单」和小秘书的私信查看；可显式再导入其他歌单。
  请求失败或缺 taskId 留在表单并提示，官方桌面没有完成轮询。H5:309–316 注册的
  nm.song.importTask 没有调用方，和实际调用的 nm.mine.importPlaylistTask 不同。
- M/15:4866 的 /api/playlist/import/task/status/v2 仅创建函数后被逗号表达式丢弃，
  未恢复官方调用方、实参或回包。非官方 netease-api-reborn 4.29.7 的
  module/playlist_import_task_status.js:1–11 传 `{taskIds: JSON.stringify([id])}`，
  这是尚未验证的线索，不能作为生产协议。没有已验证的状态枚举、错误语义、账号归属
  或任务与新歌单 ID 的绑定；即使将来验证，也只能查询已经拿到 ID 的任务。
- 小秘书提示指私信，不是 /api/msg/notices 的通知标签。恢复的 PC 私信界面按一般消息
  渲染；PrivateItem.jsx:103–175 和 TalkItem.jsx:123–190,304–327 未见该导入专用的
  消息类型、固定发送者 ID 或 taskId 与消息/歌单的绑定。不能按标题、时间或昵称自动归因。
- 丢失创建回包时没有任务编号可查，空 taskIdForLog 也没有可证明的幂等语义；
  不能自动重发、改走其他协议或宣称任务失败/完成。以下 Cumulus 实现只移植链接任务创建；
  文字、图片、红心目标及服务端任务回查仍需分别恢复和验证。

当前 Cumulus 本地子集
- 「我的歌单 → 歌单导入预览」是本地入口，明确不同于 t1 的正式侧栏入口。
  维持一个手动输入、最多十项的原输入规则，原样保留字段顺序和重复项，显式点击预览后才处理。
  该入口的预览只展示域名、平台标签或不能识别提示；预览本身不读取曲目、不创建任务。
- Core Rust 的 preview_external_playlist_inputs 是纯函数；类型化 IPC preview_external_playlist
  只返回域名、平台和空/未识别状态。输入最多十项、每项最多 16 KiB；HTTP(S) DNS 主机
  使用 URL 解析、平台按真实域名边界匹配，拒绝本机无域名、IP、凭据和非 HTTP 协议。
  安全边界与旧网页宽松子串正则不同；路径、查询、原链接不出现在返回 DTO，也不打开或上传。
  不从平台标签推断链接有效性、资源数量、账号权限或导入资格。
- 编辑或切换账号使旧结果失效，关闭丢弃草稿并还原焦点；输入与结果不写磁盘。
- core/tests/fixtures/external_playlist_input.json 的 official 值用 Node VM 直接执行固定
  哈希公开脚本注册的 pCmP 工厂得到。冻结向量只使用合成 URL，并列 Cumulus 安全差异。
  可复现：匿名读取上面的固定入口及对应 JS，提供 {window:{}} 给 VM 注册 webpackJsonp，
  只执行 pCmP 工厂并调用其 a 导出，不执行 H5 页面或其它网络模块。
- Linux 真 WebView 侧栏回归通过 51 个检查点和 51 张截图，包括实际 IPC 识别、
  非网页输入、编辑废弃旧结果、重开清空、十项上限和返回焦点。证据
  `.build/ui-proof/external-playlist-preview-20261104/audit.json`。
  无真实业务请求或账号写入；既有四次歌单排序变更只在合成夹具中运行。

Cumulus 链接任务与独立扫码授权
- 在现有「我的歌单 → 歌单导入预览」中，识别到有效链接才显示导入动作。入口和旧版
  官方按 PH-PC-songlistTransfer=t1 试验进入的侧栏菜单不同；仍保留本地预览和取消。
  启动授权需用户点击。先预览，再原生准备确切链接及名称，最后显式确认才发送。
  确认时取消按钮优先获得焦点。关闭、编辑、切账号或取消时销毁待发送草稿。
- 单独的 Interface 域身份来源为恢复材料 netease_account_probe.py:34–39,103–109,
  186–194,260–281、产品报告 01:105–112 和 07:21–27 的历史真实验证。Rust 原生
  只在该域创建 type=3 二维码（/api/login/qrcode/unikey）、读取状态
  （/api/login/qrcode/client/login）。803 或可能已经授权后的不确定状态只核对
  /api/w/nuser/account/get，不重发旧二维码请求。合成测试验证 801、802、803、
  中断核对、取消迟到、错账号及 EAPI-only Cookie。
- 另行扫码后须确认同一个用户 ID、当前 PC 账号代次和两个路径的有效 Cookie。
  接受的 Interface 会话只存在原生进程内存中，不复制、重定域名或使用 PC Cookie。
  扫码只向 Vue 暴露有界二维码矩阵和流程状态；新进程需重新授权。
- WEAPI 请求使用固定 Interface URL，禁用重试和重定向。按实际目标决定 HTTP Cookie，
  仅固定 H5 文档路径按 Domain、Path、Secure 和 HttpOnly 规则可见的 __csrf
  才进入查询和加密载荷（vendors N1T3 不解码文档的原始值）。两类 Cookie 的读取
  不打开 H5 域、不扩大凭据作用域。HTTP Origin 和 Referer 取固定 H5 来源。
- Rust 保留链接顺序及重复项，以 JS encodeURI 的保留字符和 UTF-8 字节规则封包。
  无法识别、含账户信息、IP/本地后缀或自定义端口的链接不能提交；只上传用户明确
  确认的链接，不开链接、不调用桌面不存在的预览接口。Node 独立的 encodeURI、
  AES-CBC 与 RSA 合成向量见 core/tests/fixtures/external_import_weapi.json；
  用 node scripts/research/external_import_weapi_vector.mjs 可离线复现。
- 每账号 SQLite 事务先记录本机操作及未确认状态，再核对同一个 Interface 凭据
  和 PC 账号代次，然后只向固定接口派发一次。明确未调用传输时恢复上一份回执；
  进程退出或发送后的不确定状态仍为「结果未知」。完整 200 且有合法 taskId
  才记「已受理」，不当作导入完成。迟到的正回执可结清原账号记录，但不更新新账号
  的界面。不在回执中写入链接、分享文字、Cookie 或签名；taskId 仅在原生记录中。
- 「核对本机回执」只读 SQLite。没有可证明的任务回查或找回丢失 taskId 的接口；
  用户可在已创建歌单或小秘书私信查看。没有访问真实账户的导入服务或测试真实创建。
- 复现：cargo test --locked -p cumulus-core --lib external_import；
  scripts/ci/external_import_smoke.py 使用隔离的真实桌面、封闭合成传输和进程重开。

  `.build/ui-proof/external-import-fd5f2239/verified/report.json`。没有真实扫码、
  真实任务或上游完成证据。Linux 与 Windows CI 注册同一封闭夹具。
