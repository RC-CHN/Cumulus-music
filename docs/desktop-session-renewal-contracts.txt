核心及协议
core/src/account/refresh/{signature,lifecycle,journal}.rs 保留签名、生命周期、持久化边界。
model 首个逗号替换为点，空时 fallback；官方 pn 删除低位空白再 encodeURIComponent，空白为 unknown。
签名拼接 deviceId/model/os/refreshToken/token(MUSIC_U)/userId，按 JS UTF-16 键序排序，
末尾追加 _scver=1&_sckey=7ada0f7ccadbe165e6e7fbe01113f4df，UTF-8 MD5 小写十六进制。
POST /api/login/token/refresh/v1 的业务字段为 refreshToken、clientUserId、ydDeviceToken、_scver="1"、_sign。
PC adapter传输时另附fromPage="JSK"及空x-login-chain-id，现已对照原fetch补齐。
MUSIC_U 缺失或 refreshToken 缺失：MissingCredentials，不取设备令牌，不发刷新请求。
与新JSK登录成功或上次确认续期不足 86400 秒（包括时钟回退）：NotDue。原生底层 force 仍为明确调用选项，桌面 IPC
没有 force，正常触发和手动检查均不可绕过周期。该请求无 legacy 自动回退。
200 仍需同次确认响应保存可用于此域/路径的 MUSIC_U+x-refresh-token 成对轮换回执；
再通过 /api/w/nuser/account/get 核对同一 UID 后才能记录成功时间。普通 Cookie 更新不算轮换。

失败恢复、取消和隔离
每次轮换先在当前凭据库 UID/login_refresh/jsk 写 pending；各实例通过数据库事务排他。
同一原生操作捕获账号代次和 API 实例；M/402 原生上下文准备可能等待 SDK，旧账号退出或切换
后其凭据库不一定改变。向 HTTP 交付前再次核对账号/API 与凭据 revision，并要求续期、只读身份
两个路径看到同一且唯一的 MUSIC_U。已收到的新凭据对也须匹配这两个作用域才允许身份核对。
明确没有进入续期 HTTP 的失败或本地超时只结束自己的意图，保留此前成功时间；已经进入续期 HTTP 的错误、
丢包、缺轮换头或任务中止保留 pending；未知写入不会自动重新发送。切号后已发请求的合法回执
可以按 revision 留在旧隔离库供核对，不能更新当前账号，也不能记录已确认的成功时间。
reconcile_jsk 只检查已保存的轮换回执和只读身份；底层没有新回执时返回历史枚举
ReauthenticationRequired，它不证明会话已失效。正式账号弹窗投影为 Unconfirmed 并保留登录。
有回执但身份读取失败可以再次只读核对；新 Cookie 只适用续期路径时不拿另一 Cookie 核对，
保持待核对而不推进间隔。相同作用域真实回读得出不同 UID 时，会话过期，不以旧 UID 发布资源。
core/src/client/auth/renewal.rs 是宿主无关用例：原生配置 DeviceInfo/provider；设备 ID 每次绑定
当前账号；前端只接收 epoch/state/lastSuccess/busy/canCheck/canReconcile，不接收秘密或设备事实。
一个客户端同时只有一个续期任务，45 秒截止。取消/任务丢弃释放忙状态；已进入续期 HTTP 时保留 pending。
刷新期间不持有账号切换/一起听互斥锁；账号代次/API 绑定检查拒绝旧结果，退出可以及时完成。
正在新登录时返回 LoginInProgress，避免后台与待确认登录竞争。新版账号可在后续通知检查。

桌面与 UI
生产 setup 配置 renewal::configure 并启动 RenewalPump。启动、账号变更和 30 分钟间隔只读
更新登录实验；账号状态通知直接发布当前状态。主窗口真实 Focused(true) 事件（包括符合条件
的首次原生 true）仅为当时已验证的登录 epoch 和已观察到的双 t1 排队自动检查；重复 true、
已经失焦的积压事件、未决实验或不再当前的 epoch 不会派发。初次焦点早于身份或实验准备时
不在后来补发该事件。显式检查和只读核对沿用原路径，旧版 20 小时续期不变。
主窗口销毁中止任务；若请求已发则按持久日志恢复。
自动检查完成发布 cumulus:session-renewal 和 account-changed；不调用会重新通知自身的发布函数。
IPC session_renewal(epoch) 只读；renew_session(epoch,check|reconcile) 由 core 决定是否发请求。
所有命令沿用仅主窗口限制。主前端、验证码窗口、Tauri 插件均不能注入 refreshToken/签名/deviceId。
账号窗口显示缺凭据、间隔未到、成功、未决、已失效等状态。只有完整新回执待核对身份时才显示
“核对续期结果”；缺回执可重新读取本机状态或主动重新登录，当前会话保持。
UI IPC 丢失响应后只重新读取状态，不自动重发命令；事件/读取通过代次屏障防止旧响应覆盖新事件。
这是新增的社区账号维护入口，不声称其布局为官方像素一致。

2026-11-03 新登录起算时间修正
M/1368 prepareAndSaveLoginInfo在updateLoginInfo第四个参数传Date.now()，后者将其写入
jsk_token_last_refresh_time；refreshToken以该值检查生产24小时间隔。此前Rust只有续期journal的
last_success，因而新登录收到RT后可能立即再轮换。现在原生凭据新增可缺省last_login_at，
仅在已确认完成的新JSK登录响应中与Cookie/RT原子提交，按Unix秒保存；低于一秒的边界精度不同于JS。
HTTP失败、业务失败、未读完响应、挑战开始/方法列表/发送短信、普通Cookie更新、旧链登录、
已保存账号恢复/切换均不重置这个时间。没有RT的已确认登录仍记时间，但继续显示缺少续期凭据。
旧数据库没有该字段时不猜测历史登录时间；退出/服务端失效清凭据时一并清除此字段。
真正确认轮换仍只记UID journal.last_success；两个有效时间取较晚者，不把新登录显示为续期成功。
有pending时先核对，不因新登录起算时间尚近而把未知结果隐藏成NotDue。
UI“暂时无需续期”不承诺已经轮换；lastSuccess只公开已确认轮换时间，登录时间留在原生层。
可选本地官方表达式执行：node desktop/tests/renewal_timing_official.cjs（仓库根须有官方解包材料）。

账号弹窗中的到期状态回读（2026-11-05）
M/1368:2292–2308 每次检查从存储读最近时间，并以当前时钟对照24小时；旧UI投影只保留
进程内最后一次检查结果，可能重开就错误显示可查，或过了一整天还显示暂时无需续期。
社区弹窗现以同一原生时钟和同一个24小时判定回读最近登录/已确认续期，不发送请求：
24小时前显示「暂时无需续期」，整24小时已可检查；系统时钟回拨不提前开放。重新打开
弹窗或收到原生通知时重读。已完成的成功回执在当前间隔内仍可显示，跨过间隔后显示可查并
保留独立的上次成功时间。新登录只参与原生判定，不把其时间或令牌送到UI，也不冒称成功轮换。
登录中、忙、未决写、缺凭据、禁用实验仍按原有优先级；回读到期不会自行轮换或启动新计时器。

中断与不完整续期的账号弹窗（2026-11-05）
官方 M/1368:2347–2389 对不完整凭据对、非 200 及异常只在 SDK 内处理，不执行
updateTokenInfo。M/1368:8640–8678 经 PC 原生网络桥取得回包；M/198:2979–2990
在实际 TOKEN_UPDATED 后才更新时间。没有恢复证据表明官方弹出这类错误的重新登录提示；
下述恢复入口是 Cumulus 的产品差异，行为遵循同一凭据确认条件。

- 缺少相对于本次持久意图的新完整回执：保持 Unconfirmed，重开与重启结果一致。
  显示当前仍登录，允许只读本机状态或主动重新登录；没有重发、额外核对请求或自动退出。
  中断、无完整凭据头的 200、业务 301 都不会把本次续期结果当作已确认或已失效。
- 新回执已提交、身份尚未核对：显示 RecoveryRequired。只请求
  /api/w/nuser/account/get；无论续期还是此次身份读取，都不通过普通业务的 301 拦截，
  因此不会连带发 /api/middle/account/token/refresh 或清除现有会话。身份读取失败可再核对；
  账号代次、回执版本及同 UID 一致后，才完成持久意图并记录成功时间。
- 两种状态由原生持久日志与当前凭据推导，前端不持有秘密或回执版本。
  已验证的普通业务登录失效仍走既有流程；可选重新登录沿用独立候选，取消不会替换当前账号。
