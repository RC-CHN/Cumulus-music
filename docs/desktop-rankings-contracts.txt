排行榜、畅销榜与专辑播放入口
2026-10-27；完整桌面目标仍在进行。私人 FM 不计入本批完成范围。

核心及 IPC
core/src/catalog/rankings/ 按 types/api/normalize/service 拆分。
RankingsApi 与 Api 抽象结合；Rankings 持有 AccountSession 与持久库；独立于 Tauri。
MusicClient::ranking_page(epoch,query,refresh) 返回 AccountData<RankingView>。
desktop/src/rankings.rs 只转发上述命令，不包含协议或业务判断。
query 标签：home、album_sales{year}、album_year{year}、song_sales、album{id}。
refresh=false 只读本地缓存；不存在时返回错误。refresh=true 执行真实服务读取并提交缓存。
view 包括 fetchedAt、cached、fresh、page；前端先显示缓存，再按 fresh 决定刷新。
首页 fresh 使用 10,797,000 毫秒，与官方默认三小时的阈值一致；时钟倒退视为失效。
销售榜和专辑详情每次进入都刷新，持久缓存用于立即显示和读取失败时保留内容。
首页服务下发的自定义缓存时长尚未接入配置宿主，当前采用官方默认值。

接口与数据规则
首页并发读取：
  /api/toplist/detail/v2 {}
  /api/feealbum/songsaleboard/daily/type {limit:3,albumType:0}
  /api/single/sales-ranking/get {}
仅接受成功码 200；任一路失败不提交新快照。
只保留 displayType=ONLY_COVER/TOP_3 的分组，过滤空分组；卡片只保留
nameShowStyle=singleRow/doubleRow 且 targetType=PLAYLIST。
因此 H5 商店跳转等不会变成伪歌单。普通榜单 id 保留十进制字符串，避免 JS 大整数损失。
OFFICIAL 分组追加 albumRank 和 songIndexRank；它们分别打开独立销售榜，不调用歌单详情。
预览 trackId、rank、lastRank 和 tracks[first/second] 保留官方顺序与空字符串语义；
缺 first/second 时回落 songName/artistName。预览数组长度不一致则拒绝本次刷新。
专辑预览 lastRank=rank+rankIncr；isAlbum=true。普通歌曲 lastRank=0 显示“新”。
销售榜卡片不显示播放整榜按钮；普通榜单 canPlay=true 时可直接建立完整歌单队列。
图片优先级按官方区分：TOP_3 使用 coverUrl；ONLY_COVER 使用 newFirstTextCoverUrl、
firstCoverUrl、firstCoverHdUrl。文案封面存在时不重复叠加更新时间。

专辑畅销榜：
  /api/batch，子路径 /api/feealbum/songsaleboard/{daily|week|total|year}/type
  每种周期再加一个末尾带 / 的子路径，区分同一 batch 中 albumType=0 和 albumType=1。
  子参数为 JSON 文本，含 limit:50、albumType；年榜额外含 year。
  首次共 8 个子请求；历史年榜只请求 year 的两路。逐路检查 200 后原子提交整页。
  products 映射 albumId/albumName/artistName/coverUrl/rank/rankIncr/newest/saleNum/
  salesCertificationSystemLevelCode；保留服务顺序，不自行重排销量或排名。
  UI 年份从 2018 到当前本地年份；核心允许当前 UTC 年加一以兼容跨年时区。
  唯一故意的容错差异：合法空 products 展示空状态，原 M3140 会把空数组当失败。
  首页空销售榜同样保留可打开的空卡片，避免原始 [0].coverUrl 访问崩溃。

歌曲畅销指数榜：
  /api/single/sales-ranking/get -> data.genTime、data.itemList。
  依次收集 songId，再 /api/v3/song/detail，以 c JSON 文本批量查询 {id,v:0}。
  详情顺序与服务榜单顺序无关；按 songId 重组，详情缺失保留原位置和不可播放行。
  不把销售数据中的 songId 当专辑 id。UI 保留指数、排名变化、新入榜、更新时间；
  播放、喜欢/取消、评论、下载分别复用现有原生用例与权限检查。

专辑基础详情与播放：
  /api/album/v3/detail {id}，nginxCache=true，检查 album.id 与请求一致。
  显示名称、歌手文本、封面、描述和完整 songs；不假装数字专辑购买权限属于会员权益。
  PlaySelection::Album{id,start_id,revision,quality} 在原生重新读取整张专辑，比较
  SHA256([albumId,orderedSongIds])，再分批读取歌曲详情并交给现有 PlaybackController。
  不受前端 Songs 的 500 首输入上限影响；测试专辑 501 首及末首选择通过。
  成功前检查账号代次、当前媒体焦点与选择序号；旧请求不能覆盖新播放选择。
  不可用资源沿用现有播放器的服务错误/试听/实际音质处理，不绕过购买或版权检查。
  本入口不是整个官方专辑页面的完工证明：动态收藏数/权限组合、数字购买说明、歌手导航、
  专辑收藏及评论等完整专辑页面分支还需后续统一接入。

状态与失败恢复
SQLite kind=ranking-pages-v1，owner=真实 UID，key=SHA256(序列化 query)。
记录包括 query、fetched_at 和完整原生页面；读取复核 query。更换账号即换命名空间。
同一 owner/query 的进程文件锁防止交错刷新；网络期间不持有账号或数据库互斥锁。
读取完成后 run_for 与提交时 with_token 两次核对代次；过期响应不缓存、不传入当前界面。
所有远端操作均为读取；无未知写入需要重放。读取失败保留旧缓存，前端提供显式重试。
前端 useRankings 另以请求序号和 epoch 拒绝旧查询/旧账号结果，退出页面后的迟到数据
不会覆盖另一查询；已销毁 composable 不再发布结果。
前端只接收白名单字段；原始歌曲对象和授权数据留在 core；所有图片再经 artwork 清洗，
仅允许公开图片域并移除原查询参数。业务 API 与 Cookie 不进入 WebView。
