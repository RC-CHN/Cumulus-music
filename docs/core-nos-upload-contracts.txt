传输与字段
NosAllocation::parse 只接受响应 channel=1，校验 bucket、objectKey、token、resourceId。
分配 API 已在 cloud/allocation.rs 将 key 规范化为 objectKey；两者冲突拒绝。
对象身份为 bucket + objectKey + resourceId；续期不能更换对象或重新分配资源。
NosNode 仅接受 nosup 或 nosup-<小写字母/数字分段>.127.net；统一使用 HTTPS。
有凭据、非根路径、query/fragment、异常端口及未识别主机的地址拒绝。
这些类型刻意没有 Debug；私有序列化仅用于本机账号存储，不是 IPC 数据契约。

LBS 依次使用 wanproxy、wanproxy-hz、wanproxy-bj、wanproxy-oversea.127.net 的 /lbs，
version=1.0、bucketname=<bucket>；各候选先 HTTPS 再 HTTP。
这里 HTTP 回退只传公开 bucket 路由；不带账号 Cookie 或对象令牌。
返回 upload 数组中的节点仍须通过 NosNode 校验，不能直接访问任意返回地址。

POST https://<node>/<编码后的bucket>/<整个objectKey按一个路径段编码>
  query：offset=<字节偏移>、complete=true/false、可选 context、version=1.0。
  headers：x-nos-token、Accept-Encoding: identity、Content-Type、Content-MD5。
  Content-MD5 是整个输入文件的小写十六进制 MD5，每个分片相同；不是 Base64 或分片摘要。
  正文是该偏移的原始媒体字节，不转换格式；首片无 context，末片 complete=true。
GET 同对象路径 ?uploadContext&context=<已确认context>&version=1.0 读取断点。
  查询只带对象令牌，不带音频正文或账号 Cookie。
NOS HTTP 客户端没有 CookieJar、不跟随重定向、不自动重试；令牌 Header 标记 sensitive。
连接/读取超时各30秒，单请求总超时60秒；只接受200，JSON对象响应上限1MiB。
错误不输出原始 URL、对象令牌或服务正文。HTTP状态保留为类型化错误。

POST /api/nos/token/refresh 在已认证账号原有域通过 AccountSession::run_for 调用：
  body：{"object_key":<原对象key>,"bucket":<原bucket>}。
  成功取 result.token；不用 data.token，不迁移 Cookie 到对象域。
NosUploads 每次 run 最多自动续期一次；仅实际收到 HTTP401/403 才作此处理。
该拒绝证明本次分片未被接受，清除该 pending 后才允许重新发送同一个分片。
查询断点遇到401/403也可续期，但不重置原 context/offset。
renewal 在请求前保存 Pending，得到有效令牌保存 Ready，令牌请求接受后保存 Confirmed。
失败保存 Failed；Pending/Ready/Failed 均阻止下一次 run 自动循环续期。
宿主可显式 renew_token 或 replace_token 后继续。两个操作都不会发送音频或发布歌曲。

账号、文件与持久状态
NosUploads 绑定构造时 SessionToken；同 UID 再登录也使旧实例失效。
请求前后、文件工作后、数据库读写均核对代次；迟到回复不能写入新会话状态。
日志命名空间 nos_uploads_v1；控制请求独立保存在 nos_upload_controls_v1。
公开视图只包含任务ID、状态、本地源路径、已确认/总字节、pending布尔值、续期状态、
控制请求与稳定错误标签。没有 bucket/key/context/token/resourceId 或完整授权地址。

输入须为非空普通文件，最多512MiB（适配器限制，不代表服务配额）。
创建时保存规范路径、长度、整文件MD5/SHA256；实际读取用 open_regular，无网络或 shell。
执行前验证整个输入，最后一个确认后再验证原句柄和当前路径，两者必须仍匹配原事实。
读取期间长度或 mtime 变化拒绝；增长超过初始长度立即停止，不追读持续增长的文件。
MD5服务契约与SHA256本地完整性检查分别保留，不以仅文件名/mtime判定同一输入。
默认分片256KiB，可配置1字节至4MiB；创建后分片大小随任务保存，重开不会随新默认值改变。

创建支持调用者预先保存的固定ID（最多128个ASCII字母数字/连字符/下划线）。
相同ID再次 create 仅在源文件事实、目标对象与 MIME 全部一致时返回原任务；不会清零进度。
这样上层可先保存父任务及子ID，子任务建成但父任务保存失败时可以安全重新接入。
对象令牌变化不改变身份；重新 create 不隐式替换令牌，应使用显式续期方法。

状态：Queued → Uploading → Uploaded；可暂停、失败、进入 Ambiguous 或取消。
操作锁按账号+任务区分，跨实例/进程并发工作返回 MutationBusy，不持有SQLite事务等待网络。
每个 POST 前保存 Pending{offset,end,complete}，失败则不发送。
收到响应必须 offset == 本次分片末尾；非末片须有合法非空 context。
只有确认末片并完成源文件复核，才保存 Uploaded；字节数等于文件大小本身不代表成功。
确认记录保存失败保留先前 pending；下次启动按未知写结果处理，不能伪造已确认进度。

恢复规则：
  有 context 且不是未知首片/末片：先GET查询，远端offset不能超过本任务实际已发送末尾。
  中间分片回包丢失：查询确认已接受字节后从真实偏移继续，不盲重发已确认数据。
  context查询404：仅在排除未知首片/末片后，按官方分支从0重新开始。
  首片回包丢失且没有context：Ambiguous，停止自动写入。
  末片回包丢失：Ambiguous，停止自动写入；旧context也不能证明最终发布事实。
  显式替换/刷新令牌不能解除上述未知写结果，后续run仍返回MutationUncertain。
  网络中断、HTTP非鉴权错误或错误字段不能当作“肯定没有写入”。
当前没有恢复出可可靠核对 NOS 未知首片/最终对象的通用读权限，本层不提供“强制成功”。
上层云盘的元数据/发布结果还需要它自己的日志与账号资源对账，不能由本层推导。

暂停与取消
用户 Pause/Cancel 先持久保存控制请求，正在运行的任务不需要等其操作锁释放。
下一次分片意图与控制请求在同一 SQLite 事务中判定；控制先提交则不发送该分片。
已经写入意图的分片视为在途，仍需记录其响应。末片已接受时如实保留 Uploaded，
原子清除迟到控制请求，不能把已上传对象伪装成取消成功。
如果在途分片得到明确鉴权拒绝，而暂停/取消已请求，不继续续期或重发。
Pause必须显式 resume 才解除；Cancel不可resume，不删除本地源文件或远端对象。
chunk_budget/stop 仅在分片边界暂停；这种运行预算暂停可通过下一次run继续。
远端已接受数据可能保留；取消不是 DeleteObject，也不是从用户云盘删除歌曲。
