会员 API
/api/music-vip-membership/client/vip/info {userId}。
实际五组：associator/黑胶VIP、redplus/黑胶SVIP、musicPackage/音乐包、albumVip/数字专辑、
voiceBookVip/有声书。期限严格大于服务对齐时间才生效；只显示服务证实的等级与期限。
客户端请求 lossless/hires 等不构成权益证据。播放/下载仍以服务授权等级、范围与拒绝为准。
页面进入先显示可用权益缓存，再在线读取；可见时按最近到期或五分钟较早者刷新，失败60秒后
重试；隐藏或销毁清理定时器。会话过期清空权益/页面并停止后续读取。
这不是全局身份 SDK/刷新凭证宿主生命周期的完成证明。

历史日推
/api/discovery/recommend/songs/history/recent {} → data.dates。
/api/discovery/recommend/songs/history/detail {date} → data.songs。
日期必须是实际存在的 YYYY-MM-DD，不能重复；客户端查询只能选该账号已获得的日期。
日期目录与每天内容分开存盘，数据与 fetched 时间同一 SQLite 事务提交。
切换日期不触发播放；只有用户选曲/播放全部才替换播放队列。没有播放历史上传。
页面缓存采用明确的300秒本地有效期；尚未接官方 configCenter 动态缓存参数，不宣称相同。

播放与导航
PlaySelection::Member {query,revision,section,index,quality}：原生重新读取对应账号缓存，
校验页面 revision，再准备完整列表；前端不能用任意 song ID 冒充会员推荐。
VIP 每日推荐每个资源 trial_mode=41，授权体 trialMode=41；历史日推使用普通默认 -1。
两者是有限正常队列，支持暂停/定位/切歌、模式、重启恢复；不复用 FM 的无限补曲状态机。
榜单预览只展示服务 contentList，点击榜单/榜单歌曲使用其真实 rankingListId 歌单完整读取。
专辑/歌单/有声书卡分别跳转既有专辑/歌单/播单详情；推荐歌曲的喜欢、评论、下载复用正式入口。
顶部歌曲横幅按官方普通单曲入口，不将它伪装成会员每日推荐试听。

公开活动与浏览器
相对 /playlist/<id>、/album/<id> 及官方 music.163.com 歌曲/歌单/专辑/播单 URL 解析成内部动作。
其余有效官方 HTTPS 活动链接只给前端不透明 key；原生链接表与页面内容一起参与 SHA256版本。
open_member_link {epoch,revision,key} 重读当前账号快照，核对版本后才返回宿主可打开的 URL。
拒绝脚本/file/自定义协议、带用户名/口令/端口或非 music.163.com 的地址；卡片没有可执行动作
时不伪造目标。系统浏览器通过直接 argv（Linux xdg-open、macOS open、Windows explorer）启动。
不附 Cookie，不使用 shell 插值。打开活动须用户点击；本批自动化不点击外部活动或支付操作。

持久化、失败与隔离
会员首页完整加载且公开投影校验成功后提交；失败保留上次整页并标 error。进程中断的 loading
由既有文件锁检测恢复为 error。历史的非法日期/歌曲数据在落盘前拒绝，保留旧缓存。
内容与链接内容变化都会更新 revision；旧页面选曲或打开旧活动返回 snapshot_changed。
本批新增 _for 方法固定原发起 SessionToken，避免读请求在 await 后重新绑定到新账号。
客户端最终返回继续检查代次；老账号响应不能写入新账号，前端也同时检查请求序号与账号。

黑胶乐签的主动签到与断线恢复
- 恢复 M/15、M/617：用户点击时 `POST /api/vip-center-bff/task/sign {}`；官方以 code 200 和
  JS 真值 data 确认成功。随后读 `/api/vipnewcenter/app/level/user/checkin/history/detail`
  `{type:1,signDayTime:<校准毫秒时间>}`，再刷新卡片。官方 UI 延迟约 1 秒刷新；Rust 立即回读，
  如卡片还未同步，保留已确认状态，避免二次签到。详情不可用不改变已确认状态。
- `member_sign_card` 的 `action` 给出 ready/signed/unknown/unavailable 和原生日键。
  `member_sign_command {epoch,command:{kind:"check_in",dayKey}}` 重新读取卡片、检查当前账号代次和
  日期后才允许发送；`{kind:"reconcile"}` 只读。没有可信日期、`today` 标记与日期不一致或日键已换日时不发送。
  对应 M/47 的时钟来自绑定 HTTP transport 的 Date 和单调时钟；以 UTC+8 推导服务日，再与卡片今日日期互证。
  UTC+8 是大陆服务日约定，实际跨时区/跨午夜行为未用真实账号验证。
- 操作锁作用于本地账号，跨进程防止重复发出；SQLite 按账号和日键保存结果，发送前先提交 unknown 标记。
  断线、退出、模糊失败或未确认数据保留 unknown；只读卡片/历史能确认时转 signed。
  只有明确的 `RequestNotSent` 才清除这次标记，仍由用户再次明确操作。没有匹配记录不证明写入未发生。
- 回读已签先找卡片 `signTime` 对应的历史项；若卡片尚未同步且没有时间提示，则只接受该服务日唯一记录。
  记录 ID 留在原生并保留原始类型，拿到 ID 才读 `{type:2,recordId}`；已签或待确认当天不会重放签到。
  不调用领奖、付款、分享或公开发内容接口。
