Cumulus 实现和边界
- 用户资料当前是经过认证的普通访客资料时才显示入口；目标用户为本人、注销、
  任一方向的黑名单限制时不发送。进入匿名资料不会新开登录弹窗或续发举报，
  可先通过现有登录入口验证账号。四项预设均额外要求明确确认。其他原因沿用
  文字原样发送；确认前以和 JS trim 一致的空白集校验，并额外限制 4096 UTF-8 字节。
- desktop/src/profile_relations.rs 的 profile_report 只接受当前 epoch、用户 UID 和
  类型化动作。Inspect 只读本机状态；Prepare 仅在内存生成 120 秒一次性凭据，
  绑定账号代次、目标和原始原因；Cancel 只释放匹配凭据；Submit 消费该凭据。
  WebView 不持有 PC Cookie、签名密钥或完整授权 URL。切换资料、账号、关闭弹窗
  时清除前端草稿，旧响应不能更新新窗口。菜单支持方向键和 Escape，取消恢复
  主页「更多用户操作」按钮焦点。
- core/src/client/profile_report.rs 先按当前账号与目标串行处理，并和该对象的关注/
  拉黑共用关系锁；提交重新读取 /api/w/v1/user/detail/{uid}，只接受目标身份匹配且
  可用的用户资料。实际写入前持久化账号+目标的 uncertain 状态，写接口仅调用一次。
  持久层不保存原因、请求体、错误体或凭据。只有明确的 RequestNotSent 可移除
  状态并允许用户重新确认；HTTP 成功且业务码 200、明确 -1/-2 和未知结果都不再提交。
  原客户端也读非成功 HTTP 的错误体；Cumulus 只认可其中的明确 -1/-2，不把其中
  的 200 当作成功。异常、模糊响应
  或崩溃后保留保守状态，重新打开弹窗仍生效。「核对本机回执」只读本机状态，
  不表示远端已收到。已确认/未知结果保留在弹窗内，用户可自行关闭。
- 不使用第三方客户端证据，也未触发真实举报。合成断网测试验证界面、请求体和
  恢复行为，不据此声称真实上游或 Windows WebView 验证通过。
