账号设置与桌面设置入口（2026-10-28）

范围
本批接通官方“消息与隐私”六项设置，以及正式设置页中的主题、登录账号和下载入口。
独立 Rust AccountSettings 还保留历史研究通过的 allowPeopleCanSeeMyPlayRecord 布尔写入。
这不是完整官方设置页完成声明；完整清单及未完成的本机/平台设置见 settings-mapping.json。
不使用 YesPlayMusic；没有新增依赖、代理服务或 Python 业务转发。

通知半小时循环（M128:698–795,1001–1058；恢复 app.ts:626–845,1106–1174）
  只有正延时的启动检查执行完成才注册。按设备本地时间选下一整点／半点；之后以实际首次
  原生回调为锚每 1800000ms，独立抽取 floor(random × 10 × 60 × 1000)ms。
  本机闹钟遇重复时间取较早偏移、负延时立即到期，与已核验的 JS 秋季样本一致；
  跳时导致不存在的边界顺延到第一个可解析的半点（普通一小时春季跳时已对照，
  少见非半小时偏移不保证等同 JS Date 中间 setHours 转换）。不补执行已经过完
  整个周期的旧回调，不模拟系统恢复。前台资格在抖动之后才检查。
  两类历史合并按本机日期计数。零条时启动可进入；定时只有已验证
  PH-PC-push-firstTime t1/t2/t3 且处于配置小时的第 00 分钟。已有一条时，任一
  触发都要求已验证 PH-PC-push-durationLimit t1/t2/t3、小时 >= secondPushTime，
  且距上一条严格超过对应分钟数；两条以上停止。M247 默认时段为 9/10/11、
  时长 30/60/120 分钟、第二条起始小时 17；只消费实际 PC 配置中的对应值。
  同一类型继续按同步时间检查同日、N 日频率和静默。按每个候选真实进入检查的
  本地分钟判断，跨分钟返回仍可展示确认；跨本机午夜作废。展现在 ACK 时事务性
  复核计数，过期、未确认和旧账号／凭据收据可退休、不会增加历史。
  定时版权 popup 成功但没有 ID 时结束本轮，不查询每日推荐；有 ID 而详情无可展示
  曲目，或正常业务/传输失败，则可继续每日推荐。账号、签名凭据、分组、前台已失效
  时停止本轮。两条 Daily 可选读取也在原生 EAPI 发送前检查同源凭据与当前资格。
  优先顺序随启动绑定；每轮只被动读取同账号/同 API 当前凭据的新鲜已验证分组，
  无额外实验请求，不切换到随后登录的其他账号。分组尚未刷新时跳过这轮。
  官方 M1384:4526–4535 聚焦只更新计数；M173:36–47、M1384:4627–4638 的真实
  系统恢复会重置聚焦/播放计数并重启独立延时检查。Cumulus 仍只在可信聚焦主窗
  展示，不从聚焦／时钟变化推断唤醒，不交付后台、mini、全屏、Wayland 或 OS 通知。


原研究的联动观察
playRecordSetting=1 曾使 allowPeopleCanSeeMyPlayRecord=false。
playRecordSetting=2 曾使 allowPeopleCanSeeMyPlayRecord=false、allowFollowedCanSeeMyPlayRecord=false、
socialPlaylistSetting=2。服务端可能继续调整联动规则；Rust 不在本地猜测或补写这些值。
更新后完整保存实际 setting，对 UI 仅投影已知类型的有限字段。
未知枚举、错误类型、缺失值分别保留 unsupported/missing；不能用官方初始默认值覆盖真实账号。

Rust 状态与失败恢复
core/src/account/settings/{types,service,mutation,legacy}.rs：独立领域协调器。
account-settings-v1/snapshot 保存完整原生对象、读取时间和完整对象 SHA-256 revision。
account-settings-intents-v1 按 UUID 保存 intent、目标/原值/观察值、时间和 phase。
所有读写绑定 SessionToken；所有设置共用一个跨进程 OperationLock，联动字段不能并发写入。
change_for 顺序：验证 UUID/字段/类型/revision → 查相同 intent（已存在就只返回）→ 检查全部未决操作
→ 检查本地展示版本 → 新读取服务端完整对象 → 版本不同则更新缓存并报冲突 → 持久化 Pending
→ 仅一次 update → 完整回读，实际目标匹配才 Confirmed。
目标原本一致保存 Unchanged，不发送 update。持久化失败不允许越过写入关口。
确定拒绝/RequestNotSent 保存 Rejected；丢失响应/未知失败保存 Uncertain。
收到 200 但回读失败时保留 Pending；中途取消或崩溃不会自动重放。所有联动设置继续被未决操作阻止。
切换账号后的迟到错误仍把责任记在原 owner；新账号不收到旧结果、快照或 intent。
reconcile_for 仅 GET 并更新完整快照和操作观察值；不匹配继续 Uncertain。
accept_current_for 必须已核对，并再次 GET 验证用户确认的完整 revision 未变；
  保存 AcceptedCurrentState，表示用户接受当前观察，不表示证明了原 update 的远端结果。
cancel_unseen_for 用同一锁登记 Cancelled；迟到的原 change 同 ID 只能读到 Cancelled。
  若 intent 已经存在则返回真实状态，绝不把 Pending 或完成请求伪装成取消。

旧持久化兼容
旧 resource-mutations/settings:<key> 记录在事务内迁入 UUID journal，再删除原行；
未决状态继续阻止其他设置，旧的按字段观察不能替代本次完整核对。迁入不发送请求。
AccountResources::set_setting/refresh_for(Settings)/reconcile_expected(Settings) 转到新协调器，
不再保留另一条绕过全设置互斥的写入路径。旧接口的操作枚举不能表达取消/接受当前状态，
这些结果由新的 SettingsPhase 明确暴露；旧 reconcile 不将其误称 Confirmed。
升级时不支持旧进程与新进程同时写同一个 profile；旧程序的锁协议本来不同。

宿主与界面
core/src/client/settings.rs 是安全 DTO 和用例门面；desktop/src/settings.rs 仅转发类型化 IPC。
account_settings_page(epoch,refresh) 返回 revision/fetchedAt、白名单字段、联动观察、最多20个操作。
快照和操作在同一领域锁下读取；未决操作优先，不让较新的终态挤掉恢复入口。
account_settings_command 支持 change/cancel_unseen/reconcile/accept_current，带 epoch、UUID、revision。
不把原始设置对象、服务错误正文、Cookie、URL、设备数据、服务端附加字段传给前端。
命令结果始终保留本次操作，即使它是已被较新记录挤出20条展示范围的旧 intent，避免恢复入口无法结束。
非主窗口不能访问这些命令；过期 epoch 在网络前被拒绝。

frontend/src/composables/useSettings.ts 在 App 层存活，页面切换不遗失未知 intent；账号切换清空。
进入设置页先读取本机缓存再刷新，离线时保留缓存并禁用新修改；刷新成功才恢复编辑。
点击时保持已确认的单选/勾选状态，完整回读后更新。未知 IPC 结果先读 journal，不生成第二个 UUID。
已知“设置变化/字段不可用”前置失败显示新快照，不制造假未决操作。
正式页提供“读取处理记录”“取消未开始的修改”“核对服务端状态”；接受当前状态有二次确认。
个性化服务切换有确认；不自动重启中断播放，保存后提示重新打开应用加载新的推荐。
官方客户端原实现会强制提示重启；本实现没有证明服务端推荐立即变化的时机。
播客发现补充：由于桌面不会为此重启，当前账号的设置新读回或操作后的明确回读
确认关闭时，立即清掉已显示推荐及旧分页，并使在途回执失效。已有的缓存设置或
待核对写入不当作新观察。续页调用也先读取 /api/user/setting；如果刚在另一端关闭，
则不发 /api/voice/homepage/block/page，回收该账号的推荐句柄并清空前端内容。
公开分类句柄、普通榜单和已播放歌曲不受影响。再次开启后从首页重新读。
恢复的 audio/components/Personality.tsx:165–181 首次读开关、214–230 跳到隐私设置；
续页重核和界面内立即失效是 Cumulus 不重启时的处理。关闭说明的「前往设置」
滚动并聚焦消息与隐私标题，返回后仍保留关闭状态。
