混合歌单拖动的 Linux 桌面验收
==============================

官方 M/195:388–409 与 M/3085:2470–2505 给出原始落点；M/3160:1606–1640
即使只移动本地曲目也提交过滤后的完整线上顺序；M/2997:823–861 只在成功后
写本机位置。持久回执和未知结果的保守核对见 playlist-mixed-reorder-contracts.txt。

以带前端构建的 local_ui_probe 运行。需要隔离 Xvfb、Openbox、XTest、FFprobe
和 libmpv，默认测试窗口为 1120×900：
  cargo build --locked -p cumulus-desktop --example local_ui_probe --features custom-protocol
  sh scripts/ci/loopback_only.sh env LC_ALL=en_US.UTF-8 GDK_BACKEND=x11 \
    CUMULUS_TEST_WINDOW_MANAGER=openbox xvfb-run -a -s '-screen 0 1440x1000x24 -nolisten tcp' \
    dbus-run-session -- /usr/bin/python3 scripts/ci/mixed_reorder_smoke.py \
    --binary .build/target/debug/examples/local_ui_probe --root .build/mixed-reorder-proof

夹具只创建一个可播放的 PCM WAV、一个合成账号和一张没有旧占位的自建歌单。
实际 X11 鼠标拖到表格插入线后，第一次在表格外松开，确认零写入；
第二次把本地行移到两首线上曲目之间，核对唯一请求仍发送相同线上投影。
服务收到后保持待处理，截图和本机日志核对位置不变；释放明确成功回执才落盘。
第三次把后一首线上曲目拖到首位，服务保存新线上顺序但故意丢回包；UI 显示待
核对，本机位置仍不变，直至用户按“核对结果”。记录服务线上序列、原生持久
回执、实际表格、可信指针和每阶段的同一暂停播放，逐字节核对原文件。
只使用隔离合成响应和 libmpv null，未对真实账号写入，不作为 Windows 实窗、
实体声卡或实服响应的证明。
