菜单流程
普通在线歌曲打开菜单才调用 player_quality_details(epoch,playId)；不会自动调用
player_quality_trial。读取不设置全局播放器 busy，不妨碍已经播放的音频。
账号/播放代次/偏好改变使旧读取失效，关闭或卸载停止 UI 定时读取；周期快照不关闭
菜单。成员各自 ready/missing/failed，部分失败仍展示有效信息，不能将未知解释为
没有会员。已知无音源的行按能力过滤；当前实际档位及待核对记录仍保留对应入口。
高档使用权益未知时要求先刷新，不用一次普通音源请求冒充完整试用生命周期。
播客保留原节目授权路径，不读取歌曲试用权益，不改动歌曲偏好。

文件大小读取原生十进制字符串，以 BigInt 格式化，不丢失超过 JS 安全整数的精度。
规格标注仍是档位上限；实际质量来自 player.actualQuality。标题同时展示请求与后续
偏好，降级后不把请求的无损显示成实际无损。三者相同时选择当前档位不重载；若
实际为标准而请求/偏好更高，仍允许显式改为标准，以取消较高偏好。
剩余时间只作显示及读取调度，归零显示待核对，不由前端时钟授予/撤销使用权。
部分失败不自动循环重试，用户可使用页脚“刷新音质”。

试用与失败
TrialEligible 打开确认，展示服务端时长、开始计时及暂停/关闭不会暂停计时的影响；
默认聚焦“取消”。只有点击“确认启用试用”才发 Start；重复点击被单次状态挡住。
活动权益使用 UseActive，不重新激活；待核对日志优先打开核对弹窗，Reconcile 只读。
正面回执与实际播放分别处理。激活成功但音源失败时保留回执，按钮为使用已有权益，
重试会重读当前曲目权益再发 UseActive；不把 Start 交给播放器通用“重试”。
发送或保存失败时尝试读取原生日志；读取也失败仍保留错误，没有自动重发。
处理中关闭按钮说明“稍后查看”，关闭不声称能取消已经发出的启用；结果在原生层
保留，原播放器连接仍接收实际状态。迟到回执不重新打开弹窗，不进入新账号。
切歌或手动改变偏好后，旧确认关闭，旧未决结果仍可核对但不能套用到新曲目。
日志损坏不静默重置，界面提示并保留其它可用音质；没有伪造一个尚未实现的修复按钮。
