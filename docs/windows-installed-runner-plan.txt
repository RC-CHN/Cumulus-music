1. 单独、手动的安装诊断

现有 scripts/ci/windows_nsis_smoke.py 可验证从同次 CI 取出的
NSIS 与便携 ZIP 的 SHA-256/大小/版本；它用新目录安装，核对所有
相邻 DLL 和 exe 字节，运行安装版 ffprobe 对合成 WAV，启动普通
安装文件的图形诊断模式并卸载。它只声明安装、布局、ffprobe、
图形诊断、目标运行时文件及卸载注册项清理。/S、/D 和 _?= 有
明确参数；当前“disposable runner”参数只表示调用者确认，不能创建
Windows 用户、清除宿主文件、改变网络或证明无真实资料。

.github/workflows/windows-installed-diagnostic.yml 仅可从主仓库 main
手动运行；它不改 ci.yml、release.yml、CI gate 或发布资产。
在 Actions 选择 Windows installed package diagnostic，输入：
  source_commit = 40 位小写 SHA
  source_run = main 的成功 CI run ID
  source_attempt = 同一 run 当前成功的 attempt
也可使用等价命令（仅供后续明确授权的执行者使用）：
  gh workflow run windows-installed-diagnostic.yml --ref main -f source_commit=FULL_SHA -f source_run=RUN -f source_attempt=ATTEMPT

具体验证顺序：
- 接受三个严格输入：40 位小写 SHA、正十进制 source CI run 和
  attempt。只从固定仓库的 CI workflow 元数据读
  GET actions/runs/{run}/attempts/{attempt}；核对 workflow ID、
  同一 head_repository、head_branch=main、event=push、head_sha、
  run_attempt、completed/success。再核对这一 attempt 的
  Native (windows-x64) 和全部既有必需 job（包括 CI gate）成功；
  同时核对 job 自身 SHA、run 和 attempt。不接受 PR、fork、另一
  workflow、已重跑的旧 attempt 或更近的其他 SHA。只设
  contents:read / actions:read，无发布权限。
- 下载该 source run 唯一未过期的 packages-windows-x64 artifact；
  尽管下载 API 按 run 查询，仍要求 manifest-windows-x64.json 的
  commit、ciRun、ciAttempt 全部与明确输入相同。先校验 artifact
  自带仓库、分支、run、SHA 和唯一未过期的数字 ID；按该 ID 下载
  后重新校验来源和当前 attempt，另行 checkout 并核对 source SHA。
  复用发布清单的现有版本、文件集合、digest、播放及音效凭据检查，
  不重新打包。诊断只上传本次报告，
  不上传/替换 package artifact 或 release-provenance。
- 执行在全新一次性 Windows x64 VM 与用户下（可先用独立
  windows-2022 GitHub-hosted；预检 runner 身份、x64 Python、HKCU
  和 HKLM 产品与卸载记录，以及默认安装和数据目录）。安装后须回读
  唯一 HKCU 卸载项，核对版本、安装目录、卸载器绝对路径均指向
  临时安装，并拒绝 HKLM 卸载记录；卸载后核对两处记录和运行时
  文件均已消失。普通 hosted runner 本身不保证无外网。
  /D 仅约束安装文件，Tauri 仍会触及
  HKCU 卸载与产品位置/语言键及开始菜单；正常卸载也不保证
  删除所有设置。不能把新目录当成沙箱，测试后应销毁 VM 或用户。
- 在启动真实 installer 之前读取 Windows x64 的 WebView2 Evergreen
  预安装版本：HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\
  {F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}\pv 或同标识的
  HKCU\Software\Microsoft\EdgeUpdate\Clients\…\pv 必须是有效非零
  版本。包脚本未覆盖默认 DownloadBootstrapper，缺运行时的安装器
  可外连 Microsoft，因此预检失败必须停，不更改真实包替代。
  Tauri CLI 2.12.4 模板明确先查这两个位置并分支；Microsoft
  也将大于 0.0.0.0 的版本作为预安装依据。预检排除默认下载分支，
  不是一般网络隔离证明；要求零外连时必须在已隔离的子 VM 中执行，
  先把校验产物复制进去，仅带出白名单报告。
- 清理继承的 CUMULUS_、MPV_DLL_DIR_CUMULUS、WebView2 运行时和
  browser profile 覆盖，临时工作目录和本地安装目录分离，PATH
  只包含 Windows 系统目录。脚本 graphics_smoke.py 自行分配新的
  CUMULUS_DATA_DIR；普通 graphics 子窗口显式用一次性的 WebView
  data_directory 并由 Windows Job Object 限定其子进程。
- 命令：
  python scripts/ci/windows_nsis_smoke.py --disposable-runner --packages PACKAGE_DIR --commit FULL_SHA --ci-run RUN --ci-attempt ATTEMPT --root NEW_REPORT
  工作流额外使用 --hosted-runner。只保留 install.log、uninstall.log、
  有界的 graphics 日志与 JSON、report.json；失败仍失败。报告不
  声称网络隔离、安装版普通播放或物理输出通过，也不替代发布 CI。

2. 安装版普通本地播放仍需新的 Windows 证明

Linux 的 scripts/ci/installed_linux_audio.py 使用 AT-SPI、X11 和
私有 PipeWire，不能原封移植。Windows 已有独立 SendInput 驱动的
局部基础（scripts/ci/shortcut_windows_keys.py），但没有能操控
普通安装版 WebView2 的 UI Automation 适配器。

最小完整证据：在有可用隔离 render endpoint 和隔离网络的 Windows
交互式桌面，对安装目录的 cumulus.exe 作普通启动，另设新
CUMULUS_DATA_DIR 与 WebView2 profile、保持 system-only PATH 和
应用资源默认解析，不用测试 IPC、图形诊断参数、MSYS2 DLL 路径或
从便携 ZIP 复制可执行程序替代安装文件。用 PID 限定 UI Automation
窗口、按角色和名称找“本地音乐”“选择音乐目录”/“选择目录”
与“播放全部”，处理原生目录对话框，加入有已知标题及持续时间的
合成 FLAC，检查文件已索引。通过只读观察当次 SQLite 中 local-guest
播放队列和 position，核对文件身份（Windows 扩展/短路径按文件比对）、
本地来源、同一 entry、位置两次实际前进、暂停后停住；使用真实 EQ
控件并读回预设/开关。可采用 PowerShell UIAutomationClient 或现有
SendInput，不要注入生产 JS、修改用户设置、读取登录态或使用真实曲目。
不能预设无头 runner 会提供可用 UIA/前台或音频 endpoint：缺少即
报告环境边界。再加明确选定的合成输出 loopback/频率测量，才可说
实际音频和 EQ 改变通过；进度与设置写入不等于 PCM 或物理听感。

Linux 本地的合成测试覆盖来源选择、旧 attempt/错误 artifact/失败
job 拒绝、注册表路径和环境隔离规则。该工作流尚未调度；没有运行
Windows installer 或普通 GUI，没有触发 CI/发行。
