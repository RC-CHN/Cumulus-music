Fixed stereo old-schema local equalizer
=======================================

LocalEqualizerMaterialPlan and LocalEqualizerStereoMaterial implement the
local old-schema GEQ, bass/treble and SE controls with RVB off. The only
accepted decoded format is stereo f32, 44,100 or 48,000 Hz, capacity 2048. The typed
plan does not establish a user's material rights, actual decoder format,
source identity or selection. The graph API is independent of existing
LocalStereoMaterialPlan, LocalFixedStereoMaster, ColdStereoSource and the
ordinary desktop GEQ/BT adapter. The ordinary held-file attachment below
owns its source eligibility and actual playback state separately.

Official schema and order
-------------------------

neaudioeffects.dll x64 SHA256

Addresses below are RVAs. The extracted JS module is M3091 in
hybrid_53.chunk.1482700000000.js. M3091:718–727 defines the 流行 and 舞曲
curves, including fractional gains. The corresponding sliders are ten
GEQ bands at −12…12 (1363–1373), bass/treble at −10…10 integer steps
(1382–1399,1566–1600), and SE presence −10…10 and stereoizer 0…10 integer
steps (1630–1664). M3091:1278–1305 writes exactly eq, bt, rvb, se. Each
component's enabled flag follows its controls; SE uses shaper=true and
ambience=1. The 无 RVB preset at lines19–77 has on=false with dormant
nested configuration. The parser accepts that off object and ignores the
inactive fields. EFCCE0:EFCE8E–EFCE94 skips those fields and jumps to
EFF163; the off path sends only the 6A490 disable call at EFF178.

The parser rejects active RVB, other sections, unknown EQ/BT/SE keys,
non-finite/out-of-range values, incorrectly typed numbers and conflicting
component flags. Only the verified UI-origin shape is supported. This does
not adopt the native generic bridge's defaulting for missing controls or
arbitrary material JSON. No AEV2, loudness, rotation, remote preset or
additional format support is implied.

An original device-shaped constructor starts at outer65B60/670E0 and
performs its 1B960 node reset. Then the old EFB760 material lane invokes:

1. Outer68000: processor1BBA0 sets default controls and bypasses nodes;
   1C590(false) replays the resulting flags; outer6B0C0 resets its caches
   and 1D410 sets default B0 controls. It does not clear B0 history.
2. EF9ED0/outer691D0 transfers ten GEQ f32 gains to 1CE90 → GEQ A3720.
   Then 692E0 → 1CEB0 → A36C0 enables GEQ. Off sends only 692E0(false).
3. EF8CA0/outer686B0 transfers bass and treble f32 through 1C570 → A2DF0.
   Then 68600 → 1C4B0 → A2F70 enables BT. Off sends only 68600(false).
4. EFF390 sends SE6ABE0 sliders before SE6AB30(on); its off case has no
   slider call. Then EFCCE0 sends RVB6A490(off) and 65BC0 ends the apply.

1AA50 processes the active GEQ and BT at slots48 and50, before SE28 and
B0. Slot50 is the same shared nine-slot PEQ implementation used by the
existing fixed graph. Native defaults and active settings retain type7
low at120 Hz/Q.5, type6 middle at1000 Hz/Q1 disabled, and type8 high at
6000 Hz/Q.5. The standalone BassTreble constructor uses different filter
types and middle-band behavior. Even changing its frequencies and Q to
these values did not match native active BT's first block. Use the existing
GEQ and shared PEQ kernels; neither their equations nor the standalone
BassTreble API changes here.

State transitions
-----------------
First active GEQ/BT after constructor reset has wrapper target/previous
[0,1], so the first block blends dry to wet. Full hot re-apply on the same
processor temporarily bypasses and restores defaults, writes new controls
and enables. Actual re-enable clears GEQ or BT plugin histories without
synchronizing the wrapper's previous flag: a retained active wrapper can
be [0,0], and an active-to-off wrapper [1,0]. The off edge uses the newly
restored flat/default parameters; it is not a continuation of the old
EQ curve. SE re-apply goes through its bank resets as documented in
core-effects-local-master.txt. End65BC0 does not clear any node history.

Master off is outer68770 → 6B960(true) → 1D410/1C590(true). It retains
GEQ, BT and SE settings while bypassing their active wrappers. The first
block after the switch still consumes the proven wrapper edge. Reopening
is a full material apply, not a boolean toggle. Master off and material
begin preserve B0's configured 0 dB/5 ms/100 ms default, the pending
219 frames and the gain envelope. No alternate limiter mode is supported.
The explicit reset operation is outer67F70 → 6B060 → 1B960: it clears
histories, synchronizes wrapper previous=target and discards B0 lookahead.
This can reduce total frames across a logical seek by 219. It does not
change the current material or select, authorize or seek the input source.

Each typed Rust instance exclusively owns its native allocation, SE arena
and PCM scratch buffer. Control calls validate all supplied values before
writing state, take no PCM pointer and quarantine native failures. The
existing fixed graph validates bounded finite PCM and exposes returned
frame counts and EOF. It retains the original variable-frame SE and B0
contract rather than truncating a tail to fill a desktop callback.

Ordinary local spatial controls
-------------------------------

The product controls extend the independently authorized NativeFile route,
not the NCAE catalogue or registered PEQ. In PC 3.1.42.205594 M3091,
1278–1305 writes local equalizer settings; 1403–1429 preserves the other
slider and writes only on value change, and 1630–1676 labels 环绕深度
(-10…10) and 环绕强度 (0…10), integer step one. The recovered
pages/audio-effect/views/Equalizer.tsx:288–346 shows the same commit and
reset path. Reset clears bass, treble and both spatial values without
changing the GEQ curve. Cumulus keeps the two integers with the existing
account-local EQ CAS; older records read both as zero. Either nonzero
value enables the same M3091 SE1 plan (sshaper=true, ambience=1); renderer
input has no bank, RVB, native library path, material URL or authority.

The ordinary stock filter still receives GEQ/BT only. Spatial-only
settings can qualify the same already-owned, fingerprint-checked ordinary
NativeFile on a fresh load, with the existing held descriptor, verified
packaged libFLAC 1.5.0 and exact 44.1 kHz stereo 16-bit FLAC constraints
and full independent source timeline. The graph uses 2048-frame blocks;
it applies the same local full material or native master bypass, never
a LADSPA approximation. Already-bound graphs can apply the sliders and
master in place; seeking reclaims and resets the same graph. A setting
edited on a stock/unsupported source is saved for the next qualifying
native file load without restarting the current decoder. URLs, ordinary
library entries without the native-open receipt, CUE/preview/room audio,
unsupported FLAC, independently owned PEQ or missing/wrong SDK remain
on their prior route. This adds no downloads, rights checks or mutations.

The Windows explicit native-open WAV lane uses the same graph with the
existing fixed-NTFS handle and its native playback authority. Its eligible
full signed-16 stereo source geometry is 44.1/48 kHz. See
ordinary-native-local-equalizer-proof.txt for the official local-route
evidence, exact-file seek and stock handoff rules, and hosted proof scope.

Search playback from an already published download
--------------------------------------------------

Official PC 3.1.42.205594 M/163:298–317 checks the exact song's completed
download and offline privilege before preferring it; :330 and :372–384
then use the same type=0 native path as ordinary local media. M/308:2118–
2141 sends the selected source to ordinary AudioPlayer.play. The native
type=0 branch starts at cloudmusic.dll 103B83C–103B86F; ordinary audio
passes through AudioDeviceThread 1055EF0 (SDK input/output). The old M3091
material uses the already recovered EFB760 mapping, and the SDK's
1AA50 calls slot 50 before the final B0 limiter (1ACF3). This is distinct
from an HTTP/cache type=4 source and does not establish its seek boundary.

Cumulus now tries the same recovered local material for an existing
SearchPublication only if the full, unconstrained selection already has
a verified plain FLAC descriptor, saved active local controls and no
per-track gain/invalid-gain or separate filter requirement. The header is
read from the already checked File, not its name or requested quality.
The actor must acknowledge the current preparation generation before a
worker may displace a stock filter. That descriptor's existing queue,
ledger and account checks, cancellation and output lease remain in
force on both the PCM source and stock fallback. The audio reader does
not read SQLite; the actor still rechecks durable publication rights.
The graph retains its existing exact supported stereo s16 FLAC limits
and trusted runtime checks. Decoder rejection or an unavailable SDK
can keep the original authorized descriptor on stock; it does not
request an online URL or reopen a path. A revoked descriptor is not a
fallback. After graph playback starts, same-play seek reclaims and
resets the held source, and EOF still waits for native drain.

The initial selection's existing online fallback for a missing or
corrupt publication is unchanged. Encrypted downloads, arbitrary
download rows, cloud, CUE, trial/room playback, online streams and
independent remote effects are not enabled by this route. Device
recovery does not gain a new policy for reopening a retired native
host. No change to the cold grant, installed loader or renderer API.

Held PCM WAV input
------------------

The PC 3.1.42.205594 recovered M163 `createSourcePlayInfo` hands an
ordinary local filename to the native player without CUE offset/duration
fields (see recovered product 18-cue-local-playback). The recovered local
bridge does not prove an official OS file-association list. The original
M4 WAV picker is for cloud uploads. Cumulus already supports scanning WAV
in `library/mod.rs` and identifies RIFF/WAVE for pinned playback in
`playback/engine/mod.rs`. This is a narrow extension of that Cumulus
behavior; Windows and Linux file associations are unchanged.

The private native file-open path (`--play`, including the existing Linux
warm relay) also accepts a standalone RIFF PCM tag-1 file with exactly two
channels, 44,100 Hz, signed 16-bit little endian samples, one `fmt ` chunk
and one complete interleaved `data` extent. Core validates block alignment,
byte rate, chunk sizes and padding, and the complete RIFF file length. It
bounds the file to one hour of PCM plus at most 1 MiB for headers and
padding, and reads at most 128 top-level chunks. JUNK/PAD and bounded
LIST/INFO are allowed; alternate audio lists, RF64, extensible/compressed
WAV, unknown chunk kinds and other geometries do not qualify. Queue
duration comes from the verified frame count; the explicit open uses the
filename title rather than launching a separate pathname metadata probe.
The original queue receipt keeps the checked path and fingerprint; the
renderer still cannot supply one. An unsupported explicit WAV leaves the
warm queue untouched when no valid file remains. Ordinary library and CUE
playback retain their existing acceptance and playback rules.

For the active equalizer, the sole checked native file descriptor supplies
bounded samples by `i16 / 32768.0`, identical to the approved FLAC decoder
sample conversion. The same 2048-frame graph, control acknowledgements,
startup credit, source clock, cancellation and actual graph EOF apply.
The reader checks the layout again before each prepared pass, seeks by
source frame, and rejects a physical short read rather than reporting EOF.
No libFLAC runtime is required for this WAV branch; FLAC verification is
unchanged. Pre-audio recovery and a paused handoff to independent PEQ use
the same original held file and the verified WAV demuxer. After an audible
entry, a failed replacement does not replay it as stock.

Core cases cover malformed geometry, signed conversion, seeking and
truncation, durable receipt validation and an actual held-file rename with
seven frames remaining. The separate libFLAC 1.5.0 comparison renders both
formats through active GEQ/BT/SE at frame zero and a sample seek, comparing
every f32 output byte including the native graph's tail. These checks do not
by themselves verify desktop PCM, OS association behavior or listening on
a physical sound device. This section describes the initial 44.1 kHz proof;
the expansion below has separate source and original SDK evidence.

48 kHz ordinary held file
-------------------------

For 48 kHz, the original 3.1.42.205594 SDK create/init (`65B60`/`670E0`)
accepted stereo float input enum 3 and the same 2048-frame block capacity
and SE format `0x3102`. The isolated Unicorn host ran the unmodified x64
text, original begin/default/set/end controls, master-off, seek reset and
inner `1AA50` graph. The same cases distinguish GEQ-only, BT-only, SE-only,
partial and combined material, off/reopen, reset, short input and verified
EOF. Active SE has a 48,000-frame environment tail when retained to EOF;
default B0 lookahead is 238 frames. `1B960` resets B0 lookahead as in the
44.1 kHz domain. No original outer FIFO, CEF JSON, Windows device or
acoustic test is inferred.

`effects-local-equalizer-48k-official.json.gz` freezes fourteen synthetic
flows, all 159 final PCM and timing block digests and 54 selected prefixes.
Its manifest records provenance; the manual compactor only consumes the
two exact hash-pinned synthetic private reports, never an original binary.
An independent local comparison of the production C stage plus existing
Rust B0 matched the 159 final blocks and 1,113 intermediate child hashes;
33 final blocks and 231 child hashes at 44.1 kHz remained exact. The Rust
corpus test checks the integrated graph using the public vectors.

Only explicitly opened, checked NativeFile may select this ordinary graph.
PCM WAV accepts the same strict RIFF/tag-1 signed-16 geometry at 44.1 and
48 kHz; the file byte and frame limits are calculated at the selected rate.
Its metadata rate, bitrate and source duration come from that same layout.
FLAC requires the same trusted libFLAC 1.5.0, 16-bit stereo, known frame
count, and maximum 1024-frame decoder block; the held STREAMINFO rate and
every decoder callback must agree. No source is resampled to qualify. The
verified rate reaches the raw decoder, playback credit, logical duration,
clock and sample seek, and same-descriptor paused PEQ handoff. Cold offline
FLAC still requires 44.1 kHz at admission and callback. The standalone
fixed SE-only master constructor also retains its prior rate boundary.
Online, CUE, room, 96 kHz and other unsupported formats do not enter this
graph. No system file associations or release dependencies change.

The separate SE status is pending before a qualifying load, unavailable
on a currently unsupported source, and configured/processing only for
the owned graph; processing requires native sink advancement beyond the
accepted control watermark. Master bypass and failed processing are
separate; stored sliders are preserved. The variable SE tail is drained
by the existing held-source path while the displayed source position
never extends past the original file. The frozen 98 full-graph PCM/frame/
EOF hashes above support the graph; they do not by themselves validate
the native UI attachment. The new saved-plan and stock actor tests
exercise typed settings, CAS, authority-preserving fallback and no
restart. Native/GUI evidence for this addition is tracked separately.
