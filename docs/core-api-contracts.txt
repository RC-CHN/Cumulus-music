已迁移的 Rust 底层业务契约
2026-10-25；这里列出已做本地对照的API封装，HTTP及登录协调已接入，完整播放/下载等流程仍在迁移。
原产品逻辑/详细证据位于 references/recovered-client/docs/product/；不改写旧验收结果。

共同约束
protocol::api::Api 是异步传输契约；调用返回对象且code为200或明确允许的其他码。
标识符按正十进制字符串保存，拒绝bool/负数/零/非ASCII数字，不收窄到JavaScript安全整数。
分页默认limit=200、max_pages=1000；按返回条数推进offset，尊重more/hasMore，
重复非空页、非终止空页、异常flag或到达上限均报不完整，不返回貌似成功的残缺列表。
失败写入不换协议重放、不自动重试。批量部分成功保留全部子响应交给上层对账。
调用方应通过AccountSession捕获账号代次并验证返回；缓存写入使用save_result检查代次。
底层Value响应只在原生域内使用，未经脱敏和DTO转换不得直接交给前端。

账号与登录
Api::account             /api/w/nuser/account/get
  必须读到合法profile.userId；缺身份视为301。AccountSession负责认证提交/过期/切换。
QrLogin::begin           /api/login/qrcode/unikey
  type=3；重建携带lastUniKey。返回键存在才进入waiting_scan。
QrLogin::poll            /api/login/qrcode/client/login
  key/type=3，可携带用户完成的secureCaptcha。800过期，801待扫，802待确认，803授权，
  8821挑战；挑战无输入不重复发请求，取消/替换会拒绝旧响应，不能并发轮询同一尝试。
  QrLogin本身只负责二维码协议；login::QrAuthentication负责独立候选、account/get及原子选择。
  密码/SMS/挑战、刷新与退出的完整契约见 docs/core-login-contracts.txt。
