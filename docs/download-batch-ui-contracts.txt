下载管理：已下载单曲/声音批量操作（2026-10-30）

产品入口与官方证据
- references/ui-recovery/sources/packages/pc/src/pages/download/index.tsx 的
  /download/track/batch、/download/voice/batch 是独立内容页，批量时不显示四个分类页签。
  DownloadedTrackBatchOperation、DownloadedVoiceBatchOperation 都发送
  page:download/requestAllDownloadedList，传 resourceType、orderBy，不传列表搜索关键词。
  所选记录按 offlineId 区分；动作过滤原 records，表内临时排序不改变动作顺序。
- 单曲工具栏依次播放、添加到播放列表、收藏、删除；声音为播放、添加到播放列表、删除。
  共用 BatchOperationHeader 的默认 40px 高、12px 间隔、右侧“完成”和 64px 行。
  来自 references/netease-3.1.42.205594-analysis/recovered-js/modules/
  hybrid_app.chunk.1482700000000.js/352.js:1342、hybrid_51.chunk.1482700000000.js/
  2061.js:628：单曲为复选、标题、专辑、下载时间、大小；声音没有专辑列。
  标题列显示全选/已选数量，不是标题排序入口。专辑、时间、大小可按正/反/关三态切换，
  调整列宽时统一表头和表体。106.js useSortBy 对当前内存行排序；取消后恢复进入时的顺序。
- 单曲收藏输入是原始在线歌曲，声音没有收藏操作。3085.js 的 deleteDownload 派发
  download/delete；recovered-client/docs/product/models/download.txt:1509 确认文案
  为“确定删除下载文件？”，确认后删除本地音频、歌词并更新下载记录。这是文件删除，
  不应实现为只隐藏一行或删除远端歌单歌曲。没有使用 YesPlayMusic。
- Cumulus 在确认正文列出数量并说明本地文件影响，默认焦点取消；所选记录已改变时
  禁止继续确认，返回后重新核对。保留自己的品牌、图标、选中颜色及小窗口换行策略。

界面与 IPC
1. 下载页“更多下载操作 → 批量操作”保留父页，进入独立内容区。在 batchDownloadQuery
   中取分类和原排序、清空 keyword、从 offset=0 通过 downloads(epoch, query) 取全部；
   只有 tasks.length === total 才展示列表，超过核心一次读取上限100万时给出读取错误，
   不能以一页或部分结果冒充全部。渲染节点保持有界。完成/顶栏返回/Escape回到列表，
   保留父页的筛选、滚动位置，并将焦点交回更多按钮。侧栏跨页导航不抢回旧焦点。
2. useDownloadBatch 单独保存读取代次、选中集合及排序；初次/焦点恢复、已完成数量/
   文件操作变化时重读；迟到结果不覆盖新账号或已离开的页面。列维护离线任务ID，
   点击独立切换、Shift范围、Ctrl+A全选、方向键/虚拟行回收与歌单批量表共用useBatchRows。
   点击列标题只改变显示顺序；原始动作顺序仍来自完整分类记录。
3. play_downloads(epoch, taskIds, index=0) 替换队列开始离线播放；player_action(epoch,
   {kind:'queue_downloads',task_ids,expected_queue_revision}) 从核心本机目录装载资源，
   不让前端指定文件路径或播放授权。复用普通队列当前项之后的插入/去重规则；下载用
   download_task_id 区分，不把同歌曲ID的流媒体、本地记录、不同下载版本合并。
   空队列启动，非空保留当前项；准备过程中队列变化则拒绝，FM需先切回普通队列。
   音源实际播放沿用离线登记、账号、权益和文件完整性校验。本次未增加远端取音频请求。
4. 收藏进入既有 PlaylistCollectDialog，传账号代次和可收藏的原歌曲，沿用歌单选择/
   创建/写入核对；声音无此入口。本轮只打开、取消，不写真实账号歌单。
5. download_command(epoch,{kind:'delete_files',task_ids}) 接收定格的确认选择；单次最多
   5000项，按任务ID去重。核心串行执行已有 completed.start(Delete) / resume，核对
   标识和文件完整性，每个已开始的文件有持久操作记录。返回 accepted（已完成删除的
   任务ID）、failed（未完成的任务ID及提示）。界面显示实际数量；部分失败不重放整批。
   未确认结果先重读。进程退出后已准备的未完成项可在文件操作区重新核对；
   尚未开始的剩余选择不会在重新启动后自动删除。不存在单个跨文件的原子删除事务。
   播放/加入队列/删除均明确拒绝单次超过5000项；不通过截断来显示操作成功。

边界
- 分类进入顺序来自 Rust 下载查询；恢复 SQL 的中文拼音排序差异仍在普通下载页专项，
  批量表内专辑比较采用宿主 localeCompare，不声称特殊符号/中文拼音的官方逐项一致。
- 删除整个批次对进程崩溃不是全有或全无。本轮故障证据区分单文件持久化、部分结果
  和真实 UI 删除回读；完整文件操作、迁移、冲突 UI 继续逐态核对。实验紧凑行高、
  真实封面、Windows/DPI 和所有系统刷新率仍有边界。本机 KDE 125% 两个尺寸的
  窗口截图与帧回调测量见 ui-ux-validation.txt，不外推为其他平台通过。
